공공데이터포털 인증키로 데이터 받기

인증키를 받았다면, 요청 주소와 요청 인자를 AI에 전달해 URL을 만들어 보세요.

1. 이 세 가지만 준비하세요

섹션 제목: “1. 이 세 가지만 준비하세요”

신청한 API의 상세 페이지나 활용가이드에서 사용할 조회 기능을 고릅니다.

준비할 것넣을 내용
요청 주소(URL)선택한 기능의 요청주소를 복사합니다.
요청 인자(요청변수·파라미터)항목 이름·필수 여부·형식·예시가 있는 표를 복사하거나 캡처합니다.
가져오고 싶은 데이터지역·날짜·검색어·개수 등 원하는 조건을 적습니다.

찾기 어렵다면 상세 페이지에서 Ctrl+F로 요청주소, 요청변수를 검색하거나 참고문서·활용가이드를 확인하세요.

2. 아래 프롬프트를 복사하세요

섹션 제목: “2. 아래 프롬프트를 복사하세요”

표시된 세 곳을 우리 팀의 내용으로 바꾸어 AI에 보냅니다. 실제 인증키는 보내지 않습니다.

데이터 요청 URL 만들어 달라고 하기 표시된 부분을 우리 팀의 내용으로 바꾸세요.
프롬프트 구조와 각 부분이 필요한 이유 보기

역할·프로젝트 맥락은 AI가 어떤 관점에서 어느 팀의 문제를 다루는지 정합니다.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

공공데이터포털에서 인증키를 발급받았습니다.
아래 정보를 이용해 데이터를 요청할 수 있는 URL을 만들어 주세요.

① 요청 주소(URL):
{{여기에 붙여 넣기}}

② 요청 인자(파라미터) 표:
{{여기에 복사해 넣거나 화면 첨부하기}}

③ 가져오고 싶은 데이터:
{{지역·날짜·검색어·개수 등 원하는 조건}}

인증키는 실제 값 대신 YOUR_API_KEY로 표시하고, 제가 어디에 넣으면 되는지 알려 주세요. 공식 명세에서 지원하면 JSON으로 응답받도록 만들어 주세요.
완성된 URL과 인터넷 주소창에 붙여 넣어 결과를 확인하는 방법을 짧게 알려 주세요. 주소창으로 실행할 수 없는 방식이면 해당 API의 실행 방법을 알려 주세요.
필수 정보가 부족하면 임의로 만들지 말고 무엇이 필요한지 물어봐 주세요.

3. 요청 주소는 이런 모양입니다

섹션 제목: “3. 요청 주소는 이런 모양입니다”
기호역할예
?첫 요청 인자 시작?serviceKey=YOUR_API_KEY
=인자 이름과 값 연결pageNo=1
&다음 요청 인자 연결&numOfRows=10

예를 들어 요청변수 표의 pageNo에 1을 넣는다는 뜻이 pageNo=1입니다. 인자 이름과 넣을 값의 형식은 API마다 다릅니다.

기상청 요청 주소 예시 보기

기상청 단기예보 조회서비스의 초단기실황조회는 관측된 실황을 받는 기능입니다.

이 요청은 지정한 날짜·시각과 격자의 실황을 JSON으로 보내 달라는 뜻입니다. 실행하려면 키·날짜·시각·격자를 해당 서비스의 안내에 맞게 바꿉니다. 실제 인증키를 사용한 호출 결과는 아닙니다.

공공데이터포털의 serviceKey와 기상청 API허브의 authKey는 인증 체계가 다릅니다. 신청한 서비스의 주소와 키를 함께 사용하세요.

4. 인증키를 넣고 실행하세요

섹션 제목: “4. 인증키를 넣고 실행하세요”
  1. AI가 만든 URL에서 조건값과 필수 항목이 요청변수 표에 맞는지 확인합니다.
  2. YOUR_API_KEY 자리를 본인의 인증키로 바꿉니다. Encoding/Decoding은 해당 API의 실행 안내를 따릅니다.
  3. 완성된 URL을 줄바꿈 없이 인터넷 주소창에 붙여 넣고 Enter를 누릅니다.

주소창 실행은 GET 방식이며 인증과 조건을 URL에 넣는 API에서 가능합니다. POST 방식이나 헤더 인증이 필요한 API는 기관의 테스트 도구와 공식 실행 안내를 사용합니다.

5. 받은 결과에서 값 하나를 찾아보세요

섹션 제목: “5. 받은 결과에서 값 하나를 찾아보세요”

화면에 나타난 JSON 또는 XML이 응답입니다. 처리 결과가 정상인지 확인하고, 출력결과 표와 비교해 필요한 항목의 이름·값·뜻을 찾아보세요.

보낸 것받은 것
요청 인자: 지역·날짜·검색어 등의 조건응답 항목: 이름·주소·기온 등 조회된 값

오류가 나오면 실제 키를 가린 요청 URL과 오류 문구를 AI나 선생님께 보여 주세요. 자료가 없다는 응답과 인증·요청 오류를 구분합니다.

다음 단계 · 받은 데이터를 앱에 넣으려면

현재 앱 파일 + 공식 요청·응답 설명 + 키를 가린 실제 정상 응답을 준비해 기존 앱에 연결을 요청합니다. 화면에 표시한 값은 원래 응답의 값과 비교하세요.

주소창에서 응답이 보여도 앱에서는 브라우저 접근 제한(CORS)이나 서버 설정 때문에 추가 작업이 필요할 수 있습니다. 비밀키를 사용하는 공개 앱의 연결은 선생님과 확인하세요. GitHub Pages는 비밀키를 숨기거나 서버 코드를 실행해 주지 않습니다.

☑️ 여기까지 확인하면 됩니다

어떤 조건을 보냈고, 어떤 값을 받았나요? 직접 받은 항목 하나의 이름·값·뜻을 기존 활동지에 기록하세요. 키가 들어간 URL은 공유하지 않습니다.
