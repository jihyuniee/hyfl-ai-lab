프로젝트를 구현하는 중 AI 챗봇·요약·설명 기능이 필요한 팀을 위한 도움말입니다. **우리 팀 앱에서 AI가 맡을 역할**을 정한 뒤 아래 안내에 따라 신청합니다.

<Callout kind="mission" title="AI API 사용 신청 안내">
우리 팀 웹앱에 **GPT나 Claude를 활용한 챗봇·요약·설명 기능**을 넣고 싶다면 **선생님께 API 사용을 요청하세요.** 프로젝트에 사용할 API와 연결 방법을 지원받을 수 있습니다. 사용할 서비스와 모델, 사용 기간·사용량은 선생님과 확인합니다.
</Callout>

## 1. AI API는 어떤 역할을 할까?

AI API는 우리 앱에서 보낸 질문이나 자료를 AI 모델이 처리하고, 그 결과를 앱으로 돌려주는 연결 방식입니다. 팀은 질문 입력창·답변 화면과 함께 **AI의 역할과 사용할 자료**를 설계합니다.

| 우리 팀 앱의 기능 예시 | AI에 보낼 내용 | 화면에 보여 줄 결과 |
| --- | --- | --- |
| 데이터 설명 도우미 | 원자료로 계산한 통계와 사용자의 질문 | 수치의 의미를 풀어 쓴 설명 |
| 공공시설 안내 챗봇 | 검색된 시설 정보와 사용자의 질문 | 조건에 맞는 시설과 선택 이유 |
| 외국어 정보 안내 | 출처가 있는 안내문과 선택한 언어 | 번역문과 원문 출처 |

우리 앱의 **어떤 어려움을 AI가 도울지** 한 문장으로 정하고 신청합니다. 데이터 집계·필터·정렬 결과를 AI에 전달한다면 해당 계산은 코드로 수행하고 원자료와 대조합니다.

## 3. 웹앱과 AI 연결 구조 이해하기

**사용자 질문 → 우리 앱의 서버 → GPT·Claude API → 서버 → 앱의 답변 화면** 순서로 연결합니다.

| 구성 요소 | 역할 |
| --- | --- |
| 웹앱 화면 | 질문을 입력받고 서버에 보낸 뒤 답변을 표시합니다. |
| 서버의 API 경로 | 사용 권한·요청량을 확인하고 AI에 필요한 내용만 전달합니다. |
| 서버 환경변수 | AI 서비스의 비밀 API 키를 보관합니다. |

`index.html`을 GitHub Pages에 배포하는 팀은 AI 요청을 처리할 **별도의 서버 또는 서버리스 함수**를 함께 연결합니다. 선생님이 안내한 연결 주소·사용 방법을 기준으로 구현합니다.

API 키는 **서버 환경변수에 보관**합니다. 공개 HTML·JavaScript·GitHub 저장소·활동지·AI 대화에는 키 대신 `YOUR_API_KEY` 같은 자리표시자를 사용합니다. 팀별 사용 권한과 요청량 제한은 서버에서 확인하도록 설계합니다.

## 5. 실행하고 확인하기

1. **기본 질문:** 예상한 질문을 입력하고 답변이 프로젝트 목적에 맞는지 확인합니다.
2. **자료 대조:** 답변 속 수치·시설명·날짜를 원자료와 비교합니다. AI 답변에는 오류가 있을 수 있습니다.
3. **자료 밖 질문:** 제공 자료에 없는 질문을 넣고, 확인할 수 없는 내용을 어떻게 안내하는지 살펴봅니다.
4. **오류 상황:** 빈 질문, 연속 클릭, 서버 오류, 사용량 초과 때의 안내를 확인합니다.
5. **정보 확인:** API에 전달할 자료에서 이름·연락처·상담 내용 등 개인정보를 제외합니다.

## 6. 활동지에 기록하기

| 활동지 위치 | 기록할 내용 |

| STEP 4 · AI 활용 | 사용한 서비스·모델, 구현 요청문, 사람이 검증하고 결정한 내용 |

**완료 기준:** 배포된 웹앱에서 질문과 답변을 주고받고, 답변을 원자료와 대조한 기록을 남겼습니다.
