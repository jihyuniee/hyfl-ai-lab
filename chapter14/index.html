생성형 AI와 함께 웹앱 제작하기

Part 3: Project 1. Teachable Machine AI 웹앱 프로젝트 · 14차시

🗺️ 이 챕터의 교과 결합

섹션 제목: “🗺️ 이 챕터의 교과 결합”
mindmap

    정보

    연결 다리

이 챕터는 정보 교과의 “웹앱 코드 작성·실행” 기능과, 인공지능 교과의 “학습된 모델을 활용한 추론” 개념을 결합합니다. 두 교과를 잇는 다리는 생성형 AI에게 코드를 요청하고, 그 결과를 우리가 검증하는 과정입니다.

🌟 생각 열기

섹션 제목: “🌟 생각 열기”

여러분이 앞선 차시에서 Teachable Machine으로 만든 이미지 분류 모델을 떠올려 봅시다. 그 모델은 “가위, 바위, 보”를 알아맞혔지만, 학습 페이지 안에서만 동작했습니다.

“이 모델을 친구에게 링크로 보내서, 친구 웹브라우저에서도 카메라로 동작하게 만들려면 어떻게 해야 할까요?”

정답은 웹앱(web app) 으로 만드는 것입니다. 그런데 웹앱을 만들려면 코드를 써야 합니다. 여러분이 아직 자바스크립트 전문가가 아니라면 어떻게 해야 할까요?

바로 여기서 생성형 AI가 등장합니다. 우리는 “코드를 처음부터 다 외워서 쓰는 사람”이 아니라, “AI에게 정확히 요청하고, 나온 결과를 검증해 완성하는 사람” 이 될 것입니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 생성형 AI에게 명확한 요청(프롬프트)을 보내 Teachable Machine 모델을 불러오는 웹앱 코드를 얻을 수 있다.
  • AI가 생성한 코드를 검증·수정하여 실제로 동작하는 웹앱을 완성할 수 있다.

📚 선수학습 확인

섹션 제목: “📚 선수학습 확인”
  • 10-13차시: Teachable Machine으로 이미지 분류 모델을 학습시키고, 모델 URL(공유 링크) 을 얻는 방법을 배웠습니다. 이 URL이 오늘 웹앱이 불러올 “학습 결과”입니다.
  • 웹의 기본: 웹앱은 HTML(뼈대), 자바스크립트(동작)로 이루어집니다. 파일 하나로도 브라우저에서 실행할 수 있다는 것을 기억합시다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: “AI에게 코드 심부름 시키기”

섹션 제목: “탐구: “AI에게 코드 심부름 시키기””

  • 준비물: 인터넷 연결 PC, 웹브라우저, 앞 차시에서 만든 Teachable Machine 모델 URL, 생성형 AI 채팅 도구(교사 안내 도구), 카메라(내장 또는 USB)

  • 과정:

    1. 생성형 AI에게 아무 정보 없이 “Teachable Machine 웹앱 코드 만들어 줘”라고만 요청해 봅니다.
    2. 나온 코드를 HTML 파일로 저장하고 브라우저에서 열어 봅니다.
    3. 이번엔 모델 URL, 원하는 기능, 파일 형식을 구체적으로 적어 다시 요청합니다.
    4. 두 결과를 비교합니다.

  • 결과 예측: “아무 정보 없이 요청한 코드”와 “구체적으로 요청한 코드” 중 어느 쪽이 바로 동작할까요?

  • 토의: “왜 같은 AI인데 결과가 이렇게 다를까요? AI에게 잘 요청한다는 것은 무엇을 의미할까요?”

이 탐구에서 확인한 것처럼, 생성형 AI는 입력한 정보의 질만큼만 좋은 코드를 내놓습니다. 요청이 막연하면 모델 URL이 빠져 동작하지 않는 코드가 나오고, 요청이 구체적이면 훨씬 완성도 높은 결과가 나옵니다.

🧠 핵심 개념

섹션 제목: “🧠 핵심 개념”

개념 1: 프롬프트 엔지니어링 [정보] [인공지능]

섹션 제목: “개념 1: 프롬프트 엔지니어링 [정보] [인공지능]”
  • 정의: 생성형 AI로부터 원하는 결과를 얻기 위해, 요청(프롬프트)에 맥락·목표·제약 조건을 명확히 담아 설계하는 기술입니다.
  • 비유: 프롬프트는 마치 요리사에게 주는 주문서와 같습니다. “밥 줘”라고 하면 아무 밥이나 나오지만, “매운 김치볶음밥, 계란프라이 얹어서, 1인분”이라고 하면 원하는 요리가 나옵니다.

좋은 코드 요청 프롬프트는 다음 요소를 포함합니다.

요소내용 예시
목표”카메라 영상으로 실시간 분류하는 웹앱을 만들어 줘”
재료(모델 URL)“내 모델 URL은 https://teachablemachine…/ 야”
형식”HTML 파일 하나로, 자바스크립트 포함해서 줘”
제약”초보자가 이해하도록 주석을 달아 줘”

개념 2: 생성 코드의 검증과 수정 [정보]

섹션 제목: “개념 2: 생성 코드의 검증과 수정 [정보]”
  • 정의: AI가 만든 코드를 그대로 믿지 않고, 실행해 보고 오류를 찾아 고치는 과정입니다.
  • 비유: AI가 준 코드는 초안 원고와 같습니다. 편집자인 내가 오탈자와 사실 오류를 확인해야 완성본이 됩니다.

AI 코드가 자주 틀리는 지점은 다음과 같습니다.

flowchart TD
  A[AI 생성 코드] --> B{실행해 본다}
  B -->|모델 URL 미입력| C[URL 넣기]
  B -->|라이브러리 링크 오류| D[스크립트 주소 확인]
  B -->|카메라 권한 거부| E[브라우저 권한 허용]
  B -->|정상 동작| F[완성!]
  C --> B
  D --> B
  E --> B

AI 코드는 항상 “실행 → 오류 확인 → 수정” 순환을 거쳐야 완성됩니다.

🔗 교과 간 연결

섹션 제목: “🔗 교과 간 연결”

정보 × 인공지능의 만남: 이 웹앱에서 자바스크립트 코드(정보)는 “그릇”이고, Teachable Machine 모델(인공지능)은 “그릇에 담기는 지능”입니다. 코드가 모델 URL로 학습 결과를 불러오면, 카메라 영상이 들어올 때마다 모델이 추론(inference) 하여 “바위 92%” 같은 확률을 돌려줍니다. 코드는 그 확률을 화면에 예쁘게 보여줄 뿐입니다.

즉 인공지능이 판단하고, 정보 기술이 전달합니다. 둘 중 하나만 있으면 웹앱은 완성되지 않습니다.

가로지르는 질문

섹션 제목: “가로지르는 질문”

“AI가 만든 코드로 AI 모델을 실행하는 웹앱을 만들었다면, 이 웹앱을 ‘내가 만들었다’고 말할 수 있을까요? 만든 사람은 누구일까요?”

이 질문에 답하려면 [정보]의 “저작·검증 책임” 관점과 [인공지능]의 “생성물의 창작 주체” 관점을 함께 동원해야 합니다.

👣 따라하기 실습 (5단계)

섹션 제목: “👣 따라하기 실습 (5단계)”

앞 차시에서 얻은 모델 URL을 미리 복사해 두세요. 이 실습의 핵심 재료입니다.

1단계: 요청서(프롬프트) 작성

섹션 제목: “1단계: 요청서(프롬프트) 작성”

생성형 AI에게 아래 형식으로 요청합니다.

프롬프트 구성내가 적을 내용
목표Teachable Machine 이미지 모델을 카메라로 실시간 분류하는 웹앱
모델 URL(내 모델 공유 URL 붙여넣기)
형식HTML 파일 하나, 자바스크립트 포함, 각 클래스 확률 화면 표시
제약초보자용 주석 포함, 카메라 시작 버튼 넣기

2단계: 코드 받아 저장

섹션 제목: “2단계: 코드 받아 저장”

AI가 내놓은 코드를 복사해 메모장(또는 코드 편집기)에 붙여넣고, myapp.html 이라는 이름으로 저장합니다. (파일 형식을 “모든 파일”로 지정)

3단계: 실행

섹션 제목: “3단계: 실행”

myapp.html을 더블클릭해 브라우저에서 엽니다. “카메라 시작” 버튼을 누르고 권한을 허용합니다.

4단계: 오류 확인과 수정

섹션 제목: “4단계: 오류 확인과 수정”

동작하지 않으면 아래 표로 점검합니다.

증상원인해결
화면이 하얗다모델 URL 미입력/오타코드 속 URL을 내 것으로 교체
카메라가 안 켜진다권한 거부주소창 옆 아이콘에서 카메라 허용
확률이 안 뜬다라이브러리 링크 문제AI에게 “스크립트 주소 확인해 줘” 재요청

📖 읽을거리

섹션 제목: “📖 읽을거리”

“코드를 못 짜도 개발자가 될 수 있을까?”

2022년 이후 생성형 AI 코딩 도구가 등장하면서, 소프트웨어 개발의 풍경이 바뀌었습니다. 이제 많은 개발자들이 코드를 처음부터 타이핑하기보다, AI에게 초안을 요청하고 검토·수정·통합하는 데 시간을 씁니다.

하지만 전문가들은 입을 모아 말합니다. “AI가 준 코드를 읽고 이해하지 못하면 결국 아무것도 고칠 수 없다.” 즉, 미래의 개발자에게 필요한 능력은 “코드 암기”가 아니라 코드를 읽고 판단하는 힘, 그리고 정확히 요청하는 언어 능력입니다. 오늘 여러분이 한 일이 바로 그 연습입니다.

🧩 다교과 관점 비교

섹션 제목: “🧩 다교과 관점 비교”

같은 “AI 생성 코드” 현상을 두 교과가 어떻게 바라보는지 비교해 봅시다.

쟁점정보 관점인공지능 관점
코드의 역할모델을 실행·전달하는 도구추론 결과를 담는 그릇
무엇을 검증하나코드가 오류 없이 실행되는가모델 예측이 정확한가
실패의 원인문법·링크·권한 오류학습 데이터 부족·편향
개선 방법코드 디버깅데이터 추가 학습

같은 웹앱이 안 될 때, 정보의 눈으로는 “코드 오류”를, 인공지능의 눈으로는 “모델 성능”을 의심합니다. 두 관점을 모두 가져야 진짜 문제를 찾습니다.

심화 (사고력·서술형)

섹션 제목: “심화 (사고력·서술형)”
  1. “AI가 코드를 만들고, AI 모델이 판단하는 웹앱”에서 사람이 하는 역할은 무엇인지, 정보 관점과 인공지능 관점을 모두 사용해 서술하세요.
정답 확인
  1. ④ (AI 회사의 주가는 코드 생성과 무관합니다)
  2. ② (오류 원인을 알아야 고칠 수 있습니다)
  3. 예시: “코드 속 예시 URL을 내 Teachable Machine 모델의 실제 공유 URL로 교체한다.”
  4. 예시 답안: 사람은 정보 관점에서 AI가 만든 코드가 오류 없이 실행되는지 검증·수정하고, 인공지능 관점에서 모델의 예측이 정확한지 데이터로 확인하며 필요하면 재학습을 결정한다. 즉 사람은 코드와 모델 양쪽을 검증하고 책임지는 최종 판단자이다.
