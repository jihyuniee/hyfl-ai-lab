6. Open API 맛보기: 데이터가 나오는 주소 읽기

DATA EXPLORATION · OPEN API
오늘의 질문웹앱은 공공데이터를 어떻게 직접 가져올까?

지난 시간에는 KOSIS MCP로 국가통계를 찾고, AI가 제시한 통계표를 원자료와 비교했습니다. 이번 시간에는 KOSIS 밖의 생활 데이터가 웹앱으로 들어오는 또 다른 길을 살펴봅니다. 바로 Open API입니다.

🎯 오늘의 미션

Open API가 데이터를 요청하는 주소라는 것을 이해하고, NEIS 급식 API 예시를 통해 요청 조건과 응답 데이터를 읽어 봅니다. 마지막에는 이 데이터를 간단한 웹앱으로 연결하려면 무엇을 조심해야 하는지 정리합니다.

⚠️ 먼저 생각하고 AI를 사용합니다

API 주소를 붙여 넣기 전에 먼저 어떤 값을 바꾸면 결과가 달라질지 예상합니다. 생성형 AI는 응답 구조를 읽고 표로 정리하는 데 도움을 주는 도구입니다. 어떤 데이터를 쓸지, 어떤 조건으로 볼지, 결과를 어떻게 해석할지는 사람이 결정합니다.

1. MCP와 Open API는 어떻게 다를까?

섹션 제목: “1. MCP와 Open API는 어떻게 다를까?”

KOSIS MCP와 Open API는 모두 외부 데이터를 활용한다는 점에서는 비슷합니다. 하지만 사람이 만나는 방식이 다릅니다.

구분KOSIS MCPOpen API
쉽게 말하면AI가 통계 도구를 불러와 자료를 찾는 방식주소에 조건을 넣어 데이터를 직접 요청하는 방식
사용자가 주로 하는 일자연어로 질문하고 통계표 후보 확인요청 주소와 조건값을 이해하고 응답 데이터 확인
자주 만나는 자료통계표, 수치, 설명JSON, XML, CSV
확인할 것통계표 이름, 기간, 지역, 단위API 문서, 요청 변수, 응답 항목, 인증키
프로젝트 연결국가통계 기반 분석웹앱에서 실시간 또는 조건별 데이터 조회

Open API는 앱이나 웹사이트가 데이터를 가져올 때 자주 사용하는 방식입니다. 예를 들어 날짜를 바꾸면 다른 날의 급식이 나오고, 학교 코드를 바꾸면 다른 학교의 자료가 나옵니다.

2. 오늘 살펴볼 자료: NEIS 급식식단정보

섹션 제목: “2. 오늘 살펴볼 자료: NEIS 급식식단정보”

오늘 예시는 NEIS 교육정보 개방 포털의 급식식단정보입니다. 이 자료는 학교 급식의 요리명, 원산지정보, 칼로리정보, 영양정보 등을 일자별로 제공합니다. 원자료 페이지에서 제공 기관, 적재 주기, 이용 허락 범위, 알레르기 번호 설명을 함께 확인합니다.

  • 원자료: NEIS 급식식단정보

📚 오늘의 핵심 개념

API 요청 주소는 데이터가 나오는 주소입니다. 주소 뒤에 붙은 조건값을 바꾸면 요청하는 데이터의 범위가 달라집니다.

3. API 요청 주소 읽기

섹션 제목: “3. API 요청 주소 읽기”

NEIS 급식 API 요청 주소는 다음과 같은 구조로 볼 수 있습니다. 실제 수업에서는 선생님이 제공한 인증키와 학교 코드를 사용하거나, 선생님이 미리 준비한 예시 주소와 응답 데이터를 사용합니다.

부분의미바꾸면 달라지는 것
mealServiceDietInfo급식식단정보 서비스 이름요청하는 데이터 종류
KEYAPI 인증키누가 요청하는지 확인
Type=json응답 형식JSON 또는 XML 등 형식
pIndex, pSize페이지 번호와 한 번에 받을 개수조회 결과의 범위
ATPT_OFCDC_SC_CODE시도교육청 코드어느 교육청 자료인지
SD_SCHUL_CODE학교 코드어느 학교 자료인지
MLSV_YMD급식일자어느 날짜의 급식인지

? 뒤에는 요청 조건이 이어지고, 여러 조건은 &로 연결됩니다. 조건값 하나를 바꾸면 API가 보내 주는 결과도 달라집니다.

⚠️ API 키는 비밀번호처럼 다룹니다

API 키는 공개 게시물, GitHub 저장소, GitHub Pages용 HTML 파일에 직접 넣지 않습니다. 수업에서 선생님이 제공한 키는 실습용으로만 사용하고, 공개 웹앱을 만들 때는 파일 다운로드 방식이나 서버에서 키를 숨기는 방식을 사용합니다.

4. 브라우저로 직접 요청해 보기

섹션 제목: “4. 브라우저로 직접 요청해 보기”

처음에는 코드를 쓰기보다 브라우저 주소창에서 요청 주소를 열어 봅니다.

  1. 예상하기

    날짜를 바꾸면 어떤 결과가 달라질지 먼저 예상합니다. 메뉴, 식사명, 칼로리 같은 항목이 보일지 생각해 봅니다.

  2. 요청 주소 열기

    선생님이 제공한 예시 요청 주소를 브라우저 주소창에 붙여 넣고 실행합니다.

  3. 응답 형식 확인하기

    화면에 표가 아니라 중괄호와 대괄호가 많은 JSON 구조가 보일 수 있습니다. 이것은 앱이 읽기 쉬운 데이터 형식입니다.

  4. 조건값 바꾸기

    날짜나 페이지 크기처럼 수업에서 허용한 조건 하나를 바꿔 보고 결과가 어떻게 달라지는지 확인합니다.

  5. 필요한 항목 찾기

    학교명, 급식일자, 식사명, 요리명처럼 앱에서 쓸 항목을 찾습니다.

처음부터 모든 항목을 이해할 필요는 없습니다. 오늘은 주소의 조건값이 데이터 요청을 바꾼다는 것을 확인하는 것이 목표입니다.

5. JSON 응답에서 표 만들기

섹션 제목: “5. JSON 응답에서 표 만들기”

API 응답은 보통 사람이 보기 좋은 표가 아니라, 프로그램이 읽기 좋은 구조로 옵니다. 필요한 항목을 골라 표로 바꾸면 분석하기 쉬워집니다.

응답 항목 예학생용 이름확인할 내용
SCHUL_NM학교명요청한 학교가 맞는가
MLSV_YMD급식일자원하는 날짜 또는 기간이 맞는가
MMEAL_SC_NM식사명조식, 중식, 석식 중 무엇인가
DDISH_NM요리명실제 메뉴와 알레르기 번호가 들어 있는가
CAL_INFO칼로리정보단위와 누락 여부를 확인해야 한다
NTR_INFO영양정보어떤 영양 항목이 포함되는지 확인해야 한다
API 응답 구조 읽기 프롬프트 {{빨간 부분}}을 우리 팀의 내용으로 바꾸세요.
프롬프트 구조와 각 부분이 필요한 이유 보기

역할·프로젝트 맥락은 AI가 어떤 관점에서 어느 팀의 문제를 다루는지 정합니다.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

아래 Open API 요청 주소 또는 응답 데이터를 바탕으로 구조를 읽어줘.

요청 주소:
[API 요청 주소 붙여 넣기]

응답 일부:
[JSON 또는 XML 응답 일부 붙여 넣기]

다음 순서로 설명해줘.
1. 이 API가 어떤 자료를 제공하는지
2. 요청 주소에서 바꿀 수 있는 조건값
3. 응답 데이터에서 한 행 또는 한 기록이 무엇을 뜻하는지
4. 날짜, 학교명, 식사명, 메뉴처럼 분석에 쓸 항목
5. 표로 바꾸면 열 이름을 어떻게 정하면 좋을지
6. 이 자료로 알 수 있는 것
7. 이 자료만으로는 알 수 없는 것
8. 원자료 또는 공식 문서에서 다시 확인해야 할 것

확실하지 않은 내용은 단정하지 말고 "확인 필요"라고 표시해줘.

AI가 정리한 표가 맞는지 원자료와 비교합니다. 특히 날짜, 학교명, 식사명, 메뉴는 직접 찾아볼 수 있어야 합니다.

6. 간단한 웹앱으로 연결하기

섹션 제목: “6. 간단한 웹앱으로 연결하기”

Open API를 이해하면 다음 단계에서 웹앱으로 연결할 수 있습니다. 사용자가 날짜를 고르면 앱이 API에 요청을 보내고, 응답에서 메뉴를 뽑아 화면에 보여 주는 방식입니다.

만들 수 있는 기능필요한 데이터주의할 점
오늘의 급식 조회날짜, 학교명, 식사명, 메뉴API 키 공개 금지
특정 메뉴가 나온 날 찾기기간별 요리명기간 조회와 중복 처리 기준
월별 메뉴 빈도 보기날짜, 요리명메뉴 이름 정리 기준
알레르기 번호 확인요리명 원문번호의 의미를 원자료에서 확인
칼로리 비교칼로리정보단위와 누락값 확인

NEIS 급식 Open API를 사용해 간단한 급식 조회 앱을 설계하려고 해.

주의할 점: API 키는 공개 저장소에 올리지 않는다. API 응답은 공식 문서와 비교한다.

다음 항목으로 도와줘.
1. 앱 첫 화면에 필요한 입력 요소
2. API 요청에 필요한 조건값
3. 응답 데이터에서 사용할 항목
4. 결과를 표나 카드로 보여 주는 방식
5. 결과 없음, 잘못된 날짜, API 오류 때의 안내 문구
6. GitHub Pages 같은 공개 정적 웹앱에서 API 키를 직접 넣으면 안 되는 이유
7. Streamlit처럼 서버에서 실행할 때 API 키를 숨기는 기본 원칙
8. 이번 시간에 구현할 최소 기능과 나중에 확장할 기능

AI가 코드를 바로 만들기보다 먼저 설계와 주의점을 정리해줘.

이번 차시에는 앱을 완성하는 것이 목표가 아닙니다. API가 어떤 방식으로 데이터를 가져오는지 알고, 다음 프로젝트에서 파일·API·MCP 중 어떤 길을 선택할지 판단할 수 있으면 충분합니다.

7. Streamlit로 확장할 수 있는 이유

섹션 제목: “7. Streamlit로 확장할 수 있는 이유”

Streamlit은 파이썬으로 간단한 데이터 웹앱을 만들 때 사용할 수 있습니다. API 키를 코드에 직접 쓰지 않고 비밀값으로 관리하면, 사용자는 화면에서 날짜와 학교를 선택하고 앱은 뒤에서 API를 호출할 수 있습니다.

방식장점조심할 점
브라우저에서 API 주소 직접 열기구조를 이해하기 쉽다키와 조건값이 그대로 보인다
CSV 파일 다운로드 후 웹앱에서 선택공개 저장소에 키를 넣지 않아도 된다자료가 자동으로 갱신되지는 않는다
Streamlit 앱에서 API 호출조건별 조회 앱을 만들기 좋다키 관리, 배포 설정, 오류 처리가 필요하다
정적 HTML에서 직접 API 호출단일 파일로 보여 주기 쉽다공개하면 키가 노출될 수 있다

프로젝트에서는 처음부터 실시간 API 앱을 고집하지 않아도 됩니다. 파일을 내려받아 분석하는 방식이 더 안전하고 정확할 때도 있습니다. 중요한 것은 데이터 출처와 처리 기준을 설명할 수 있는 것입니다.

8. 팀 프로젝트로 이어가기
