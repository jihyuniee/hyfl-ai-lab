간단한 Agent 제작 실습

Part 4. AI Agent: 대답하는 AI에서 행동하는 AI로

🗺️ 이 챕터의 교과 결합

이번 시간에는 정보 교과의 워크플로우·논리 설계를 뼈대로, 인공지능 교과의 언어모델 활용을 결합하여 “실제로 동작하는 Agent”를 만듭니다. 그리고 Agent가 남긴 실행 기록을 데이터로 분석·시각화하여, “우리가 만든 Agent가 얼마나 잘 작동하는가”를 숫자로 확인합니다.

🤔 생각 열기

섹션 제목: “🤔 생각 열기”

여러분이 스마트폰에게 “내일 아침 7시에 깨워줘”라고 말하면, 스마트폰은 단순히 대답만 하지 않습니다. 실제로 알람을 설정합니다.

말로 대답만 하는 AI(챗봇)와, 행동까지 하는 AI(Agent)의 차이는 무엇일까요?

“질문에 답하는 AI”에서 “일을 처리하는 AI”로 넘어가려면, AI에게 무엇을 더 붙여줘야 할까요?

답은 두 가지입니다. “언제 무엇을 할지 정하는 규칙(워크플로우)“과 “실제로 실행할 도구(기능)“입니다. 오늘 우리는 이 두 가지를 직접 조립해 봅니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 노코드/로우코드 도구를 활용해 간단한 Agent를 제작할 수 있다. [정보] [인공지능]
  • Agent의 실행 기록을 데이터로 수집·시각화하여 성능을 평가할 수 있다. [정보] [데이터 분석]

📌 선수학습 확인

섹션 제목: “📌 선수학습 확인”
  • 워크플로우(Workflow) [정보]: 일이 처리되는 순서와 조건 분기를 도식화한 것입니다. 이전 차시에서 “입력 → 판단 → 도구 실행 → 응답” 구조로 설계했습니다.
  • Agent의 4요소 [인공지능]: 지각(입력 받기) → 판단(무엇을 할지 결정) → 행동(도구 실행) → 응답. 챗봇과 달리 “행동” 단계가 있습니다.
  • 프롬프트(Prompt) [인공지능]: 언어모델에게 역할과 규칙을 지시하는 문장입니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: 종이로 먼저 굴려보는 “급식 알리미 Agent”

섹션 제목: “탐구: 종이로 먼저 굴려보는 “급식 알리미 Agent””

노코드 도구를 켜기 전에, 손으로 Agent를 흉내 내며 어디서 막히는지 찾아봅니다.

  • 준비물: 역할 카드 3장(사용자·판단·도구), 포스트잇, 필기구

  • 과정:

    1. 세 명이 각각 “사용자”, “판단(AI 두뇌)”, “도구(급식 정보 검색)” 역할을 맡습니다.
    2. 사용자가 질문을 던집니다. 예: “오늘 급식 뭐야?”, “고마워”, “3일 뒤 급식은?”
    3. “판단” 역할은 질문을 듣고 “이건 도구를 써야 하는 질문인가, 그냥 대답할 질문인가”를 포스트잇에 적어 결정합니다.
    4. 도구를 써야 하면 “도구” 역할에게 넘기고, 아니면 직접 대답합니다.
    5. 세 질문을 모두 처리하며, 판단이 헷갈린 지점을 기록합니다.

  • 결과 예측: “오늘 급식”은 도구 호출, “고마워”는 직접 응답으로 쉽게 갈립니다. 하지만 “3일 뒤 급식”에서 판단이 멈칫할 것입니다.

  • 토의: “왜 ‘3일 뒤 급식’에서 판단이 헷갈렸을까요?” → 도구가 “며칠 뒤”라는 정보(날짜)를 받아야 하는데, 그걸 질문에서 뽑아내는 규칙이 없었기 때문입니다.

이 탐구에서 확인한 것처럼, Agent를 만들려면 두 가지 규칙이 필요합니다. ① “도구를 쓸지 말지 결정하는 규칙”, ② “질문에서 도구에 넘길 정보를 뽑아내는 규칙”. 이것이 오늘의 핵심 개념입니다.

💡 핵심 개념

섹션 제목: “💡 핵심 개념”

개념 1. 의도 분기 — “언제 도구를 쓸 것인가” [인공지능] [정보]

섹션 제목: “개념 1. 의도 분기 — “언제 도구를 쓸 것인가” [인공지능] [정보]”
  • 정의: Agent가 사용자의 입력을 보고 “이건 정보를 검색해야 하는 요청인지, 그냥 대화인지”를 나누는 판단 규칙입니다. 정보 교과의 조건 분기(if-else)와 인공지능의 의도 인식이 결합한 지점입니다.
  • 비유: 의도 분기는 마치 병원 접수처와 같습니다. 접수처는 환자를 보고 “내과인가, 정형외과인가”를 나눕니다. 잘못 나누면 엉뚱한 진료실로 가듯이, 의도 분기가 틀리면 Agent가 엉뚱한 도구를 씁니다.
flowchart TD
  A[사용자 입력] --> B{의도 판단}
  B -->|급식 정보 요청| C[급식 검색 도구 실행]
  B -->|일반 대화| D[LLM이 직접 응답]
  C --> E[결과를 문장으로 정리]
  D --> E
  E --> F[사용자에게 응답 + 로그 기록]

[그림 24-1] 의도 분기를 중심으로 한 Agent 흐름도입니다. 오른쪽 아래 “로그 기록”이 데이터 분석의 재료가 됩니다.

개념 2. 실행 로그 — “잘 작동했는지 숫자로 본다” [정보] [데이터 분석]

섹션 제목: “개념 2. 실행 로그 — “잘 작동했는지 숫자로 본다” [정보] [데이터 분석]”
  • 정의: Agent가 처리한 각 요청의 기록입니다. 최소한 “입력 내용, 판단 결과, 성공 여부”를 남깁니다. 이 기록을 모으면 데이터가 되고, 집계하면 성능 지표가 됩니다.
  • 비유: 실행 로그는 마치 운동 일지와 같습니다. 매일 뛴 거리를 적어두면, 한 달 뒤 “내가 얼마나 늘었나”를 그래프로 볼 수 있습니다. 로그가 없으면 Agent가 잘하는지 못하는지 “느낌”으로만 알 수 있습니다.
로그 항목예시 값데이터 분석에서의 쓰임
입력”오늘 급식 뭐야?”어떤 질문이 많은지 분류
판단 결과급식 검색분기별 빈도 집계
성공 여부성공성공률 계산 → 막대그래프

🌉 교과 간 연결 — 세 교과가 만나는 지점

섹션 제목: “🌉 교과 간 연결 — 세 교과가 만나는 지점”

Agent 하나를 만드는 데 세 교과가 각각 다른 일을 합니다.

단계정보 [정보]인공지능 [인공지능]데이터 분석 [데이터]
설계워크플로우 흐름도 작성어느 지점에 LLM을 둘지 결정무엇을 로그로 남길지 기획
제작조건 분기 블록 연결프롬프트로 역할·규칙 지시로그 형식(표) 정의
평가오류 발생 지점 추적판단 정확도 점검성공률 집계·시각화

연결 다리의 핵심: 인공지능이 “판단”을 담당하지만, 그 판단을 언제 실행할지 배치하는 것은 정보 교과의 논리입니다. 그리고 그 판단이 정확했는지 증명하는 것은 데이터입니다. 세 교과 중 하나라도 빠지면 “동작은 하지만 믿을 수 없는 Agent”가 됩니다.

🔀 가로지르는 질문

섹션 제목: “🔀 가로지르는 질문”

“우리 Agent가 100번 중 80번 성공했다면, 이것은 ‘좋은 Agent’인가요?”

이 질문은 한 교과만으로 답할 수 없습니다.

  • [데이터] 80%라는 숫자 자체는 데이터가 알려줍니다.
  • [정보] 하지만 나머지 20%가 “어느 분기에서 실패했는가”는 로그 구조를 봐야 압니다.
  • [인공지능] 그리고 “80%면 실제 서비스로 써도 되는가”는 용도(장난감이냐, 의료냐)에 따라 다릅니다.

여러분은 이 질문에 답하기 위해 어느 교과의 도구를 먼저 꺼낼지 직접 정해 보세요.

🛠️ 따라하기 실습 — 급식 알리미 Agent 만들기

섹션 제목: “🛠️ 따라하기 실습 — 급식 알리미 Agent 만들기”

노코드 도구(예: 블록형 워크플로우 편집기)에서 아래 5단계를 따라 합니다. 실제 도구가 없다면 종이 워크시트로 각 블록을 그려도 됩니다.

1단계: 입력 블록 놓기 [정보]

섹션 제목: “1단계: 입력 블록 놓기 [정보]”

사용자 메시지를 받는 시작 블록을 배치합니다. 출력은 “사용자가 입력한 문장”입니다.

2단계: 의도 판단 블록 연결 [인공지능]

섹션 제목: “2단계: 의도 판단 블록 연결 [인공지능]”

LLM 블록을 놓고 아래 프롬프트를 넣습니다.

너는 급식 알리미다. 사용자 메시지를 보고 딱 한 단어로 분류하라. 급식 정보를 묻는 질문이면 “급식”, 그 외 대화면 “일반”. 다른 말은 절대 붙이지 마라.

3단계: 조건 분기 블록 놓기 [정보]

섹션 제목: “3단계: 조건 분기 블록 놓기 [정보]”

2단계 출력이 “급식”이면 검색 도구로, “일반”이면 응답 블록으로 가는 if-else 분기를 만듭니다.

4단계: 도구·응답 블록 연결 [인공지능]

섹션 제목: “4단계: 도구·응답 블록 연결 [인공지능]”
  • “급식” 경로: 급식 정보(미리 준비한 표 데이터)를 찾아 문장으로 정리합니다.
  • “일반” 경로: LLM이 짧게 대답합니다.

5단계: 로그 기록 블록 추가 [데이터]

섹션 제목: “5단계: 로그 기록 블록 추가 [데이터]”

마지막에 아래 표 형식으로 한 줄씩 기록을 남깁니다.

순번입력판단성공(O/X)
1오늘 급식 뭐야?급식O
2고마워일반O
3다음 주 급식은?급식X

이제 Agent에게 10개의 질문을 던지고 로그를 채웁니다.

데이터 시각화 — 성공률을 그래프로 [데이터]

섹션 제목: “데이터 시각화 — 성공률을 그래프로 [데이터]”

로그에서 “판단”별 성공 개수를 세어 막대그래프로 그립니다.

  title 판단 유형별 처리 비율 (예시)
  "급식-성공" : 5
  "급식-실패" : 2
  "일반-성공" : 3

[그림 24-2] 10건 처리 결과 예시입니다. “급식-실패” 2건이 눈에 띕니다. 이 2건의 로그를 다시 보면 대부분 “다음 주”, “3일 뒤”처럼 날짜 정보가 필요한 질문임을 발견하게 됩니다. → 다음 개선 목표가 데이터로 정해집니다.

실습 트러블슈팅

섹션 제목: “실습 트러블슈팅”
증상원인해결
분류가 “급식입니다”처럼 문장으로 나옴프롬프트 지시 부족”딱 한 단어로”, “다른 말 붙이지 마라” 강조
인사도 급식으로 분류됨예시 부족프롬프트에 “고마워→일반” 예시 추가
로그가 안 쌓임기록 블록 미연결두 경로 모두 로그 블록으로 이어졌는지 확인

📖 읽을거리

섹션 제목: “📖 읽을거리”

“행동하는 AI”의 시작, 심부름 봇

초기 AI 비서들은 대부분 “대답만” 했습니다. 날씨를 물으면 알려주지만, “우산 챙기라고 알림 보내줘”는 못 했습니다. 2020년대 들어 LLM에 도구 호출(Tool Calling) 기능이 붙으면서 상황이 바뀌었습니다. AI가 스스로 “지금은 계산기를 써야겠다”, “지금은 검색을 해야겠다”고 판단해 외부 기능을 부르기 시작한 것입니다.

흥미로운 점은, 이 “판단”의 정확도를 높이는 핵심이 화려한 알고리즘이 아니라 로그 데이터 분석이었다는 사실입니다. 개발자들은 Agent가 틀린 사례를 수천 건 모아 분석하고, 어떤 유형에서 실패가 몰리는지 그래프로 확인한 뒤 규칙을 고쳤습니다. 오늘 여러분이 한 “로그 → 그래프 → 개선”의 순환이, 바로 실제 AI 회사가 하는 일과 똑같은 방식입니다.

✅ 확인 문제

섹션 제목: “✅ 확인 문제”

기본 (개념 확인)

섹션 제목: “기본 (개념 확인)”

1. Agent가 사용자의 입력을 보고 “도구를 쓸지, 그냥 대답할지” 나누는 판단 규칙을 무엇이라 하나요?

2. Agent의 실행 기록(로그)을 남기는 가장 큰 이유는 무엇인가요? ① 저장 공간을 채우려고 ② 성능을 숫자로 측정·개선하려고 ③ 속도를 높이려고

응용 (적용)

섹션 제목: “응용 (적용)”

3. 다음 로그에서 “급식” 판단의 성공률(%)을 구하세요.

입력판단성공
오늘 급식급식O
내일 급식급식X
고마워일반O
점심 뭐야급식O

심화 (사고력·서술형)

섹션 제목: “심화 (사고력·서술형)”

4. 여러분의 Agent가 “다음 주 급식은?” 같은 질문에서 자꾸 실패합니다. 이 문제를 정보·인공지능·데이터 세 교과의 도구를 각각 하나씩 사용해 해결하는 방법을 서술하세요.

정답 확인

1. 의도 분기(의도 판단, 의도 인식)

2. ② 성능을 숫자로 측정·개선하려고

3. “급식” 판단은 3건(오늘·내일·점심), 그중 성공 2건. → 2/3 ≈ 66.7%

4. (예시 답안)

  • [데이터] 실패 로그를 모아보니 “다음 주”, “3일 뒤”처럼 날짜 정보가 들어간 질문에서 실패가 몰려 있음을 그래프로 확인한다.
  • [인공지능] 프롬프트를 고쳐, 질문에서 날짜 표현을 뽑아내도록 지시한다. 예: “질문에 날짜가 있으면 함께 추출하라.”
  • [정보] 워크플로우에 “날짜 추출 → 해당 날짜로 검색” 분기를 추가하여, 뽑아낸 날짜를 검색 도구에 넘기는 논리를 연결한다. 세 교과를 함께 써야 “발견 → 판단 개선 → 흐름 재설계”가 완결된다.

📚 단원 정리

섹션 제목: “📚 단원 정리”

  • 핵심 개념 요약

    • 의도 분기 [인공지능]``[정보]: 입력을 보고 “도구를 쓸지, 대답할지” 나누는 판단 규칙. 병원 접수처처럼 잘못 나누면 엉뚱한 실행이 일어난다.
    • 실행 로그 [정보]``[데이터]: Agent의 처리 기록. 모으면 데이터가 되고, 집계하면 성공률·개선점을 숫자로 보여준다.
    • 세 교과의 결합: 정보(논리 배치) + 인공지능(판단) + 데이터(증명)가 모두 있어야 “믿을 수 있는 Agent”가 된다.

  • 다음 차시 예고: 다음 시간에는 오늘 만든 Agent에 여러 도구를 연결하고, 도구를 순서대로 사용하는(멀티 스텝) Agent로 확장하는 방법을 알아봅니다.
