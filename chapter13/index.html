이 챕터는 [정보]와 [인공지능]을 결합합니다. [정보]는 테스트를 체계적으로 수행하고 결과를 데이터로 기록·시각화하는 절차를 제공합니다. [인공지능]은 그 데이터가 왜 그렇게 나왔는지, 모델이 무엇을 잘못 배웠는지 해석하는 렌즈를 제공합니다.

🤔 생각 열기

섹션 제목: “🤔 생각 열기”

여러분이 만든 손동작 분류 모델이 있습니다. 훈련할 때는 정확도 98%였는데, 친구에게 시켜 보니 자꾸 틀립니다. 특히 “가위”를 “보”로 착각합니다.

왜 훈련 화면에서는 잘 맞던 모델이 실제로는 자꾸 틀릴까요?

정답을 아는 문제집만 잘 풀던 학생이 시험장에서 무너지는 것과 비슷합니다. 모델도 “본 적 있는 데이터”에는 강하지만 “처음 보는 데이터”에는 약할 수 있습니다. 오늘은 모델이 어디서, 왜 틀리는지를 탐정처럼 추적하고, 그 원인을 데이터로 되돌려 고쳐 봅니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 모델의 오분류 사례를 수집·분석하여 그 원인을 파악할 수 있다.
  • 분석 결과를 바탕으로 데이터를 보완하여 모델 성능을 개선할 수 있다.

선수학습 확인

섹션 제목: “선수학습 확인”
  • 12차시: Teachable Machine으로 이미지/포즈 모델을 훈련하고, 클래스별 신뢰도(confidence)가 실시간으로 바뀌는 것을 확인했습니다.
  • 신뢰도란 모델이 “이 입력은 A클래스일 확률이 얼마”라고 스스로 매기는 점수(0-100%)입니다.
  • 훈련 데이터가 한쪽으로 치우치면 모델도 한쪽으로 치우쳐 판단한다는 것을 배웠습니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: 우리 모델은 어디서 틀릴까?

섹션 제목: “탐구: 우리 모델은 어디서 틀릴까?”

  • 준비물: 12차시에서 만든 Teachable Machine 모델, 테스트용 입력(직접 취한 포즈/이미지) 20개, 기록용 표(아래 양식)

  • 과정:

    1. 팀에서 클래스 3개(예: 가위·바위·보)를 정하고, 각 클래스당 실제 입력을 정답을 알고 있는 상태로 준비합니다.
    2. 한 명이 입력을 제시하고, 다른 한 명이 모델이 내놓은 예측 클래스와 신뢰도를 기록합니다.
    3. 정답과 예측이 다른 경우(오분류)에 별표(★)를 칩니다. 그 순간의 화면을 캡처합니다.
    4. 20회 반복하여 아래 표를 채웁니다.
번호실제 정답모델 예측신뢰도(%)맞음/틀림틀렸다면 무엇이 달랐나
1가위보71★틀림손가락이 겹쳐 보였음
2바위바위95맞음
…

  • 결과 예측: “어떤 클래스에서 가장 많이 틀릴까요? 틀릴 때 신뢰도는 높을까요, 낮을까요?”

  • 토의:

    • “특정 클래스에서 오분류가 몰린다면 그 이유는 무엇일까요?” [인공지능]
    • “신뢰도가 높은데도 틀린 경우는 무엇을 의미할까요?” [인공지능]
    • “이 기록을 어떻게 표로 정리하면 문제가 한눈에 보일까요?” [정보]

📘 핵심 개념

섹션 제목: “📘 핵심 개념”

개념 1. 혼동 행렬 (Confusion Matrix) [정보] [인공지능]

섹션 제목: “개념 1. 혼동 행렬 (Confusion Matrix) [정보] [인공지능]”

  • 정의: 모델의 예측 결과를 실제 정답(행)과 모델 예측(열)의 표로 정리한 것입니다. 대각선은 맞은 것, 대각선을 벗어난 칸은 틀린 것(오분류)입니다.

  • 비유: 혼동 행렬은 마치 성적표의 오답 분포표와 같습니다. “국어를 수학으로 착각했다”처럼, 어떤 클래스를 어떤 클래스로 헷갈렸는지 한 장에 보여 줍니다.

탐구에서 모은 20개 기록을 아래처럼 정리합니다. 행은 실제 정답, 열은 모델 예측입니다.

예측: 가위예측: 바위예측: 보
실제: 가위403
실제: 바위070
실제: 보105

이 표에서 “실제 가위인데 보로 예측한 3건”이 눈에 띕니다. 오분류가 특정 칸에 몰려 있다는 것은, 모델이 그 두 클래스를 구분하는 특징을 제대로 배우지 못했다는 신호입니다.

flowchart LR
  A[테스트 입력] --> B[모델 예측]
  B --> C{정답과 같은가?}
  C -->|같음| D[대각선 칸 +1]
  C -->|다름| E[오분류 칸 +1]
  E --> F[혼동 행렬에서<br/>몰린 칸 찾기]

개념 2. 오분류의 원인과 데이터 보강 [인공지능]

섹션 제목: “개념 2. 오분류의 원인과 데이터 보강 [인공지능]”

오분류는 대개 세 가지 원인에서 옵니다.

원인설명데이터로 고치는 법
데이터 부족특정 클래스·각도·조명의 예시가 적음부족한 상황의 데이터를 더 수집
데이터 편향훈련 데이터가 특정 환경(밝은 배경 등)에 치우침다양한 배경·사람·조명으로 촬영
클래스 혼동두 클래스의 특징이 실제로 비슷함구분되는 특징이 뚜렷한 예시 추가

  • 정의: 데이터 보강이란 오분류 원인을 분석한 뒤, 부족하거나 치우친 데이터를 의도적으로 추가·재수집하여 모델을 다시 훈련하는 과정입니다.

  • 비유: 오답노트를 쓰는 것과 같습니다. 자주 틀리는 유형만 골라 문제를 더 풀면 그 유형에 강해지듯, 자주 틀리는 상황의 데이터를 더 넣으면 모델이 그 상황에 강해집니다.

flowchart TD
  A[혼동 행렬로<br/>몰린 칸 발견] --> B[오분류 원인 추정]
  B --> C{어떤 원인?}
  C -->|데이터 부족| D[해당 상황 촬영 추가]
  C -->|편향| E[다양한 환경 촬영]
  C -->|클래스 혼동| F[뚜렷한 예시 보강]
  D --> G[재훈련 후 다시 테스트]
  E --> G
  F --> G

🔗 교과 간 연결 다리

섹션 제목: “🔗 교과 간 연결 다리”

[정보]의 테스트 기록·표 시각화와 [인공지능]의 오분류 해석은 이렇게 맞물립니다.

[정보]가 없으면 오분류는 “그냥 좀 틀리네”라는 인상에 머뭅니다. 혼동 행렬이라는 표 구조로 데이터를 정리해야 “가위→보 3건”이라는 패턴이 드러납니다. 그 패턴을 보고 [인공지능]의 언어로 “이건 클래스 혼동이다”라고 원인을 진단합니다. 진단이 서면 다시 [정보]의 절차로 돌아가 어떤 데이터를 추가할지 재설계합니다.

📖 읽을거리

섹션 제목: “📖 읽을거리”

2015년, 한 대형 사진 서비스의 이미지 분류 AI가 특정 인물 사진을 엉뚱한 대상으로 태그하는 심각한 오분류를 일으켜 큰 논란이 됐습니다. 원인은 훈련 데이터의 편향이었습니다. 특정 피부색·환경의 사진이 부족했던 것입니다. 개발팀은 급히 해당 태그 기능을 중단하고 데이터를 보강했습니다.

이 사건은 “정확도 숫자 하나”가 아니라 “어디서, 누구에게 틀리는가”를 봐야 한다는 교훈을 남겼습니다. 여러분이 오늘 그린 혼동 행렬이 바로 그 “어디서”를 찾는 첫 도구입니다.

✅ 확인 문제

섹션 제목: “✅ 확인 문제”

기본 (개념 확인)

섹션 제목: “기본 (개념 확인)”

1. 혼동 행렬에서 대각선 칸이 의미하는 것은 무엇입니까?

2. 오분류의 세 가지 원인 중, “훈련 데이터가 밝은 배경에만 치우쳐 있어서 어두운 곳에서 자꾸 틀리는” 경우는 어디에 해당합니까?

응용 (적용)

섹션 제목: “응용 (적용)”

3. 아래 혼동 행렬에서 모델이 가장 많이 헷갈리는 클래스 쌍을 찾고, 어떤 데이터를 보강해야 할지 한 가지 쓰세요.

예측: A예측: B예측: C
실제: A640
실제: B370
실제: C008

심화 (사고력·서술형)

섹션 제목: “심화 (사고력·서술형)”

4. 여러분의 모델이 “신뢰도 92%로 자신 있게 틀리는” 오분류를 반복합니다. 이 상황이 “신뢰도 50%로 애매하게 틀리는” 것보다 왜 더 위험한지, 그리고 이를 개선하기 위해 어떤 데이터를 어떻게 보강할지 서술하세요. ([정보]와 [인공지능] 관점을 모두 사용할 것)

정답 확인

1. 실제 정답과 모델 예측이 일치한 경우, 즉 맞게 분류한 건수를 의미합니다.

2. 데이터 편향에 해당합니다. 훈련 데이터가 밝은 배경에 치우쳐 다양한 조명을 배우지 못했습니다.

3. 실제 A를 B로 4건, 실제 B를 A로 3건 틀려 A와 B가 서로 가장 많이 혼동됩니다(클래스 혼동). A와 B를 뚜렷하게 구분해 주는 특징이 담긴 예시 데이터를 다양한 각도·조명으로 추가 수집해 보강합니다.

4. (예시) [인공지능] 관점: 높은 신뢰도의 오답은 모델이 잘못된 특징을 “확신”하며 배운 것이므로, 사용자가 그 결과를 의심 없이 신뢰해 버려 더 위험합니다. [정보] 관점: 먼저 이런 고신뢰 오분류가 어떤 입력에서 반복되는지 표로 집계해 공통 조건(예: 특정 각도)을 찾습니다. 그 조건의 데이터를 집중적으로 추가 수집하고, 반대로 잘못 학습된 편향 데이터는 정리한 뒤 재훈련하여 다시 테스트합니다.

📌 단원 정리

섹션 제목: “📌 단원 정리”

  • 핵심 개념 요약:

    • 혼동 행렬 [정보]은 오분류가 어느 클래스 쌍에 몰리는지 표로 드러냅니다.
    • 오분류의 원인은 데이터 부족·편향·클래스 혼동으로 나뉘며, 각각에 맞는 데이터 보강 [인공지능]으로 개선합니다.
    • 개선은 테스트 → 분석 → 보강 → 재훈련 → 재테스트의 순환입니다.

  • 다음 차시 예고: 다음 시간에는 개선한 모델을 웹앱에 연결하여, 사용자가 직접 입력하고 결과를 확인하는 AI 웹앱 화면을 완성해 봅니다.
