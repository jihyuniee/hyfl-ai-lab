Part 4. AI Agent: 대답하는 AI에서 행동하는 AI로

🗺️ 이 챕터의 교과 결합

섹션 제목: “🗺️ 이 챕터의 교과 결합”
mindmap

    정보
      알고리즘 흐름 설계

이 챕터는 [정보] 교과의 “알고리즘 흐름과 순서도” 도구로 두 시스템의 동작을 분해하고, [인공지능] 교과의 “응답 원리와 자율 행동” 개념으로 그 차이의 본질을 설명합니다. 두 교과를 잇는 다리는 “한 번의 응답이냐, 목표를 향한 여러 단계의 행동이냐” 입니다.

🤔 생각 열기

섹션 제목: “🤔 생각 열기”

“내일 오전 9시에 부산 가는 기차표 알려줘.”

두 개의 AI에게 똑같이 물어봤습니다.

AI-A의 대답

“부산행 KTX는 서울역에서 자주 출발합니다. 코레일 앱에서 예매하실 수 있어요.”

AI-B의 대답

“예매 사이트에 접속했습니다. → 9시 12분 출발 KTX 좌석 2개 확인했습니다. → 창가 좌석으로 예매를 완료했습니다. 예매 번호는 8821입니다.”

같은 질문인데 결과가 왜 이렇게 다를까요? AI-A는 알려주기만 했고, AI-B는 직접 해냈습니다. 이 차이가 오늘 우리가 파헤칠 주제입니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 단순 응답형 챗봇(Chatbot)과 목표를 수행하는 에이전트(Agent)의 차이를 설명할 수 있다.
  • 두 시스템의 동작 과정을 순서도로 표현하고, 데이터로 차이를 시각화할 수 있다.

📌 선수학습 확인

섹션 제목: “📌 선수학습 확인”
  • 챗봇(Chatbot): 사람의 말에 자연스럽게 대답하는 대화형 AI. 이전 차시에서 우리는 언어모델이 “다음에 올 말”을 확률로 예측해 문장을 만든다는 것을 배웠습니다.
  • 입력-처리-출력: 모든 프로그램은 입력을 받아 처리한 뒤 결과를 내놓습니다. [정보] 교과의 기본 구조입니다.
  • 이번 시간에는 여기에 “행동(action)“과 “여러 단계(steps)“라는 새 개념을 더합니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: 같은 요청, 다른 처리 — 두 AI의 동작 분해하기

섹션 제목: “탐구: 같은 요청, 다른 처리 — 두 AI의 동작 분해하기”

  • 준비물: 필기구, 활동지(아래 표), 모둠(3-4인)

  • 과정

    1. 아래 “요청 카드” 3개를 읽습니다.
    2. 각 요청에 대해 챗봇(응답형)과 에이전트(행동형)가 각각 어떤 단계를 거칠지 화살표로 적어봅니다.
    3. 두 경우의 “단계 개수”를 세어 표에 기록합니다.

요청 카드

번호요청 내용
1”이번 주 날씨 알려줘”
2”이번 주말 비 오는 날에 실내 데이트 코스 3개 예약해줘”
3”내 사진첩에서 강아지 사진만 모아 앨범 만들어줘”

1

  • 결과 예측: “요청이 복잡해질수록 두 AI의 단계 수 차이는 어떻게 될까요?”

  • 토의

    1. 어떤 요청에서 챗봇과 에이전트의 차이가 가장 컸나요? 왜 그럴까요?
    2. 에이전트가 “예약”, “앨범 만들기”를 하려면 챗봇에게 없는 무엇이 필요할까요?

예상 결과: 요청 1은 단계 차이가 거의 없지만, 요청 2, 3처럼 “직접 무언가를 해야 하는” 요청일수록 에이전트의 단계가 크게 늘어납니다. 에이전트는 계획을 세우고, 도구를 쓰고, 결과를 확인하는 여러 단계를 거치기 때문입니다.

💡 핵심 개념

섹션 제목: “💡 핵심 개념”

개념 1: 챗봇 — 한 번의 응답 [인공지능] [정보]

섹션 제목: “개념 1: 챗봇 — 한 번의 응답 [인공지능] [정보]”
  • 정의: 사용자의 입력을 받아 한 번의 텍스트 응답을 생성하고 끝나는 대화형 AI. 자신이 직접 무언가를 실행하지는 않습니다.
  • 비유: 챗봇은 마치 똑똑한 안내 데스크 직원과 같습니다. 길을 물으면 친절하게 알려주지만, 대신 그곳까지 데려다주지는 않습니다.

챗봇의 동작은 [정보] 교과의 기본 구조 그대로입니다. 입력을 받아, 언어모델이 처리하고, 답을 출력합니다. 처리 흐름이 한 방향으로 한 번 흐릅니다.

flowchart LR
  A[사용자 입력] --> B[언어모델 처리]
  B --> C[텍스트 응답 출력]
  C --> D([종료])

[그림 1-1] 챗봇의 동작: 입력에서 출력까지 한 번의 직선 흐름.

개념 2: 에이전트 — 목표를 향한 여러 단계의 행동 [인공지능] [정보]

섹션 제목: “개념 2: 에이전트 — 목표를 향한 여러 단계의 행동 [인공지능] [정보]”
  • 정의: 사용자가 준 목표(goal)를 달성하기 위해, 스스로 계획을 세우고, 도구를 사용하며, 결과를 확인하고 다음 행동을 반복하는 AI. 응답이 아니라 행동이 목적입니다.
  • 비유: 에이전트는 마치 심부름을 완수하는 비서와 같습니다. “회의 잡아줘”라고 하면, 일정을 확인하고, 참석자에게 연락하고, 방을 예약하는 여러 일을 알아서 해냅니다.

에이전트의 핵심은 반복 고리(loop)입니다. 목표에 도달할 때까지 “생각 → 행동 → 관찰”을 되풀이합니다. [정보] 교과에서 배운 반복 구조가 AI의 행동에 적용된 것입니다.

flowchart TD
  A[목표 입력] --> B[계획 세우기]
  B --> C[행동: 도구 사용]
  C --> D[결과 관찰]
  D --> E{목표 달성?}
  E -->|아니오| B
  E -->|예| F[완료 보고]

[그림 1-2] 에이전트의 동작: 목표 달성까지 “계획-행동-관찰”을 반복하는 고리 구조.

🌉 교과 간 연결 다리

섹션 제목: “🌉 교과 간 연결 다리”

두 AI의 차이를 어떻게 설명하느냐는 어느 교과의 도구를 쓰느냐에 따라 달라집니다.

관점[정보]의 렌즈[인공지능]의 렌즈

[정보] 교과의 순서도는 “어떻게 도는지”를 보여주고, [인공지능] 교과의 자율성 개념은 “왜 도는지”를 설명합니다. 두 렌즈를 겹쳐야 에이전트의 정체가 완전히 드러납니다.

🔀 가로지르는 질문

섹션 제목: “🔀 가로지르는 질문”

“챗봇에 검색 기능 하나만 붙이면 에이전트가 될까?”

이 질문에 답하려면 두 교과 도구가 모두 필요합니다.

  • [정보]: 검색을 붙였을 때 처리 흐름이 반복 고리로 바뀌는가를 순서도로 확인.
  • [인공지능]: 검색 결과를 보고 스스로 다음 행동을 결정하는가(자율성)를 판단.

여러분의 생각을 모둠에서 나눠보세요. (힌트: 도구가 있어도 “한 번 쓰고 끝”이면 여전히 챗봇에 가깝습니다.)

📖 읽을거리: “생각하고 행동하는 AI”의 아이디어

섹션 제목: “📖 읽을거리: “생각하고 행동하는 AI”의 아이디어”

에이전트라는 개념은 사실 오래된 인공지능의 꿈입니다. 1950년대 AI 연구자들은 “환경을 인식하고(perceive), 스스로 판단해 행동하는(act) 시스템”을 지능형 에이전트라고 불렀습니다.

최근 언어모델이 발전하면서 이 오래된 아이디어가 현실이 되었습니다. 2022년 이후 연구자들은 언어모델에게 “생각을 글로 적으면서 단계별로 추론하라”고 시켰더니 문제 해결력이 크게 올라가는 것을 발견했습니다. 여기에 “검색해봐”, “계산기를 써봐” 같은 도구 사용 능력을 더하자, 단순히 대답만 하던 AI가 직접 일을 해내는 AI로 진화했습니다. 대답하는 AI에서 행동하는 AI로의 전환, 이것이 지금 우리가 서 있는 지점입니다.

🧩 데이터로 시각화하기 (미니 산출물)

섹션 제목: “🧩 데이터로 시각화하기 (미니 산출물)”

탐구 활동에서 모은 “단계 수” 데이터를 간단한 막대그래프로 그려봅시다. [정보] 교과의 데이터 시각화 활동입니다.

모둠 데이터 예시

요청챗봇 단계 수에이전트 단계 수
날씨 알려줘11
데이트 코스 예약15
강아지 앨범 만들기14

이 데이터로 만든 비율 그래프입니다.

pie showData
  title 에이전트의 총 처리 단계 비중
  "날씨 알려줘" : 1
  "데이트 코스 예약" : 5
  "강아지 앨범 만들기" : 4

[그림 1-3] 요청이 복잡할수록 에이전트의 단계 수가 커집니다. 챗봇은 언제나 1단계입니다.

해석 포인트: 그래프에서 챗봇의 막대는 모든 요청에서 똑같이 낮습니다. 반면 에이전트의 막대는 요청의 복잡도에 따라 높아집니다. 이 “높아지는 정도”가 바로 자율 행동의 크기입니다.

✅ 확인 문제

섹션 제목: “✅ 확인 문제”

기본 (개념 확인)

섹션 제목: “기본 (개념 확인)”

1. 다음 중 에이전트(Agent)의 특징으로 옳은 것은? ① 항상 한 번의 응답으로 끝난다. ② 목표 달성을 위해 여러 단계를 반복한다. ③ 도구를 전혀 사용하지 않는다. ④ 텍스트만 출력하고 실제 행동은 하지 않는다.

2. 챗봇의 처리 흐름을 가장 잘 나타낸 것은? ① 입력 → 처리 → 출력의 직선 흐름 ② 목표 → 계획 → 행동 → 관찰의 반복 고리 ③ 여러 도구를 순서대로 실행 ④ 결과를 보고 스스로 다음 행동 결정

응용 (적용)

섹션 제목: “응용 (적용)”

3. 다음 요청 중 에이전트가 챗봇보다 훨씬 유용한 상황을 모두 고르세요. ① “광합성이 뭐야?” ② “다음 주 회의실 예약하고 참석자에게 안내 메일 보내줘” ③ “이 영어 문장 뜻 알려줘” ④ “내 이메일에서 안 읽은 메일 정리하고 중요한 것만 요약해줘”

심화 (사고력·서술형)

섹션 제목: “심화 (사고력·서술형)”

4. 어떤 회사가 “고객 문의에 답만 하던 챗봇”을 “환불까지 직접 처리하는 에이전트”로 바꾸려 합니다. 이때 처리 흐름이 어떻게 바뀌어야 하는지, [정보]의 순서도 관점(직선 vs 반복)과 [인공지능]의 자율성 관점을 모두 사용해 3-4문장으로 설명하세요.

정답 확인

1. ② (에이전트는 목표 달성을 위해 여러 단계를 반복한다.)

2. ① (챗봇은 입력-처리-출력의 직선 흐름이다.)

3. ②, ④ (실제로 여러 단계의 행동과 도구 사용이 필요한 요청. ①③은 한 번의 응답으로 충분한 챗봇형 질문.)

4. (예시 답안) 기존 챗봇은 “문의 입력 → 답변 출력”으로 끝나는 직선 흐름이었습니다. 에이전트로 바꾸면 “환불 요건 확인 → 결제 정보 조회 → 환불 실행 → 결과 확인”처럼 조건이 만족될 때까지 도는 반복 고리 구조가 됩니다([정보]). 또한 에이전트는 환불 시스템이라는 도구를 스스로 사용하고, 요건 미충족 시 다음 행동을 판단하는 자율성을 가져야 합니다([인공지능]). 즉 응답형에서 행동형으로 바뀌는 것입니다.
