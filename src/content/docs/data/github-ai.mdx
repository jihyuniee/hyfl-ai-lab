GitHub에 저장한 우리 팀의 웹앱을 AI와 수정하고, 같은 배포 주소에서 결과를 확인합니다. 프로젝트의 주제·공공데이터·기존 파일 구조를 이어 사용하는 **선택 참고 자료**입니다.

<Callout kind="mission" title="작업 순서">
최신 코드 준비 → AI에 수정 요청 → GitHub에 저장 → 배포된 웹앱에서 확인
</Callout>

## 1. 준비하기

- 우리 팀의 현재 프로젝트 파일과 정상 작동하는 원본
- 프로젝트 저장소를 수정할 권한이 있는 GitHub 계정
- 아래에서 선택한 AI 도구를 사용할 수 있는 계정과 GitHub 연결 권한
- 우리 팀의 저장소 주소, 작업 브랜치, 실제 웹앱 주소

사용할 기능과 권한은 계정의 연결 화면에서 확인합니다. 공개 저장소에는 공개할 수 있는 코드와 자료를 준비하고, 비밀번호·서버용 비밀키·GitHub 토큰은 별도로 보관합니다. [OpenAI의 연결 기능 안내](https://learn.chatgpt.com/docs/plugins)

## 2. 프로젝트를 GitHub에 올리고 배포하기

이미 배포 중인 팀은 **현재 저장소와 배포 설정을 사용**하며 3단계로 이동합니다. 새 HTML 프로젝트는 다음 순서로 준비합니다.

1. GitHub의 **New repository**에서 팀의 **Public** 저장소를 만들고 README를 추가합니다.
2. **Add file → Upload files**에서 `index.html`을 저장소 맨 위에 올립니다. 연결된 CSS·JavaScript·이미지·JSON도 **기존 폴더 구조대로 함께 올립니다.**
3. 파일을 올릴 브랜치를 확인하고 **Commit changes**로 저장합니다.
4. **Settings → Pages → Source: Deploy from a branch**를 선택합니다. **Branch: main / (root)**를 선택하고 **Save**합니다. 다른 브랜치를 사용한다면 파일이 있는 브랜치를 지정합니다.
5. 배포가 완료되면 **Visit site**로 웹앱을 열고 기존 기능을 확인합니다. 빌드가 필요한 프로젝트나 다른 배포 서비스를 사용하는 팀은 기존 배포 절차를 따릅니다.

[GitHub Pages의 공개 브랜치·폴더 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

| 기록할 주소 | 형식 예시 |
| --- | --- |
| 코드가 저장된 **저장소 주소** | `https://github.com/my-team/our-webapp` |
| 실행 결과를 확인하는 **웹앱 주소** | `https://my-team.github.io/our-webapp/` |

표의 예시를 우리 팀의 실제 주소로 바꿔 기록합니다. 이후 작업은 **GitHub에 저장된 최신 파일**을 기준으로 진행합니다.

## 3. AI에 우리 저장소 연결하기

**파일을 AI에 전달해 수정한 뒤 GitHub에 직접 저장**할 수 있습니다. 이 방법은 7단계를 참고합니다. GitHub 연결 기능이 있는 계정은 아래 방법도 선택할 수 있습니다.

| 작업 화면 | 수정 내용을 GitHub에 반영하는 방법 |
| --- | --- |
| ChatGPT Work · 웹 Codex | A·B에서 쓰기 권한 확인 → 커밋 또는 PR |
| Google AI Studio Build | C에서 기존 저장소 연결 → 변경 내용 보내기(push) |
| Claude Code 웹 | D에서 작업 브랜치에 저장 → PR |
| 일반 제미나이 · 클로드 채팅 | 수정안을 받아 7단계에서 파일 직접 반영 |

### A. ChatGPT Work의 GitHub 연결

1. **Plugins / 플러그인**에서 GitHub를 찾아 지원 작업과 요청 권한을 확인하고 설치합니다. **Apps / 앱** 메뉴를 제공하는 계정에서는 해당 메뉴에서 연결합니다.
2. 내 GitHub 계정으로 로그인하고 사용할 프로젝트 저장소를 선택합니다. 팀 저장소의 수정 권한도 확인합니다.
3. 새 **Work 대화**에서 GitHub를 사용하도록 요청합니다. `@` 선택을 지원하는 화면에서는 GitHub를 선택할 수 있습니다.
4. 아래 요청문으로 저장소 파일과 현재 사용할 수 있는 읽기·수정·저장 기능을 확인합니다.

[Work 시작하기](https://learn.chatgpt.com/docs/get-started-with-work) · [연결된 앱의 기능과 권한](https://learn.chatgpt.com/docs/build-plugins#include-apps-in-your-plugin)

### B. 웹 Codex의 Cloud 작업 환경

1. **Work in → Cloud → Select environment → Create environment** 또는 **Settings → Codex Cloud → Environments**에서 환경을 만듭니다.
2. GitHub 계정을 연결하고 우리 프로젝트 저장소를 선택합니다.
3. **Get started**를 누르고 설정 결과를 확인합니다. 프로젝트가 단순 HTML이라면 현재 파일을 사용하는 프로젝트임을 설명합니다.
4. 준비된 환경을 **Publish**하고 **Start a new task**로 시작합니다. 기존 환경이 있으면 해당 환경을 선택합니다.
5. 아래 요청문으로 저장소와 작업 기준 브랜치를 확인합니다.

**환경 Publish는 AI 작업 환경을 저장합니다.** 웹앱 배포는 코드 변경을 배포 브랜치에 반영한 뒤 5단계에서 확인합니다. [Codex Cloud 환경 안내](https://learn.chatgpt.com/docs/environments/cloud-environments)

### C. 제미나이 · Google AI Studio Build

1. [Google AI Studio](https://aistudio.google.com/apps) 왼쪽 **BUILD → New app**을 누릅니다. **Playground**와 구분합니다.
2. 가운데 입력창의 **+ → Import from GitHub**를 누르고 우리 팀의 저장소를 가져옵니다. GitHub 연결 화면이 나오면 사용할 계정과 저장소를 확인합니다.
3. 가져온 파일을 확인하고 입력창에 **“현재 HTML·데이터·지도·검색·폴더 구조를 유지하고, [바꿀 부분]만 수정해줘.”**라고 요청합니다. **Code** 탭에서 수정한 파일과 미리보기를 확인합니다.
4. **Settings → GitHub**에서 **기존 팀 저장소 연결**을 확인하고 변경 내용을 GitHub로 보냅니다(push). AI Studio 미리보기에서 바뀐 것만으로 GitHub에 저장된 것은 아닙니다.
5. GitHub에서 **같은 저장소의 브랜치·커밋·변경 파일**을 확인한 뒤 5단계로 이동합니다. 작업 브랜치에 저장했다면 배포 브랜치로 PR을 만들어 반영합니다.

팀원이 GitHub에서 수정했다면 다음 작업 전에 **Settings → GitHub**에서 최신 변경을 가져옵니다(pull). 충돌이 표시되면 팀원과 양쪽 변경을 비교합니다. HTML 프로젝트는 기존 GitHub Pages 주소에서도 실행되는지 확인합니다.

위 순서는 [공식 안내의 GitHub 양방향 동기화](https://aistudio.google.com/docs/aistudio-build-mode#github-integration)를 기준으로 합니다. **기존 저장소 연결·변경 보내기 메뉴가 없거나 새 저장소 만들기만 보이면 7단계**를 사용합니다. ZIP으로 코드를 내려받았다면 압축을 풀고 수정한 파일만 원래 위치에 반영합니다.

일반 [제미나이 웹 채팅의 GitHub 가져오기](https://support.google.com/gemini/answer/16176929?hl=ko)는 코드 참고용이며, GitHub에 직접 쓰기와 이후 변경의 자동 동기화를 지원하지 않습니다. 이 화면에서는 7단계를 사용합니다.

### D. 클로드 · Claude Code 웹

1. [Claude Code 웹](https://claude.ai/code)에 로그인하고 **Sign in with GitHub**로 GitHub를 연결합니다. 우리 팀 저장소에 접근할 수 있도록 권한 화면을 확인합니다.
2. **Default** 환경을 사용합니다. 처음 환경 생성 화면이 나오면 **Create & finish**를 누릅니다.
3. 입력창 아래 **저장소 선택 메뉴 → 우리 팀 저장소**를 선택하고, 옆의 브랜치 선택 메뉴에서 기준 브랜치를 확인합니다.
4. **Accept edits**를 선택하고 4단계의 제목 수정 요청문을 입력한 뒤 **Enter**를 누릅니다. 요청문의 저장 방식은 **검토용 PR**로 작성합니다.
5. 작업이 끝나면 **Changes**의 변경 줄 수를 눌러 수정 내용을 확인하고 **Create PR**을 누릅니다. 생성된 GitHub PR의 **Files changed**와 대상 브랜치를 확인한 뒤 5단계로 이동합니다.

이 순서는 [Claude Code 공식 연결·수정·PR 안내](https://code.claude.com/docs/en/web-quickstart)를 기준으로 합니다. **Claude Code 작업 화면을 사용할 수 없다면 7단계**를 사용합니다. 일반 클로드 채팅의 **+ → Add from GitHub**는 [코드를 참고 자료로 추가하는 기능](https://support.claude.com/en/articles/10167454-use-the-github-integration)이며, 이 연결만으로 GitHub 저장이 완료되지는 않습니다.

## 4. 제목 한 곳 수정하기

현재 첫 화면의 제목과 바꿀 제목을 정합니다. 저장소 쓰기 권한이 있는 GPT 작업 환경이나 Claude Code에서는 아래 요청문으로 수정을 요청합니다. AI Studio는 C의 순서로 수정하고 GitHub로 보냅니다. 파일을 직접 전달하는 경우에는 7단계를 따릅니다.

| 저장 방식 | 확인할 내용 |
| --- | --- |
| **PR 만들기** | 변경안을 별도 브랜치에 저장합니다. GitHub의 **Files changed**에서 수정 내용을 검토하고 대상 브랜치에 병합합니다. |
| **직접 커밋하기** | 선택한 브랜치에 변경 이력을 저장합니다. 커밋 링크에서 수정한 파일과 내용을 확인합니다. |

**커밋(commit)**은 변경 이력 한 건, **브랜치(branch)**는 작업 흐름을 나눈 공간, **PR(pull request)**은 다른 브랜치에 변경 내용을 합치기 위한 제안입니다.

<CopyPrompt title="첫 수정: 제목 한 곳 바꾸기" content={firstRepositoryEditPrompt} />

## 5. 배포 결과 확인하기

1. 커밋 또는 PR 링크에서 **저장소·파일·수정 내용**을 확인합니다.
2. PR 방식이면 대상 브랜치를 확인하고 **Merge pull request**로 병합합니다. Pages의 배포 브랜치가 `main`이면 변경 내용이 `main`에 들어간 뒤 배포됩니다.
3. **Actions**에서 해당 변경의 배포 완료를 확인합니다. 다른 배포 서비스를 사용하는 팀은 해당 서비스의 배포 상태를 확인합니다.
4. 처음 기록한 **같은 웹앱 주소**를 열어 새 제목을 확인합니다.
5. 기존 입력·검색·지도·버튼 중 우리 앱에 있는 기능도 실행합니다. 데이터 처리 기능을 수정했다면 원자료와 결과를 대조합니다.

GitHub Pages의 변경 반영에는 최대 10분이 걸릴 수 있습니다. 화면 갱신을 확인할 때는 저장한 브랜치와 배포 상태를 먼저 확인하고 새로고침합니다. [GitHub의 배포 후 확인 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## 6. 팀의 기능 개선하기

모바일 버튼 배치, 빈 검색 결과 안내, 선택 항목 설명처럼 **기능 하나씩** 수정합니다. 매 요청에서 저장소의 최신 파일을 확인하고, 팀이 선택한 데이터와 기존 정상 기능을 유지합니다. 팀원은 반영된 변경을 확인한 뒤 다음 작업을 이어 갑니다.

## 7. 연결이 안 될 때 · 파일 편집과 변경 복구하기

저장소가 보이지 않으면 **로그인한 GitHub 계정·팀 저장소 권한·연결 앱에 허용한 저장소 목록**을 확인합니다. 읽기만 가능하다면 코드 참고용 연결인지, 쓰기를 지원하는 작업 화면인지 확인합니다.

1. GitHub에서 **현재 브랜치 → 수정할 파일**을 열고 오른쪽 위 내려받기 아이콘(**Download raw file**)으로 최신 파일을 받습니다. 연결된 CSS·JavaScript·JSON도 함께 준비하고 원본 사본을 보관합니다.
2. AI 채팅의 파일 첨부로 최신 파일을 전달하고, 아래 요청문에 바꿀 동작과 유지할 기능을 적습니다. 받은 코드 조각을 파일 편집기에 적용해 **같은 파일 이름**으로 저장합니다. 수정된 파일을 제공받았다면 내려받아 원본과 변경 내용을 비교합니다.
3. GitHub의 **원래 파일이 있는 폴더 → Add file → Upload files → choose your files**에서 수정한 파일을 올립니다. 이름과 폴더 경로를 기존과 같게 맞춥니다. ZIP으로 받았다면 압축을 풀고 수정한 파일만 올립니다.
4. 변경 설명과 저장할 브랜치를 확인하고 **Commit changes** 또는 **Propose changes**로 저장합니다. 새 브랜치에 저장했다면 PR을 만들고, 5단계에서 병합·배포·기존 기능을 확인합니다.

코드 조각만 바꿀 때는 GitHub에서 **해당 파일 → 연필 아이콘(Edit this file)**으로 편집하고 **Commit changes**로 저장해도 됩니다. [파일 내려받기](https://docs.github.com/en/repositories/working-with-files/using-files/viewing-and-understanding-files) · [파일 올리기](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)

<CopyPrompt title="수정 위치와 코드 조각 요청" content={partialEditPrompt} />

병합한 PR을 되돌릴 때는 해당 PR의 **Revert**로 되돌리기 PR을 만들고, 변경 내용을 확인해 병합합니다. 충돌이 생기면 선생님과 함께 확인합니다. [GitHub의 PR 되돌리기 안내](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/reverting-a-pull-request)

## 8. 기존 활동지에 기록하기

| 활동지 위치 | 기록할 내용 |
| --- | --- |
| **STEP 2-4 · 구현** | 수정 이유, 바꾼 기능, 요청 내용, 커밋 또는 PR 링크 |
| **STEP 3-2 · 검증** | 실제 웹앱의 입력·결과, 기존 기능 점검, 원자료와 대조한 내용 |
| **STEP 4 · AI 활용** | AI의 도움, 사람이 판단한 내용, 검증 후 수정한 내용 |

**완료 기준:** 저장소에서 변경 이력을 찾을 수 있고, 같은 웹앱 주소에서 수정한 내용과 기존 기능을 확인했습니다.
