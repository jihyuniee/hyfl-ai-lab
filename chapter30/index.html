이 챕터는 정보 교과의 “프로그램 작성·검토” 역량과 인공지능 교과의 “생성형 AI 활용·비판적 검증” 역량을 결합합니다. 핵심은 AI에게 코드를 대신 짜게 하는 것이 아니라, AI가 만든 코드를 사람이 읽고 이해하고 검증하는 것입니다.

🌱 생각 열기

섹션 제목: “🌱 생각 열기”

여러분이 친구에게 “우리 반 급식 만족도 설문 결과를 그래프로 보여주는 프로그램 만들어 줘”라고 부탁했다고 합시다. 친구가 5분 만에 코드를 뚝딱 가져왔습니다.

그런데 그 코드가 정말 여러분이 원한 것을 만드는지, 여러분은 어떻게 확신할 수 있을까요?

생성형 AI는 바로 그 “5분 만에 코드를 가져오는 친구”와 같습니다. 빠르고 유능하지만, 가끔 엉뚱한 것을 만들거나 조용히 틀립니다. 그래서 진짜 실력은 “AI에게 시키는 힘”이 아니라 “AI가 만든 것을 검토하는 힘”에 있습니다.

[정보] [인공지능]

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 작성한 요구사항을 바탕으로 생성형 AI에게 프로토타입 코드 생성을 요청할 수 있다.
  • AI가 생성한 코드의 동작을 사람이 직접 읽고 이해하며, 요구사항과 일치하는지 검토할 수 있다.

🔁 선수학습 확인

섹션 제목: “🔁 선수학습 확인”
  • 29차시에서 우리는 “무엇을 만들 것인가”를 명확히 적는 요구사항 명세를 작성했습니다. (입력·처리·출력, 수용 기준)
  • 지금까지 배운 프롬프트 작성법: 맥락·역할·구체적 지시를 담아 AI에게 요청하는 방법.
  • 데이터 시각화의 기본: 막대그래프는 범주별 비교, 꺾은선그래프는 시간에 따른 변화를 보여줍니다.

이번 시간에는 이 요구사항을 실제로 AI에게 코드로 바꿔 달라고 요청하고, 그 결과물을 읽고 검토합니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: “AI가 만든 코드, 정말 맞을까?”

섹션 제목: “탐구: “AI가 만든 코드, 정말 맞을까?””
  • 준비물: 생성형 AI 챗봇(교사가 지정), 온라인 코드 실행 환경(예: 웹 기반 파이썬 실행기), 29차시에 작성한 요구사항 명세, 활동지
  • 탐구 목표: 같은 요구사항을 두 가지 방식으로 AI에게 주고, 결과 코드의 차이를 비교합니다.

과정

섹션 제목: “과정”
  1. 모호한 요청을 먼저 던집니다.

    “급식 만족도 데이터를 그래프로 그려 줘.”

  2. AI가 준 코드를 실행 환경에 붙여 넣고 실행합니다. 결과를 관찰합니다.
  3. 구체적 요청으로 다시 던집니다. (요구사항 명세를 그대로 활용)

    “다음 5개 항목의 만족도 점수(1-5점) 데이터를 막대그래프로 그려 줘. x축은 메뉴 이름, y축은 평균 점수, 제목은 ‘우리 반 급식 만족도’로 해 줘. 데이터는 다음과 같아: 불고기 4.5, 김치찌개 3.2, 돈까스 4.8, 나물비빔밥 2.9, 카레 4.1”

  4. 두 번째 코드도 실행하고 결과를 관찰합니다.
  5. 두 결과를 활동지에 비교 기록합니다.

비교 기록 활동지

섹션 제목: “비교 기록 활동지”
항목모호한 요청구체적 요청
데이터가 코드에 들어있나?

축 이름·제목이 있나?
실행하면 에러 없이 나오나?
내가 수정할 부분은?

결과 예측

섹션 제목: “결과 예측”

“모호한 요청은 AI가 임의의 가짜 데이터를 넣거나, 우리가 원하지 않은 그래프를 그릴 것입니다. 구체적 요청은 우리 데이터와 의도에 더 가까운 코드를 만들 것입니다.”

토의

섹션 제목: “토의”
  • “왜 같은 AI인데 결과가 이렇게 달라졌을까요?”
  • “AI가 만든 코드가 실행은 되는데 의도와 다르다면, 그건 성공일까요 실패일까요?”

탐구에서 확인한 것처럼, AI의 코드 품질은 요청(프롬프트)의 구체성에 크게 좌우됩니다. 그리고 실행이 된다고 해서 요구사항을 만족하는 것은 아닙니다. 이제 이 두 가지를 개념으로 정리합니다.

📌 핵심 개념

섹션 제목: “📌 핵심 개념”

개념 1. 요구사항 → 코드 변환 (프롬프트 엔지니어링) [정보] [인공지능]

섹션 제목: “개념 1. 요구사항 → 코드 변환 (프롬프트 엔지니어링) [정보] [인공지능]”
  • 정의: 우리가 만들고 싶은 프로그램의 요구사항(입력·처리·출력)을 AI가 이해할 수 있는 명확한 프롬프트로 바꾸어, 코드를 생성하도록 요청하는 과정입니다.
  • 비유: 요구사항 → 코드 변환은 마치 요리 주문서를 요리사에게 건네는 것과 같습니다. “맛있는 거 주세요”보다 “간장 베이스, 매운맛 3단계, 면은 꼬들하게”라고 말할 때 원하는 요리가 나옵니다.

좋은 코드 생성 프롬프트에는 네 가지가 들어갑니다.

요소내용예시
목표무엇을 만들지”막대그래프를 그리는 코드”
입력 데이터실제 데이터”불고기 4.5, 김치찌개 3.2 …”
형식 지정출력 모양”x축 메뉴명, y축 평균점수, 제목 지정”
제약 조건지켜야 할 규칙”파이썬, matplotlib 사용”
flowchart LR
  A[요구사항 명세<br/>입력·처리·출력] --> B[프롬프트로 변환<br/>목표+데이터+형식+제약]
  B --> C[생성형 AI]
  C --> D[코드 생성]

위 그림은 요구사항이 프롬프트를 거쳐 코드로 변환되는 흐름을 보여줍니다.

개념 2. AI 코드 검토 (사람이 이해하고 검증하기) [정보] [인공지능]

섹션 제목: “개념 2. AI 코드 검토 (사람이 이해하고 검증하기) [정보] [인공지능]”
  • 정의: AI가 생성한 코드를 사람이 한 줄씩 읽어 동작을 이해하고, 요구사항과 일치하는지·오류가 없는지·위험은 없는지 판단하는 과정입니다.
  • 비유: AI 코드 검토는 마치 번역기가 번역한 문장을 다시 읽어 보는 것과 같습니다. 번역기가 매끄러운 문장을 내놓아도 원래 뜻과 다를 수 있듯, AI 코드도 그럴듯하게 실행되지만 의도와 어긋날 수 있습니다.

검토는 세 가지 질문으로 합니다.

검토 질문확인하는 것
① 이해되는가?코드의 각 부분이 무슨 일을 하는지 설명할 수 있는가
② 일치하는가?요구사항(입력·처리·출력)을 실제로 만족하는가
③ 안전한가?가짜 데이터·오류·의도치 않은 동작은 없는가
flowchart TD
  A[AI 생성 코드] --> B{① 이해되는가?}
  B -->|아니오| E[AI에게 설명 요청]
  B -->|예| C{② 요구사항과 일치?}
  C -->|아니오| F[프롬프트 수정 재요청]
  C -->|예| D{③ 안전한가?}
  D -->|아니오| F
  D -->|예| G[채택]

위 순서도는 “AI가 줬으니 그냥 쓴다”가 아니라, 세 관문을 통과해야 채택하는 검토 절차를 나타냅니다.

🌉 교과 간 연결 다리

섹션 제목: “🌉 교과 간 연결 다리”

  • [정보] 교과의 도구: 코드를 읽는 능력(변수, 반복, 함수의 역할 파악)과 디버깅(오류 찾기).
  • [인공지능] 교과의 도구: 프롬프트 설계와 AI 출력의 신뢰성 검증(환각·가짜 데이터 감지).

이 둘이 만나는 지점이 바로 “AI가 만든 코드를 사람이 검토한다”입니다. AI만 있으면 코드는 나오지만 검증이 안 됩니다. 코드 읽기 능력만 있으면 검증은 되지만 빠르게 만들지 못합니다. 두 도구가 함께여야 빠르면서도 믿을 수 있는 프로토타입이 완성됩니다.

가로지르는 질문

섹션 제목: “가로지르는 질문”

“AI가 완벽하게 실행되는 코드를 줬는데, 그 코드가 데이터를 몰래 지어냈다면 이것은 ‘성공한 프로그램’일까요?”

이 질문은 정보 교과의 “실행 성공” 기준만으로도, 인공지능 교과의 “신뢰성” 기준만으로도 답할 수 없습니다. 두 교과의 도구를 모두 동원해야 합니다. 여러분은 어떤 도구를 먼저 쓰겠습니까?

AI에게 이렇게 물어보세요: “위 코드의 3번째 줄이 무슨 일을 하는지 초보자에게 설명해 줘.”

4단계: 실행하고 결과 검토 (②일치·③안전)

섹션 제목: “4단계: 실행하고 결과 검토 (②일치·③안전)”

코드를 실행합니다. 나온 그래프가 요구사항과 일치하는지 검토표로 확인합니다.

  • 그래프에 내가 준 데이터가 정확히 반영되었는가
  • AI가 없는 데이터를 임의로 추가하지 않았는가
  • 축 이름·제목이 요구사항대로인가
  • 그래프 종류가 의도한 것인가

5단계: 재요청 또는 채택

섹션 제목: “5단계: 재요청 또는 채택”

검토를 통과하지 못하면 프롬프트를 수정해 다시 요청합니다. 통과하면 채택하고, “왜 채택했는지” 한 줄로 기록합니다.

재요청 예시: “y축 범위를 0에서 5로 고정하고, 평균 점수를 막대 위에 숫자로 표시해 줘.”

📖 읽을거리

섹션 제목: “📖 읽을거리”

“AI가 짠 코드를 그대로 배포했다가…”

실제 개발 현장에서는 AI가 생성한 코드를 검토 없이 사용했다가 보안 취약점이나 잘못된 계산이 그대로 서비스에 들어간 사례가 종종 보고됩니다. 그래서 많은 기업이 “AI가 코드를 짜도, 사람이 반드시 리뷰(검토)한다”는 규칙을 둡니다.

흥미로운 점은, AI 시대에 코드를 처음부터 다 짜는 능력보다 AI가 준 코드를 빠르게 읽고 판단하는 능력이 더 중요해지고 있다는 것입니다. 여러분이 오늘 연습한 “검토하는 힘”이 바로 그 능력입니다.

정답 확인

2. ③ 안전한가

3. ③ (실행 성공이 요구사항 충족을 의미하지 않는다. AI의 환각 데이터를 감지하고 재요청해야 한다.)

4. (예시 답안) 정보 교과의 관점에서는 코드가 문법 오류 없이 실행되어 결과를 출력했으므로 ‘동작’에는 성공했다고 볼 수 있다. 그러나 인공지능 교과의 관점에서는 AI가 실제 데이터가 아닌 지어낸(환각) 데이터를 사용했으므로 결과의 신뢰성이 없다. 프로그램의 목적은 ‘올바른 정보를 보여주는 것’이므로, 실행이 되더라도 데이터가 조작되었다면 요구사항을 만족하지 못한 실패한 프로그램이다. 따라서 실행 성공과 신뢰성은 별개이며, 두 기준을 모두 통과해야 진짜 성공이다.

📋 단원 정리

섹션 제목: “📋 단원 정리”

  • 핵심 개념 요약

    • 요구사항 → 코드 변환: 목표·데이터·형식·제약 네 요소를 담은 프롬프트가 좋은 코드를 만든다.
    • AI 코드 검토: ①이해되는가 ②일치하는가 ③안전한가, 세 관문을 통과해야 채택한다.
    • 실행 성공 ≠ 요구사항 충족: AI가 준 코드가 돌아간다고 해서 옳은 것은 아니다. 사람의 검토가 반드시 필요하다.

  • 오늘의 한 문장

    AI 시대의 진짜 실력은 “AI에게 시키는 힘”이 아니라 “AI가 만든 것을 검토하는 힘”이다.
