School Image Lab에서는 사진·음성·포즈 데이터를 직접 모으고, AI 모델이 그 데이터에서 패턴을 찾아 새로운 입력을 분류하는 과정을 경험했습니다. 이제 최종 프로젝트에서는 우리가 직접 모은 데이터만 사용하지 않습니다. 공공기관이 공개한 데이터를 찾아보고, 그 안에서 의미 있는 사실과 한계를 확인한 뒤, 사람에게 도움이 되는 AI 서비스를 기획합니다.

<Callout kind="mission" title="오늘부터 시작하는 최종 프로젝트">관심 분야의 공공데이터를 탐색하고, 데이터에서 발견한 사실이나 문제의식을 바탕으로 AI 서비스 기획서를 완성합니다. **오늘은 코딩이나 모델 학습을 하지 않습니다.** 프로젝트의 주제와 데이터 후보를 찾고, 기획의 출발점을 세우는 시간이 목표입니다.</Callout>

```text
관심 분야 또는 문제의식
→ 공공데이터 탐색
→ 데이터의 출처·항목·기준 확인
→ 분석과 비교를 통한 인사이트 도출
→ 필요한 AI 기능 판단
→ AI 서비스 기획서 작성
```

## 1. 이번 프로젝트에서 만들 것

이번 프로젝트의 최종 결과물은 **공공데이터 기반 AI 서비스 기획서**입니다. 실제 AI 모델을 학습시키거나 웹 서비스를 완성하는 것이 필수는 아닙니다. 중요한 것은 어떤 문제를 왜 살펴보았고, 어떤 데이터를 근거로 삼았으며, 그 결과 어떤 AI 서비스가 필요하다고 판단했는지를 설명하는 것입니다.

| 프로젝트 요소 | 학생이 해야 할 일 |
| --- | --- |
| 동기 | 평소 관심 분야나 문제라고 느낀 현상을 정한다 |
| 데이터 탐색 | 관련 공공데이터를 찾고 제공 기관·형식·기준 시점을 기록한다 |
| 분석과 인사이트 | 데이터를 비교하거나 살펴보며 의미 있는 사실과 한계를 구분한다 |
| AI 서비스 기획 | 데이터에서 발견한 내용을 바탕으로 필요한 AI 기능과 사용자 장면을 설계한다 |
| 생성형 AI 활용 | 검색어 확장, 데이터 설명, 아이디어 정리, 기획서 문장 다듬기에 활용한다 |
| 검증과 책임 | AI가 제안한 내용과 수치는 원자료에서 다시 확인한다 |

<Callout kind="concept" title="생기부에 남는 흐름">이 프로젝트는 **동기 - 과정 - 결과**가 드러나도록 진행합니다. “평소 어떤 문제에 관심을 가졌는가”, “어떤 공공데이터를 찾아 어떻게 살펴보았는가”, “데이터를 통해 무엇을 알게 되었고 어떤 AI 서비스를 기획했는가”가 기록의 중심이 됩니다.</Callout>

## 2. 프로젝트는 두 가지 방식으로 시작할 수 있습니다

처음부터 정답 같은 문제를 정할 필요는 없습니다. 데이터를 보며 생각이 바뀌는 것도 좋은 탐구입니다.

| 시작 방식 | 흐름 | 예시 문장 틀 |
| --- | --- | --- |
| 문제의식에서 출발 | 평소 문제라고 생각한 현상 → 관련 데이터 탐색 → 데이터로 확인하거나 수정 → 서비스 기획 | “평소 [현상]을 문제라고 생각하여 관련 공공데이터를 찾아보았다. 데이터를 살펴본 결과 [인사이트]를 발견했고, 이를 바탕으로 [AI 서비스]를 기획했다.” |
| 데이터 탐색에서 출발 | 관심 분야 데이터 탐색 → 뜻밖의 차이·변화·한계 발견 → 문제 재정의 → 서비스 기획 | “[분야]의 공공데이터를 탐색하던 중 [현상]을 발견했다. 이 현상이 [사용자]에게 영향을 줄 수 있다고 판단하여 [AI 서비스]를 기획했다.” |

<Callout kind="caution" title="데이터는 문제를 대신 결정하지 않습니다">공공데이터는 현상과 차이를 보여줄 수 있지만, 그 원인을 자동으로 증명하지는 않습니다. 데이터에서 확인한 사실, 가능한 해석, 추가 확인이 필요한 원인 가설을 구분해야 합니다.</Callout>

## 3. 공공데이터란 무엇일까?

공공데이터는 공공기관이 업무를 수행하며 만들거나 관리하는 데이터 중 시민이 활용할 수 있도록 제공되는 데이터입니다. 공공데이터라고 해서 자동으로 우리 질문에 맞거나 항상 최신이라는 뜻은 아닙니다. 제공 기관, 기준 시점, 수집 기준, 이용 조건을 확인해야 합니다.

| 찾아볼 수 있는 곳 | 주로 확인할 수 있는 자료 |
| --- | --- |
| 공공데이터포털 | 여러 공공기관의 파일 데이터와 오픈 API |
| KOSIS 국가통계포털 | 인구·경제·사회·교육 등 국가 통계 |
| 기상자료개방포털 | 기온·강수량 등 기상 관측 자료 |
| NEIS 교육정보 개방 포털 | 학교 기본 정보·급식·학사 일정 등 교육 관련 API |
| 영화진흥위원회 KOBIS | 박스오피스·영화·상영 정보 |
| 지방자치단체 또는 공공기관 홈페이지 | 지역별 행정·교통·환경·문화 관련 공개 자료 |

### 반드시 확인할 것

- 누가 제공하는 데이터인가?
- 언제 기준의 데이터인가?
- 어떤 기준으로 수집하거나 집계했는가?
- 어떤 항목과 단위가 들어 있는가?
- 우리 질문에 직접 답할 수 있는가?
- 이 데이터만으로 알 수 없는 것은 무엇인가?

## 4. 데이터는 어떤 모양으로 제공될까?

공공데이터는 한 가지 형태로만 제공되지 않습니다. 오늘은 깊이 분석하기보다, 내가 찾은 데이터가 어떤 형태인지 먼저 확인합니다.

| 데이터 형태 | 특징 | 예 |
| --- | --- | --- |
| 정형 데이터 | 행과 열이 정해져 있는 표 형태 | CSV, XLSX, 통계표 |
| 반정형 데이터 | 구조는 있지만 고정된 표 모양은 아닌 형태 | JSON, XML, API 응답 |
| 비정형 데이터 | 정해진 행과 열 구조가 없는 자료 | 이미지, 음성, 영상, 문서 본문 |

지난 프로젝트의 사진·음성·포즈는 주로 **비정형 데이터**였습니다. 이번 프로젝트에서는 표 형태의 **정형 데이터**와 API가 제공하는 **반정형 데이터**를 주로 만나게 됩니다.

## 5. 데이터를 가져오는 방법 선택하기

오늘은 세부 기술을 모두 배우지 않습니다. 다만 내가 찾은 데이터가 어떤 방식으로 제공되는지 확인하고, 왜 그 방법이 적절한지 설명할 수 있어야 합니다.

| 방법 | 의미 | 적합한 상황 | 확인할 것 |
| --- | --- | --- | --- |
| 파일 | CSV·XLSX 등을 내려받아 직접 확인한다 | 표의 구조, 열, 결측값, 단위를 직접 보고 싶을 때 | 파일명, 출처, 다운로드 날짜, 열 이름, 단위 |
| API | 정해진 주소와 조건을 보내 데이터를 응답으로 받는다 | 날짜·지역 같은 조건을 바꾸어 반복 조회할 때 | 요청 주소, 변수, 인증키 필요 여부, 응답 항목 |
| AI 도구 활용 | 생성형 AI나 연결된 도구를 이용해 데이터 후보를 찾고 정리한다 | 검색어를 넓히거나 자료 후보를 빠르게 비교할 때 | AI가 제시한 출처, 조건, 단위, 확인 필요 사항 |

<Callout kind="caution" title="AI가 찾아준 것도 원자료로 확인합니다">생성형 AI가 추천한 데이터 이름, 기관, 수치, 해석은 그대로 믿지 않습니다. 실제 공공데이터 페이지나 공식 자료에서 출처·기준 시점·항목·단위를 다시 확인해야 합니다.</Callout>

## 7. 생성형 AI를 어떻게 활용할까?

이번 프로젝트에서는 생성형 AI를 계속 활용합니다. 다만 AI가 답을 대신 정해주는 것이 아니라, 우리가 더 잘 탐색하고 정리하고 검증하도록 돕는 도구로 사용합니다.

| 프로젝트 순간 | AI에게 맡길 수 있는 도움 | 사람이 해야 할 판단 |
| --- | --- | --- |
| 주제 탐색 | 관심 분야와 관련된 검색어를 넓혀 보기 | 내가 실제로 궁금한 주제인지 판단 |
| 데이터 탐색 | 찾아볼 만한 공공데이터 사이트와 키워드 제안 받기 | 실제 사이트에서 데이터 존재 여부 확인 |
| 데이터 이해 | 열 이름, 단위, 한 행의 의미를 설명하게 하기 | 설명이 원자료와 맞는지 확인 |
| 인사이트 정리 | 관찰한 사실을 문장으로 정리하게 하기 | 사실·해석·추측을 구분 |
| 서비스 기획 | 사용자, 입력, AI 기능, 출력 구조를 제안 받기 | 필요한 기능과 위험 요소를 선택·수정 |
| 발표 준비 | 기획서 문장과 발표 흐름 다듬기 | 과장된 표현이나 확인 안 된 내용 삭제 |

### 오늘 사용할 수 있는 프롬프트

```text
나는 고등학교 인공지능 원리탐구 수업에서 공공데이터 기반 AI 서비스 기획 프로젝트를 시작하고 있어.

관심 분야: [나의 관심 분야]
궁금한 점 또는 문제의식: [내가 궁금하거나 문제라고 생각한 점]

1. 이 주제와 관련해 공공데이터를 찾을 때 사용할 검색어를 한국어로 제안해줘.
2. 찾아볼 만한 공공데이터 사이트 후보를 제안해줘.
3. 내가 확인해야 할 데이터 항목과 기준 시점을 알려줘.
4. 이 데이터로 알 수 있는 것과 알 수 없는 것을 구분해줘.
5. 아직 확인되지 않은 내용은 단정하지 말고 “확인 필요”라고 표시해줘.
6. 바로 해결책을 만들기보다, 먼저 확인해야 할 질문을 3개 제안해줘.
```

## 8. 데이터에서 AI 서비스로 연결하기

AI 서비스를 기획할 때는 “AI를 넣으면 좋아 보인다”가 아니라, **이 문제의 어떤 부분에 AI가 필요한지**를 설명해야 합니다.

```text
사용자 상황
→ 입력 데이터
→ AI가 하는 일
→ 사용자에게 보여줄 결과
→ 사람이 확인하거나 선택할 일
```

| AI 역할 | 언제 필요한가 | 예시 표현 |
| --- | --- | --- |
| 예측 | 앞으로의 값이나 가능성을 추정해야 할 때 | “지역별 변화 추세를 바탕으로 수요를 예측한다.” |
| 분류 | 입력을 유형이나 상태로 나누어야 할 때 | “문의 내용을 유형별로 분류한다.” |
| 추천 | 조건에 맞는 선택지를 제안해야 할 때 | “사용자 조건에 맞는 정보를 추천한다.” |
| 요약·질의응답 | 복잡한 자료를 쉽게 이해하게 해야 할 때 | “공공데이터 내용을 사용자의 질문에 맞게 설명한다.” |
| 생성 | 안내문, 보고서, 학습 자료 등 새 결과물을 만들어야 할 때 | “확인된 정보를 바탕으로 맞춤형 안내문을 생성한다.” |

<Callout kind="concept" title="AI가 필요하지 않을 수도 있습니다">간단한 검색, 표 정리, 규칙 기반 안내로 충분하다면 AI 서비스가 아니어도 좋은 해결책입니다. 이번 프로젝트에서는 AI가 꼭 필요한 부분과 사람이 확인해야 하는 부분을 구분하는 태도가 중요합니다.</Callout>

## 9. 오늘의 완료 기준

<Callout kind="checklist" title="오늘 수업이 끝날 때 남길 것">
- 관심 분야 또는 문제의식을 하나 이상 적었다.
- 관련 공공데이터를 검색해 데이터 후보를 하나 이상 찾았다.
- 데이터 이름, 제공 기관, 제공 형식, 기준 시점 또는 갱신일을 기록했다.
- 이 데이터로 알 수 있는 것과 알 수 없는 것을 구분했다.
- 데이터에서 어떤 AI 서비스 기획으로 이어질 수 있을지 한 문장으로 적었다.
- 생성형 AI가 제안한 내용 중 실제로 확인해야 할 항목을 표시했다.
</Callout>

오늘 작성한 카드는 최종 기획서가 아닙니다. 이번 주에는 주제와 데이터를 계속 바꾸고 다듬어도 됩니다. 좋은 프로젝트는 처음 생각을 끝까지 밀어붙이는 것이 아니라, 데이터를 보며 질문을 고치고 더 나은 방향을 찾아가는 과정에서 만들어집니다.
