Part 6. AI와 함께 만드는 프로그램: Vibe Coding

🗺️ 이 챕터의 교과 결합

섹션 제목: “🗺️ 이 챕터의 교과 결합”
mindmap
  root((실행·디버깅<br/>반복 개선))
    정보
      코드 실행과 검증
      오류 메시지 읽기
      테스트 케이스 설계
    인공지능
      AI와 오류 진단 대화
      프롬프트로 수정 요청
      결과 재검증 루프
    연결 다리
      "AI가 만든 것을<br/>사람이 검증한다"
      데이터로 개선 추적

이 챕터는 정보 교과의 ‘실행·검증·테스트’ 도구와 인공지능 교과의 ‘AI 협업 진단’ 도구를 결합합니다. 핵심은 하나입니다. AI가 코드를 만들어주는 것이 끝이 아니라, 사람이 결과를 이해하고 검증하며 원하는 결과에 다가가도록 반복하는 것이 진짜 프로그래밍입니다.

🤔 생각 열기

섹션 제목: “🤔 생각 열기”

여러분이 AI에게 “급식 메뉴를 요일별로 보여주는 프로그램을 만들어줘”라고 했습니다. AI가 순식간에 코드를 뱉어냈습니다. 그런데 실행해 보니 화면에 빨간 글씨가 잔뜩 뜨고 아무것도 나오지 않습니다.

“AI가 만들어줬는데 왜 안 되지?”

이 순간, 여러분은 프로그래머의 가장 중요한 순간에 서 있습니다. 코드를 만든 것과 코드가 작동하는 것은 전혀 다른 일이기 때문입니다.

혹시 게임을 하다가 버그를 만난 적 있나요? 유명 게임 회사도 수백 명이 몇 년을 만들어도 버그가 나옵니다. AI가 5초 만에 만든 코드에 오류가 없다면 그게 오히려 이상한 일입니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • AI가 만든 결과를 실행하며 오류를 발견하고 AI와 함께 원인을 진단·수정할 수 있다.
  • 완성된 프로그램을 테스트하고 데이터로 개선 과정을 추적하며 반복적으로 개선할 수 있다.

📚 선수학습 확인

섹션 제목: “📚 선수학습 확인”

지난 차시까지 우리는 프롬프트(prompt, AI에게 주는 명령·요청문)를 설계해 AI에게 코드를 생성하게 했습니다. [인공지능] 좋은 프롬프트는 목표·조건·예시를 담아야 한다는 것을 배웠습니다. [정보] 또한 프로그램이 입력 → 처리 → 출력의 흐름으로 이루어진다는 것도 확인했습니다.

이번 시간에는 그렇게 ‘만들어진’ 코드를 실제로 돌려보고 고치는 단계로 넘어갑니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: 일부러 고장 난 코드를 살려내기

섹션 제목: “탐구: 일부러 고장 난 코드를 살려내기”

  • 준비물: AI 코딩 도구(웹 기반 IDE 또는 챗봇형 코딩 환경), 오류가 포함된 예제 프로그램, 실패 기록지

  • 과정:

    1. 교사가 배포한 “요일별 급식 출력 프로그램”을 실행합니다. (일부러 오류가 심어져 있습니다.)
    2. 화면에 뜨는 오류 메시지(error message) 를 한 글자도 빼지 않고 그대로 복사합니다.
    3. AI에게 “이 오류가 왜 났는지 알려주고, 초보자도 이해하게 설명해줘”라고 오류 메시지를 붙여 넣습니다.
    4. AI의 설명을 읽고 내가 이해한 원인을 한 문장으로 적습니다.
    5. AI가 제안한 수정안을 적용하고 다시 실행합니다. 또 오류가 나면 2번으로 돌아갑니다.

  • 결과 예측: “한 번에 고쳐질까요, 여러 번 반복해야 할까요?”

  • 토의:

    • “AI의 설명 중 내가 정말 이해한 부분과 그냥 넘어간 부분은 어디인가요?”
    • “오류 메시지를 통째로 복사한 것과 요약해서 물어본 것 중 어느 쪽이 더 정확한 답을 얻었나요?”
flowchart LR
  A[실행] --> B{오류 발생?}
  B -->|예| C[오류 메시지 복사]
  C --> D[AI에게 진단 요청]
  D --> E[원인 이해·수정]
  E --> A
  B -->|아니오| F[테스트로 검증]

이 순환 그림처럼, 디버깅은 한 번에 끝나는 직선이 아니라 돌고 도는 고리입니다.

💡 핵심 개념

섹션 제목: “💡 핵심 개념”

개념 1: 디버깅 루프 [정보]

섹션 제목: “개념 1: 디버깅 루프 [정보]”

  • 정의: 프로그램을 실행하여 오류를 발견하고, 원인을 진단해 수정한 뒤, 다시 실행해 확인하는 반복 순환 과정입니다. ‘버그(bug, 프로그램의 결함)를 없앤다(de-)‘는 뜻에서 디버깅이라 부릅니다.

  • 비유: 디버깅은 마치 의사의 진료와 같습니다. 증상(오류 메시지)을 보고, 원인(병)을 진단하고, 처방(수정)을 내린 뒤, 다시 경과를 관찰(재실행)합니다. 한 번의 처방으로 낫지 않으면 다시 진료합니다.

오류는 크게 세 종류입니다. 이 구분을 알면 AI에게 더 정확히 물을 수 있습니다.

오류 종류언제 나타나나예시
문법 오류(syntax error)실행 전, 코드 형식이 틀림괄호를 안 닫음
실행 오류(runtime error)실행 도중 멈춤없는 파일을 불러옴
논리 오류(logic error)실행은 되나 결과가 틀림평균을 합계로 잘못 계산

가장 까다로운 것은 논리 오류입니다. 오류 메시지가 안 뜨기 때문에, 결과를 사람이 직접 검증해야만 발견됩니다. 바로 여기서 “사람의 역할”이 결정적입니다.

개념 2: AI 협업 디버깅 [인공지능]

섹션 제목: “개념 2: AI 협업 디버깅 [인공지능]”

  • 정의: 오류의 원인 진단과 수정안 도출을 AI와의 대화로 수행하되, 최종 판단과 검증은 사람이 맡는 협업 방식입니다.

  • 비유: AI는 박식하지만 가끔 착각하는 조수입니다. 방대한 지식으로 빠르게 답을 주지만, 확신에 찬 목소리로 틀린 답을 줄 때도 있습니다. 그래서 조수의 말을 그대로 믿지 않고 직접 확인하는 것이 사람의 몫입니다.

좋은 AI 디버깅 질문에는 세 가지가 들어갑니다.

좋은 디버깅 프롬프트의 3요소

  1. 오류 메시지 전체 (요약하지 말고 그대로)
  2. 문제의 코드 (어느 부분인지)
  3. 내가 원한 결과 (“이렇게 나와야 하는데 이렇게 나온다”)
flowchart TD
  A[사람: 오류 상황 전달] --> B[AI: 원인 추정·수정안]
  B --> C[사람: 이해하고 검증]
  C --> D{맞는가?}
  D -->|아니오| E[사람: 추가 정보로 재질문]
  E --> B
  D -->|예| F[사람: 적용·재실행]

핵심은 화살표의 시작과 끝이 모두 사람이라는 점입니다. AI는 중간의 조수일 뿐, 운전대는 사람이 잡습니다.

🌉 교과 간 연결

섹션 제목: “🌉 교과 간 연결”

[정보]의 테스트 케이스(test case, 프로그램이 맞게 작동하는지 확인하는 입력-기대출력 쌍) 개념과 [인공지능]의 반복 프롬프트 개념이 만나면 강력해집니다.

예를 들어 “평균 점수 계산 프로그램”을 검증한다고 합시다.

입력기대 출력실제 출력판정
90, 80, 1009090통과
0, 0, 00오류실패
(빈 값)“데이터 없음”0실패

[정보] 사람은 이 표로 어디가 틀렸는지 데이터로 특정합니다. [인공지능] 그다음 AI에게 “빈 값일 때 ‘데이터 없음’을 출력하도록 고쳐줘”라고 정확한 개선 지점을 전달합니다. 막연히 “고쳐줘”가 아니라 실패한 테스트 케이스를 근거로 요청하는 것, 이것이 두 교과의 도구가 결합하는 지점입니다.

🔀 가로지르는 질문

섹션 제목: “🔀 가로지르는 질문”

“AI가 준 수정안이 오류 메시지는 없앴지만, 결과가 여전히 이상하다면 나는 무엇을 근거로 ‘AI가 틀렸다’고 판단할 수 있을까?”

이 질문에 답하려면 [정보]의 테스트 케이스(기대 출력과 비교)와 [인공지능]의 재질문 전략(무엇이 왜 틀렸는지 전달)을 모두 동원해야 합니다. 여러분은 어떤 도구를 먼저 쓰겠습니까?

🛠️ 따라하기: 급식 통계 프로그램 살려서 시각화까지

📖 읽을거리: 최초의 ‘버그’는 진짜 벌레였다

섹션 제목: “📖 읽을거리: 최초의 ‘버그’는 진짜 벌레였다”

1947년, 컴퓨터 과학자 그레이스 호퍼(Grace Hopper)가 이끌던 팀은 거대한 컴퓨터가 오작동하는 원인을 찾고 있었습니다. 기계 안을 뒤지던 그들은 놀라운 것을 발견합니다. 회로 사이에 끼어 죽은 나방 한 마리였습니다.

팀은 그 나방을 작업 일지에 테이프로 붙이고 이렇게 적었습니다. “최초로 발견된 실제 버그(bug) 사례.” 이때부터 프로그램의 결함을 ‘버그’, 그것을 잡는 일을 ‘디버깅’이라 부르게 되었다는 이야기가 널리 퍼졌습니다.

재미있는 점은, 오늘날 AI가 코드를 대신 써주는 시대에도 버그를 잡는 마지막 눈은 여전히 사람이라는 사실입니다. 호퍼가 나방을 직접 찾아낸 것처럼요.
