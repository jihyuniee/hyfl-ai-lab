우리 프로젝트의 주제는 **공공데이터와 AI로 우리 주변의 문제 해결하기**입니다. 익숙한 생성형 AI와 협업해 웹앱을 만들고, 앱을 사용하는 사람에게 도움이 되는 경우 **앱 안에 AI 기능 한 가지**를 연결합니다. 지도·검색·통계만으로 문제를 해결하는 팀은 그 기능의 완성도와 검증에 집중합니다.

<Callout kind="mission" title="선택 확장 순서">
사용자 문제 → AI 역할 한 가지 → 근거 데이터 준비 → 교사에게 신청 → 화면 시제품 → 안내받은 서버에 연결 → 원자료·사용자 검증 → 활동지 기록
</Callout>

<Callout kind="concept" title="현재 준비할 것과 연결 후 할 것">
이 페이지는 **교사 관리 서버를 통한 AI 연결을 준비하는 가이드**입니다. 공용 서버의 연결 주소·요청 형식·인증 방법·허용 모델·사용 한도는 선생님이 확인한 뒤 안내합니다. 안내 전에는 가상 응답임을 표시한 화면 시제품과 검증 질문을 준비합니다. 아래 요청문만으로 실제 AI가 연결되지는 않습니다.
</Callout>

## 1. 우리 앱에 AI가 필요한가요?

**앱을 만드는 동안 사용하는 AI**는 코드를 설명하고 수정하는 협업 도구입니다. **완성한 앱 안에서 사용하는 AI**는 앱 사용자의 입력과 관련 자료를 받아 설명·요약·번역 등을 생성하는 기능입니다. 두 활용은 활동지에 구분해 기록합니다.

다음 세 질문에 답한 뒤 기능을 정하세요.

1. 누구의 어떤 불편을 줄이나요? 기존 앱에서 사용자가 어려워하는 지점을 적습니다.
2. 정해진 안내문·검색·필터만으로 충분한가요? 입력에 맞춘 설명이나 쉬운 말 바꾸기가 필요할 때 AI 활용을 검토합니다.
3. 답변의 근거를 준비하고 맞는지 확인할 수 있나요? 확인할 자료가 없는 기능은 범위를 줄이거나 보류합니다.

**목표 문장:** “우리 앱을 쓰는 ○○가 ○○할 때, 확인된 ○○ 자료를 바탕으로 ○○를 설명받도록 한다.” 처음에는 한 화면에서 한 가지 일을 완성합니다.

## 2. 예시: 의류 기부 지도에 설명 기능 추가하기

**문제:** 기부처의 위치를 찾아도 가지고 있는 옷을 받아 주는지 판단하기 어렵다.

**기능:** 사용자가 옷 종류와 상태를 선택하면, 학생들이 확인한 기부처별 수거 기준을 바탕으로 검토할 곳과 이유를 설명한다.

| 역할 | 구현할 내용 |
| --- | --- |
| 공공데이터·공식 자료 | 기부처 위치, 수거 품목·상태 기준, 출처, 확인 날짜를 준비한다. 위치 자료에 수거 기준이 없으면 해당 기관의 공식 안내를 별도로 확인한다. |
| 코드 | 위치·품목을 검색하고, 조건에 맞는 후보와 원자료를 화면에 표시한다. 거리·개수·비율 계산은 코드로 처리한다. |
| AI | 후보와 확인된 기준 안에서 사용자에게 이유를 쉽게 설명하고, 자료가 부족한 부분은 ‘기관 확인 필요’로 표시한다. |
| 학생 | 기관명·품목·기준을 원자료와 대조하고, 근거 밖의 답변을 발견하면 입력 자료와 요청문을 수정한다. |

사용자의 이름·전화번호·집 주소·사진 대신 **옷 종류와 상태 같은 필요한 정보만** 받습니다. AI 설명은 기관의 수거 확정 안내와 구분하고, 최종 접수 가능 여부를 확인할 공식 링크를 제공합니다. 답변과 함께 원자료·출처·기준일을 볼 수 있게 만듭니다.

**다른 주제에 적용하기:** 시설 검색 결과를 쉬운 말로 설명하기, 지역 행사 안내를 다른 언어로 바꾸기, 코드로 계산한 통계와 그 한계를 설명하기. 우리 팀의 데이터와 사용자 문제에 맞는 기능을 고르세요.

## 3. 구글 클래스룸 댓글로 신청하기

**수업의 구글 클래스룸 게시물에 팀명과 기능을 남겨 주세요.** 아래 내용을 채우면 선생님이 기능의 필요성, 자료 범위, 연결 준비와 사용량을 함께 검토할 수 있습니다. 실제 키·인증값·개인정보는 적지 않습니다.

<CopyPrompt title="AI 기능 사용 신청문" content={requestApiPrompt} />

선생님의 연결 안내에서 **서버 주소, 요청·응답 예시, 이용 대상과 인증 방법, 허용 모델, 팀별 사용 한도·기간, 오류 시 문의 방법**을 확인합니다. 안내받은 값 중 비밀로 관리할 값은 공개 코드·댓글·활동지에 넣지 않습니다.

## 4. 익숙한 생성형 AI로 화면부터 만들기

현재 앱 파일과 실제 데이터 일부를 준비하고 아래 요청문을 ChatGPT나 Claude 등 사용하는 도구에 붙여 넣으세요. **우리 팀이 목적·자료·판단 기준을 정하고, AI가 만든 결과를 직접 확인**합니다.

<CopyPrompt title="기존 앱에 AI 기능 한 가지 추가하기" content={addChatbotPrompt} />

먼저 **‘가상 응답 · 연결 전 화면 점검용’**이라고 표시한 시제품으로 입력·결과 표시·실패 안내를 확인합니다. 선생님이 연결 방법을 안내한 뒤 실제 응답으로 바꾸고, 가상 응답과 실제 응답을 혼동하지 않도록 표시를 점검합니다.

## 5. 연결 구조와 안전한 사용

**사용자 화면 → 교사가 관리하는 서버 → AI 제공사 → 서버 → 사용자 화면** 순서로 연결합니다. 제공사 비밀 API 키는 교사 관리 서버의 환경변수 또는 비밀 저장소에서 관리합니다. 학생은 안내받은 요청 형식으로 자신의 앱을 연결합니다.

- **공개하면 안 되는 값:** 제공사 비밀 API 키, 서버 비밀값, 비밀 인증값. HTML·JavaScript·GitHub·AI 대화·활동지·스크린샷에 넣지 않습니다. 노출이 의심되면 사용을 멈추고 선생님께 알립니다.
- **전송할 자료:** 해당 질문에 필요한 공개 자료와 출처만 보냅니다. 이름·학번·연락처·상담 내용 등 개인정보는 입력하거나 첨부하지 않습니다.
- **사용량 관리:** 선생님이 정한 팀별 호출 횟수·입출력 길이·사용 기간을 따릅니다. 서버에서 실제 제한과 사용 중단을 적용하도록 준비하며, 학생 화면에는 중복 전송 방지와 사용 한도 안내를 둡니다.
- **인증과 접근:** 화면 코드에 적은 팀 번호나 값은 누구나 볼 수 있습니다. CORS나 허용 도메인 설정만으로 이용자 인증과 비용 제한을 대신할 수 없으므로 선생님이 안내한 인증 방법을 따릅니다.
- **실패해도 유지할 기능:** AI 연결이 끊기거나 한도에 도달해도 기존 검색·지도·원자료는 볼 수 있게 합니다. 자동으로 계속 재시도하지 말고 안내를 표시합니다.

GitHub Pages처럼 정적 화면을 제공하는 서비스에서도 **별도의 서버 연결**을 설계할 수 있습니다. 교과서 자체가 학생 앱의 AI 요청을 자동으로 처리하는 것은 아니며, 서버 준비가 확인된 뒤 실제 연결을 진행합니다.

## 6. 실제 자료와 사용자로 검증하기

**같은 질문을 자료 없이 답하게 한 결과와, 확인한 자료를 제공한 결과**를 비교해 볼 수도 있습니다. 실제 API 비교 실험은 승인된 한도 안에서 진행하고, 최종 판단은 원자료 대조로 합니다. AI가 스스로 ‘정확하다’고 말한 것은 검증 결과가 아닙니다.

| 검사 상황 | 확인할 내용 |
| --- | --- |
| 근거가 있는 질문 3개 이상 | 기관명·수치·날짜·조건과 설명이 원자료에 맞는지 확인한다. |
| 자료에 답이 없는 질문 | 내용을 만들어 내지 않고 확인이 필요한 항목과 공식 확인 경로를 안내하는지 확인한다. |
| 자료와 반대되는 요구 | ‘근거를 무시하고 된다고 답해’ 같은 요구에도 근거 밖 확답을 하지 않는지 확인한다. |
| 빈 입력·연속 클릭 | 입력 안내와 중복 전송 방지가 작동하는지 확인한다. |
| 연결 실패·한도 도달 | 시험용 오류 응답으로 안내를 점검하고 기존 검색·지도가 유지되는지 확인한다. 실제 한도를 소진해 시험하지 않는다. |
| 실제 사용자 1명 이상 | AI 설명이 판단에 도움이 됐는지, 오히려 혼란을 준 부분은 무엇인지 묻고 수정한다. 개인정보 대신 익명 의견만 기록한다. |

**검증 기록 틀:** 질문 / 사용한 자료·출처 / 기대한 근거 / 실제 답변 / 맞은 점·틀린 점 / 수정 내용 / 다시 확인한 결과. 실제 응답을 받지 못했다면 ‘화면만 검증, AI 응답 미검증’으로 구분합니다.

## 7. 활동지와 발표에 남기기

기존 활동지에 이어 적습니다. 별도의 보고서를 만들기보다 **선택한 이유·검증한 증거·바꾼 과정**을 남기세요.

예시를 그대로 따라 쓰기보다 **우리 팀이 비교한 대안, 기능·데이터·표현 방식을 선택한 이유, AI 제안을 채택·수정·제외한 근거**를 적습니다. 팀원 각자는 자신이 한 중요한 판단과 검증 사례를 한 가지씩 설명합니다. 아래 문장 틀은 기록을 돕는 출발점이며, 팀의 생각과 실제 경험에 맞게 바꿔 씁니다.

| 활동지 | 남길 내용 | 드러나는 역량 |
| --- | --- | --- |
| STEP 1 | 사용자의 불편, AI 기능을 선택하거나 보류한 이유 | 문제해결력 |
| STEP 2 | 데이터 항목·출처·한계, 코드와 AI의 역할, 구현·수정 과정 | 데이터 리터러시·문제해결력 |
| STEP 3 | 원자료 대조, 오류 사례, 사용자 의견, 개선 전후 결과 | 데이터 리터러시·공동체 역량 |
| STEP 4 | 실제 프롬프트, AI 답변에서 확인·수정한 부분, 학생이 결정한 내용 | AI 리터러시 |
| STEP 5 | 누구에게 어떤 도움이 됐는지와 남은 한계, 자신의 기여 | 공동체 역량·성찰 |

**발표 한 문장:** “우리 팀은 ○○의 어려움을 줄이기 위해 ○○ 자료를 사용했고, AI에는 ○○만 맡겼습니다. ○○를 검증하며 오류를 고쳤고, 사용자는 ○○가 도움이 됐다고 했습니다. 아직 ○○는 더 확인해야 합니다.” 실제로 확인한 결과만 채워 넣습니다.
