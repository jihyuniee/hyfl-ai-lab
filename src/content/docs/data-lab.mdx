## 프로젝트 질문

<Callout kind="mission" title="공통 프로젝트">
**공공데이터를 이용해 하나의 질문에 근거 있게 답하고, 생성형 AI가 수행한 분석 과정과 결과를 직접 검증해봅니다.**
</Callout>

처음에는 학급 전체가 같은 질문과 데이터를 사용합니다. 선생님과 함께 전체 분석 과정을 경험한 뒤, 각자 관심 분야의 질문으로 확장합니다.

## 1. 데이터보다 질문을 먼저 정하기

좋은 분석은 파일을 내려받거나 그래프를 만드는 데서 시작하지 않습니다.

> **우리가 알고 싶은 것은 무엇인가?**

질문은 비교할 대상, 시간과 지역의 범위, 확인하려는 변화가 드러나도록 구체화합니다.

## 2. 공공데이터 찾고 이해하기

공공기관이 공개한 자료에서 질문에 필요한 데이터를 찾습니다. 파일을 내려받기 전에 다음을 확인합니다.

- 제공 기관과 원자료의 주소
- 수집 목적과 방법
- 조사 대상과 기간
- 행과 열의 의미
- 값의 단위
- 최근 갱신일
- 이용 조건과 개인정보 포함 여부

<Callout kind="caution" title="검색 결과보다 원자료">
누군가 정리한 글이나 AI의 설명만 보지 않고, 가능하면 데이터를 제공한 기관의 설명과 원자료를 확인합니다.
</Callout>

## 3. 생성형 AI와 함께 분석하기

파일 처리와 코드 실행을 지원하는 생성형 AI는 파일 구조 설명, 결측치·중복값·이상치 탐색, 기초 통계 계산, 그래프 생성, 변수 관계 탐색과 간단한 모델 실험을 도울 수 있습니다.

<Steps>
	<Step title="분석 계획 세우기">AI를 사용하기 전에 질문, 사용할 열, 필요한 비교와 예상 그래프를 먼저 적습니다.</Step>
	<Step title="구조 확인 요청">파일의 행과 열, 자료형, 단위, 결측치와 중복을 표로 정리하게 합니다.</Step>
	<Step title="정리 방법 검토">AI가 제안한 삭제·대체·변환 방법을 바로 실행하지 않고 이유와 영향을 확인합니다.</Step>
	<Step title="그래프 만들기">질문에 맞는 그래프를 만들고 축·단위·범례·집계 방법을 점검합니다.</Step>
	<Step title="사실만 먼저 쓰기">그래프에서 직접 확인되는 변화와 차이를 해석 없이 기록합니다.</Step>
	<Step title="해석과 반론 탐색">가능한 의미와 함께 다른 설명, 빠진 변수, 추가 자료를 찾습니다.</Step>
	<Step title="분석 재현하기">AI가 사용한 열, 처리 방법, 계산 또는 코드를 확인하여 같은 결과가 나오는지 검증합니다.</Step>
	<Step title="판단의 범위 정하기">데이터로 말할 수 있는 내용과 아직 말할 수 없는 내용을 나눕니다.</Step>
</Steps>

## 4. AI의 분석을 검증하는 질문

- 질문과 맞는 열을 사용했는가?
- 행을 삭제하거나 값을 바꾸었는가? 그 이유는 타당한가?
- 단위가 다른 값을 함께 계산하지 않았는가?
- 그래프의 축이 차이를 과장하거나 숨기지 않는가?
- 일부 집단이나 기간만 보고 전체를 일반화하지 않았는가?
- 상관관계를 원인처럼 설명하지 않았는가?
- 데이터에 없는 사실이나 출처를 덧붙이지 않았는가?

<Callout kind="concept" title="AI가 계산해도 책임은 사라지지 않는다">
AI가 코드를 작성하고 그래프를 만들었더라도, **어떤 질문을 분석했고 어떤 처리를 거쳐 어떤 결론을 내렸는지 설명할 수 있어야 합니다.**
</Callout>

## 5. 필요할 때만 예측 모델 만들기

모든 데이터 분석에 머신러닝이 필요한 것은 아닙니다. 현황을 비교하거나 변화를 설명하는 것만으로 질문에 충분히 답할 수 있다면 모델을 만들지 않아도 됩니다.

예측할 가치가 있고 데이터가 적절하다면 다음 과정을 진행합니다.

```text
예측할 값 정하기
   ↓
입력 변수와 목표 변수 구분
   ↓
학습 데이터와 테스트 데이터 분리
   ↓
분류 또는 회귀 모델 선택
   ↓
새로운 데이터에서 성능 확인
   ↓
오류와 실제 사용 가능성 판단
```

정확도가 높다는 이유만으로 좋은 예측이라고 결론 내리지 않습니다. 예측 대상의 민감성, 데이터 편향, 잘못된 예측의 영향도 함께 살펴야 합니다.

## 6. 인사이트 작성하기

1. 우리가 세운 질문
2. 사용한 데이터와 출처
3. 데이터 품질을 확인하고 수정한 내용
4. 그래프에서 직접 확인한 사실
5. 사실이 의미할 가능성
6. 다른 설명의 가능성과 분석의 한계
7. 추가로 필요한 데이터
8. AI가 도운 작업
9. AI의 제안을 수정하거나 거부한 부분
10. 현재 근거로 내릴 수 있는 최종 판단

## 개인·모둠 주제 프로젝트

공통 프로젝트가 끝나면 외국어, 교육, 진로, 경제, 환경, 문화, 교통, 안전, 인구, 건강, 정보 격차 등 관심 분야에서 질문을 정하고 같은 과정을 반복합니다.

<Callout kind="reflect" title="프로젝트의 핵심">
멋진 그래프나 복잡한 모델보다 **좋은 질문, 믿을 수 있는 데이터, 검증 가능한 분석, 근거의 범위를 지킨 판단**이 더 중요합니다.
</Callout>
