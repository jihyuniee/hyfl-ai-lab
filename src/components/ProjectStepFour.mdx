## STEP 4 · AI 모델을 서비스로 확장하고 공유하기

지금까지 우리 팀은 문제를 정의하고, 데이터를 모아 분류 모델을 학습시킨 뒤 새로운 데이터로 시험하고 한계를 확인했습니다. 이제 모델을 다른 사람이 직접 사용할 수 있는 **웹 기반 AI 서비스**로 확장하고 인터넷에 배포합니다.

### AI 모델과 AI 서비스는 무엇이 다를까?

AI 모델은 이미지·소리·포즈 같은 입력을 분석하여 분류나 예측 결과를 만듭니다. 그러나 모델만으로 사용자가 편리하게 사용하는 완성된 서비스가 되지는 않습니다. AI 서비스에는 입력을 받는 화면이나 장치, 결과를 보여주는 화면, 사용 안내, 오류 처리, 개인정보 보호와 사람이 확인할 조건이 함께 필요합니다.

| 구분 | AI 모델 | AI 서비스 |
| --- | --- | --- |
| 주요 역할 | 입력을 분석하여 분류·예측 결과 생성 | 사용자가 AI를 실제 목적에 맞게 사용하도록 구성 |
| 입력 | 이미지·소리·포즈 데이터 | 카메라·마이크·버튼 등을 통한 사용자 입력 |
| 처리 | 학습된 모델의 추론 | 모델 실행, 화면 갱신, 결과 표시, 오류 처리 |
| 출력 | 클래스와 확률 | 사용자가 이해할 수 있는 결과와 안내 |
| 이번 프로젝트 | 티처블 머신 분류 모델 | 모델을 연결한 체험 웹페이지 |

이번에 만든 티처블 머신 모델은 서비스의 핵심 구성 요소입니다. 이 모델을 사용자가 쉽게 실행하고 결과를 확인할 수 있는 웹페이지에 연결하면 웹 기반 AI 서비스로 확장할 수 있습니다. 다만 웹페이지에 연결했다는 사실만으로 결과가 항상 옳거나 안전한 서비스가 되는 것은 아닙니다. 모델의 한계와 사용 환경, 오류 처리와 사람의 최종 판단까지 함께 설계해야 합니다.

우리 팀의 분류 모델은 전체 시스템에서 주로 **처리의 일부**를 담당합니다. 실제 시스템이 되려면 입력을 받는 장치, 모델의 예측을 사용할 프로그램, 결과를 전달하거나 행동을 실행하는 출력이 함께 필요합니다.

| 확장 형태 | 입력 | 처리 | 출력과 다음 변화 |

| 피지컬 컴퓨팅 | 센서·버튼·카메라·마이크 | 입력값 처리와 동작 결정 | LED·스피커·모터 작동 |
| 인공지능 에이전트 | 센서로 환경 인식 | 정보와 목표를 바탕으로 행동 결정 | 환경에 행동하고 변화한 환경을 다시 입력받음 |

예를 들어 분리수거 모델은 웹페이지에 결과를 표시할 수도 있고, 알맞은 분리수거함의 LED를 켜거나 모터로 뚜껑을 여는 시스템으로 확장할 수도 있습니다. 이때 예측이 불확실하거나 틀렸을 때 장치를 바로 작동할지, 사람이 먼저 확인할지도 함께 정해야 합니다.

> 우리가 만든 분류 모델은 입력을 분류하는 처리 기능을 가지고 있습니다. 이제 다른 사람이 이 기능을 쉽게 사용하려면 입력을 시작하고 결과를 확인할 수 있는 화면이 필요합니다. 그래서 이번에는 모델을 웹페이지에 연결하여 하나의 AI 체험 서비스로 확장합니다.

### HTML·CSS·JavaScript와 index.html

| 구성 요소 | 역할 | 이번 페이지에서 하는 일 |
| --- | --- | --- |
| HTML | 웹페이지의 내용과 구조를 표시하는 마크업 언어 | 제목, 설명, 버튼, 결과 영역을 만듦 |
| CSS | 색·간격·배치와 화면 크기 대응을 정하는 스타일 언어 | 스마트폰에서도 읽고 누르기 편하게 표현 |
| JavaScript | 입력과 사건에 반응하고 데이터를 처리하는 프로그래밍 언어 | 모델 로딩, 장치 실행, 예측과 화면 갱신 |

이번 활동에서는 HTML 안의 `<style>`에 CSS를, `<script>`에 JavaScript를 포함하여 하나의 `index.html`로 만듭니다. 웹 서버는 주소에서 파일명이 생략되면 관례적으로 `index.html`을 첫 화면으로 찾습니다. `.html`은 브라우저가 읽는 HTML 문서임을 나타내는 확장자입니다.

### 우리 수업의 바이브 코딩 방식

바이브 코딩은 자연어로 원하는 프로그램을 설명하고 생성형 AI와 함께 코드를 만드는 방식입니다. 그러나 **요청 한 번 → 코드 복사 → 제출**을 뜻하지 않습니다. 우리 수업에서는 다음 과정을 반복합니다.

```text
① 자신의 말로 요청하기 → ② AI가 만든 코드 실행하기
→ ③ 화면과 동작을 읽고 문제 찾기 → ④ 프롬프트와 코드 개선하기
→ ⑤ 같은 조건에서 다시 실행하고 비교하기
```

| 단계 | 학생이 할 일 |
| --- | --- |
| 요청 | 문제·사용자·입력·출력·필수 기능·성공 기준을 설명한다 |
| 실행 | 파일을 저장하고 실제 브라우저와 기기에서 작동시킨다 |
| 관찰 | 보이는 화면, 버튼 동작, 오류 메시지, 모델 결과를 기록한다 |
| 이해 | 핵심 코드가 입력·모델 실행·출력을 어떻게 연결하는지 찾는다 |
| 개선 | 발견한 문제 하나를 프롬프트에 구체적으로 반영해 다시 요청한다 |
| 비교 | 처음 결과와 수정 결과를 같은 기준으로 시험한다 |

<Callout kind="concept" title="코드보다 먼저 결과를 읽고, 필요한 코드는 끝까지 추적합니다">
처음부터 모든 문법을 해석하려고 멈추지 않습니다. 먼저 프로그램을 실행해 **무엇이 작동하고 무엇이 실패하는지** 관찰합니다. 그다음 문제와 직접 관련된 HTML·CSS·JavaScript 부분을 찾아 AI에게 설명을 요청하고 직접 수정합니다. AI가 코드를 작성해도 무엇을 만들지 정하고, 실행 결과를 검증하고, 공개한 결과를 책임지는 사람은 학생입니다.
</Callout>

### 경로 A · 생성형 AI와 바이브 코딩하기

생성형 AI의 결과는 프롬프트에 제공한 맥락과 조건, 사용한 모델과 대화 문맥 등에 따라 달라질 수 있습니다. 무료 버전에서는 전체 코드가 생략되거나 모델 종류에 맞지 않는 라이브러리가 연결되고, 시작·중지나 모바일 화면과 오류 처리가 빠질 수도 있습니다. 생성된 코드는 완성품으로 간주하지 않고 반드시 실행하여 검증합니다.

#### 먼저 내가 요청해 보기 · 5분

아래의 구체적인 프롬프트를 보기 전에 우리 팀의 모델을 실행하는 웹페이지를 만들어 달라고 자신의 말로 요청합니다. 첫 결과에서 모델 종류와 주소, 시작·중지, 클래스별 확률, 오류 안내, 모바일 사용과 전체 코드 제공 여부를 확인합니다.

**간단한 요청**

> 티처블 머신 모델을 실행하는 예쁜 웹페이지를 만들어줘.

이 문장만으로는 생성형 AI가 모델 종류, 사용자, 입력과 출력, 권한 요청 시점, 오류 처리, 모바일 환경, 파일 형식과 검증 기준을 추측해야 합니다. 필요한 정보가 빠지면 사용자가 기대한 것과 다른 결과가 만들어질 수 있습니다.

### 경로 B · 모델 종류별 기본 파일 활용하기

생성된 코드가 작동하지 않거나 검증된 구조에서 시작하고 싶다면 모델 종류에 맞는 파일을 선택합니다. 파일을 내려받아 최종 이름을 `index.html`로 바꾼 뒤, 코드 위쪽의 **여기부터 우리 팀이 수정** 영역에서 모델 주소와 팀 정보만 수정합니다. 클래스 이름은 모델의 메타데이터에서 자동으로 불러옵니다.

| 파일 | 입력 | 사용 라이브러리 |
| --- | --- | --- |
| 이미지 분류용 | 웹캠 이미지 | Teachable Machine Image |
| 음성 분류용 | 마이크 소리 | Speech Commands 기반 Teachable Machine Audio |
| 포즈 분류용 | 웹캠 영상과 관절 위치 | Teachable Machine Pose |

> 자신이 만든 티처블 머신 모델 종류와 같은 파일을 선택하세요. 파일을 내려받은 뒤 표시된 설정값을 우리 팀의 내용으로 바꾸고 최종 파일 이름을 `index.html`로 저장합니다.

## 실행하고 검증하기

파일을 메모장으로 저장한다면 **파일 형식은 모든 파일**, **인코딩은 UTF-8**, 파일 이름은 정확히 `index.html`로 지정합니다. 컴퓨터에서 파일을 직접 열면 브라우저 보안 정책으로 카메라·마이크가 제한될 수 있으므로 최종 기능은 HTTPS가 적용되는 GitHub Pages에서 확인합니다.

- [ ] 우리 팀 모델이 정상적으로 불러와지는가?
- [ ] 모델의 실제 클래스 이름이 모두 표시되는가?
- [ ] 시작 버튼을 눌렀을 때 장치 권한 요청이 나타나는가?
- [ ] 시작과 중지가 정상적으로 작동하며 중복 실행되지 않는가?
- [ ] 새로운 테스트 데이터로 시험할 수 있는가?
- [ ] 클래스별 확률과 가장 높은 예측 결과가 표시되는가?
- [ ] 스마트폰에서도 글자·버튼·입력 화면이 잘 보이는가?
- [ ] 모델의 한계와 사람이 확인해야 할 부분이 표시되는가?
- [ ] 오류가 발생했을 때 사용자가 다음 행동을 알 수 있는가?

## GitHub로 웹페이지 배포하기

GitHub는 코드와 파일을 저장하고 변경 내용을 관리하며 공유할 수 있는 온라인 서비스입니다. 이번 활동에서는 GitHub Pages를 이용해 `index.html`을 인터넷에서 접속할 수 있는 웹사이트로 배포합니다.

| 용어 | 이번 활동에서의 의미 |
| --- | --- |
| GitHub | 웹페이지 파일을 저장하고 관리하는 서비스 |
| Repository | 우리 팀 파일을 모아 두는 온라인 프로젝트 공간 |
| Commit | 파일을 추가하거나 수정한 내용을 변경 기록으로 저장하는 것 |
| GitHub Pages | 저장소의 정적 웹 파일을 웹사이트로 공개하는 기능 |
| Deploy | 다른 사람이 인터넷 주소로 접속할 수 있게 공개하는 것 |

<Callout kind="caution" title="공개하기 전에 개인정보를 확인합니다">
학번·전화번호·집 주소·개인 이메일·비밀번호·API 키와 동의받지 않은 얼굴·음성을 공개하지 않습니다. 티처블 머신 학습 데이터와 화면에도 개인정보가 없는지 확인하고, 팀원 이름 공개는 수업의 제출 기준을 따릅니다.
</Callout>

<Steps>
<Step title="1. 로그인하고 새 저장소 만들기">GitHub에 로그인하고 오른쪽 위 **+ → New repository**를 선택합니다. 이름은 영문·숫자·하이픈으로 정하고 **Public**, **Add a README file**을 선택한 뒤 **Create repository**를 누릅니다.</Step>
<Step title="2. index.html 올리기">저장소에서 **Add file → Upload files**를 선택해 `index.html`을 올리고 **Commit changes**를 누릅니다. 파일은 폴더 안이 아니라 저장소 맨 위에 둡니다.</Step>
<Step title="3. Pages 켜기">저장소의 **Settings → Pages**에서 **Build and deployment → Source**를 **Deploy from a branch**로 정합니다.</Step>
<Step title="4. 공개 위치 정하기">Branch는 **main**, 폴더는 **/(root)**를 선택하고 **Save**를 누릅니다.</Step>
<Step title="5. 주소 확인하기">배포가 끝나면 Pages 화면의 **Visit site**를 누릅니다. 주소는 보통 `https://깃허브아이디.github.io/저장소이름/` 형식입니다.</Step>
<Step title="6. 실제 기기에서 재검증하기">스마트폰과 PC에서 접속해 카메라·마이크 권한을 허용하고 기능과 화면을 다시 확인합니다. 가능하면 다른 팀원의 기기에서도 시험합니다.</Step>
</Steps>

배포에는 몇 분이 걸릴 수 있습니다. 수정한 파일을 같은 주소에 반영하려면 기존 `index.html`을 교체하고 다시 Commit합니다.

| 문제 | 확인할 내용 |
| --- | --- |
| 화면이 나오지 않음 | 파일 이름이 소문자 `index.html`인지 확인 |
| 404 오류 | 파일이 `main` 브랜치의 저장소 맨 위에 있는지 확인 |
| 배포 주소가 없음 | Pages가 **Deploy from a branch**, **main / (root)**인지 확인 |
| 수정 내용이 보이지 않음 | Commit과 Actions의 배포 상태를 확인하고 잠시 후 새로고침 |
| 모델 로딩 실패 | 티처블 머신 공유 주소와 주소 끝의 `/` 확인 |
| 카메라·마이크 실행 실패 | HTTPS 주소인지, 브라우저 사이트 권한이 허용인지 확인 |
| 권한 요청이 다시 안 나옴 | 주소창의 사이트 설정에서 카메라·마이크 권한 변경 |
| 스마트폰 화면이 깨짐 | 화면 너비, 버튼 크기, 카메라 비율 확인 |
