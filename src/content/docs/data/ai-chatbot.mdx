**우리 웹앱 안에서 AI가 설명하거나 번역하는 기능을 넣고 싶은 팀을 위한 선택 도움말입니다.** 코딩할 때 AI의 도움을 받는 것과, 앱 사용자가 AI에게 질문할 수 있게 만드는 것은 별도의 작업입니다.

먼저 검색·표·그래프·지도 등 핵심 기능을 완성하고, 필요한 AI 기능 한 가지를 정합니다. 검색·거리·개수 계산은 코드로 처리하고, AI에는 찾은 자료를 쉽게 설명하는 일 등을 맡깁니다.

<Callout kind="mission" title="따라갈 순서">
**기능 정하기 → 시작 파일 준비 → GitHub에 저장 → Vercel 연결 → 서버에 키 등록 → 실제 답변 확인**

키를 등록하기 전에도 파일과 화면은 준비할 수 있습니다. 실제 API 사용 권한·비용·사용 한도와 키 등록은 선생님과 확인합니다.
</Callout>

## 1. 왜 서버와 API 키가 필요할까요?

**API 키는 ‘누구의 사용 권한으로 AI를 이용하는지’ 확인하는 열쇠입니다.** 다른 사람이 가져가 사용하면 우리 계정의 사용량이나 비용이 늘어날 수 있습니다. 화면에 보이지 않아도 HTML·JavaScript 안에 넣으면 앱 이용자가 찾아볼 수 있습니다.

그래서 **키를 보관하고 AI에 대신 물어봐 주는 프로그램**을 둡니다. 여기서 말하는 **서버**입니다.

1. **우리 앱**이 서버에 질문과 참고 자료를 보냅니다.
2. **서버**가 보관한 키로 AI에 요청하고 답을 받습니다.
3. **우리 앱**은 서버가 돌려준 답을 화면에 보여 줍니다. API 키는 브라우저로 보내지 않습니다.

**Vercel은 이 서버 프로그램을 인터넷에서 실행해 주는 서비스 중 하나입니다.** 이 안내에서는 준비된 시작 파일을 Vercel에 올려 사용합니다. 내 컴퓨터에 별도 서버 프로그램을 설치하고 계속 켜 두는 방식은 아닙니다.

GitHub는 파일을 보관하는 곳입니다. GitHub Pages는 정적 웹앱을 제공하지만, 이 예제의 AI 요청을 처리하는 서버 코드를 실행하지는 않습니다. **실제 AI 기능은 아래에서 만든 Vercel 웹앱 주소로 시험합니다.**

<details>
<summary>공공데이터 API도 꼭 서버가 필요한가요?</summary>

API마다 다릅니다. 브라우저에서 직접 읽는 방식을 허용하고 키의 이용 조건도 맞으면 바로 연결할 수 있습니다. 직접 읽기가 허용되지 않거나 비밀키를 서버에 보관해야 하면 서버가 대신 요청하는 방식을 검토합니다. 인증·조건값 오류는 요청부터 고쳐야 합니다. **이 챗봇 시작 파일은 AI 요청용이며, 공공데이터 API를 자동으로 연결해 주지는 않습니다.** [받은 응답을 앱에 연결하는 안내](/hyfl-ai-lab/data-project/#open-api-help)를 참고하세요.

</details>

## 2. 기능을 정하고 시작 파일 준비하기

예를 들어 **의류 기부 지도에서 확인한 수거 기준을 쉬운 말로 설명하기**처럼, 사용자에게 필요한 작은 기능 하나를 고릅니다. AI가 설명할 실제 자료와 출처도 준비합니다. 자료에 없는 조건은 만들어내지 않고 확인이 필요하다고 안내해야 합니다.

1. **[AI 챗봇 시작 파일 ZIP 내려받기](/hyfl-ai-lab/templates/ai-chatbot-starter.zip)**를 눌러 압축을 풉니다. 기존에 받은 팀은 현재 파일을 이어 사용합니다.
2. 기존 앱이 있으면 원본을 보관하고, **최신 앱 파일과 압축을 푼 시작 파일을 함께** 코딩에 사용하는 AI에 제공합니다. 저장소를 연결했다면 최신 파일을 읽게 합니다. [GitHub 연결·코드 수정 방법](/hyfl-ai-lab/data/github-ai/)
3. 아래 요청문으로 기존 화면·자료·기능을 유지하며 AI 질문창을 연결합니다. 앱이 없다면 시작 파일의 화면에서 출발할 수 있습니다.

<CopyPrompt title="우리 앱에 AI 기능 연결 준비하기" content={addChatbotPrompt} />

처음부터 서버 코드를 모두 작성할 필요는 없습니다. 시작 파일에는 다음 부분이 준비되어 있습니다.

| 파일 | 맡는 일 |
| --- | --- |
| `index.html` | 이용 코드·질문·참고 자료 입력과 답변 화면 |
| `api/chat.js`, `server/chat.js` | 이용 코드를 확인하고, 서버의 비밀키로 AI에 요청 |
| `package.json`, `vercel.json` | 실행·배포 설정 |
| `.gitignore` | 로컬 비밀 설정 파일 등을 Git에서 제외 |

**확인:** 화면 파일과 `api`·`server` 폴더가 있고, 기존 앱의 기능도 유지되어 있습니다. 키 설정 전의 연결 오류는 다음 설정을 마친 뒤 다시 확인합니다. 가상 답변으로 화면만 시험했다면 ‘예시 답변 · 실제 AI 연결 전’을 표시합니다.

## 3. GitHub에 저장하고 Vercel에 연결하기

1. 준비한 프로젝트를 **우리 팀 GitHub 저장소에 저장**합니다. `index.html`뿐 아니라 `api`·`server` 폴더와 설정 파일도 같은 구조로 올립니다. 기존 저장소를 사용하면 팀원의 최신 변경을 확인하고 반영합니다.
2. Vercel에서 **Add New → Project**를 열고 해당 GitHub 저장소를 선택합니다. 이미 연결된 프로젝트는 기존 설정을 사용합니다.
3. **Root Directory**는 앱의 `package.json`과 `index.html`이 있는 폴더입니다. 이 시작 파일을 저장소 맨 위에 올렸으면 기본값을 사용합니다.
4. 이 시작 파일의 **Framework Preset은 Other**입니다. 제공된 `vercel.json`은 Build Command·Install Command를 빈 값, Output Directory를 `.`으로 설정합니다. 기존 앱이 다른 구조라면 설정 파일을 덮어쓰지 말고 AI와 현재 프로젝트에 맞게 확인합니다.
5. 아래 4단계의 환경변수를 등록하고 **Deploy**합니다. 이미 배포했다면 값을 등록한 뒤 **Redeploy**합니다.

**확인:** 배포가 완료되어 Vercel의 HTTPS 웹앱 주소를 열 수 있습니다. GitHub의 코드 화면 주소와 구분해 적습니다. 기존 카카오 지도를 함께 사용한다면 새 웹앱 도메인도 지도 설정에 등록합니다.

## 4. 서버에 API 키 등록하기

**환경변수는 코드와 따로 등록해 두고 프로그램이 읽는 설정값**입니다. API 비밀키는 서버 설정에 등록하고 서버 코드만 읽게 합니다. 환경변수의 값을 다시 HTML·브라우저용 코드에 넣으면 키가 노출되므로 그렇게 바꾸지 않습니다.

팀명·원하는 AI 기능·앱 주소를 구글 클래스룸 수업 게시물에 남기고 선생님과 **API 사용 권한·모델·비용·사용 한도**를 확인합니다. 코딩에 쓰는 AI 계정 연결과 앱의 AI API 사용 설정은 별도입니다. 실제 키는 댓글·AI 대화·활동지에 붙여 넣지 않습니다.

**GPT를 연결하는 경우**, Vercel 프로젝트의 **Settings → Environment Variables**에 다음 이름과 값을 등록합니다. API 키와 이용 코드는 선생님과 정한 관리자가 해당 설정 화면에 직접 입력합니다.

| 이름 그대로 입력 | 넣을 값 |
| --- | --- |
| `AI_PROVIDER` | `openai` |
| `AI_MODEL` | 선생님이 사용 가능 여부를 확인한 실제 API 모델 ID |
| `OPENAI_API_KEY` | 해당 프로젝트에서 사용할 실제 API 비밀키 |
| `CHAT_ACCESS_CODE` | 선생님과 정한 앱 이용 코드: 무작위 영문·숫자·`_`·`-` 16~128자 |

표의 설명 문장을 값으로 입력하지 않습니다. **Production 배포에서 사용할 설정인지 확인하고 새로 배포**합니다. Preview 주소로 시험하려면 그 환경에도 설정해야 합니다.

**API 키와 앱 이용 코드는 다릅니다.** API 키는 서버가 AI 서비스에 요청할 때 사용합니다. 앱 이용 코드는 허용된 사용자가 질문 화면에 입력하는 코드입니다. 이용 코드를 HTML이나 공개 저장소에 미리 적어 두지 않습니다. 키를 숨긴 뒤에도 실제 사용량과 비용은 선생님과 확인합니다.

<details>
<summary>Claude를 연결하거나 추가 설정이 필요하다면</summary>

Claude는 `AI_PROVIDER`를 `anthropic`으로 설정하고 `OPENAI_API_KEY` 대신 `ANTHROPIC_API_KEY`를 사용합니다. 모델 ID와 나머지 설정은 선생님과 확인합니다. 워크스페이스 등 자세한 설정은 압축 파일 안의 `README.md`를 따릅니다. 서비스는 한 가지를 선택합니다.

</details>

**확인:** 필요한 값이 서버 설정에 등록되었고, 변경한 설정으로 새 배포가 완료되었습니다. 아직 키를 받지 못했다면 화면 구현과 원래 앱의 검증을 이어가고, 실제 AI 연결은 미완료로 기록합니다.

## 5. 실제 답변을 받고 막힌 곳 확인하기

1. **Vercel에 배포한 우리 웹앱 주소**를 엽니다. HTML을 더블클릭하거나 기존 GitHub Pages 주소에서 이 서버 함수를 시험하지 않습니다.
2. 질문 화면에 **앱 이용 코드**를 입력합니다. API 비밀키를 입력하는 칸이 아닙니다.
3. ‘함께 참고할 자료’에 공개 가능한 자료명·출처·기준일과 질문에 필요한 내용을 넣고, 그 자료로 답할 수 있는 질문을 보냅니다. 기존 앱에 연결했다면 선택한 자료가 실제로 함께 전달되는지 확인합니다.
4. 답변의 이름·수치·날짜·조건을 원자료와 대조합니다. 예시 답변을 사용했다면 실제 연결을 확인한 뒤 예시 표시를 바꿉니다.

| 화면의 안내·현상 | 다음에 확인할 것 |
| --- | --- |
| 서버의 AI 연결 설정 확인 | 네 가지 설정의 이름·값, 시험 중인 배포 환경과 새 배포 적용 여부 |
| 이용 코드를 확인해 주세요 | 입력한 코드와 서버의 `CHAT_ACCESS_CODE`가 같은지 |
| AI 서비스의 연결 권한·이용 한도 확인 | 선생님과 해당 API의 권한·모델·사용량 확인 |
| 서버 응답 확인·404·HTML 응답 | Vercel 앱 주소인지, `api`·`server` 폴더가 함께 배포됐는지 |

막혔다면 **앱 주소·누른 순서·실제 오류 문구**를 보여 주세요. 키와 이용 코드는 가립니다. 오류나 한도 안내가 나오면 반복 전송을 멈추고 원인을 확인합니다.

## 6. 자료와 비교하고 활동지에 기록하기

기존 활동지 STEP 3에서 **자료에 답이 있는 질문·자료에 답이 없는 질문·빈 입력·연결 실패**를 시험합니다. 답변이 근거와 맞는지, 모르는 내용을 지어내지 않는지, AI가 실패해도 원래 검색·지도·자료를 사용할 수 있는지 확인합니다. 이름·학번·연락처·상담 내용 같은 개인정보는 보내지 않습니다.

기록은 원래 활동지에 이어 적습니다. 구현한 것은 STEP 2, 시험한 결과는 STEP 3, AI의 제안에서 선택·수정한 부분은 STEP 4에 남깁니다. STEP 5에서는 각자 한 일과 배운 점을 돌아봅니다. **예시 화면만 확인했는지, 실제 AI 답변까지 확인했는지 구분**해 적습니다.

예시: “설명에 자료에 없는 조건이 들어갔다. 원문 링크를 함께 보여 주고, 근거가 없는 부분은 확인 필요로 표시하도록 고쳤다.” 우리 팀이 실제로 겪은 일과 판단을 자신의 말로 적어 보세요. 수업 일정·STEP 순서·제출물은 기존 프로젝트 안내를 따릅니다.
