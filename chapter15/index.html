이 챕터는 정보 교과의 버전 관리·웹 호스팅 지식과, 인공지능 교과의 모델 배포·데이터 수집 관점을 결합합니다. 지금까지 내 컴퓨터에서만 돌던 AI 웹앱을, 전 세계 누구나 접속할 수 있는 실제 웹 주소로 내보내는 것이 오늘의 목표입니다.

🤔 생각 열기

섹션 제목: “🤔 생각 열기”

여러분이 열심히 만든 Teachable Machine 웹앱이 있습니다. 그런데 이 앱은 지금 여러분의 노트북 안에서만 작동합니다. 친구에게 보여주려면 노트북을 들고 다녀야 하고, 전원을 끄면 사라집니다.

유튜브 영상은 왜 내 컴퓨터를 끄고 자도 다른 사람이 볼 수 있을까요? 카카오톡 프로필 사진은 어디에 저장되어 있길래 친구 폰에서도 보일까요?

정답은 누군가의 컴퓨터가 24시간 켜져 있기 때문입니다. 그 컴퓨터를 서버(server)라고 부릅니다. 오늘은 여러분의 AI 웹앱을 GitHub의 서버에 올려서, 링크 하나만 보내면 세계 어디서든 열리는 진짜 웹앱으로 만들어 봅니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • GitHub 저장소를 만들고 웹앱 코드를 업로드할 수 있다. [정보]
  • GitHub Pages로 AI 웹앱을 인터넷에 배포하고 URL을 공유할 수 있다. [정보]
  • 배포된 앱으로 실사용 데이터를 모으는 것이 왜 AI 개선에 중요한지 설명할 수 있다. [인공지능]

📌 선수학습 확인

섹션 제목: “📌 선수학습 확인”
  • 14차시에서 Teachable Machine 모델을 학습시키고, 이를 불러오는 웹앱(HTML 파일)을 완성했습니다.
  • 웹앱은 HTML·CSS·JavaScript 파일과, Teachable Machine이 내보낸 모델 파일 URL로 구성됩니다.
  • 지금까지는 이 파일들을 로컬(내 컴퓨터)에서만 실행했습니다. [정보]

🔍 탐구 활동

섹션 제목: “🔍 탐구 활동”

탐구: “로컬”과 “배포”는 무엇이 다를까?

섹션 제목: “탐구: “로컬”과 “배포”는 무엇이 다를까?”
  • 준비물: 완성된 웹앱 HTML 파일, 스마트폰, 짝꿍
  • 과정:
    1. 내 컴퓨터에서 웹앱 HTML 파일을 더블클릭해 엽니다. 주소창의 주소를 확인합니다. (file:///...로 시작)
    2. 이 상태에서 짝꿍의 스마트폰으로 그 주소를 열어 봅니다.
    3. 열리는지, 안 열리는지 기록합니다.
  • 결과 예측: “짝꿍 폰에서 내 앱이 열릴까요, 안 열릴까요?”
  • 토의: “왜 file:///로 시작하는 주소는 나만 볼 수 있을까요? 세상 사람 모두가 볼 수 있는 주소는 무엇으로 시작할까요?”

탐구 정리: file:/// 주소는 “내 컴퓨터 안의 경로”라서 남에게 열리지 않습니다. 반면 https://로 시작하는 주소는 인터넷 서버를 가리키므로 누구나 접속할 수 있습니다. 오늘 우리가 할 일은 바로 이 https:// 주소를 만드는 것입니다.

💡 핵심 개념

섹션 제목: “💡 핵심 개념”

개념 1: 버전 관리와 GitHub [정보]

섹션 제목: “개념 1: 버전 관리와 GitHub [정보]”
  • 정의: 버전 관리(version control)란 파일의 변경 이력을 시간 순으로 기록·저장하는 기술입니다. GitHub는 이 기록을 인터넷 서버에 보관해 주는 웹 서비스입니다.
  • 비유: GitHub는 마치 게임의 세이브 파일 클라우드와 같습니다. 언제든 이전 상태로 돌아갈 수 있고, 파일이 인터넷에 안전하게 보관됩니다.

GitHub에 코드를 올려두면 두 가지 이득이 있습니다. 첫째, 실수로 파일을 지워도 복구할 수 있습니다. 둘째, 그 코드를 웹사이트로 즉시 배포할 수 있습니다. 두 번째가 오늘의 핵심입니다.

flowchart LR
  A["내 컴퓨터<br/>(로컬 파일)"] -->|업로드| B["GitHub 저장소<br/>(Repository)"]
  B -->|Pages 설정| C["웹 주소<br/>https://..."]
  C -->|링크 공유| D["누구나 접속"]

내 파일이 GitHub 저장소를 거쳐 공개 웹 주소가 되는 흐름입니다.

개념 2: 배포와 실사용 데이터 [인공지능]

섹션 제목: “개념 2: 배포와 실사용 데이터 [인공지능]”
  • 정의: 배포(deployment)란 완성한 프로그램을 실제 사용자가 쓸 수 있는 환경에 올리는 것입니다.
  • 비유: 배포는 요리를 다 만든 뒤 식당 문을 여는 순간입니다. 손님(사용자)이 들어와야 비로소 “이 메뉴가 맛있는지”에 대한 진짜 반응을 얻습니다.

AI 관점에서 배포는 특별한 의미가 있습니다. 내 컴퓨터에서만 테스트하면 내가 준비한 데이터로만 확인됩니다. 하지만 배포해서 여러 사람이 쓰면, 내가 예상 못 한 다양한 입력(다른 조명, 다른 각도, 다른 물건)이 들어옵니다. 이렇게 모인 실사용 데이터가 모델의 약점을 드러내고, 다음 개선의 재료가 됩니다.

관점배포를 보는 시각핵심 질문
정보 [정보]코드를 서버에 올려 접속 가능하게 만드는 기술 작업”어떻게 안정적으로 서비스할까?”
인공지능 [인공지능]실사용 데이터를 모으는 학습의 시작점”실제 사용자는 어떤 입력을 넣을까?”

🌉 교과 간 연결 다리

섹션 제목: “🌉 교과 간 연결 다리”

배포는 정보와 인공지능이 만나는 지점입니다.

  • 정보의 도구: GitHub 저장소 + Pages 호스팅 → https:// 웹 주소 생성
  • 인공지능의 목표: 그 웹 주소로 실사용자를 초대 → 모델이 실제로 마주할 데이터 확인

즉, 정보 교과의 배포 기술이 없으면 인공지능 교과의 데이터 수집을 시작할 수 없습니다. 코드를 올리는 행위 하나가, “이 AI가 세상에서 잘 작동할까?”라는 질문에 답할 기회를 엽니다.

🔀 가로지르는 질문

섹션 제목: “🔀 가로지르는 질문”

“내 AI 웹앱을 100명이 사용했더니 정확도가 떨어졌다는 피드백이 왔습니다. 이것은 ‘기술(배포) 문제’일까요, ‘모델(학습 데이터) 문제’일까요?”

이 질문에 답하려면 두 교과의 도구가 모두 필요합니다. [정보] 배포 환경(모바일에서 카메라 권한, 로딩 속도)을 점검하고, [인공지능] 학습 데이터가 실사용 상황을 충분히 대표했는지 검토해야 합니다. 여러분은 어느 쪽부터 확인하겠습니까?

🛠️ 따라하기: GitHub Pages로 웹앱 배포하기 (5단계)

섹션 제목: “🛠️ 따라하기: GitHub Pages로 웹앱 배포하기 (5단계)”

아래 5단계를 그대로 따라 하면 여러분의 AI 웹앱이 세계 어디서든 열리는 주소를 갖게 됩니다.

1단계 — GitHub 계정 만들기 github.com에 접속해 회원가입합니다. 이메일 인증까지 마칩니다. (이미 계정이 있으면 로그인)

2단계 — 새 저장소(Repository) 만들기 우측 상단 + → New repository 클릭. 저장소 이름을 my-ai-webapp처럼 정합니다. Public을 선택하고, Add a README file에 체크한 뒤 Create repository를 누릅니다.

3단계 — 웹앱 파일 업로드하기 저장소 화면에서 Add file → Upload files 클릭. 14차시에 만든 웹앱 파일(HTML 파일 등)을 드래그해서 올립니다. 이때 시작 파일 이름은 반드시 index.html이어야 합니다. 아래 Commit changes 버튼을 눌러 저장합니다.

4단계 — GitHub Pages 켜기 저장소 상단 Settings → 왼쪽 메뉴 Pages 클릭. Branch 항목에서 main을 선택하고 Save를 누릅니다. 잠시(1분에서 2분) 기다립니다.

5단계 — 배포 주소 확인 및 공유 Pages 화면 위쪽에 Your site is live at https://사용자이름.github.io/my-ai-webapp/ 형태의 주소가 나타납니다. 이 주소를 스마트폰으로 열어 카메라 권한을 허용하고, AI가 작동하는지 확인합니다. 짝꿍에게도 링크를 보냅니다.

flowchart TD
  A[1. 계정 만들기] --> B[2. 저장소 생성]
  B --> C["3. index.html 업로드"]
  C --> D[4. Pages 설정]
  D --> E["5. https 주소 확인·공유"]

배포 5단계 전체 흐름입니다.

⚠️ 자주 나오는 오류와 해결

섹션 제목: “⚠️ 자주 나오는 오류와 해결”

📖 읽을거리

섹션 제목: “📖 읽을거리”

“세상에 내놓아야 진짜가 된다”

2007년, 넷플릭스는 자사 추천 AI의 정확도를 10% 높이는 팀에게 100만 달러를 걸었습니다. 전 세계 개발자들이 도전했고, 우승팀의 알고리즘은 실험실에서 훌륭했습니다. 그런데 넷플릭스는 결국 그 알고리즘을 실제 서비스에 적용하지 않았습니다. 실사용 환경에서는 계산 비용이 너무 컸고, 사용자 취향도 빠르게 변했기 때문입니다.

이 사건은 AI 개발자들에게 큰 교훈을 남겼습니다. 실험실 성능과 실사용 성능은 다르다. 여러분이 오늘 배포한 앱도 마찬가지입니다. 내 컴퓨터에서 100% 맞히던 모델이, 친구 폰의 어두운 조명에서는 틀릴 수 있습니다. 그래서 배포하고, 실사용 데이터를 모으고, 개선하는 순환이 AI 개발의 진짜 모습입니다.

심화 (사고력·서술형)

섹션 제목: “심화 (사고력·서술형)”
  1. 어떤 학생이 “내 컴퓨터에서는 AI가 완벽하게 맞혔으니 배포만 하면 끝”이라고 말합니다. 이 주장의 문제점을 인공지능 관점(실사용 데이터)과 연결해 3문장 이상으로 반박해 보세요.
정답 확인

  1. index.html

  2. ② https:// (인터넷 서버를 가리키는 주소)

  3. 파일 이름이 index.html인지 확인해야 합니다. GitHub Pages는 시작 파일로 index.html을 찾는데, 이름이 다르면 페이지를 찾지 못해 404 오류가 발생하기 때문입니다.

  4. (예시 답안) 내 컴퓨터에서 완벽했던 것은 내가 준비한 제한된 데이터로만 테스트했기 때문입니다. 실제 사용자는 다른 조명, 다른 각도, 예상 못 한 물건 등 훨씬 다양한 입력을 넣기 때문에 정확도가 떨어질 수 있습니다. 따라서 배포는 끝이 아니라 실사용 데이터를 모아 모델의 약점을 찾고 개선하는 순환의 시작입니다.
