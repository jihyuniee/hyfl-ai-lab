## 시작 전에 세 번 묻기

1. **누구의 어떤 문제인가?** 실제로 불편을 겪는 사람이 있는가?
2. **사진으로 판단할 수 있는가?** 냄새·마음·맥락처럼 이미지에 보이지 않는 정보가 필요한 문제는 아닌가?
3. **AI가 필요한가?** 간단한 표지판이나 규칙이 더 안전하고 쉬운 해결책은 아닌가?

가능한 예: 분리배출 상태, 칠판 정리 상태, 창문 개폐 상태, 준비물 종류. 사람의 능력·성격·감정·위험도를 사진만으로 판단하는 주제는 선택하지 않습니다.

<Steps>
<Step title="문제와 사용자 정하기">문제가 발생하는 장면과 도움을 받을 사람을 한 문장으로 씁니다.</Step>
<Step title="클래스 기준 합의하기">팀원 누구나 같은 사진에 비슷한 정답을 붙일 수 있도록 기준을 정합니다.</Step>
<Step title="데이터 계획 세우기">사람·배경·거리·각도·조명·물체 상태를 어떻게 다양하게 담을지 계획합니다.</Step>
<Step title="첫 모델과 기준 테스트">학습 자료와 분리한 공통 테스트 묶음을 정하고 첫 결과를 기록합니다.</Step>
<Step title="실패 지도 만들기">어떤 조건에서 누구에게 더 자주 틀리는지 모읍니다. 배경 같은 엉뚱한 단서를 학습했는지 확인합니다.</Step>
<Step title="한 가지 개선하기">실패 원인 가설에 맞는 데이터를 추가·수정하고 다시 학습합니다.</Step>
<Step title="같은 조건으로 재검증">개선 전후를 같은 테스트 묶음으로 비교합니다.</Step>
<Step title="실제 사용 여부 판단하기">오분류 피해, 개인정보, 편향, 사람의 확인 절차를 고려해 사용 범위를 정합니다.</Step>
</Steps>

## 반드시 남길 증거

| 증거 | 확인할 내용 |
| --- | --- |
| 문제 정의 | 사용자·상황·불편이 구체적인가 |
| 데이터 계획 | 양·다양성·정확성·대표성을 고려했는가 |
| 실패 사례 | 조건과 예측 결과가 기록되었는가 |
| 개선 근거 | 무엇을 왜 바꾸었는가 |
| 비교 결과 | 같은 테스트로 전후를 비교했는가 |
| 최종 판단 | AI의 역할·사람의 역할·사용 한계를 설명했는가 |

<Callout kind="caution" title="이미지 수집 원칙">친구의 얼굴이나 개인 물품을 촬영할 때는 동의를 받습니다. 불필요한 얼굴·이름·학번은 담지 않고, 수업 목적이 끝난 데이터의 보관 여부도 팀이 정합니다.</Callout>

<Callout kind="concept" title="프로젝트의 핵심">모델이 틀렸다는 사실보다 **왜 틀렸다고 생각했고, 어떤 데이터를 바꾸었으며, 다시 어떻게 확인했는지**가 더 중요합니다.</Callout>
