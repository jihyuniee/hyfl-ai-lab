Part 3 · Project 1. Teachable Machine AI 웹앱 프로젝트 (11/37차시)

🧭 이 챕터의 교과 결합

섹션 제목: “🧭 이 챕터의 교과 결합”
mindmap

이 챕터는 정보 교과의 “문제 해결 절차·산출물 설계”와 인공지능 교과의 “분류 문제와 학습 데이터” 개념을 결합합니다. 정보가 *“무엇을 만들 것인가”*를 정의하면, 인공지능이 *“그것을 학습시키려면 어떤 데이터가 필요한가”*를 설계합니다.

🌱 생각 열기

섹션 제목: “🌱 생각 열기”

여러분의 스마트폰 사진첩을 떠올려 봅시다. 갤러리 앱은 사진을 자동으로 “인물”, “음식”, “풍경”으로 분류해 줍니다. 누가 이 사진이 음식인지 하나하나 손으로 알려 줬을까요?

아닙니다. 수많은 음식 사진을 미리 보여 주고 “이것이 음식이다”라고 학습시킨 것입니다.

“그렇다면 여러분이 직접 AI에게 무언가를 구별하도록 가르친다면, 무엇을 가르치고 싶나요? 그리고 그걸 가르치려면 무엇을 준비해야 할까요?”

오늘부터 우리는 Teachable Machine으로 나만의 분류 AI를 만드는 프로젝트를 시작합니다. 그 첫걸음은 좋은 문제를 정의하는 것과 가르칠 데이터를 설계하는 것입니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 팀별로 머신러닝으로 해결할 문제를 정의할 수 있다.
  • 문제 해결에 필요한 데이터를 설계하고 수집할 수 있다.

🔁 선수학습 확인

섹션 제목: “🔁 선수학습 확인”

앞선 차시에서 우리는 다음을 배웠습니다.

  • 지도학습: 정답(레이블)이 붙은 데이터로 AI를 학습시키는 방식 [인공지능]
  • 분류(Classification): 입력을 미리 정한 몇 개의 그룹(클래스) 중 하나로 나누는 문제 [인공지능]
  • Teachable Machine: 코딩 없이 이미지·음성·자세를 학습시켜 분류 모델을 만드는 웹 도구 [정보]

핵심만 다시 정리하면, 분류 AI는 “클래스별로 예시 데이터를 모아 보여 주면, 새로운 입력이 어느 클래스인지 맞히는 기계”입니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: “잘 배우는 AI vs 헷갈리는 AI” — 데이터가 결과를 바꾼다

섹션 제목: “탐구: “잘 배우는 AI vs 헷갈리는 AI” — 데이터가 결과를 바꾼다”

  • 준비물: 팀별 노트북 1대, 웹 브라우저, Teachable Machine 접속(별도 설치 불필요), 필기구

  • 과정

    1. 팀에서 서로 다른 두 물건을 정합니다. (예: 볼펜, 지우개)
    2. 실험 A: 각 물건을 웹캠 앞 같은 위치·같은 배경에서 15장씩 찍어 두 클래스로 학습시킵니다.
    3. 실험 B: 같은 물건을 배경·각도·조명을 매번 바꿔 가며 15장씩 찍어 학습시킵니다.
    4. 두 모델에 각각 처음 보는 각도로 물건을 비춰 정확도를 비교합니다.
    5. 결과를 아래 표에 기록합니다.
구분실험 A (똑같은 조건)실험 B (다양한 조건)
새 각도 인식 성공?
예측 확률(%)
헷갈린 경우

  • 결과 예측: “어떤 모델이 처음 보는 각도를 더 잘 맞힐까요?”

  • 토의

    • “실험 B가 더 잘 맞혔다면, 왜 그럴까요?” [인공지능]
    • “만약 이 AI를 우리 반 전체가 쓴다면, 실험 A 방식의 데이터로 충분할까요?” [정보]

이 탐구에서 확인한 것처럼, AI의 성능은 코드가 아니라 데이터의 질과 다양성이 결정합니다. 이것이 오늘 배울 두 핵심 개념의 출발점입니다.

💡 핵심 개념

섹션 제목: “💡 핵심 개념”

개념 1. 머신러닝 문제 정의 [정보] [인공지능]

섹션 제목: “개념 1. 머신러닝 문제 정의 [정보] [인공지능]”
  • 정의: 머신러닝으로 해결할 문제를 정의한다는 것은, *“어떤 입력을 받아 어떤 클래스로 나눌 것인가”*를 명확히 정하는 일입니다.
  • 비유: 문제 정의는 마치 여행의 목적지를 정하는 것과 같습니다. 목적지가 흐릿하면 어떤 길로 갈지, 무엇을 챙길지 정할 수 없습니다.

좋은 분류 문제는 세 가지 조건을 갖춥니다.

조건설명나쁜 예 → 좋은 예
분류 가능성사람이 눈·귀로 구별 가능해야 함”행복한 사진 분류” → “웃는 얼굴/무표정 분류”
명확한 클래스클래스가 겹치지 않고 뚜렷함”동물/귀여운 동물” → “고양이/강아지”
데이터 수집 가능성예시를 실제로 모을 수 있음”우주 생명체 분류” → “재활용/일반 쓰레기 분류”

[그림 11-1] 설명: 문제 정의에서 산출물까지의 흐름을 나타내는 순서도.

flowchart LR
  A["관심 주제<br/>선정"] --> B["분류 목표<br/>결정"]
  B --> C["클래스<br/>정의"]
  C --> D["필요 데이터<br/>파악"]
  D --> E["웹앱 산출물<br/>목표 설정"]

개념 2. 학습 데이터 설계와 수집 [인공지능] [정보]

섹션 제목: “개념 2. 학습 데이터 설계와 수집 [인공지능] [정보]”
  • 정의: 학습 데이터 설계란, 각 클래스마다 어떤 데이터를, 얼마나, 어떤 다양성으로 모을지 계획하는 일입니다.
  • 비유: 데이터 설계는 마치 시험 공부를 위한 문제집 고르기와 같습니다. 한 유형만 반복 풀면 실전에서 처음 보는 문제에 무너집니다. 다양한 유형을 풀어야 진짜 실력이 됩니다.

좋은 데이터가 갖춰야 할 세 가지를 기억합시다.

원칙의미탐구와의 연결
충분한 양클래스당 최소 수십 장 이상많을수록 안정적
다양성각도·배경·조명·개체 변화 포함실험 B가 강했던 이유
균형클래스별 데이터 수가 비슷한쪽만 많으면 편향 발생

특히 데이터 편향(bias)을 조심해야 합니다. 예를 들어 “마스크 착용 여부”를 분류하는데 착용 사진만 밝은 곳에서, 미착용 사진만 어두운 곳에서 찍었다면, AI는 마스크가 아니라 밝기를 학습해 버립니다. [인공지능]

🌉 교과 간 연결: “좋은 문제 = 좋은 데이터”

섹션 제목: “🌉 교과 간 연결: “좋은 문제 = 좋은 데이터””

정보 교과의 문제 정의와 인공지능 교과의 데이터 설계는 사실 하나의 고리입니다.

  • 문제에서 정한 클래스가 곧 데이터 수집의 폴더 이름이 됩니다. [정보]→[인공지능]
  • 데이터를 모으다 보면 “이 두 클래스는 구별이 안 되네”라며 문제 정의를 수정하게 됩니다. [인공지능]→[정보]

즉, 문제 정의와 데이터 수집은 순서대로 한 번 끝나는 게 아니라 서로를 다듬는 왕복 과정입니다.

다교과 관점 비교

섹션 제목: “다교과 관점 비교”

가로지르는 질문

섹션 제목: “가로지르는 질문”

“우리 팀 AI가 ‘공정하다’는 것은 무엇으로 판단해야 할까?”

이 질문은 정보(문제 설계)만으로도, 인공지능(정확도)만으로도 답할 수 없습니다. 팀별로 어떤 교과의 도구를 동원할지 직접 선택해 답을 만들어 보세요.

🛠️ 프로젝트 시작하기 (팀 활동)

📖 읽을거리

섹션 제목: “📖 읽을거리”

2018년, MIT 연구자 조이 부올람위니는 얼굴 인식 AI가 밝은 피부의 남성은 99% 정확히 인식하면서 어두운 피부의 여성은 35%까지 오류를 내는 것을 발견했습니다. 원인은 알고리즘이 아니라 학습 데이터였습니다. 학습에 쓰인 얼굴 사진 대부분이 백인 남성이었던 것입니다.

이 발견은 전 세계 기업이 데이터 다양성을 다시 점검하게 만든 계기가 되었습니다. 여러분이 오늘 겨우 15장의 사진을 다양하게 찍는 연습을 하는 이유가 바로 여기에 있습니다.

✅ 확인 문제

섹션 제목: “✅ 확인 문제”

기본 (개념 확인)

섹션 제목: “기본 (개념 확인)”
  1. 좋은 분류 문제가 갖춰야 할 세 조건을 쓰시오.
  2. “마스크 착용 사진은 밝은 곳에서만, 미착용 사진은 어두운 곳에서만 찍었다.” 이 데이터의 문제는 무엇인가?

응용 (적용)

섹션 제목: “응용 (적용)”
  1. 다음 중 Teachable Machine으로 실현하기 어려운 문제를 고르고 이유를 쓰시오.
    • (가) 사과와 오렌지 사진 분류
    • (나) 손 씻는 자세와 안 씻는 자세 분류
    • (다) 어제 꾼 꿈이 좋은 꿈인지 분류

심화 (사고력·서술형)

섹션 제목: “심화 (사고력·서술형)”
  1. 우리 학교 급식 잔반을 줄이기 위해 “먹을 수 있는 음식 / 남긴 음식”을 분류하는 AI를 만들려고 합니다. 이때 발생할 수 있는 데이터 편향을 하나 예상하고, 이를 줄이기 위한 데이터 수집 계획을 3줄 이내로 서술하시오.
정답 확인

  1. 분류 가능성(사람이 구별 가능), 명확한 클래스(겹치지 않음), 데이터 수집 가능성(예시를 실제로 모을 수 있음).

  2. AI가 마스크 여부가 아니라 사진의 밝기(조명)를 학습하게 되는 데이터 편향이 발생한다. 조명 조건을 두 클래스 모두 다양하게 섞어야 한다.

  3. (다). 꿈은 눈이나 귀로 관찰·수집할 수 있는 데이터가 아니어서 학습 예시를 모을 수 없다. (데이터 수집 가능성 조건 위배)

  4. (예시) 특정 메뉴(예: 국물 요리)만 남긴 사진이 많으면 AI가 메뉴 자체로 판단할 수 있다. → 여러 메뉴, 여러 식판, 여러 조명에서 ‘남긴 음식’과 ‘먹은 음식’을 골고루 촬영하고 클래스별 장수를 비슷하게 맞춘다.
