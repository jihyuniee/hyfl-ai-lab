## 수업 철학

```text
미션을 만난다 → 먼저 해본다 → 결과와 실패를 비교한다
→ 필요한 개념과 AI 활용법을 그 순간 익힌다
→ 다시 시도한다 → 판단과 근거를 기록한다
```

생성형 AI 활용법을 별도 공식으로 길게 가르치지 않습니다. MCP 공공데이터 탐색, 조회 조건 확인, 원 통계 교차 검증, 필요한 경우의 파일 분석, 그래프, 해석, 서비스 기획의 각 순간에 왜 맥락·조건·결과 형식·검증 요청이 필요한지 경험하게 합니다.

김현철 교수의 인간 중심 관점을 수업 전체에 적용합니다. AI는 빠른 계산·패턴 인식·생성을 돕는 엔진이지만, 질문과 목적 설정, 맥락 이해, 직관적 통찰, 가치 판단, 최종 책임은 학생에게 남깁니다. 목표는 AI를 능숙하게 조작하는 학생보다 **AI와 함께 질문하고 검증하고 판단할 수 있는 학생**입니다.

## School Image Lab 이후의 AI 학습 원칙

Chris Piech 교수의 인터뷰 영상은 학생에게 직접 제시하는 필수 영상이 아니라, 후속 단원을 설계하는 교사용 참고 자료로 활용합니다.

- 참고 영상: [AI 시대에도 프로그래밍과 기초를 배워야 하는 이유](https://youtu.be/_qYUwrJ_XHo)
- AI가 문법·코드·분석을 대신할 수 있어도 문제를 이해하고 분해하는 기초는 건너뛰지 않습니다.
- AI를 제공하는 것만으로 학습 동기와 사고력이 자동으로 높아진다고 가정하지 않습니다.
- 먼저 학생의 생각과 예측을 기록하고 AI의 결과와 비교하게 합니다.
- AI가 만든 결과를 제출하는 데서 멈추지 않고 구조·처리·오류 지점을 학생이 설명하게 합니다.
- 결과물의 완성도뿐 아니라 **AI와 함께 작업하며 학생의 이해와 독립적인 문제 해결 능력이 성장했는지** 확인합니다.
- 교사는 정답을 대신 주는 역할만이 아니라 학생의 호기심을 자극하고, 어려운 지점에서 다시 시도하도록 돕는 사람의 역할을 맡습니다.

학생에게는 영상의 주장이나 인물을 반복해 설명하기보다 다음 네 문장으로 일관되게 안내합니다.

> 내 생각을 먼저 세운다.  
> 큰 문제를 작은 문제로 나눈다.  
> AI가 한 일을 설명하고 검증한다.  
> 결과물과 함께 나도 성장한다.

## 학생 수요 반영

2학년 5개 반 113명의 응답에서 생성형 AI를 적어도 주 1회 사용하는 학생은 100명입니다. 배우고 싶은 내용은 생성형 AI를 제대로 활용하는 방법 72명, 웹앱 만들기 53명, AI와 함께 코딩하기 48명, 나만의 AI 서비스 만들기 45명, 데이터 분석·시각화 30명 순이었습니다.

데이터 분석을 독립 이론으로 내세우기보다 학생이 원하는 서비스 기획을 위한 **문제 탐정 도구**로 사용합니다. 실제 구현은 선택으로 두고, 데이터 근거와 서비스의 필요성을 설명하는 기획 과정을 필수로 둡니다.

## 최종 프로젝트 운영

3인 내외 팀은 **같은 관심 분야 + 다른 강점**을 원칙으로 구성합니다. 학생 설문의 역할 응답은 데이터 탐색·근거, 분석·검증, 서비스 기획·표현 역할을 배치하는 보조 자료로 활용하되 중요한 판단은 공동으로 하게 합니다.

```text
문제 가설 → 파일·API·MCP로 공공데이터 탐색 → 질문에 맞는 시각화 → 핵심 근거 검증 → 인사이트
→ 문제 재정의 → AI 필요성 → 서비스 시나리오
→ 위험·책임 → 피드백·수정 → 발표
```

공공데이터 분석은 문제를 확인하는 필수 근거입니다. 데이터 과학의 분석 기법을 폭넓게 다루기보다, 데이터의 출처와 구조를 이해하고 질문에 맞는 기초 시각화로 사실·해석·원인 가설·한계를 구분하는 데 초점을 둡니다. 파일·API·MCP 중 목적에 맞는 방법으로 관련 데이터를 탐색하고, 최종 주장에 사용하는 핵심 수치는 원 통계표에서 교차 확인합니다. 여러 파일의 결합·전처리·새 변수 계산·재현이 필요한 팀만 CSV·XLSX 원파일 분석을 수행합니다. 설문·인터뷰·관찰·보고서는 보충할 수 있습니다. 분석 결과가 예상과 다르면 문제 정의와 서비스 방향을 수정하게 합니다. 공공데이터가 문제 확인에 쓰였다고 해서 실제 서비스의 AI를 곧바로 학습시킬 수 있는 것은 아니라는 점을 구분합니다.

## 평가 관점

| 평가 요소 | 무엇을 보는가 |
| --- | --- |
| 질문과 문제 변화 | 현재 상태와 목표 상태를 구분하고, 큰 문제를 확인 가능한 작은 문제로 나누어 분석 후 수정했는가 |
| 데이터 출처와 품질 | MCP 도구·기관·통계표·항목·기간·지역·단위·수집 맥락을 확인했는가 |
| 분석과 검증 | 질문 조건과 그래프 선택 이유가 남아 있고 핵심 수치를 공식 통계에서 교차 확인했는가 |
| 인사이트 | 사실·해석·원인 가설·한계를 구분했는가 |
| 서비스 연결 | 분석 결과가 사용자 문제와 기능의 필요성으로 이어지는가 |
| AI와 인간의 역할 | AI 필요성, 사람의 확인·이의 제기·책임을 설계했는가 |
| AI 협업 | 자신의 생각을 먼저 세우고 AI의 결과를 검증·수정하며 핵심 과정을 설명할 수 있는가 |
| 학습 성장 | AI 활용 후 학생이 새롭게 이해하거나 스스로 할 수 있게 된 것이 근거로 드러나는가 |
| 피드백과 기여 | 피드백 전후 변화와 팀원별 기여가 드러나는가 |

## 교사의 핵심 발문

- AI는 어떤 MCP 도구와 통계표를 선택했나요?
- 대상·기간·지역·항목·단위가 질문과 맞나요?
- 이 분석에 원파일이 필요한가요? 필요하다면 왜 필요한가요?
- 그래프에서 직접 확인한 사실은 무엇인가요?
- 그것은 해석인가요, 원인인가요, 데이터에서 확인한 사실인가요?
- 상관계수와 산점도가 함께 보여주는 것은 무엇인가요?
- 처음 생각한 문제는 분석 후 어떻게 달라졌나요?
- 이 공공데이터는 문제를 확인하는 데 쓰였나요, 실제 서비스에도 쓰이나요?
- AI가 아니라 규칙·검색·사람의 안내가 더 나은 기능은 무엇인가요?
- AI가 틀렸을 때 누가 확인하고 누가 책임지나요?
- AI가 한 일과 팀이 판단한 일은 무엇인가요?
- 현재 상태와 목표 상태의 차이를 어떤 작은 문제로 나누었나요?
- AI에게 요청하기 전에 여러분이 먼저 세운 생각은 무엇인가요?
- AI가 만든 코드·분석·기능을 팀의 말로 설명할 수 있나요?
- AI를 사용한 뒤 여러분이 새롭게 이해하거나 스스로 할 수 있게 된 것은 무엇인가요?

## 바이브 코딩 운영 원칙

당곡고 데이터 과학 수업의 `샘플 프롬프트 → AI 코드 실행·결과 읽기 → 프롬프트 개선` 반복 구조를 참고하되, 우리 수업에서는 다음과 같이 운영합니다.

```text
자신의 말로 요청 → AI 코드 실행 → 화면·동작·오류 관찰
→ 문제와 관련된 핵심 코드 이해 → 프롬프트·코드 수정 → 같은 조건에서 재검증
```

처음부터 모든 문법을 해석하게 하지는 않지만, 결과 화면만 보고 끝내지도 않습니다. 학생은 입력·처리·출력을 연결하는 핵심 부분, 직접 바꾼 코드, 대표 오류와 해결 과정을 설명합니다. AI가 작성한 코드라도 실행·수정·공개한 사람에게 검증과 책임이 있음을 강조합니다.

## 참고 자료 반영 원칙

- Chris Piech 인터뷰: AI 시대에도 기초 개념과 문제 해결을 배워야 한다는 관점, AI에 사고를 모두 맡기지 않는 자기 인식, 문제 분해, AI가 만든 결과에서 다시 배우는 방법, 인간 교사의 동기와 호기심 지원 역할을 반영했습니다. 영상은 교사용 참고 자료로만 사용합니다.
- 김현철 교수 자료: AI 작동 단계마다 인간의 맥락 인식·통찰·가치 판단이 필요하다는 관점, AI는 엔진이고 인간은 운전자라는 비유, 주체성·적응성·호기심·창의·문제 해결·통찰·통합·맥락의 휴먼스킬을 수업 철학에 반영했습니다.
- 제7회·제8회 공공데이터 대회 자료: 안전·교통·환경·건강·진로·학교문화 등 학생이 탐구할 수 있는 **주제의 폭을 설계하는 교사용 참고 자료**로만 활용합니다. 학생에게 수상작을 읽거나 그 수준을 따라 하도록 요구하지 않습니다.
- 1학기 학생 작품: 문제와 데이터가 서비스 아이디어로 이어지는 여러 방향을 보여주는 선배 사례로 선택적으로 소개할 수 있습니다. 분석량·발표 디자인·구현 수준은 2학기 학생의 필수 기준으로 삼지 않습니다.
