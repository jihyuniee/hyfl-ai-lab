7. DATA TO WEB APP

TEAM PROJECT · 프로젝트 3~12차시
오늘의 질문내가 해결해 보고 싶었던 문제를, 데이터와 생성형 AI로 실현할 수 있을까?

🎯 내가 제안한 문제, 데이터와 AI로 실현하기

처음 설문에 적었던 문제나 만들어 보고 싶었던 것을 다시 살펴봅니다. 문제에 맞는 자료를 탐색·분석하고, 발견한 내용을 바탕으로 웹 서비스를 기획·개발합니다. 실제로 사용하고 검증하며 처음의 아이디어를 더 나은 해결책으로 발전시킵니다.

1. 설문 속 아이디어를 프로젝트로 바꾸기

섹션 제목: “1. 설문 속 아이디어를 프로젝트로 바꾸기”

수업에서 안내한 방법으로 자신의 설문 응답을 다시 확인합니다. 지금도 해결하고 싶은 문제를 고르고, 비슷한 관심을 가진 친구와 팀을 구성합니다. 처음 적었던 아이디어를 수정하거나 다른 친구의 아이디어에 합류해도 됩니다. 아직 구체적인 생각이 없다면 아래 후보에서 출발합니다.

아래는 설문에서 나온 관심과 아이디어를 이름 없이 요약하여 다듬은 예시입니다. 이미 완성된 기획이나 분석 결과는 아닙니다. 실제 자료와 분석 방법을 확인한 뒤 팀의 질문을 결정합니다.

출발점프로젝트 후보확보·확인할 자료분석해 볼 질문
공부 계획·일정을 정리하고 싶다.학습 일정·과제 관리 서비스사용이 허용된 학사 일정·과제 정보, 본인이 기록한 소요 시간과목별 마감이 언제 겹치는가? 예상 시간과 실제 소요 시간은 어떻게 다른가?
외국어 학습·퀴즈·복습을 돕고 싶다.상황별 표현·복습 서비스직접 만들거나 사용이 허용된 예문·문항·정답, 본인의 연습 기록어떤 상황의 표현이 부족한가? 어떤 문항 유형에서 오류가 반복되는가?
국가와 사회의 정보를 쉽게 비교하고 싶다.세계지리·사회정보 비교 서비스기관의 국가·지역별 공개 지표와 그 정의같은 기준 연도에서 선택한 국가의 지표는 어떻게 다른가? 비교할 수 없는 항목은 무엇인가?
정확한 정보로 진로를 탐색하고 싶다.관심 분야 직업 비교 서비스출처와 사용 범위를 확인한 직업·학과 정보관심 분야의 직업들은 어떤 업무·준비 과정에서 공통점과 차이가 있는가?
관심 주제와 취향에 맞는 책을 찾고 싶다.주제별 독서 탐색 서비스실제 도서 목록·분류·서지 정보, 근거를 확인한 주제 설명확보한 도서는 주제·언어·출판 시기별로 어떻게 분포하는가? 찾기 어려운 범주는 무엇인가?

범위는 구체적으로, 서비스는 단계적으로

섹션 제목: “범위는 구체적으로, 서비스는 단계적으로”

처음부터 모든 과목·언어·국가·직업·책을 다루지 않습니다. 사용자 한 집단, 이용 상황 하나, 처음 분석할 자료 범위를 정합니다. 예를 들어 한 과목의 한 단원, 한 언어의 몇 가지 상황, 선택한 국가와 지표처럼 출발점을 정합니다. 자료를 확장할 때는 이유를 남깁니다.

같은 주제나 데이터를 여러 팀이 골라도 됩니다. 질문·분석 기준·사용 흐름이 다르면 서로 다른 프로젝트가 됩니다. 목록 밖의 제안도 실제 자료, 분석 질문, 검증 방법을 갖추면 검토할 수 있습니다.

📚 핵심 사용 흐름을 완성한 뒤 확장합니다

최종 기능 수를 하나로 제한하지 않습니다. 먼저 사용자에게 필요한 핵심 흐름을 완성하고, 분석과 사용 결과를 바탕으로 비교·시각화·복습·상세 정보 등의 기능을 연결합니다. 기능마다 필요한 이유와 확인 방법을 설명합니다.

2. 공통으로 지킬 데이터 탐구 기준

섹션 제목: “2. 공통으로 지킬 데이터 탐구 기준”

공공데이터를 우선 검토하되, 문제에 맞는 자료가 따로 있다면 출처와 사용 범위를 확인하여 선택합니다. 팀별로 자료의 종류는 달라도 데이터를 이해하고 분석한 뒤 기능으로 연결하는 과정은 모두 수행합니다.

자료 선택사용할 수 있는 경우먼저 확인할 것
공공데이터·기관의 공개 자료국가·지역 비교, 학교 일정, 직업·도서 정보 등 질문에 맞는 자료가 있다.원자료·항목 정의·기준 시점·조회 범위·이용 조건
사용이 허용된 학습·학교 자료예문·문항·정답·과제 정보 등 해당 문제에 직접 필요한 자료가 있다.제공자·정확성·사용과 공개의 허용 범위. 교재 전체를 임의로 복제하지 않는다.
직접 만든 자료·관찰·연습 기록자신의 계획·소요 시간·풀이 기록이나 직접 만든 콘텐츠를 기준에 따라 정리한다.기록 방법·기간·분류 기준·자료 수·한계. 다른 사람의 기록 수집은 사전에 수업 운영 기준을 확인한다.

학생 개인의 성적·상담 내용·가정 형편·연락처처럼 수업에 불필요한 정보는 모으지 않습니다. 이름만 지웠다고 공개해도 되는 자료로 간주하지 않습니다. 실제 개인 기록을 공개 저장소나 앱에 넣지 않고, 수업 내 분석 범위와 공개할 집계 결과를 구분합니다.

가상 자료는 오류 상황을 재현하거나 화면을 시연할 때 사용할 수 있습니다. 가상 자료로 계산한 결과를 실제 사용자나 사회 현상에 대한 발견으로 발표하지 않습니다. AI가 만든 예문·정답도 확인을 마치기 전에는 검증된 자료로 취급하지 않습니다.

⚠️ 자료를 넣었다고 분석이 끝난 것은 아닙니다

단어 목록에서 퀴즈가 나오거나 일정표가 화면에 표시되는 것만으로는 분석을 했다고 보기 어렵습니다. 질문에 따라 분류·비교·계산하고, 그 결과가 무엇을 의미하며 어떤 기능의 판단을 바꾸었는지 설명합니다. 숫자 분석뿐 아니라 기준을 정한 표현·정보의 비교도 가능합니다.

이번 프로젝트에서 보여 줄 세 가지 역량

섹션 제목: “이번 프로젝트에서 보여 줄 세 가지 역량”
역량프로젝트에서 하는 일설명할 수 있어야 하는 것
문제 해결력사용자의 불편을 구체화하고, 발견을 기능으로 연결하며, 피드백으로 개선한다.왜 이 문제와 기능을 선택했고 무엇을 바꾸었는가?
데이터 리터러시출처·범위를 확인하고, 기준을 정해 분석하며, 수치·해석·한계를 검증한다.무엇을 근거로 어디까지 말할 수 있는가?
AI 활용 역량목적·자료·제약을 설명해 AI와 협업하고, 결과를 검토·수정한다.AI의 제안 중 무엇을 받아들이거나 바꾸었고, 어떻게 확인했는가?

AI를 사용한 횟수보다 요구사항을 명확히 하고 결과를 근거로 판단한 과정을 기록합니다. 앱 화면의 화려함뿐 아니라 데이터와 결과를 설명할 수 있는지 확인합니다.

3. 12차시 진행 계획

섹션 제목: “3. 12차시 진행 계획”

총 12차시에는 6번의 공통 실습 2차시가 포함됩니다. 이 팀 프로젝트는 3~12차시입니다. 차시는 진행 상황에 따라 조정하되 분석·검증·개선 과정은 남깁니다.

차시중심 활동확인할 결과
1~2차시 · 6번공공데이터 공통 실습, 앱 제작·수정·검증실행본·계산 근거·수정 기록
3차시설문 아이디어 다시 보기, 팀 구성, 문제 정의처음 아이디어 → 이번 탐구 질문
4차시자료 후보 확인, 실제 자료 확보, 분석 범위 결정데이터 카드·열어 본 자료·자료별 사용 범위
5차시정리 기준 수립, 분류·비교·계산핵심 표·그래프·원자료 대조
6차시인사이트 도출, 필요하면 문제 재정의발견 → 의미 → 해결 방향
7차시서비스 기획, 화면·사용 흐름·개발 순서 설계기획서·기능 우선순위·테스트 기준
8~9차시생성형 AI와 개발, 기능 연결·확장실제 자료로 작동하는 첫 완성본
10차시데이터·기능 검증과 오류 수정기대 결과와 실제 결과·재검증
11차시다른 팀의 사용, 피드백 반영막힌 장면·개선본
12차시앱 체험·시연·발표·개인 성찰최종 서비스·프로젝트 기록

중간 점검은 세 번 합니다. 4차시에는 실제 자료와 분석 질문, 6차시에는 인사이트와 기능의 연결, 9차시에는 작동하는 핵심 사용 흐름을 확인합니다. 개발이 늦어지면 기능 우선순위를 조정하고 데이터 해석이나 테스트를 생략하지 않습니다.

팀 구성과 공동 책임

섹션 제목: “팀 구성과 공동 책임”

3인 내외로 팀을 구성하여 질문·데이터, 분석·검증, 구현·사용성을 나누어 주도합니다. 역할은 고정된 독점 업무가 아닙니다. 팀원 모두 실제 자료를 읽고 AI 요청 또는 수정 작업에 참여하며, 하나 이상의 원자료 대조나 기능 테스트를 직접 수행합니다. 중요한 문제·데이터·기능 결정은 함께 내립니다.

STEP 1 · 아이디어를 확인 가능한 문제로 바꾸기

섹션 제목: “STEP 1 · 아이디어를 확인 가능한 문제로 바꾸기”

자신의 처음 응답에서 해결하고 싶은 상황을 골라 지금의 질문으로 바꿉니다. 학생 전체의 원본 설문을 공개하거나 다른 사람의 개인 응답을 임의로 가져오지 않습니다. 팀에서는 선택한 아이디어와 필요한 내용만 공유합니다.

아이디어 출발 카드우리 팀 기록
처음 설문에서 떠올린 문제·만들고 싶은 것
지금도 이 문제를 선택하는 이유
누구의 어떤 이용 상황인가?
실제로 확인한 불편과 아직 가정한 부분
이번에 데이터로 확인할 질문
처음 분석할 과목·유형·지역·기간 등의 범위

[사용자]는 [상황]에서 [하려는 일]을 수행하려고 한다. 현재 [불편]이 있다. 우리는 먼저 [대상·범위·비교 기준이 드러나는 질문]을 자료로 확인한다.

사용 장면을 관찰하거나 사용할 친구에게 필요한 점을 물을 수 있습니다. 소수의 의견을 모든 학생의 의견으로 일반화하지 않습니다. 실제 자료나 반응이 예상과 다르면 문제 정의를 수정합니다.

STEP 2 · 실제 자료를 확보하고 범위 정하기

섹션 제목: “STEP 2 · 실제 자료를 확보하고 범위 정하기”

우선 자료 후보 두 개 이내를 살펴보고 질문에 맞는 자료부터 사용합니다. 출처 페이지가 있는 것과 필요한 내용이 실제 자료에 있는 것은 다릅니다. 앱을 만든 뒤에만 생기는 이용 기록이 필요하다면, 분석 전에 본인의 소규모 연습 기록을 먼저 준비하거나 이미 확보 가능한 질문으로 바꿉니다.

  1. 자료 열기

    실제 파일·통계표·예문·기록의 내용을 확인합니다. 샘플·일부 기간·전체 자료를 구분합니다.

  2. 질문과 맞추기

    필요한 항목·기간·분류·단위가 있는지 확인합니다. 없는 항목을 만들지 않고 질문이나 기능을 조정합니다.

  3. 분석 범위 정하기

    사용할 행·열 또는 텍스트 범위, 비교할 대상, 분류 기준을 정합니다.

  4. 원본과 사용 범위 기록

    원자료와 분석 사본을 분리하고 출처·확보일·변경 내용·공개 가능 범위를 기록합니다.
데이터 카드우리 팀 기록
자료 이름·제공 기관 또는 작성자·원문 위치
직접 기록했다면 기록 방법·기간·조건
이용 조건·AI 도구 입력 및 공개 가능 범위

공개 자료 탐색에는 4번에서 살펴본 공식 포털을 활용할 수 있습니다. 학습·학교 자료는 사용할 수 있는 범위를 먼저 확인합니다. 이 페이지의 후보 목록은 자료가 모두 준비되어 있다는 뜻이 아닙니다. 확보가 어려우면 수업에서 사용이 확인된 공통 자료로 돌아가 다른 질문을 정합니다.

STEP 3 · 기준을 정해 분석하기

섹션 제목: “STEP 3 · 기준을 정해 분석하기”

원본의 값을 정리하는 과정과 새로운 결과를 계산하는 과정을 구분하여 기록합니다. 텍스트나 직업 정보를 비교할 때도 어떤 기준으로 분류했고 어떤 근거를 사용했는지 남깁니다.

점검할 문제결정할 기준
누락된 값0·오답·무료 등으로 자동 해석하지 않고 확인 필요 또는 분석 제외로 표시한다.
중복 기록같은 날짜·문항·책·사례를 무엇으로 구분할지 정한다.
표기·정의 차이날짜·단위·항목 정의를 확인하고 변환 기준과 원문을 보존한다.
비교 기준같은 조건에서 비교하는지, 합계·비율·평균 또는 범주 비교 중 무엇이 적절한지 판단한다.
자료 범위본인의 기록이나 일부 사례를 모든 학습자·국가·직업으로 일반화하지 않는다.

질문에 답하는 핵심 표나 그래프를 만들고 중요한 결과 두 개 이상을 원자료와 직접 대조합니다. 수치라면 계산식과 사용한 값을, 문장·범주라면 분류 기준과 근거 문장을 확인합니다. 도구가 처리하기 어렵다는 이유로 모호한 내용을 억지로 숫자로 바꾸지 않습니다.

STEP 4 · 인사이트를 도출하고 문제 다시 보기

섹션 제목: “STEP 4 · 인사이트를 도출하고 문제 다시 보기”

인사이트는 이 프로젝트에서 분석한 내용이 사용자의 상황과 서비스 설계에 어떤 의미가 있는지 판단한 결과입니다. “그래프가 높다”에서 끝내지 않고 어떤 정보를 함께 보여 주어야 하는지, 어떤 조건이나 연습이 필요한지 설명합니다.

발견에서 기능으로 연결하는 예

섹션 제목: “발견에서 기능으로 연결하는 예”

아래는 외국어 복습 서비스를 설명하기 위한 가상의 기록이며 실제 학생의 분석 결과가 아닙니다.

단계예시
분석 결과단어 뜻 문항은 10개 중 8개, 상황에 맞는 표현 문항은 10개 중 4개를 맞혔다.
인사이트이 연습 기록에서는 유형별 정답률이 80%, 40%로 다르다. 전체 점수만으로는 어느 유형을 다시 볼지 파악하기 어렵다.
설계 판단유형별 결과와 문항 수를 함께 보여 주고, 사용자가 복습할 유형을 골라 다시 풀도록 한다.
검증 기준8/10과 4/10의 계산, 유형 선택, 해당 문항 표시와 해설을 확인한다.

이 기록만으로 모든 학습자의 약점이나 그 원인을 단정하지 않습니다. 실제 팀은 자신이 확보한 자료에서 확인한 결과로 인사이트를 작성합니다. 사용자의 불편, 자료에서 확인한 패턴, 서비스의 기대 효과도 각각 구분합니다.

STEP 5 · 서비스 기획과 개발 순서 정하기

섹션 제목: “STEP 5 · 서비스 기획과 개발 순서 정하기”

사용자의 행동이 시작되어 결과 확인까지 이어지는 흐름을 설계합니다. 예를 들어 연습 → 유형별 결과 확인 → 복습할 유형 선택 → 다시 풀기, 또는 조건 선택 → 후보 찾기 → 비교 → 출처 확인이 하나의 흐름이 될 수 있습니다.

기능마다 필요한 이유 → 필요한 데이터 → 구현 순서 → 확인 방법을 적습니다. 핵심 기능 한 가지 이상은 분석에서 어떤 발견을 했기 때문에 설계했는지 설명해야 합니다. 모든 화면 요소에 별도의 통계 근거를 억지로 붙일 필요는 없습니다.

STEP 6 · 생성형 AI와 개발하고 기능 연결하기

섹션 제목: “STEP 6 · 생성형 AI와 개발하고 기능 연결하기”

공통 실습의 데이터 읽기·조건 처리·계산·출력 구조를 재사용할 수 있습니다. 새 자료의 항목과 의미에 맞게 수정합니다. 먼저 핵심 사용 흐름을 완성하고, 필요한 기능을 순서대로 연결합니다.

정상 실행본을 보관한 뒤 한 번에 변경할 부분을 정합니다. 오류가 나면 입력 조건·기대 결과·실제 결과·오류 메시지를 제시하여 수정을 요청합니다. AI가 제안한 변경이 왜 필요한지 확인하고, 수정 후 같은 조건으로 다시 테스트합니다.

구현 범위를 정할 때

섹션 제목: “구현 범위를 정할 때”

기본 버전은 파일과 검증한 자료로 작동하도록 만들 수 있습니다. 자유 회화·자동 교정·실시간 요약처럼 별도 AI 연결이 필요한 기능은 자료·이용 조건·비용·키 관리·평가 방법을 먼저 확인하고 확장합니다. 연결하지 않은 기능을 이미 작동하는 것처럼 설명하지 않습니다.

검증한 예문을 보여 주는 기능과 새 답변을 생성하는 기능을 구분하여 표시합니다. 실제 구현에는 자료의 성격에 맞는 방법을 선택하며, 추가 모델 학습 자체는 공통 요구사항이 아닙니다.

자료는 사용이 허용된 파일을 선택하는 방식 또는 공개 가능한 자료만 포함하는 방식으로 사용합니다. 공개 코드와 AI 채팅에 개인정보나 인증키를 넣지 않습니다. 다른 사람의 자료를 활용할 때는 수업 내 사용과 온라인 공개의 범위를 따로 확인합니다.

다른 팀이 우리 앱을 사용한다면?

섹션 제목: “다른 팀이 우리 앱을 사용한다면?”

원자료를 바탕으로 준비한 검색·비교·연습 과제를 다른 팀에게 줍니다. 공개할 수 없는 개인 기록은 제공하지 않습니다. 시연용 가상 자료를 사용했다면 그렇게 표시하고, 실제 탐구에 사용한 자료와 구분합니다.

사용자의 이름이나 개인 성적 대신 과제, 실제 행동, 완료 여부, 막힌 장면, 의견을 기록합니다. 버그를 발견하면 재현 조건과 근거를 전달합니다. 수정한 뒤 같은 과제를 다시 수행하여 달라진 점을 확인합니다.

오류나 의견을 바탕으로 한 가지 이상 수정하고 기존 기능도 다시 검사합니다. 소수의 짧은 사용 결과만으로 성적 향상·적성 판정·사회문제 해결 효과가 입증되었다고 발표하지 않습니다. 직접 확인한 개선과 앞으로 검증할 효과를 나누어 설명합니다.
