AI 기능 넣기(선택)

기본 웹앱을 만든 뒤, 필요한 팀만 찾아보는 도움말입니다. 먼저 우리 팀이 정한 검색·표·그래프·지도 등 핵심 기능을 완성하세요. 개발할 때는 평소 사용하는 생성형 AI의 도움을 받아도 됩니다.

완성한 앱 안에서도 자료를 쉽게 설명하거나 번역하는 기능이 있으면 좋겠다고 생각할 때, 아래 순서로 시도해 보세요.

📚 지금 할 수 있는 범위

기능 한 가지를 정하고, 화면을 만든 뒤, 답변을 자료와 비교해 봅니다. 실제 AI 연결은 선생님과 가능 여부를 먼저 확인합니다. 현재 공용 연결 서버는 준비 전이므로, 지금은 예시 답변을 넣은 화면까지 만들어 볼 수 있습니다. 연결을 기다리는 동안에는 원래 앱의 구현·검증을 이어갑니다.

1. 작은 기능 한 가지 정하기

섹션 제목: “1. 작은 기능 한 가지 정하기”

“앱을 쓰는 사람이 무엇을 어려워할까?”에서 출발하세요. 정해진 안내문이나 검색 결과만으로 충분하면 그 방법을 사용합니다. 입력에 맞춰 설명을 바꾸는 일이 꼭 필요할 때 AI 기능을 생각해 봅니다.

예시: 의류 기부 지도

  • 기본 기능: 실제 자료에서 기부처를 찾아 지도에 표시하고 수거 기준을 보여 줍니다.
  • 더해 볼 기능: 사용자가 옷 종류와 상태를 선택하면, 확인한 수거 기준을 쉽게 설명해 줍니다.
  • 먼저 준비할 자료: 기부처 위치, 수거 품목·상태 기준, 공식 출처와 확인 날짜. 위치 자료에 수거 기준이 없다면 기관 안내에서 확인합니다.

검색·거리·개수 계산은 코드로 처리하고, AI에는 찾은 자료를 바탕으로 설명하는 일을 맡깁니다. AI가 기부 가능 여부를 확정하지 않도록 하고, 기준이 없거나 오래된 경우에는 기관에 확인할 수 있는 링크를 보여 줍니다.

다른 팀은 시설 안내를 쉬운 말로 바꾸기, 행사 정보를 다른 언어로 설명하기처럼 자신의 자료와 사용자에 맞는 기능을 고르면 됩니다.

2. 현재 앱에 화면부터 만들기

섹션 제목: “2. 현재 앱에 화면부터 만들기”

현재 앱 파일과 사용할 공개 자료를 준비하고, 아래 요청문의 표시된 부분을 바꿔 생성형 AI에 전달하세요. 기존에 잘 작동하던 기능은 그대로 유지합니다.

AI 설명 화면 만들기 표시된 부분을 우리 팀의 내용으로 바꾸세요.
프롬프트 구조와 각 부분이 필요한 이유 보기

역할·프로젝트 맥락은 AI가 어떤 관점에서 어느 팀의 문제를 다루는지 정합니다.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

우리 팀의 기존 웹앱에 설명 기능 화면 한 가지를 추가해줘.
현재 앱: {{첨부한 최신 파일 또는 저장소}}
사용자가 어려워하는 점: {{구체적인 상황}}
더하고 싶은 기능: {{자료 설명 / 쉬운 말 바꾸기 / 번역 등}}
사용할 공개 자료와 출처: {{필요한 항목과 기준일}}
유지할 기능: {{검색·표·그래프·지도 등}}

1. 현재 파일을 읽고 기존 기능과 데이터를 유지해줘.
2. 아직 AI 서버 연결 전이야. 유료 API를 호출하지 말고, ‘예시 답변 · 실제 AI 연결 전’이라고 표시한 화면을 만들어줘. 서버 주소나 인증 방법을 추측하지 마.
3. 입력·버튼·답변·원자료 출처를 볼 수 있게 해줘. 검색과 계산은 기존 코드에서 처리하고, 설명과 실제 자료는 구분해줘.
4. 빈 입력, 처리 중, 연결 실패 상황을 확인할 수 있게 하고, 버튼을 여러 번 눌러도 중복 전송되지 않게 해줘.
5. 실제 비밀키와 개인정보를 요구하거나 공개 코드에 넣지 마. 나중에 선생님이 연결 방법을 안내하면 바꿀 위치를 알려줘.
6. 수정한 파일, 바꾼 이유, 직접 확인할 순서를 짧게 정리해줘. 실제 AI 답변은 아직 미검증이라고 표시해줘.

화면에 ‘예시 답변 · 실제 AI 연결 전’을 표시합니다. 버튼을 눌렀을 때 결과가 보이는지, 내용이 길어도 읽기 편한지, 기존 검색·지도는 그대로 작동하는지 직접 확인하세요.

3. AI 기능 연결 문의하기

섹션 제목: “3. AI 기능 연결 문의하기”

앱에 AI 기능을 연결하고 싶은 팀은 구글 클래스룸 수업 게시물에 팀명과 원하는 기능을 댓글로 남겨 주세요. 만들고 있는 화면이나 앱 주소를 함께 올리면 더 구체적인 도움을 받을 수 있습니다.

연결이 가능한 경우, 선생님이 안내한 방법으로 적용합니다. 연결 주소나 설정을 아직 받지 않았다면 임의로 만들지 말고, 예시 화면과 실제로 연결된 화면을 구분해 둡니다.

지킬 것 세 가지

  • 실제 비밀 API 키는 코드·AI 대화·댓글·활동지에 붙여 넣지 않습니다. 키 설정은 선생님과 진행합니다.
  • 이름·학번·연락처·상담 내용 같은 개인정보를 입력하거나 전송하지 않습니다. 질문에 필요한 공개 자료만 사용합니다.
  • 선생님이 안내한 사용 범위 안에서 시험합니다. 오류나 사용 한도 안내가 나오면 반복 전송을 멈추고 문의합니다.

4. 자료와 비교하고 고치기

섹션 제목: “4. 자료와 비교하고 고치기”

이 기능을 추가한 팀은 기존 활동지 STEP 3의 검증 과정에서 다음을 골라 확인합니다. 수업 일정·STEP 순서·제출물은 기존 안내를 따릅니다.

  • 자료에 답이 있는 질문: 이름·숫자·날짜·조건이 원자료와 맞나요?
  • 자료에 답이 없는 질문: 내용을 지어내지 않고 확인이 필요하다고 안내하나요?
  • 사용하기 어려운 상황: 빈 입력·연속 클릭·연결 오류가 나도 기존 검색과 자료를 볼 수 있나요?
  • 다른 사람이 써 본 결과: 설명이 도움이 됐나요? 이해하기 어렵거나 잘못된 부분은 없었나요?

예시 화면만 시험했다면 ‘화면만 확인, 실제 AI 답변은 아직 확인 전’으로 적습니다. 오류가 있으면 아래 요청문에 관찰한 내용을 적어 수정해 보세요.

오류를 고칠 때 사용할 요청문
AI 기능 오류 확인 표시된 부분을 우리 팀의 내용으로 바꾸세요.
프롬프트 구조와 각 부분이 필요한 이유 보기

역할·프로젝트 맥락은 AI가 어떤 관점에서 어느 팀의 문제를 다루는지 정합니다.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

현재 파일과 관찰한 결과를 바탕으로 오류를 찾아줘.
현재 앱: {{최신 파일 또는 주소}}
확인 중인 것: {{예시 화면 / 실제 연결된 기능}}
하려던 일: {{입력과 기대 결과}}
실제 결과: {{화면 안내·오류 문구·답변}}
비교할 공개 자료: {{원자료·출처 또는 해당 없음}}

1. 확인한 원인과 아직 확인이 필요한 부분을 구분해줘.
2. 기존 정상 기능을 유지하면서 필요한 부분만 수정해줘.
3. 답변이 자료와 다르면 틀린 부분과 수정 방법을 알려줘.
4. 실제 키·인증값·개인정보를 요구하지 마. 서버 설정이나 사용 한도는 선생님께 확인할 사항으로 따로 적어줘.
5. 수정 후 직접 시험할 순서를 알려줘. 시험하지 않은 부분은 미검증으로 표시해줘.

기록은 원래 활동지에 이어 적습니다. 구현하면서 바꾼 것은 STEP 2, 시험한 결과는 STEP 3, AI의 제안에서 선택·수정한 부분은 STEP 4에 남깁니다. STEP 5에서는 자신이 한 일과 새로 알게 된 점을 돌아봅니다.

예시: “설명에 자료에 없는 조건이 들어갔다. 원문 링크를 함께 보여 주고, 근거가 없는 부분은 확인 필요로 표시하도록 고쳤다.” 우리 팀이 실제로 겪은 일과 판단을 자신의 말로 적어 보세요.

기존 시작 파일로 진행하던 팀

섹션 제목: “기존 시작 파일로 진행하던 팀”

기존 챗봇 시작 파일 ZIP은 그대로 받을 수 있습니다. 현재 앱 파일과 압축을 푼 시작 파일을 함께 생성형 AI에 제공하고, “기존 기능을 유지하며 우리 자료를 설명하는 화면을 연결해 줘”라고 요청할 수 있습니다.

이 예제에는 화면과 서버가 함께 들어 있습니다. 이미 사용 중인 팀은 현재 파일을 선생님께 보여 주고 설정을 함께 확인하세요. 새로 시작하는 팀은 위의 화면 만들기부터 진행하면 됩니다.
