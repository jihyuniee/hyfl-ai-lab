<Stage label="OPTION · WEB APP · 0~3차시" question="데이터에서 출발한 핵심 아이디어를 가장 간단하게 어떻게 보여줄 수 있을까?" />

이 페이지는 핵심 장면을 설명하는 선택 표현 도움말입니다. **8장 팀 프로젝트의 실제 데이터 기반 웹앱과 활동지 제출 기준은 그대로 적용**합니다. 여기의 화면 구성안은 웹앱 제출을 대신하는 과제가 아닙니다.

- 분석에서 발견한 문제와 핵심 기능을 연결해 설명합니다.
- 필요하면 핵심 화면과 이용 흐름을 간단히 그립니다.
- 추가 표현 방법은 팀이 선택하며, 새로운 필수 제출물은 없습니다.

<Steps>
<Step title="핵심 장면 하나 선택">사용자가 분석에서 발견한 문제를 해결하는 가치를 가장 잘 느끼는 장면만 고릅니다.</Step>
<Step title="사용 흐름 그리기">상황·입력 데이터·AI 처리·결과·사람의 확인을 3~5단계로 그립니다.</Step>
<Step title="선택하여 표현하기">화면 구성안으로 표현하거나, 원하는 팀만 생성형 AI와 바이브 코딩으로 핵심 기능 하나를 구현합니다.</Step>
<Step title="설명하고 한계 밝히기">AI가 만든 것과 팀이 결정·수정한 것, 실제 서비스에 더 필요한 데이터와 기능을 구분합니다.</Step>
</Steps>

<Callout kind="caution" title="코드가 길다고 좋은 프로젝트가 아닙니다">추가 기능이 데이터 근거와 사람의 판단 과정을 흐린다면 추가 기능을 줄이고 핵심 기능과 근거를 분명히 합니다. 화면 완성도와 코딩 실력은 프로젝트의 수준을 결정하지 않습니다.</Callout>

<Callout kind="checklist" title="설명할 수 있어야 우리 결과물입니다">
- 어떤 사용자 문제를 해결하는 장면인지 설명할 수 있다.
- AI가 만든 부분과 팀이 직접 결정·수정한 부분을 구분할 수 있다.
- 실제 서비스가 되려면 더 필요한 것과 한계를 설명할 수 있다.
</Callout>
