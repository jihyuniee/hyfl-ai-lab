이 페이지는 **지도 기능이 필요한 팀을 위한 선택 실습**입니다. 모든 팀이 해야 하는 필수 과제는 아닙니다. 먼저 준비된 실습창에서 지도를 띄워 보고, 우리 프로젝트에 필요하면 자신의 웹앱과 실제 위치 자료로 확장하세요.

<Callout kind="mission" title="먼저 여기까지 해 봅시다">
<strong>카카오 배경 지도 + 가상 지점 3개 + 지점을 눌렀을 때 설명</strong>이 나오면 첫 실습을 마친 것입니다. 세 지점은 실제 CCTV가 아닌 연습용 위치입니다.
</Callout>

## 1. 실습창을 열고 등록할 주소 복사하기

<a href="/hyfl-ai-lab/labs/kakao-map/" target="_blank" rel="noopener noreferrer"><strong>카카오맵 실습창 새 탭에서 열기 ↗</strong></a>

1. 위 링크를 엽니다. 실습창은 별도 사이트 로그인 없이 사용할 수 있습니다.
2. 왼쪽 **‘이 주소를 먼저 등록하세요’** 아래의 주소를 확인합니다.
3. 주소 옆 **복사 버튼**을 누릅니다. 자동 복사가 안 되면 선택된 주소를 직접 복사합니다.

정식 교과서 실습창에서 등록할 주소는 다음과 같습니다.

~~~text
https://jihyuniee.github.io
~~~

뒤의 `/hyfl-ai-lab/labs/kakao-map/` 경로는 등록값에 넣지 않습니다. 교과서와 실습창을 각각 열어 두고, 다음 설정은 [카카오디벨로퍼스](https://developers.kakao.com)에서 진행합니다.

**직접 확인:** 실습창의 주소 표시를 읽고 복사했습니다. 아직 키를 넣지 않았으므로 지도가 보이지 않아도 됩니다.

## 2. 카카오 앱을 선택하고 ‘사용 설정 ON’ 확인하기

1. [카카오디벨로퍼스](https://developers.kakao.com)에 카카오 계정으로 로그인합니다. 처음이면 개발자 등록을 진행합니다.
2. **앱**에서 사용할 앱을 선택합니다. 아직 없다면 앱 생성 화면에서 이름 등 필수 정보를 입력해 만듭니다.
3. 선택한 앱의 **카카오맵 → 사용 설정 → 상태**를 **ON**으로 바꿉니다.

<Callout kind="caution" title="키가 있어도 카카오맵 사용 설정을 켜야 합니다">
이번 실습에서 특히 확인할 설정은 <strong>카카오맵 → 사용 설정 → ON</strong>입니다. JavaScript 키를 복사하거나 도메인을 등록하는 것과 별도로 확인하세요.
</Callout>

다음과 같은 응답이 나오면 **입력한 키가 속한 앱에서 카카오맵 서비스가 비활성화된 상태**라는 뜻입니다.

~~~text
App(우리팀앱) disabled OPEN_MAP_AND_LOCAL service.
~~~

이때는 오류에 해당하는 앱을 열어 **카카오맵 사용 설정을 ON**으로 바꾼 뒤 실습창에서 다시 연결합니다. 이미 ON이라면 지금 확인하는 앱과 입력한 키의 앱이 같은지 살펴봅니다. 이 오류를 지도 저작권 문제로 해석하지 않습니다.

앱 정보의 **카카오맵 무료 쿼터** 표시도 확인하세요. 현재 새로 활성화하는 경우 **개발자 계정에서 처음 카카오맵 API를 활성화한 앱**에 무료 쿼터가 제공됩니다. 두 번째 이후의 새 활성화 앱이나 무료 제공량 초과 사용에는 유료 API 설정이 필요합니다. 기존 앱과 사용량은 **통계 → 쿼터** 및 [현재 이용 조건](https://developers.kakao.com/docs/ko/kakaomap/common)에서 확인합니다. 유료 사용 설정은 이 실습의 진행 절차에 포함하지 않습니다.

**직접 확인:** 사용할 앱과 **카카오맵 상태 ON**을 확인했습니다.

## 3. JavaScript 키의 SDK 도메인 등록하기

1. 같은 앱에서 **앱 설정 → 앱 → 플랫폼 키**로 이동합니다.
2. **JavaScript 키**를 선택합니다. 지도 Web SDK에는 이 키를 사용합니다.
3. 해당 키의 **JavaScript SDK 도메인**에 1단계에서 복사한 `https://jihyuniee.github.io`를 추가하고 저장합니다.
4. 방금 선택한 **JavaScript 키**의 복사 버튼을 누릅니다.

등록 위치는 **선택한 JavaScript 키 안의 SDK 도메인**입니다. 앱의 대표 도메인이나 다른 키의 설정만 바꾸지 않았는지 확인하세요. 설정 화면은 [카카오 지도 공식 준비 안내](https://apis.map.kakao.com/web/guide/)에서 함께 볼 수 있습니다.

| 이번에 확인할 항목 | 맞는 값 또는 상태 |
| --- | --- |
| 사용할 키 종류 | JavaScript 키 |
| 카카오맵 사용 설정 | ON |
| 처음 실습할 SDK 도메인 | `https://jihyuniee.github.io` |

JavaScript 키는 웹 지도에서 사용하는 브라우저용 키입니다. **REST API 키·어드민 키·서버용 비밀키를 대신 넣지 않습니다.** 키 값을 활동지나 오류 화면 설명에 적을 필요는 없습니다.

**직접 확인:** 같은 앱의 JavaScript 키에 교과서 실습 도메인을 등록하고, 그 키를 복사했습니다.

## 4. 실습창에 키를 넣고 지도 확인하기

1. 열어 둔 **카카오맵 실습창**으로 돌아갑니다.
2. **JavaScript 키** 입력칸에 복사한 값을 붙여 넣습니다.
3. **지도 띄우기**를 누르고 연결 결과를 기다립니다.
4. 연결되면 지도 위 마커 또는 **연습 지점 A·B·C 카드**를 눌러 봅니다. **전체 보기**로 세 지점의 범위를 다시 확인할 수 있습니다.

| 확인할 것 | 직접 볼 결과 |
| --- | --- |
| 배경 지도 | 도로와 지명이 실제로 보임 |
| 마커 | 가상 연습 지점 세 곳이 표시됨 |
| 클릭 | 선택한 지점의 이름·가상 위치 안내가 열림 |
| 출처 | 카카오 로고와 저작권 표시가 가려지지 않음 |

‘지도 초기화 완료’ 문구만 보고 끝내지 말고 **도로·지명이 보이는지** 확인하세요. 회색 배경 위에 마커만 있는 경우는 배경 이미지가 제대로 로드되지 않았을 수 있습니다.

**직접 확인:** 배경·세 지점·클릭 설명·출처가 보이면 첫 실습 완료입니다. 지도가 필요한 팀은 아래 확장 활동을 이어갑니다.

## 5. 실패하면 카카오의 실제 오류 문구 확인하기

‘지도 연결을 완료하지 못했어요’가 나오면 지도 아래 **오류 확인** 영역을 봅니다. 설정을 추측해서 여러 번 바꾸기보다, 카카오가 보낸 문구를 확인합니다.

1. 갈색 **카카오 오류 내용 열기** 버튼이 보이면 누릅니다. 카카오의 응답이 새 탭에 열립니다.
2. 새 탭에서 **`message`에 적힌 오류 문구**를 복사합니다. 주소창에는 키가 포함되므로 주소 전체를 복사하지 않습니다.
3. 원래 실습창으로 돌아와 **오류 문구 붙여 넣기**에 붙입니다. 붙여 넣은 내용의 키 값은 자동으로 가려지고, 문구에 맞는 점검 안내가 나옵니다.
4. 도움이 더 필요하면 **키 없이 오류 복사**를 눌러 선생님이나 AI에게 보냅니다. 자동 복사가 제한되면 나타난 진단 내용을 직접 복사합니다.
5. 안내에 따라 설정을 고친 뒤 **지도 띄우기**를 다시 누릅니다.

갈색 버튼이 없는 경우는 카카오 파일 요청 전이나 다른 단계에서 멈춘 것일 수 있습니다. 표시된 실패 단계를 읽고 **키 없이 오류 복사**를 사용하세요. 새 탭에 오류 대신 긴 프로그램 코드가 보이면 그 코드를 붙이지 말고 ‘프로그램 코드가 보인다’고 알려 주세요. 새 탭 요청과 처음 실패한 요청의 결과가 다를 수 있습니다.

| 실제 응답 또는 현상 | 다음에 확인할 것 |
| --- | --- |
| `disabled OPEN_MAP_AND_LOCAL service` | 입력한 키의 앱에서 **카카오맵 → 사용 설정 → ON** |
| `domain mismatched` | 그 JavaScript 키의 SDK 도메인에 **실습창이 표시한 주소**가 등록됐는지 |
| `wrong appkey format`·`invalid appkey` | JavaScript 키 전체를 복사했는지, 따옴표·설명 문장을 함께 넣지 않았는지 |
| 쿼터·호출 한도 관련 문구 | 해당 앱의 무료 쿼터 적용 여부와 **통계 → 쿼터** |
| 401·403만 보임 | 상태 코드만으로 원인을 단정하지 않고 실제 응답 문구를 확인 |
| 지도 틀·마커만 보이고 배경은 회색 | 배경 요청·네트워크·이용 상태를 추가 확인 |

흰 화면이나 연결 실패를 곧바로 저작권 문제라고 단정하지 않습니다. 이번 실습에서 확인한 비활성화 오류는 **해당 앱의 카카오맵 사용 설정 ON**으로 해결하는 경우입니다.

## 확장 선택 A. 우리 팀 웹앱에 지도 넣기

이제 지도 기능을 자신의 프로젝트에 넣고 싶은 팀만 진행합니다. **첫 실습은 교과서 실습 주소**, **팀 웹앱은 팀의 실행 주소**를 등록합니다.

| 지도가 실행되는 곳 | JavaScript SDK 도메인에 등록할 값 |
| --- | --- |
| 교과서 실습창 `https://jihyuniee.github.io/hyfl-ai-lab/labs/kakao-map/` | `https://jihyuniee.github.io` |
| 팀 웹앱 `https://my-team.github.io/cctv-map/` | `https://my-team.github.io` |
| 로컬 웹 서버 `http://localhost:3000/index.html` | `http://localhost:3000` |

팀 주소는 예시입니다. 등록값에서는 뒤의 경로를 빼고, localhost는 실제 포트까지 포함합니다. **같은 앱·JavaScript 키를 계속 사용할 수 있다면 그 키의 SDK 도메인에 팀 주소를 추가**합니다. 지도 기능을 하나 더 만들 때마다 새 키를 만들 필요는 없습니다. 앱의 이용 조건과 한도는 이어서 적용됩니다.

### 시작 파일 내려받기

아래 **index.html 다운로드**로 한 파일짜리 시작 예제를 받습니다. 지금 사용한 키 입력 실습창과 달리, 이 파일은 코드를 직접 수정해 팀 웹앱으로 만드는 출발점입니다. 현재 프로젝트 원본은 따로 보관합니다.

### GitHub Pages에 올리기

이미 팀 웹앱 주소가 있다면 기존 배포 방법을 사용합니다. 처음이라면 다음 순서로 주소를 만듭니다.

1. GitHub의 **+ → New repository**에서 공개 가능한 연습용 **Public** 저장소와 README를 만듭니다.
2. **Add file → Upload files**로 `index.html`을 저장소 맨 위에 올리고 **Commit changes**를 누릅니다.
3. **Settings → Pages → Build and deployment → Source**를 **Deploy from a branch**로 선택합니다.
4. **Branch: main / (root)**를 선택하고 **Save**합니다.
5. 배포가 끝나면 **Visit site**로 실제 주소를 확인합니다. 아직 열리지 않으면 **Actions**의 배포 상태를 봅니다.

자세한 절차는 [기존 교과서의 배포 안내](/hyfl-ai-lab/project1/#github로-웹페이지-배포하기)에서 볼 수 있습니다. 팀 주소의 도메인을 카카오에 추가한 뒤, 파일의 다음 줄에서 자리표시자만 자신의 JavaScript 키로 바꿉니다.

~~~js
const javascriptKey = 'YOUR_JAVASCRIPT_KEY';
~~~

수정한 파일을 같은 저장소에 다시 올려 배포하고, **팀 웹앱 주소**에서 배경·가상 세 지점·클릭을 확인합니다. AI 미리보기나 `file://` 직접 열기는 외부 지도 인증·실행이 제한될 수 있으므로, 실제 배포 주소로 확인합니다.

## 확장 선택 B. 실제 CCTV CSV 연결하기

배경 지도는 카카오가 보내 주고, CCTV 마커는 **우리 파일의 위도·경도**로 만듭니다. 지도 연결만으로 실제 CCTV 정보가 자동으로 생기지는 않습니다.

### 좌표부터 확인하기

아래는 **가상 자료 4행**의 좌표 검사입니다. 위도·경도 열을 고르고 **좌표 확인하기**를 누른 뒤, 열을 거꾸로 선택하거나 빈칸이 있는 행을 비교해 보세요. 지도 실습의 가상 지점 3개와는 별도의 자료입니다.

<CoordinateLab />

[전국CCTV표준데이터](https://www.data.go.kr/data/15013094/standard.do) 또는 지자체 공개 자료에서 CSV와 항목 설명을 확인합니다. 원본을 보관하고, 프로젝트에 필요한 지역·목적을 정합니다. 자료가 크면 그 범위를 별도 CSV로 추리고 사용한 범위를 표시합니다. 한글이 깨지면 인코딩을 확인하고 편집한 자료는 CSV UTF-8로 저장합니다.

| 확인할 열 | 기능과 확인할 점 |
| --- | --- |
| 위도·경도 | WGS84인지 확인하고 위치 표시. 빈 값·문자를 0으로 바꾸지 않기 |
| 주소·설치 위치·목적 | 실제로 있는 설명과 필터에 사용 |
| 카메라 대수 | 한 행이 한 대인지 설치 지점 한 곳인지 구분 |
| 데이터 기준일·출처 | 자료의 시점과 근거 표시 |

카카오의 `new kakao.maps.LatLng(위도, 경도)`는 **위도, 경도** 순서입니다. GeoJSON의 `[경도, 위도]`, 미터 단위 좌표, 기상 격자와 구분하세요.

### 파일 선택 기능 추가하기

1. 현재 팀 웹앱의 HTML과 실제 CSV를 AI에 함께 첨부합니다. HTML 사본의 키는 `YOUR_JAVASCRIPT_KEY`로 바꿔 제공합니다.
2. 아래 요청의 빨간 부분을 실제 파일에서 확인한 값으로 바꿉니다. 없는 정보는 ‘없음’ 또는 ‘확인 필요’로 적습니다.
3. 수정된 HTML에 본인이 키를 다시 넣고, 같은 팀 웹앱 주소에 배포합니다.
4. **팀 웹앱의 CSV 파일 선택 버튼**으로 파일을 엽니다. 가상 지점이 실제 파일의 마커와 섞이지 않는지 확인합니다.

AI에 CSV를 첨부한 것과 웹앱이 파일을 읽는 것은 별개입니다. 샘플 몇 행을 하드코딩하지 않고 **선택한 파일 전체를 읽어 계산**해야 합니다. CSV 파일 선택 방식에는 별도의 공공데이터 API 키나 서버 저장이 필요하지 않습니다. 새로 접속하면 파일을 다시 고를 수 있으며, CSV를 공개 저장소에 올릴 필요는 없습니다.

### 원자료 3행과 결과 대조하기

원자료에서 서로 다른 위치 3행을 골라 지도 위치·주소·목적·대수를 비교합니다. 다음도 직접 확인합니다.

- 빈 좌표는 잘못된 위치에 점을 만들지 않고 제외한 행 수에 반영되는가?
- 다른 CSV를 고르면 이전 마커가 정리되는가? 설치 목적 필터가 있다면 목록과 지도가 함께 바뀌는가?
- **현재 조건의 행 수 = 유효 좌표 행 수 + 좌표 문제로 제외한 행 수**인가? 머리글·겹친 마커·서로 다른 설치 지점 수·카메라 대수를 구분했는가?
- 데이터 출처·기준일·지도 저작권 표시가 보이는가?

공개 위치 자료만으로 현재 운영 상태·실시간 영상·특정 길의 안전을 보장할 수는 없습니다. 확인하지 못한 것은 ‘확인 필요’로 남깁니다.
