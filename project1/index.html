3. School Image Lab

MINI PROJECT 1 · TEAM LAB · 5~7차시
오늘의 질문학교 안에서 사진으로 상태를 구분하면 도움이 될 문제는 무엇일까?

이 프로젝트는 짧은 실습을 한 번 더 하는 시간이 아닙니다. 팀이 학교 안의 문제를 발견하고, 사진으로 구분할 수 있는지 판단하고, 데이터를 설계하고, 모델을 실패시키고, 개선하며, 다른 사람에게 보여 주는 작은 연구·제작 프로젝트입니다.

완성도 높은 앱이나 가장 높은 정확도가 목표는 아닙니다. 문제 정의 → 데이터 설계 → 1차 학습 → 실패 분석 → 데이터 개선 → 재검증 → 사용 한계 판단의 과정이 프로젝트의 핵심입니다.

🎯 팀 미션

학교 안에서 실제로 관찰한 작은 문제 하나를 정하고, 사진으로 상태를 구분하는 AI가 도움이 될지 실험하세요. 그 뒤 팀의 모델과 실험 과정을 간단한 웹 페이지로 보여 주고, 동료의 피드백을 받아 최종 판단을 설명합니다.

1단계 · 문제를 발견하고 주제를 정하기

섹션 제목: “1단계 · 문제를 발견하고 주제를 정하기”

시작 전에 세 번 묻기

섹션 제목: “시작 전에 세 번 묻기”
  1. 누구의 어떤 문제인가? 실제로 불편을 겪거나 도움을 받을 사람이 있는가?
  2. 사진으로 판단할 수 있는가? 냄새·감정·의도·성격처럼 사진에 보이지 않는 정보를 추측해야 하는 문제는 아닌가?
  3. AI가 필요한가? 표지판·점검표·간단한 규칙이 더 쉽고 안전한 해결책은 아닌가?
주제의 방향가능한 예피해야 할 예
상태 구분창문 열림/닫힘, 칠판 정리/미정리, 분리배출 상태사람의 성격·감정·능력 판단
물체 구분준비물 종류, 재활용품 종류, 시설물 종류얼굴로 신원·건강·위험도 판단
관리 보조물품 정리 상태, 좌석·공간 사용 상태사진만으로 규칙 위반 여부 단정

⚠️ 좋은 주제는 ‘AI를 만들 수 있는 주제’보다 ‘AI를 써도 되는 주제’이다

사람에게 불이익을 주거나 민감한 개인정보를 추론할 수 있는 주제는 선택하지 않습니다. 모델의 결과가 틀려도 큰 피해가 생기지 않고, 사람이 최종 확인할 수 있는 작은 문제부터 시작합니다.

팀이 제출할 주제 제안

섹션 제목: “팀이 제출할 주제 제안”

팀은 다음 내용을 한 장으로 정리해 주제를 확정합니다.

  • 문제 상황: 언제, 어디서, 어떤 불편이 생기는가?
  • 대상 사용자: 누가 도움을 받는가?
  • AI가 구분할 두세 가지 클래스: 무엇과 무엇을 구분하는가?
  • 사진만으로 가능한 이유: 이미지에서 실제로 보이는 차이는 무엇인가?
  • AI가 필요하다고 판단한 이유: 기존 방법의 한계는 무엇인가?
  • 예상되는 위험과 한계: 틀리면 어떤 문제가 생기며 사람은 어떻게 확인할 것인가?

2단계 · 데이터 계획을 세우고 촬영하기

섹션 제목: “2단계 · 데이터 계획을 세우고 촬영하기”

주제가 정해졌다고 바로 모델을 학습시키지 않습니다. 먼저 모델이 실제로 만날 상황을 상상하고 데이터 수집 계획을 세웁니다.

계획할 항목팀이 정할 내용
클래스 기준각 클래스의 포함·제외 기준을 한 문장으로 정하기
데이터 수클래스마다 어느 정도의 사진을 목표로 할지 정하기
촬영 조건사람·배경·거리·각도·조명·물체 상태를 어떻게 다양하게 담을지 정하기
역할 분담촬영, 라벨 확인, 기록, 테스트를 누가 맡을지 정하기
동의·개인정보촬영 대상의 동의, 얼굴·이름·학번이 담기지 않도록 하는 방법 정하기
테스트 묶음학습에 쓰지 않고 마지막 비교에만 사용할 사진을 미리 확보하기

📚 데이터 계획의 핵심

데이터는 많기만 하면 좋은 것이 아닙니다. 양은 패턴을 찾기에 충분해야 하고, 정확성은 라벨과 기준이 맞아야 하며, 다양성은 실제로 만날 여러 조건을 담아야 합니다. 실제 사용 대상과 상황을 고르게 담는 대표성도 함께 살핍니다.

촬영 기간 동안 지킬 원칙

섹션 제목: “촬영 기간 동안 지킬 원칙”
  • 같은 조건의 사진만 반복해서 많이 찍지 않습니다.
  • 사진을 모을 때마다 클래스 기준과 라벨이 맞는지 확인합니다.
  • 학습용 사진과 테스트용 사진을 섞지 않습니다.
  • 촬영 조건과 데이터 수를 기록합니다.
  • 다른 팀원·다른 장소·다른 시간대의 사진도 가능하면 포함합니다.

3단계 · 첫 모델을 만들고 실패를 찾기

섹션 제목: “3단계 · 첫 모델을 만들고 실패를 찾기”

첫 모델은 성공 여부를 판정하는 마지막 결과가 아니라, 모델이 무엇을 놓치는지 알아보기 위한 출발점입니다.

  1. 첫 학습 결과 기록

    각 클래스의 데이터 수, 학습 날짜, 사용한 설정, 익숙한 조건에서의 결과를 기록합니다.

  2. 같은 조건의 테스트

    팀이 미리 확보한 테스트 묶음으로 첫 결과를 확인합니다.

  3. 조건을 하나씩 바꾸기

    사람·배경·거리·각도·조명·물체 상태 중 한 조건씩 바꾸며 모델을 시험합니다.

  4. 일부러 틀리게 만들기

    클래스에 없는 대상, 비슷한 색·모양, 가려진 물체, 낯선 배경을 넣어 봅니다.

  5. 실패 지도 만들기

    언제, 무엇을, 어느 클래스로 틀렸는지 표나 사진으로 기록합니다.
실패 사례 기록예
입력 조건복도에서 멀리 찍은 창문 닫힘 사진
모델 결과열림 78%
바뀐 조건교실이 아닌 복도, 촬영 거리 증가
원인 가설복도·먼 거리 조건의 닫힘 사진이 부족했을 수 있음
다음 개선복도·먼 거리·다른 각도의 닫힘 사진을 추가함

4단계 · 데이터를 개선하고 다시 학습하기

섹션 제목: “4단계 · 데이터를 개선하고 다시 학습하기”

모델이 틀렸을 때 ‘사진을 더 많이 찍자’로 끝내지 않습니다. 실패 원인에 맞는 데이터를 추가하거나 잘못된 라벨·불분명한 클래스 기준을 고칩니다.

여러 조건을 한꺼번에 바꾸면 무엇이 영향을 주었는지 알기 어렵습니다. 가능한 한 한 번에 한 가지를 바꾸고, 개선 전후에 같은 테스트 사진을 사용합니다.

⚠️ 정확도 숫자 하나로 끝내지 않기

높은 점수가 나와도 테스트 사진이 학습 사진과 너무 비슷하면 실제 성능을 과대평가할 수 있습니다. 전체 점수뿐 아니라 어떤 조건에서 잘되고, 어떤 조건에서 실패하는지를 함께 보여 주세요.

5단계 · 간단한 웹 페이지로 보여 주기

섹션 제목: “5단계 · 간단한 웹 페이지로 보여 주기”

선생님이 제공하는 기본 웹 페이지 코드를 사용해 팀의 모델과 프로젝트 내용을 간단히 보여 줍니다. 기본 페이지를 그대로 사용해도 됩니다. 웹 제작은 프로젝트의 핵심 평가 대상이 아닙니다.

기본 페이지에 담을 내용팀이 채울 내용
프로젝트 제목문제와 사용자에게 맞는 제목
해결하려는 문제누구의 어떤 불편을 다루는가
분류 클래스무엇을 구분하는 모델인가
모델 사용 화면모델을 직접 시험해 볼 수 있는 간단한 화면
데이터와 개선처음 데이터, 실패 사례, 개선 내용
한계와 사람의 역할언제 틀릴 수 있으며 누가 최종 확인하는가
  • 기본형: 제공된 코드에 팀의 제목·설명·모델 링크·사진·결과만 넣어 배포합니다.
  • 확장형: 필요한 팀은 색상·레이아웃·설명·기능을 자유롭게 수정할 수 있습니다.

웹 페이지를 멋지게 꾸미는 것보다, 방문자가 팀의 문제·데이터·모델 결과·한계를 이해할 수 있게 만드는 것이 중요합니다.

6단계 · 발표하고 동료 평가하기

섹션 제목: “6단계 · 발표하고 동료 평가하기”

팀 발표에서 보여 줄 것

섹션 제목: “팀 발표에서 보여 줄 것”
  1. 누구의 어떤 문제를 발견했는가?
  2. 사진으로 무엇을 구분하려 했는가?
  3. 데이터는 어떻게 계획하고 수집했는가?
  4. 첫 모델은 어디서 실패했는가?
  5. 무엇을 바꾸어 다시 학습했으며 결과는 어떻게 달라졌는가?
  6. 모델의 한계와 사람이 최종 확인해야 할 부분은 무엇인가?
  7. 웹 페이지는 이 프로젝트를 어떻게 보여 주는가?

동료 평가 질문

섹션 제목: “동료 평가 질문”
  • 문제와 대상 사용자가 구체적으로 설명되었는가?
  • 사진으로 구분하는 방식이 실제 문제와 잘 맞는가?
  • 데이터의 양·정확성·다양성을 고려한 흔적이 있는가?
  • 실패 사례와 개선 근거가 설득력 있게 제시되었는가?
  • 높은 점수만 보여 주지 않고 한계와 사람의 역할을 설명했는가?
  • 웹 페이지가 모델과 프로젝트의 핵심을 이해하는 데 도움이 되는가?

프로젝트 최종 제출물

섹션 제목: “프로젝트 최종 제출물”
제출물필수 내용
프로젝트 기록문제 정의, 클래스 기준, 데이터 계획·수집 기록, 실패·개선 과정
학습 모델팀이 학습·테스트한 이미지 분류 모델
웹 페이지제공된 기본형 또는 팀이 수정한 프로젝트 소개·모델 실행 페이지
발표 자료문제·데이터·실패·개선·한계·사람의 역할
동료 평가다른 팀의 프로젝트를 근거를 들어 평가한 기록

📚 프로젝트의 마지막 문장

모델이 틀렸다는 사실보다 왜 틀렸다고 생각했고, 어떤 데이터를 바꾸었으며, 다시 어떻게 확인했는지가 더 중요합니다. AI의 판단은 데이터와 학습 과정의 영향을 받으므로, 결과를 이해하려면 결과 숫자뿐 아니라 그 과정 전체를 살펴야 합니다.
