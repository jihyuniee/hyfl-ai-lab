윤리는 마지막에만 배우는 별도 목록이 아니었습니다. 이미지 수집에서는 동의와 대표성을, 데이터 분석에서는 출처와 일반화를, 생성형 AI에서는 사실 확인과 저작권을, 서비스 설계에서는 공정성·안전·사람의 개입을 판단해왔습니다.

## 경험을 한 줄로 연결하기

| 경험 | AI가 한 일 | 사람이 해야 했던 일 |
| --- | --- | --- |
| 이미지 분류 | 데이터에서 패턴을 찾아 클래스 예측 | 데이터·테스트 설계, 실패 해석, 사용 여부 판단 |
| 공공데이터 분석 | 정리·계산·시각화·패턴 탐색 지원 | 질문·출처·처리 과정 검증, 사실과 해석 구분 |
| 생성형 AI 협업 | 관점·대안·초안 생성 | 목적 설정, 원자료 확인, 수정·거부·최종 판단 |
| 서비스 기획 | 가능한 기능과 시나리오 확장 | 문제 선택, 역할 분담, 위험과 책임 설계 |

## 기술적으로 가능한 것과 실제로 해야 하는 것

다음 질문으로 최종 프로젝트를 다시 봅니다.

- 도움을 받는 사람과 피해를 볼 수 있는 사람은 누구인가?
- 가장 위험한 실패는 무엇인가?
- 어떤 데이터와 사람이 빠져 있는가?
- 결과를 확인·수정·거부하거나 이의를 제기할 수 있는가?
- 최종 결정과 책임은 누구에게 있는가?
- AI를 사용하지 않는 편이 더 좋은 지점은 없는가?

<Callout kind="reflect" title="학기 첫 답과 비교하기">처음에는 AI를 무엇이라고 생각했나요? 지금은 AI가 잘하는 일, 한계, 사람의 역할을 어떻게 설명할 수 있나요? 생각이 바뀐 계기가 된 실험이나 프로젝트를 근거로 답합니다.</Callout>

<Callout kind="concept" title="이 과목의 마지막 문장">AI가 더 많은 일을 할수록 사람에게는 **무엇을 위해 사용할지 질문하고, 결과를 검증하며, 다른 사람에게 미칠 영향을 살피고, 최종 판단을 책임지는 능력**이 더 중요해집니다.</Callout>
