1단원에서 AI가 여러 분야에서 보고·예측하고·문제를 해결하는 모습을 살펴보았습니다. 이제 작은 이미지 분류 모델을 직접 가르쳐 보며, AI가 데이터에서 패턴을 학습한다는 말의 의미를 확인합니다.

이 실험의 목표는 높은 정확도나 멋진 앱을 만드는 것이 아닙니다. **모델이 무엇을 보고 배웠는지, 언제 틀리는지, 데이터를 바꾸면 결과가 왜 달라지는지** 발견하는 것이 목표입니다.

## 먼저 알아둘 실험 언어

| 개념 | 이번 실험에서의 뜻 | 예 |
| --- | --- | --- |
| **데이터** | 모델에게 보여 주는 사례 | 직접 찍은 이미지 |
| **클래스** | 모델이 구분하도록 정한 범주 | `가위`와 `주먹`, `열림`과 `닫힘` |
| **라벨** | 각 데이터가 어느 클래스인지 알려 주는 정답 이름 | 이 사진은 `가위`라는 표시 |
| **모델** | 데이터에서 찾은 패턴을 담아 새 입력의 결과를 만드는 계산 구조 | 새 사진을 보고 두 클래스 중 하나를 예측함 |
| **분류** | 입력을 미리 정한 범주 가운데 하나 이상으로 구분하는 작업 | 사진을 `가위` 또는 `주먹`으로 예측함 |

<Callout kind="concept" title="이번 실험은 지도학습이다">
**지도학습**은 입력 데이터와 정답 라벨을 함께 보여 주고, 둘 사이의 관계를 학습하게 하는 방법입니다.

이번 실험에서는 이미지가 입력이고, 각 이미지에 붙인 클래스 이름이 정답 라벨입니다. 따라서 새 이미지가 들어오면 모델은 학습한 관계를 이용해 어느 클래스에 더 가까운지 예측합니다.
</Callout>

## 사람이 규칙을 쓰는 것과 모델을 학습시키는 것은 무엇이 다를까?

이미지에서 가위를 찾으려면 ‘손가락 두 개가 벌어져 있고, 손바닥이 보이며…’처럼 모든 규칙을 사람이 작성할 수도 있습니다. 하지만 사람·배경·거리·조명·각도에 따라 모습이 달라지므로 완전한 규칙을 쓰기는 어렵습니다.

| 규칙 기반 방식 | 학습 기반 방식 |
| --- | --- |
| 사람이 판단 규칙을 직접 작성한다. | 여러 이미지와 정답을 보여 주고 모델이 구분에 도움이 되는 패턴을 찾게 한다. |
| `규칙 + 새 입력 → 결과` | `데이터 + 라벨 → 학습 → 모델`<br />`모델 + 새 입력 → 예측 결과` |
| 규칙을 고치려면 사람이 프로그램을 수정한다. | 실패 원인을 보고 데이터·라벨·학습 조건을 고쳐 다시 학습한다. |

머신러닝은 사람이 아무것도 하지 않아도 알아서 배우는 기술이 아닙니다. 사람은 **문제, 클래스, 데이터, 라벨, 평가 기준, 실제 사용 여부**를 정합니다. 모델은 그 범위 안에서 예측에 도움이 되는 수학적 패턴을 찾습니다.

## 컴퓨터는 어떻게 ‘학습’할까?

<div class="ai-function-map" aria-label="이미지 분류 모델의 학습 흐름">
	<div><span>1</span><strong>이미지와 라벨</strong><p>두 클래스의 사례를 제공한다</p></div>
	<div><span>2</span><strong>예측</strong><p>현재 모델이 어느 클래스인지 추측한다</p></div>
	<div><span>3</span><strong>비교·조정</strong><p>예측과 라벨의 차이가 줄도록 내부 값을 조정한다</p></div>
	<div><span>4</span><strong>학습된 모델</strong><p>새 이미지에 예측 결과를 낸다</p></div>
</div>

학습은 이미지를 통째로 외워 두는 과정이 아닙니다. 모델은 많은 이미지에서 색·선·모양·질감·배치처럼 분류에 도움이 되는 특징의 조합을 계산합니다. 학습 뒤에는 처음 보는 이미지에도 그 패턴을 적용해 결과를 만들 수 있습니다. 그러나 배경이나 촬영한 사람처럼 우리가 의도하지 않은 단서를 배울 수도 있습니다.

### 딥러닝은 이 과정에서 어떤 역할을 할까?

많은 이미지 분류 모델은 **딥러닝**을 사용합니다. 딥러닝은 여러 층의 인공신경망이 이미지의 단순한 특징부터 더 복잡한 특징의 조합까지 학습하는 머신러닝 방법입니다.

```text
이미지 → 여러 층의 계산 → 클래스별 점수 → 가장 높은 클래스 예측
```

학생이 손가락 모양이나 배경 규칙을 하나하나 작성하지 않아도 되는 이유가 여기에 있습니다. 다만 모델이 어떤 특징을 중요하게 보았는지 항상 사람이 이해하기 쉬운 말로 설명되지는 않으므로, 새로운 조건에서 시험해 보는 과정이 필요합니다.

## 이제 직접 가르쳐 보자

<Steps>
<Step title="문제와 두 클래스 정하기">사진만 보고도 일관되게 구분할 수 있는 두 범주를 정합니다. 예: `가위/주먹`, `뚜껑 열림/닫힘`, `재활용 가능/불가능`.</Step>
<Step title="구분 기준 먼저 말로 정하기">각 클래스가 무엇을 뜻하는지 한 문장으로 적습니다. 기준이 불분명하면 데이터와 라벨도 흔들립니다.</Step>
<Step title="이미지 데이터 모으기">각 클래스의 이미지를 비슷한 수로 모읍니다. 한 사람·한 배경·한 각도에만 몰리지 않게 합니다. 얼굴 등 개인정보가 포함되면 당사자의 동의를 먼저 받습니다.</Step>
<Step title="라벨 확인하기">각 이미지가 올바른 클래스에 들어갔는지 다시 확인합니다. 잘못 붙은 라벨은 모델에게 잘못된 답을 가르치는 것과 같습니다.</Step>
<Step title="첫 모델 학습하기">도구에 이미지와 클래스 이름을 넣고 학습합니다. 첫 결과는 완성본이 아니라 비교를 위한 출발점입니다.</Step>
<Step title="익숙한 조건에서 시험하기">학습할 때와 비슷한 사람·배경·거리·조명에서 먼저 확인합니다. 어떤 결과와 점수가 나오는지 기록합니다.</Step>
<Step title="새로운 조건에서 시험하기">다른 사람, 다른 배경, 거리, 각도, 조명 중 한 조건씩 바꾸어 봅니다. 무엇이 바뀌었을 때 예측이 흔들리는지 확인합니다.</Step>
<Step title="일부러 실패시키기">클래스에 없는 대상, 가려진 대상, 비슷한 색·모양, 낯선 배경을 입력해 봅니다. 모델이 무엇을 제대로 구분하지 못하는지 찾습니다.</Step>
</Steps>

## 화면의 결과를 어떻게 읽을까?

### 예측 클래스와 확률

분류 모델은 보통 각 클래스에 대한 점수를 표시하고, 그중 가장 높은 결과를 예측 클래스로 보여 줍니다. 예를 들어 `가위 92%, 주먹 8%`처럼 보일 수 있습니다.

<Callout kind="caution" title="92%는 ‘현실에서 92% 확실하다’는 뜻이 아니다">
이 값은 현재 모델이 학습한 클래스 사이에서 이 이미지가 어느 쪽에 더 가깝다고 계산했는지를 나타내는 점수에 가깝습니다. 모델이 한 번도 배우지 않은 물체를 넣어도 기존 클래스 중 하나에 높은 점수를 줄 수 있습니다.
</Callout>

### 학습 데이터와 테스트 데이터

- **학습 데이터**: 모델이 패턴을 찾는 데 사용한 이미지
- **테스트 데이터**: 학습에 사용하지 않고, 새로운 상황에서도 작동하는지 확인하는 이미지

학습에 사용한 사진을 다시 맞히는 것만으로는 모델이 잘 배웠다고 판단할 수 없습니다. 학습과 다른 사람·배경·각도·조명에서 시험해야 모델이 새 상황에도 적용되는지 알 수 있습니다. 이 실험에서 찾은 실패는 다음 단원에서 **일반화·과대적합·데이터 편향**이라는 개념으로 다시 설명합니다.

## 머신러닝에서 중요한 것은 데이터다

모델이 무엇을 배우는지는 어떤 데이터를 어떻게 제공했는지에 크게 영향을 받습니다. 사진이 많아도 모두 같은 사람·같은 배경·같은 각도라면, 모델은 새로운 상황에서 쉽게 흔들릴 수 있습니다. 반대로 사진이 다양해도 라벨이 틀리거나 기준이 들쑥날쑥하면 잘못된 관계를 배울 수 있습니다.

| 데이터에서 확인할 것 | 질문 | 이미지 분류 실험의 예 |
| --- | --- | --- |
| **양** | 패턴을 찾기에 사례가 충분한가? | 각 클래스에 너무 적은 사진만 있지 않은가? |
| **정확성** | 사진과 라벨이 기준에 맞고 일관적인가? | `열림`과 `닫힘`의 기준이 팀원마다 다른 것은 아닌가? |
| **다양성** | 실제로 만날 여러 조건을 담았는가? | 사람·배경·거리·각도·조명·물체 상태가 다양하게 포함되었는가? |
| **대표성** | 실제 사용 대상과 상황을 고르게 반영하는가? | 특정 교실·특정 물체·특정 사람의 사진만 반복되지는 않았는가? |

<Callout kind="caution" title="많을수록 무조건 좋은 것은 아니다">
같은 조건의 사진을 수백 장 더 모으는 것보다, 모델이 틀린 조건의 사진을 정확한 라벨과 함께 추가하는 편이 더 도움이 될 수 있습니다. 데이터의 양·정확성·다양성·대표성을 함께 살펴야 합니다.
</Callout>

## 실험 기록에서 꼭 남길 것

| 기록할 것 | 예 |
| --- | --- |
| 클래스와 구분 기준 | `뚜껑이 완전히 닫힌 상태 / 열린 상태` |
| 각 클래스의 데이터 수와 조건 | 각 40장, 창가·책상·복도에서 촬영 |
| 테스트에서 바꾼 조건 | 사람, 배경, 거리, 각도, 조명 중 무엇을 바꾸었는가 |
| 모델의 결과 | 예측 클래스와 표시 점수 |
| 실패 사례 | 어떤 입력에서 무엇을 틀렸는가 |
| 원인 가설 | 배경만 보고 판단했을까? 특정 각도의 데이터가 부족할까? |

<Callout kind="concept" title="AI와 사람의 역할">
**AI**는 주어진 이미지에서 학습한 패턴으로 예측 결과를 냅니다.<br />
**사람**은 구분 기준과 데이터를 정하고, 테스트 조건을 설계하며, 실패 원인을 해석하고 실제 사용 여부를 판단합니다.
</Callout>

## 다음 학습으로 연결하기

이제 팀 프로젝트에서 학교 안의 문제를 정하고, 데이터 계획부터 다시 설계해 봅니다. 모델은 왜 익숙한 사진에서는 잘 맞히다가 새로운 사람·배경·각도에서 흔들렸을까요? 프로젝트 안에서 실패 원인을 기록하고 데이터를 개선하며 답을 찾아봅니다.

> **좋은 데이터는 많기만 한 데이터가 아니라, 목적에 맞게 정확하고 다양하며 대표적인 데이터입니다.**
