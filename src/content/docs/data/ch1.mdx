이미지 분류에서 우리는 **어떤 데이터를 모았는지가 모델의 판단을 바꾼다**는 사실을 경험했습니다. 이제 표 형태의 데이터로 현실을 해석해봅니다. 데이터는 현실 전체가 아니라 특정 목적과 방법으로 관찰해 기록한 일부입니다.

## 표를 읽는 최소 개념

| 개념 | 확인할 질문 |
| --- | --- |
| 행 | 한 행은 사람·지역·날짜 등 무엇 하나를 나타내는가? |
| 열·변수 | 무엇을 어떤 방식으로 기록했는가? |
| 범주형 데이터 | 종류나 집단처럼 이름으로 구분되는가? |
| 수치형 데이터 | 계산 가능한 수량인가? 단위는 무엇인가? |
| 결측치 | 기록되지 않은 값이 왜 생겼는가? |
| 중복값 | 같은 대상을 두 번 센 것은 아닌가? |
| 이상치 | 매우 다른 값이 오류인가, 중요한 현상인가? |

## 분석은 질문에서 시작한다

```text
질문 설정 → 출처·수집 맥락 → 구조·품질 확인 → 필요한 정리
→ 시각화·비교 → 관찰한 사실 → 가능한 해석 → 한계와 판단
```

그래프부터 만들면 보기 좋은 그림은 생겨도 무엇을 알아보려 했는지 흐려질 수 있습니다. 먼저 비교 대상·기간·단위가 들어간 질문을 정합니다.

<Callout kind="concept" title="사실과 해석을 분리하기">
**사실**은 표와 그래프에서 직접 확인할 수 있는 내용입니다.<br />
**해석**은 그 사실이 왜 나타났는지 설명하는 생각으로, 추가 근거가 필요합니다.

두 변수가 함께 변하는 **상관관계**만으로 하나가 다른 하나의 원인이라는 **인과관계**를 단정할 수 없습니다.
</Callout>

## 생성형 AI를 사용할 때

AI는 파일 구조 확인, 결측치 탐색, 전처리 코드 작성, 기초 통계와 그래프 생성에 도움을 줄 수 있습니다. 그러나 어떤 열을 썼고 어떤 값을 삭제·변경했는지, 단위와 그래프 축은 맞는지, 해석이 데이터 범위를 넘지 않는지는 사람이 확인해야 합니다.

<Callout kind="concept" title="오늘 기억할 내용">데이터 분석은 그래프 제작이 아니라 **질문에 필요한 근거를 만들고, 그 근거가 말할 수 있는 범위와 말할 수 없는 범위를 판단하는 과정**입니다.</Callout>
