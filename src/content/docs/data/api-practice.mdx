## 1. 활용신청 다음에 펼칠 화면

[공공데이터포털](https://www.data.go.kr/)의 **인증키 화면과 API 사용 설명 화면을 함께** 펼쳐 둡니다. API 명세서·활용가이드는 “어느 주소에 어떤 값을 보내면 무엇을 받을 수 있는지” 적힌 사용설명서입니다.

### 먼저, 내가 신청한 API 찾기

1. 로그인한 뒤 **마이페이지의 Open API·활용신청 현황**에서 신청한 서비스 이름과 승인 상태를 확인합니다. 메뉴가 단계별로 보이는 경우 `마이페이지 → 데이터 활용 → Open API → 활용신청 현황`으로 이동합니다.
2. **서비스 이름과 제공기관**을 확인하고 그 API의 상세 페이지를 엽니다. 설명 화면을 찾기 어려우면 포털의 **공공데이터 → 데이터목록**에서 같은 서비스 이름을 검색해 **오픈API** 항목을 엽니다.
3. 상세 페이지에서 **참고문서·활용가이드**를 찾습니다. ZIP 파일이면 내려받아 압축을 풀고 사용설명서와 코드표를 확인합니다.

### 기상청 상세 페이지에서 실제로 찾을 위치

[기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)를 열고 다음 순서로 찾아보세요. 화면에서 글자를 찾기 어려우면 `Ctrl+F`로 **참고문서**, **활용 정보**, **요청주소**를 검색합니다.

| 화면에서 찾을 곳 | 할 일 | 확인할 결과 |
| --- | --- | --- |
| 이 페이지의 구성 → **참고문서** | 활용가이드를 내려받습니다. | 상세기능 설명과 요청·응답 예시를 읽을 수 있습니다. |
| **활용 정보 → 상세기능** | **API 서비스** 목록에서 **초단기실황조회**를 고르고 **조회하기**를 누릅니다. | 선택한 기능의 설명과 요청변수 표가 나타납니다. |
| **API 기본 정보 → 요청주소** | 기능까지 들어 있는 주소를 복사합니다. | 주소 끝에 `getUltraSrtNcst`가 있습니다. |
| **요청변수(Request Parameter)** | `필수`인 행의 영문 이름·형식·샘플을 찾습니다. | 날짜·시각·격자 등 내가 보내야 할 값이 보입니다. |
| **출력결과(Response Element)** | 받고 싶은 항목의 이름과 뜻을 찾습니다. | 기온은 `category`와 `obsrValue`를 함께 읽는다는 것을 확인합니다. |

여기서 **조회하기는 선택한 기능의 사용 설명을 보는 단계**입니다. 실제 데이터는 뒤에서 완성한 요청주소를 실행하거나, 제공되는 **OpenAPI 호출** 기능을 사용해 받습니다. **출력결과 표와 문서의 샘플은 응답 형식을 설명하는 예시**이며, 방금 내 조건으로 받은 자료는 호출 후 응답에서 확인합니다.

다른 기관의 화면에서는 같은 역할의 항목 이름이 조금씩 다를 수 있습니다. 아래 표로 대응해 보세요.

| 포털·명세서의 표현 | 뜻과 가져올 내용 |
| --- | --- |
| 참고문서·활용가이드 | API 사용 명세서입니다. 내려받아 필요한 기능의 설명·요청 예시·응답 예시를 읽습니다. 첨부 ZIP이면 압축을 풀어 문서와 코드표도 확인합니다. |
| 상세기능·오퍼레이션(operation) | 같은 API 안에서 할 수 있는 조회 작업입니다. 원하는 자료를 주는 기능 하나를 선택합니다. |
| 서비스 URL·End Point | 기관의 API가 있는 기본 주소입니다. 상세기능 경로를 더해야 하는지 예시와 비교합니다. |
| 요청주소 | 선택한 기능까지 포함한 주소일 수 있습니다. 포털이 완성된 요청주소를 주면 기능 이름을 또 붙이지 않습니다. |
| 요청변수·요청인자 | **기관으로 보낼 값**입니다. 변수 이름·필수 여부·길이·형식·예시를 확인합니다. |
| 출력결과·응답메시지 | **기관에서 받을 값**입니다. 항목 이름·목록 위치·단위·정상/오류 코드를 확인합니다. |

예를 들어 보낼 값은 ‘격자와 시각’이고 받을 값은 ‘기온·습도 등’일 수 있습니다. 입력과 출력은 같은 이름으로 일대일 대응하지 않습니다. 문서에 없는 검색 조건을 마음대로 추가하지 않습니다.

## 2. 기상청 예제로 요청 기능 정하기

이 예제는 **공공데이터포털에서 발급받은 키**로 [기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)의 **초단기실황조회(getUltraSrtNcst)**를 요청합니다. 서비스 이름에 ‘예보’가 있지만 이 기능은 **관측된 실황**을 조회합니다. 미래 기온 예보를 받는 기능과 구분하세요.

기상청 예제를 직접 실행하려면 **이 서비스의 활용신청 승인**을 확인합니다. 우리 팀이 다른 API를 신청했다면 그 API의 요청주소와 조건으로 진행하세요.

> 같은 기상청이라도 **공공데이터포털 `apis.data.go.kr`의 `serviceKey`**와 **기상청 API허브의 `authKey`**는 다른 인증 체계입니다. 활용가이드에 API허브 예제가 함께 있더라도 주소와 키를 섞지 않습니다. 아래는 공공데이터포털 방식으로 통일합니다.

| 목적 | 선택할 기능 | 보내는 조건 | 받을 항목 | 앱에서 보여 줄 값 |
| --- | --- | --- | --- | --- |
| 한 지역·기준시각의 기온 확인 | `getUltraSrtNcst` | 격자 `nx`,`ny`, 날짜 `base_date`, 시각 `base_time` | `category`가 `T1H`인 항목의 `obsrValue` | 기온(℃), 관측 기준시각, 격자 |

**지역 이름 대신 격자 좌표를 보냅니다.** 포털 참고문서의 격자 자료에서 지역에 맞는 `nx`,`ny`를 찾습니다. 서울특별시 대표 격자 예시는 **60, 127**입니다. 모든 서울 동네가 같은 격자라는 뜻은 아니며, 위도·경도 값을 그대로 넣지 않습니다.

| 요청변수 | 구분 | 값의 예·형식 | 필요한 이유 |
| --- | --- | --- | --- |
| `serviceKey` | 필수 | `YOUR_API_KEY` | 요청자의 이용 권한 확인 |
| `pageNo` | 필수 | `1` | 받을 페이지 |
| `numOfRows` | 필수 | `1000` | 한 페이지에서 받을 개수. 실제 전체 건수와 받은 범위도 확인 |
| `dataType` | 선택 | `JSON` (기본 XML) | 이번 실습은 읽을 형식을 JSON으로 지정 |
| `base_date` | 필수 | 선택한 날짜의 `YYYYMMDD` | 관측 기준 날짜 |
| `base_time` | 필수 | 선택한 정시의 `HH00`, 예: `0900` | 관측 기준 시각(한국 시각) |
| `nx`, `ny` | 필수 | `60`, `127` | 조회할 예보 격자 X·Y |

**현재 시각과 자료가 준비된 기준시각은 다를 수 있습니다.** 초단기실황은 `base_time`에 정시를 넣습니다. 첫 연습에서는 현재 한국 시각보다 한 시간 앞선 정시로 시험해 보세요. 예를 들어 오전 10시 25분에 실행한다면 같은 날짜의 `0900`, 오전 0시 25분이라면 **전날 날짜의 `2300`**으로 조건을 잡아 봅니다. 실제 제공 시각·범위는 공식 활용가이드와 응답을 확인합니다. 아래 날짜 자리표시자는 조회 가능한 실제 날짜로 바꿉니다.

## 3. 요청 URL을 한 부분씩 만들기

**① 기본 주소**

~~~text
https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0
~~~

**② 상세기능을 한 번 붙인 요청주소**

~~~text
https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst
~~~

**③ `?` 뒤에 첫 조건, `&` 뒤에 다음 조건을 붙입니다.** `이름=값`에서 왼쪽은 문서에 나온 정확한 변수 이름, 오른쪽은 넣을 값입니다. 대소문자·버전·철자를 유지합니다.

**요청변수 표의 한 행을 주소로 옮기는 방법**입니다. 예를 들어 `nx`라는 항목에 `60`을 보내려면 `nx=60`이라고 씁니다. 앞에 이미 다른 조건이 있으면 `&nx=60`으로 이어 붙입니다.

| 설명서에서 읽은 내용 | 주소에 넣는 모양 | 뜻 |
| --- | --- | --- |
| 항목 이름 `nx`, 넣을 값 `60` | `&nx=60` | 격자 X 좌표를 60으로 지정 |
| 항목 이름 `ny`, 넣을 값 `127` | `&ny=127` | 격자 Y 좌표를 127로 지정 |
| 항목 이름 `base_time`, 넣을 값 `0900` | `&base_time=0900` | 09시를 기준시각으로 지정 |
| 항목 이름 `dataType`, 넣을 값 `JSON` | `&dataType=JSON` | JSON 형식으로 받기 |

`?`는 조건이 시작되는 자리에 한 번, `&`는 조건과 조건 사이에, `=`는 이름과 값 사이에 들어갑니다. **국문 항목명은 뜻을 읽을 때, 영문 항목명은 요청을 만들 때** 사용합니다. 필수 항목을 먼저 채우고, 선택 검색 조건은 기본 요청이 된 다음 하나씩 더합니다.

~~~text
.../getUltraSrtNcst?serviceKey=YOUR_API_KEY
.../getUltraSrtNcst?serviceKey=YOUR_API_KEY&pageNo=1
.../getUltraSrtNcst?serviceKey=YOUR_API_KEY&pageNo=1&numOfRows=1000&dataType=JSON
~~~

위 `...`는 구조 설명용이며 실행 주소가 아닙니다. 아래 완성형에서 **키·날짜·시각·격자**를 바꿉니다.

~~~text
https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst?serviceKey=YOUR_API_KEY&pageNo=1&numOfRows=1000&dataType=JSON&base_date=YYYYMMDD&base_time=HH00&nx=60&ny=127
~~~

- `YOUR_API_KEY`: 교사가 안내한 개인 실습 환경에서 직접 적용합니다. AI 대화·공개 문서·저장소에는 넣지 않습니다.
- `YYYYMMDD`: 현재 제공되는 범위에서 선택한 실제 날짜로 바꿉니다.
- `HH00`: 자료가 준비된 정시 네 자리로 바꿉니다. 예를 들어 오전 9시는 `0900`입니다.
- `60`,`127`: 격자 자료에서 확인한 우리 지역 값으로 바꿉니다.

이 주소는 **“내 인증키로, 이 날짜·시각의 격자 60·127에 해당하는 실황을, JSON 형식으로, 첫 페이지에서 최대 1000개 보내 주세요”**라는 요청입니다. `numOfRows=1000`은 요청하는 페이지 크기이며, 실제로 몇 항목을 받았는지는 응답에서 확인합니다.

### Encoding과 Decoding 중 무엇을 넣나요?

두 표시는 **같은 인증키를 URL에서 표현하는 방식**입니다. 지금 사용하는 도구에 맞춰 한 번만 인코딩합니다.

| 지금 하는 작업 | 사용할 값 |
| --- | --- |
| 위와 같은 **완성 URL 문자열의 `YOUR_API_KEY`를 직접 교체** | 공식 예시에 맞는 **한 번 인코딩된 값**을 넣습니다. 포털에서 Encoding 키를 제공하면 그 값을 확인합니다. |
| 포털의 **Swagger 입력칸**에서 호출 | 해당 공식 안내에 따라 **일반 인증키(Decoding)**를 넣습니다. |
| `URLSearchParams`처럼 **자동으로 URL 변환하는 코드** | **Decoding 값**을 넣고 도구가 한 번 인코딩하도록 합니다. |

이미 Encoding된 값을 자동 인코딩 도구에 다시 넣으면 `%2B`가 `%252B`처럼 바뀔 수 있습니다. 인증 오류가 나면 실행 도구의 입력 안내와 실제 요청주소를 비교합니다. 표와 샘플코드의 항목 표기가 다를 때도 해당 서비스의 공식 실행 화면·샘플 요청을 함께 확인하세요. [공공데이터포털의 실행 화면 안내](https://www.data.go.kr/images/biz/swagger-guide/gw/gateway_swagger_guide.pdf) · [URLSearchParams의 인코딩 설명](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams#percent_encoding)

이번처럼 **GET이고 인증·조건이 URL 쿼리에 들어가는 요청**은 완성형을 **줄바꿈 없는 한 줄**로 브라우저 주소창에 붙여 넣어 실행할 수 있습니다. 헤더 인증이나 POST가 필요한 다른 API는 주소창만으로 같은 요청을 만들 수 없습니다. 기관 테스트 도구와 해당 명세의 방법을 사용하세요. 키가 들어간 주소는 공유·캡처·공개 북마크로 남기지 않습니다.

### 직접 응답 받기: 복사 → 값 교체 → 주소창 → Enter

2. `YOUR_API_KEY`, `YYYYMMDD`, `HH00`을 실제 값으로 바꾸고 격자를 확인합니다. **`?`, `&`, `=`와 항목 이름은 유지**합니다.

## 4. 받은 응답에서 기온 찾기

**글자와 중괄호가 길게 나와도, 그 안에 데이터가 들어 있습니다.** JSON은 이름과 값을 짝지어 적는 형식입니다. `{ ... }`는 관련 항목을 묶고, `[ ... ]`는 여러 항목을 목록으로 담습니다. 기상청 예제에서는 다음 순서로 읽습니다.

| 순서 | 화면에서 찾아볼 것 | 판단할 내용 |
| --- | --- | --- |
| ① 처리 결과 | `Ctrl+F`로 `resultCode` 찾기 | 이 API의 정상 코드 `00`인지 확인하고 `resultMsg`도 읽습니다. |
| ② 실제 목록 | `totalCount`, `items`, `item` 찾기 | 자료가 있는지, 몇 항목을 받았는지 확인합니다. |
| ③ 필요한 값 | `T1H`를 찾아 같은 항목의 `obsrValue` 읽기 | `T1H`는 기온 항목이며 `obsrValue`가 값입니다. |
| ④ 요청과 대조 | `baseDate`, `baseTime`, `nx`, `ny` | 내가 보낸 날짜·시각·격자가 맞는지 확인합니다. |

**HTTP 상태**와 **응답 본문의 기관 처리 결과**도 구분합니다. HTTP 200이어도 본문에 오류가 담길 수 있습니다. 이 API는 `response.header.resultCode`와 `resultMsg`를 확인한 다음 실제 목록을 읽습니다. `03`은 자료없음, `10`은 요청변수 오류, `11`은 필수값 누락, `22`는 요청 제한, `30`은 미등록 키를 뜻하는 이 서비스의 코드 예입니다. 다른 기관에서는 그 명세서의 정상·오류 기준을 확인합니다.

아래는 **구조 설명용으로 만든 모의 JSON**입니다. 실제 조회 결과도, 현재 날씨도 아닙니다. 실제 응답 구조와 값은 직접 요청한 결과와 비교합니다.

~~~json
{
  "response": {
    "header": { "resultCode": "00", "resultMsg": "NORMAL_SERVICE" },
    "body": {
      "dataType": "JSON", "pageNo": 1, "numOfRows": 1000, "totalCount": 2,
      "items": { "item": [
        { "baseDate": "YYYYMMDD", "baseTime": "HH00", "category": "REH", "nx": 60, "ny": 127, "obsrValue": "60" },
        { "baseDate": "YYYYMMDD", "baseTime": "HH00", "category": "T1H", "nx": 60, "ny": 127, "obsrValue": "18.2" }
      ] }
    }
  }
}
~~~

1. `response → header`에서 처리 결과를 읽습니다.
2. `response → body → items → item`에서 기록 목록을 찾습니다.
3. `category=T1H`를 요청 URL에 임의로 추가하는 것이 아니라 받은 목록에서 고릅니다. 목록의 **첫 항목이라고 기온은 아닙니다.** `category === "T1H"`인 항목을 찾습니다.
4. 그 항목의 `obsrValue`가 기온 값이며 단위는 **℃**입니다. `REH`는 습도(%), `RN1`은 1시간 강수량(mm)처럼 항목별 단위가 다릅니다.
5. `baseDate`, `baseTime`, `nx`, `ny`가 내가 요청한 조건과 맞는지 비교합니다. 요청의 `base_date`와 응답의 `baseDate`는 이름부터 다릅니다.

예시의 `"category": "T1H", "obsrValue": "18.2"`는 **“기온 항목의 값이 18.2℃”**라는 뜻입니다. `base_time=0900`처럼 **내가 보낸 조건**과 `obsrValue`처럼 **기관이 돌려준 값**을 구분해 설명해 보세요. 위 숫자는 읽는 연습을 위한 모의 값입니다.

**실제 항목 수와 페이지도 확인합니다.** `pageNo=1`은 첫 페이지, `numOfRows`는 요청한 페이지 크기, `totalCount`는 조건에 맞는 전체 건수입니다. 지금 받은 목록의 길이가 전체 건수보다 작으면 다음 페이지가 필요할 수 있습니다. 첫 페이지만 읽은 경우에는 그 범위에서 확인한 결과로 기록합니다.

<Callout kind="checklist" title="여기까지 되면 첫 응답 확인 완료">
**우리 팀이 직접 받은 응답**을 보며 세 가지를 설명합니다: ① 보낸 조건 한 가지 ② 실제 받은 항목 이름과 값 한 가지 ③ 그 값의 의미·단위. 기록은 기존 활동지의 자료 확보·검증 부분에 짧게 이어 적습니다.
</Callout>

`obsrValue`가 `-999` 등 공식 결측 범위(−900 이하 또는 +900 이상)에 해당하면 실제 기온으로 표시하지 않고 **관측값 없음**으로 안내합니다.

## 5. 응답이 예상과 다를 때

| 관찰한 결과 | 먼저 확인할 것 |
| --- | --- |
| HTTP 404·찾을 수 없는 경로 | 기관·버전·상세기능의 철자, 기능 경로 중복 여부 |
| HTTP 401/403 또는 본문에 인증·권한 오류 | 해당 서비스의 활용신청 승인 상태, 키의 발급기관과 요청주소가 맞는지, 인증 위치·이름·인코딩 방식. HTTP와 기관 코드를 같은 뜻으로 단정하지 않기 |
| 본문에 요청변수 오류 | 필수값 누락, 변수 대소문자, 날짜8자리·시각4자리·격자 형식 |
| 정상 응답이지만 목록 없음 또는 자료없음 메시지 | 오래된 날짜, 아직 생성되지 않은 시각, 제공 범위·격자. ‘기온 0도’로 바꾸지 않기 |
| JSON 대신 XML·문자 오류 응답 | `dataType=JSON` 여부와 원문 내용. 인증 단계의 오류는 다른 형식일 수도 있음 |
| 일부 항목만 보임 | `numOfRows`, `pageNo`, `totalCount`, 실제 받은 목록 길이 |
| 주소창에서는 보이지만 앱에서 실패 | Console·Network의 실제 오류, CORS 허용, HTTPS 페이지에서 HTTP 호출, 요청 생성·JSON 처리 코드, 서버 설정을 구분 |

**오류 원문을 먼저 읽고 한 항목씩 고칩니다.** 상태를 모르는데 인증키부터 재발급하거나 전체 앱을 다시 만들지 않습니다. 도움을 받을 때는 요청 URL·오류 문구·화면 캡처의 키·토큰·개인정보를 지웁니다. 브라우저의 `no-cors`로 바꿔도 JSON을 읽을 수 있게 되지 않으며, 임의의 공개 프록시에 키를 보내지 않습니다.

## 6. 확인한 값을 앱에 표시하기

연결 순서는 **화면 입력 → 요청변수 만들기 → 요청 실행 → HTTP·기관 결과 확인 → 필요한 항목 선택 → 화면 표시**입니다. 조건이 바뀌면 새 요청이 필요할 수도 있고, 이미 받은 목록에서 고르면 될 수도 있습니다. 명세가 지원하는 요청조건과 앱 안의 필터를 구분합니다.

예를 들어 앞에서 확인한 실황 목록에서 기온을 고르는 코드는 다음과 같습니다. `raw`는 **직접 받은 정상 JSON을 읽은 객체**이며, 아래 코드 자체가 API에 요청을 보내지는 않습니다.

~~~js
const items = raw.response.body.items.item;
const temperature = items.find(item => item.category === 'T1H');
const value = String(temperature?.obsrValue ?? '').trim();
if (value !== '' && Number.isFinite(Number(value)) && Number(value) > -900 && Number(value) < 900) {
  document.querySelector('#temperature').textContent = value + ' ℃';
} else {
  document.querySelector('#temperature').textContent = '기온 항목이 없거나 관측값이 없습니다.';
}
~~~

실제 앱에서는 이 코드 전에 HTTP·기관 오류와 빈 목록도 처리해야 합니다. **값 하나를 꺼내는 부분과 데이터 요청 부분을 나누어 확인**하면 문제가 생긴 위치를 찾기 쉽습니다.

<details>
<summary>참고 · 같은 요청을 코드로 옮길 때</summary>

아래는 앞에서 주소창에 보낸 **같은 GET 요청을 서버 코드로 옮기는 원리**입니다. **브라우저 HTML에 붙여 넣는 코드가 아닙니다.** `process.env`를 읽고 `fetch`를 실행하는 서버 환경이 이미 준비된 경우의 예시이며, 이 안내가 서버나 키 설정을 만들어 주지는 않습니다. 공개 앱의 서버 연결은 선생님과 확인합니다.

~~~js
// 서버 전용 예시: 실제 키는 서버 환경변수에 따로 설정합니다.
async function requestWeather({ baseDate, baseTime, nx, ny }) {
  const key = process.env.DATA_GO_KR_SERVICE_KEY; // Decoding 값
  if (!key) throw new Error('서버의 인증값 설정이 필요합니다.');
  const params = new URLSearchParams({
    serviceKey: key, pageNo: '1', numOfRows: '1000', dataType: 'JSON',
    base_date: baseDate, base_time: baseTime,
    nx: String(nx), ny: String(ny)
  }); // 각 값을 한 번 인코딩합니다.
  const endpoint = 'https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getUltraSrtNcst';
  const response = await fetch(`${endpoint}?${params}`, { method: 'GET' });
  if (!response.ok) throw new Error(`HTTP 상태 확인: ${response.status}`);
  const raw = await response.json();
  const code = String(raw.response?.header?.resultCode ?? '');
  if (code === '03') return { status: 'no-data' };
  if (code !== '00') throw new Error(`기관 처리 코드 확인: ${code || '형식 확인 필요'}`);
  return { status: 'ok', data: raw };
}
~~~

`baseDate`·`baseTime`·`nx`·`ny`에는 앞서 직접 확인한 조건을 전달합니다. 서버는 허용할 입력·호출량·오류·시간 제한도 별도로 처리해야 합니다. 요청 URL에는 키가 들어가므로 로그나 오류 화면에 전체 주소를 출력하지 않습니다. 인증 오류가 XML 등으로 왔다면 JSON 처리 오류만 보고 판단하지 말고, 키를 가린 원문 형식을 확인합니다. 정상 응답을 받으면 앞의 `T1H` 선택 과정으로 화면에 필요한 값을 연결합니다.

</details>

현재 앱 파일·공식 명세·키를 가린 정상 응답을 함께 준비합니다. 앱이 이미 허용된 방식으로 데이터를 요청한다면 그 구조를 유지하며 응답을 화면에 연결합니다. 공개 앱에서 비밀키를 사용하려면 서버에서 키를 보관하고 호출하는 구성이 필요할 수 있습니다. **GitHub Pages는 정적 파일을 제공하며 비밀키를 숨겨 주거나 서버 코드를 실행해 주지 않습니다.** 서버 연결이 준비되지 않았다면 파일 기반 화면으로 확인한 범위를 남기고 선생님과 다음 설정을 확인합니다.

## 7. 다른 기관은 이름부터 다시 확인하기

[식품의약품안전처 의약품 제품 허가정보](https://www.data.go.kr/data/15095677/openapi.do)의 현재 목록 조회 예시는 `DrugPrdtPrmsnInfoService08/getDrugPrdtPrmsnInq08`입니다. 기상청 주소의 기관 이름만 바꿔 쓰는 것이 아닙니다.

| 비교 | 기상청 초단기실황 | 식약처 의약품 목록 조회 |
| --- | --- | --- |
| 원하는 자료 | 격자·시각의 관측값 | 품목명 등 조건에 맞는 허가정보 |
| 조건 예 | `nx`, `ny`, `base_date`, `base_time` | `item_name`(품목명), `entp_name`(업체명) 등 명세의 조건 |
| JSON 지정 | `dataType=JSON` | `type=json` |
| 출력 예 | `category`, `obsrValue` | `ITEM_NAME`, `ENTP_NAME`, `ITEM_PERMIT_DATE` |

식약처의 현재 승인 범위·상세기능·필수값은 그 페이지에서 확인합니다. 허가정보는 복용 적합성이나 개인별 의학적 판단을 대신하지 않습니다. 다른 기관도 **이용 목적 → 상세기능 → 요청변수 → 응답 항목 → 앱 표시** 순서로 명세를 읽습니다.

## 8. 짧게 바꿔 보고 확인하기

원래 활동지의 자료 확보·구현·검증 기록에 필요한 내용을 이어 적습니다. 추가 제출물은 없습니다.

- 요청 URL에서 **기본 주소·상세기능·인증·조회조건**을 구분해 설명할 수 있나요?
- 필수값과 형식, 선택값을 생략했을 때의 기본값을 명세에서 확인했나요?
- 실제 응답의 목록 경로·필드·단위를 확인하고 원문 한 건과 화면 값을 비교했나요?
- **조건 하나만 바꿔** 다시 요청하고, 응답의 지역·기준시각과 필요한 항목을 비교했나요?
- 실패했다면 **실제 오류**로 원인을 좁혔나요? 아직 확인하지 못한 내용도 구분했나요?
- 앱에 **실제 자료·출처·관측 기준시각·조회시각**이 표시되나요? 저장 파일이면 실시간이 아님을 알렸나요?
- 공개 코드·AI 대화·활동지·오류 캡처에 실제 키가 남지 않았나요?
