Project 1. 나만의 이미지 분류 AI 웹앱

🎯 Mission

우리 생활의 작은 문제를 해결하는 이미지 분류 AI를 만들어라.

거창할 필요 없습니다. “내 물병과 친구 물병이 자꾸 섞인다”, “분리수거할 때 이게 플라스틱인지 헷갈린다”처럼 교실·집·학교에서 진짜로 겪는 작은 불편함에서 시작하세요. (약 5~7차시)

  1. 생활 속 문제 발견

    모둠별로 “이미지로 구분할 수 있는 작은 문제”를 하나 찾습니다. AI에게 시킬 일은 결국 사진을 보고 무엇인지 구분하는 것입니다.

    📚 데이터란 무엇인가

    AI가 학습하는 재료를 데이터라고 합니다. 이 프로젝트에서 데이터는 곧 ‘사진’입니다. 좋은 문제는 곧 좋은 데이터를 모을 수 있는 문제입니다. 사진으로 찍어서 눈으로 구분이 되는 문제인지 먼저 점검하세요.

  2. 대상 사용자 정하기

    이 AI는 누구를 위한 것인가요? 나 자신인가요, 같은 반 친구들인가요, 급식실을 이용하는 전교생인가요? 대상 사용자에 따라 데이터를 얼마나 다양하게 모아야 하는지가 달라집니다.

  3. AI가 무엇을 인식해야 하는지 결정

    문제를 풀기 위해 AI가 사진에서 정확히 무엇을 구별해야 하는지 한 문장으로 정리합니다. (예: “플라스틱류인지 종이류인지 구별한다”)

  4. 클래스 설계

    AI가 구분해야 할 범주(클래스)가 몇 개이고 각각 무엇인지 정합니다. 최소 2개 이상, 서로 눈으로 확실히 구분되도록 설계하세요. 애매한 클래스는 나중에 반드시 문제를 일으킵니다.

    📚 클래스와 레이블

    클래스는 AI가 구분해야 할 범주(카테고리)입니다. 레이블은 각 데이터(사진)에 붙이는 정답 이름입니다. “이 사진은 Class 1(플라스틱)이다”라고 붙이는 이름표가 레이블입니다.

  5. 데이터 촬영 계획

    클래스별로 최소 30~50장씩 촬영할 계획을 세웁니다. 각도, 배경, 조명, 거리를 다양하게 바꿔가며 찍을 방법을 정하세요.

    📚 특징(feature) · 훈련 데이터

    AI는 사진 전체를 사람처럼 ‘이해’하지 않고, 색깔·모양·질감 같은 특징(feature)의 패턴을 수치로 찾아냅니다. 배경이나 조명처럼 신경 쓰지 않는 요소도 특징으로 잘못 잡힐 수 있어서, 다양한 조건에서 찍는 것이 중요합니다.

    지금 촬영해서 모델을 학습시키는 데 사용할 데이터를 훈련 데이터라고 합니다. 모델의 실력은 훈련 데이터의 양과 다양성에 달려 있습니다.

  6. 1차 모델 학습

    Teachable Machine에 데이터를 업로드하고 학습시킵니다.

    📚 모델

    학습이 끝난 결과물을 모델이라고 부릅니다. “이런 특징을 가진 사진은 Class 1일 확률이 높다”는 판단 기준을 갖게 된 프로그램입니다. 아직 실제로 얼마나 똑똑한지는 다음 단계에서 확인해야 합니다.

  7. 새로운 사람과 환경으로 테스트

    촬영에 참여하지 않은 친구, 다른 배경, 다른 조명에서 모델을 테스트합니다.

    📚 테스트 데이터 · 정확도

    모델을 학습시킬 때 쓰지 않고 성능을 평가하기 위해 따로 남겨둔 데이터를 테스트 데이터라고 합니다. 진짜 실력은 한 번도 보지 못한 데이터로 확인해야 정확합니다.

    테스트 데이터 중 모델이 맞힌 비율을 정확도(Accuracy)라고 합니다. 다만 정확도 하나만으로 모델이 완벽하다고 판단하면 안 됩니다.

  8. 오분류 수집

    친구가 테스트했을 때 틀린 사진들을 모아둡니다. 자연스러운 일입니다 — 이 실패가 이번 프로젝트에서 가장 중요한 순간입니다.

  9. 실패 원인 가설 작성

    “내 사진에서는 100%였는데, 왜 친구 사진에서는 틀렸을까?” 틀린 사진들의 공통점을 찾아 원인 가설을 세웁니다.

    ⚠️ 일반화 · 과적합 · 데이터 편향

    • 일반화(Generalization): 훈련 때 보지 못한 새로운 데이터에서도 잘 작동하는 능력. 우리가 원하는 진짜 목표입니다.
    • 과적합(Overfitting): 모델이 훈련 데이터를 너무 ‘외워버려서’, 새로운 데이터에는 오히려 성능이 떨어지는 현상. 훈련 정확도는 높은데 테스트 정확도가 낮다면 과적합을 의심하세요.
    • 데이터 편향(Bias): 훈련 데이터가 한쪽으로 치우쳐 있으면 모델도 그 치우침을 그대로 배웁니다. (예: 한 사람, 한 배경으로만 찍었다면 다른 사람·다른 배경에서는 성능이 떨어집니다.)

    내 모델이 친구 사진에서 틀린 이유는 이 셋 중 무엇에 가장 가까운가요?

  10. 한 가지 조건 개선

    원인 가설을 바탕으로 딱 한 가지 조건만 바꿉니다. (예: 배경을 다양화한 사진 추가, 부족한 각도 보강, 클래스별 데이터 수 맞추기) 여러 가지를 한꺼번에 바꾸면 무엇이 효과가 있었는지 알 수 없습니다.

  11. 재학습

    개선한 데이터로 모델을 다시 학습시킵니다.

  12. 같은 테스트 데이터로 전후 비교

    8단계에서 썼던 것과 같은 테스트 데이터로 다시 테스트해서 개선 전후를 공정하게 비교합니다.

    ⚠️ 공정한 테스트 지키기

    테스트 데이터를 계속 들여다보면서 그 데이터에 맞춰 모델을 고치면, 더 이상 공정한 테스트가 아닙니다 — 결국 훈련 데이터처럼 ‘외워버린’ 것이기 때문입니다. 비교할 때는 정확도 숫자만 보지 말고 다음도 함께 확인하세요.

    • 어떤 클래스를 어떤 클래스로 자주 틀리는가?
    • 특정 학생이나 배경에서 오류가 집중되는가?
    • 클래스별 테스트 데이터 수가 균형적인가?
    • 모델이 의도한 특징이 아니라 배경을 학습한 것은 아닌가?

  13. 웹앱 제작

    완성된 모델을 Teachable Machine의 Export Model 기능으로 내보내고, 생성형 AI의 도움을 받아 웹페이지를 만듭니다. 웹앱에는 다음이 반드시 포함되어야 합니다.

    • 해결하려는 문제와 대상 사용자
    • 이미지 또는 카메라 입력
    • 클래스별 결과 표시
    • 사용자가 이해하기 쉬운 안내
    • AI가 틀릴 수 있다는 설명
    • 잘 작동하는 조건과 모델의 한계
    • 개인정보 관련 주의사항 (얼굴·신체가 촬영될 경우)

  14. 공유와 발표

    완성한 웹앱을 GitHub Pages 등으로 배포해 다른 모둠과 링크를 공유하고, 서로의 AI를 테스트합니다.

발표 질문

섹션 제목: “발표 질문”

모둠별로 5분 내외로 발표합니다.

  1. 어떤 문제를 풀려고 했고, 대상 사용자는 누구였나요?
  2. 클래스는 어떻게 설계했나요?
  3. 처음 테스트에서 무엇이 실패했고, 원인은 무엇이었나요?
  4. 무엇을 한 가지 바꿔서 얼마나 개선되었나요? (정확도 변화 + 그 외 확인한 것)
  5. 이 모델의 한계는 무엇인가요?

📊 평가 관점

결과물의 화려함보다 다음을 중심으로 평가합니다.

  • 문제 정의의 구체성
  • 데이터 설계의 다양성
  • 테스트의 공정성
  • 실패 원인 분석의 타당성
  • 개선 근거의 명확성
  • 모델 한계에 대한 정직한 설명
  • 전체 과정에 드러난 사고 과정
