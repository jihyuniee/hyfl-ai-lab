## 1. 기본 앱 만들기

기본 앱은 NEIS 급식 API에서 기간별 급식 데이터를 요청하고, JSON 응답의 주요 값을 HTML 화면에 표시합니다. 사용자는 조회 기간과 식사구분을 선택합니다. 화면에는 급식 날짜, 식사명, 메뉴 목록, 칼로리정보, 안내 문구가 표시됩니다.

| 기본 앱 기능 | 사용자가 화면에서 고르는 값 | 화면에 보여 줄 값 |
| --- | --- | --- |
| 기간별 급식 조회 | 조회 시작일, 조회 종료일 | 급식 날짜 |
| 식사구분 선택 | 전체, 조식, 중식, 석식 | 식사명 |

| 칼로리 확인 | 없음 | 칼로리정보 |
| 결과 없음 안내 | 없음 | 안내 문구 |

## 2. 기본 앱에서 확인하기

웹앱을 실행한 뒤 아래 항목을 확인합니다. 이 단계의 확인 기준은 API 요청, 데이터 연결, 화면 표시입니다. 기간을 넓혔다면 전체 건수와 받은 건수를 확인하고, 한 페이지의 일부 결과만 전체 결과처럼 표시하지 않는지도 확인합니다.

| 확인할 기능 | 테스트 방법 |
| --- | --- |
| API 요청 | 조회 버튼을 눌렀을 때 데이터가 불러와지는지 확인 |
| 기간 반영 | 시작일과 종료일을 바꾸면 다른 날짜가 나오는지 확인 |
| 식사구분 반영 | 전체, 조식, 중식, 석식 선택 결과가 달라지는지 확인 |
| 메뉴 줄바꿈 | <code>DDISH_NM</code>의 <code>&lt;br/&gt;</code>이 줄바꿈으로 보이는지 확인 |
| 결과 없음 | 데이터가 없을 때 안내 문구가 나오는지 확인 |
| 출처 표시 | 화면 아래에 NEIS 급식식단정보 출처가 보이는지 확인 |

## 3. 활동지 STEP 6 반영하기

활동지 STEP 6에서 체크한 JSON 이름표는 수정할 재료입니다. 기능 한 줄에 필요한 값부터 고릅니다.

| JSON 이름표 | HTML 화면에서는 | 수정 아이디어 |
| --- | --- | --- |
| <code>MLSV_YMD</code> | 급식 날짜 | 날짜별 카드 제목으로 보여주기 |
| <code>MMEAL_SC_NM</code> | 조식, 중식, 석식 표시 | 식사구분 배지로 보여주기 |
| <code>DDISH_NM</code> | 메뉴 목록, 알레르기 번호 | 메뉴 검색, 알레르기 번호 강조 |
| <code>CAL_INFO</code> | 칼로리 | 기준 칼로리 이상만 보기, 높은 순 정렬 |
| <code>NTR_INFO</code> | 영양정보 | 영양정보 펼쳐보기 |
| <code>RESULT.MESSAGE</code> | 데이터가 없을 때 안내 문구 | 결과 없음 문구를 친절하게 바꾸기 |

## 4. 요청인자와 앱 필터 구분하기

요청인자는 API 서버에 보내는 조건입니다. 앱 필터는 데이터를 받은 뒤 JavaScript가 다시 고르는 조건입니다.

| 구분 | 예시 | 설명 |
| --- | --- | --- |
| API 요청인자 | <code>MLSV_FROM_YMD</code>, <code>MLSV_TO_YMD</code>, <code>MMEAL_SC_CODE</code> | API 주소에 넣어 서버에 보내는 값 |
| 앱 필터 | 메뉴 검색어, 알레르기 번호, 칼로리 기준값 | API 응답을 받은 뒤 앱 안에서 고르는 값 |

“급식에 케이크가 언제 나왔는지 찾고 싶다”는 조건은 메뉴 검색 기능입니다. API는 기간별 급식 데이터를 요청하고, 앱은 받은 <code>DDISH_NM</code> 값에서 <code>케이크</code>라는 글자를 찾아 화면에 표시합니다.

## 5. API 키가 코드에서 쓰이는 위치

HTML 앱은 JavaScript 코드 안에서 API 주소를 만들고 데이터를 요청합니다. 지난 시간에 확인한 값이 코드의 재료가 됩니다.

~~~js
const API_KEY = "수업용_인증키";
const OFFICE_CODE = "B10";
const SCHOOL_CODE = "7010259";
const API_URL = "https://open.neis.go.kr/hub/mealServiceDietInfo";
~~~

사용자가 화면에서 기간과 식사구분을 선택하면 앱은 그 값을 API 요청 주소에 넣습니다. 서버가 JSON 응답을 보내면 앱은 <code>row</code> 안에서 <code>MLSV_YMD</code>, <code>DDISH_NM</code>, <code>CAL_INFO</code> 같은 값을 찾아 화면에 표시합니다.

~~~js
const params = new URLSearchParams({
  KEY: API_KEY,
  Type: "json",
  pIndex: "1",
  pSize: "100",
  ATPT_OFCDC_SC_CODE: OFFICE_CODE,
  SD_SCHUL_CODE: SCHOOL_CODE,
  MLSV_FROM_YMD: "20261001",
  MLSV_TO_YMD: "20261031",
});
~~~

<Callout kind="caution" title="수업용 API 키 사용 범위">수업용 API 키는 교사가 안내한 범위에서 사용합니다. 오늘 제출 파일은 교실 안에서 확인하고, 공개 GitHub Pages나 공개 저장소에 올릴 때는 실제 키를 제거합니다. 키를 제거한 파일만으로는 인증 요청이 실행되지 않으므로, 공개 실행에 필요한 서버 연결 등은 선생님과 확인합니다.</Callout>

## 9. 팀 프로젝트로 이어가기

### 공공데이터와 AI로 우리 주변의 문제 해결하기

오늘 만든 급식 앱은 최종 프로젝트를 위한 작은 연습입니다. 팀 프로젝트에서는 관심 분야에서 문제를 발견하고, 공공데이터로 현재 상태를 살펴봅니다. 분석에서 얻은 인사이트를 바탕으로 사용자의 판단이나 행동을 돕는 웹앱을 기획·구현합니다.

<Callout kind="mission" title="우리 팀의 미션">우리 주변의 문제를 공공데이터로 탐구하고, 분석에서 얻은 인사이트를 바탕으로 사람들에게 도움이 되는 서비스를 기획·구현합니다.</Callout>

다음은 조사 전의 아이디어 예시입니다. 실제 사용자 상황과 데이터 항목을 확인한 뒤, 출발점으로 삼아 우리 팀의 주제를 정해 봅시다. 각 팀은 **누구의 어떤 판단이나 행동을 돕는 앱인지**를 구체적으로 설명합니다.

| 출발점과 사용자 문제 | 데이터 활용 방식 | 서비스 예시 |
| --- | --- | --- |
| 생활 속 불편함: 통학하는 학생이 필요한 교통정보를 여러 곳에서 찾아야 한다. | 정류장·노선 등 공공 교통자료로 필요한 이동 정보 확인 | 출발지와 목적지 주변의 정류장·노선 정보를 모아 보여 주는 통학 안내 앱 |
| KOSIS 탐색: 지역별 문화시설 차이를 보고, 청소년이 이용할 수 있는 활동을 더 찾아보고 싶다. | 국가통계로 지역 차이를 살펴보고, 실제 시설·프로그램 공공데이터를 함께 확인 | 우리 지역에서 이용할 수 있는 문화활동을 찾아 비교하는 앱 |
| 조건별 생활 데이터: 학생이 날짜별 급식과 알레르기 표시를 함께 확인하고 싶다. | Open API로 기간·학교·식사구분에 맞는 데이터를 요청하고 메뉴 정보 확인 | 날짜와 메뉴 검색어로 급식을 찾고 알레르기 표시를 확인하는 앱 |
| 공식 자료 비교: 지역 주민이 자신에게 맞는 정책·복지 정보를 비교하기 어렵다. | 공공데이터와 공식 안내에서 대상·조건·지역·기준 시점을 확인 | 조건에 맞는 정책의 주요 내용을 비교하고 공식 안내로 연결하는 앱 |

학교 안의 경험이나 친구들의 의견이 궁금할 때는 설문·인터뷰·관찰을 보조 자료로 사용할 수 있습니다. 이번 팀 프로젝트의 중심 근거는 공공데이터와 공식 자료입니다. 설문·인터뷰·관찰에서 알게 된 사용자 상황을 공식 자료로 확인한 현재 상태와 함께 해석합니다.

팀별로 주제와 진행 속도를 정하고, 필요한 단계로 돌아가며 탐구합니다. 중요한 발견과 판단, 방향을 바꾼 이유, AI를 활용하고 검증한 내용, 팀이 의견을 조율한 과정을 하나의 누적 기록에 이어 남깁니다.

마지막에는 **구글 클래스룸에서 배부한 활동지 최종본과 작동하는 웹앱** 두 가지를 제출합니다. 활동지는 구글 클래스룸 과제에 제출하며, AI 활용 기록과 팀원별 돌아보기도 같은 활동지에 포함합니다. 발표는 활동지의 핵심 표·그래프와 웹앱 시연으로 진행하고, 문제를 발견한 이유부터 데이터·인사이트·구현 결과까지 연결하여 설명합니다. 슬라이드는 선택 사항입니다.
