🌱 생각 열기

섹션 제목: “🌱 생각 열기”

여러분이 만든 Teachable Machine 웹앱은 “정확도 92%“라는 숫자를 보여줍니다. 그런데 발표 자리에서 친구가 이렇게 묻습니다.

“92%면 100번 중 8번 틀린다는 거잖아. 어떤 걸 잘 틀려?”

이 질문에 “그냥 가끔 틀려요”라고 답한다면 발표는 거기서 멈춥니다. 하지만 “고양이를 강아지로 착각하는 경우가 대부분이고, 배경이 어두울 때 오류가 몰려 있어요”라고 답한다면 어떨까요?

같은 92%라도 두 대답의 무게는 완전히 다릅니다. 차이를 만드는 것은 데이터를 읽고 이야기로 바꾸는 능력입니다. 오늘은 그 번역 작업을 해 봅니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 프로젝트 결과를 발표하고 팀의 문제 해결 과정을 성찰할 수 있다. [정보]
  • 모델 성능 데이터(정확도, 혼동 행렬)를 시각화하고 발표 언어로 해석할 수 있다. [인공지능]

선수학습 확인

섹션 제목: “선수학습 확인”
  • 14차시: 웹앱을 GitHub Pages 등으로 배포하는 방법을 배웠습니다.
  • 15차시: 모델의 정확도(accuracy), 클래스별 성능을 확인하는 화면을 다뤘습니다.
  • 혼동 행렬(confusion matrix): 모델이 “실제 정답”과 “예측한 답”을 어떻게 짝지었는지 보여주는 표. 어떤 클래스를 어떤 클래스로 착각하는지 한눈에 드러납니다. [인공지능]

탐구 활동

섹션 제목: “탐구 활동”

탐구: 우리 모델의 오답에는 규칙이 있을까?

섹션 제목: “탐구: 우리 모델의 오답에는 규칙이 있을까?”

  • 준비물: 팀이 만든 웹앱, 테스트용 이미지/소리 데이터 20개, 기록지(아래 표)

  • 과정:

    1. 팀 웹앱에 테스트 데이터 20개를 하나씩 입력합니다.
    2. 각 입력의 실제 정답과 모델 예측을 아래 표에 기록합니다.
    3. 틀린 경우 “어떤 클래스를 어떤 클래스로 착각했는지” 표시합니다.
    4. 틀린 데이터들의 공통점을 찾습니다. (밝기, 각도, 배경 소음 등)

  • 결과 예측: “틀린 데이터는 무작위로 흩어져 있을까요, 아니면 특정 조건에 몰려 있을까요?”

  • 토의: “우리 모델이 자주 헷갈리는 두 클래스는 무엇인가요? 왜 그 둘을 헷갈릴까요? 데이터를 더 모은다면 어떤 데이터를 모아야 할까요?” [인공지능] [정보]

대부분의 팀은 오답이 무작위가 아니라 특정 클래스 쌍에 몰려 있다는 사실을 발견합니다. 이것이 다음 핵심 개념으로 이어집니다.

핵심 개념

섹션 제목: “핵심 개념”

개념 1. 혼동 행렬 — 성능을 “번역”하는 표 [인공지능]

섹션 제목: “개념 1. 혼동 행렬 — 성능을 “번역”하는 표 [인공지능]”

  • 정의: 혼동 행렬은 각 행이 “실제 정답 클래스”, 각 열이 “모델 예측 클래스”인 표입니다. 대각선(정답=예측)에 값이 몰릴수록 좋은 모델입니다.

  • 비유: 혼동 행렬은 마치 시험 오답 노트와 같습니다. 총점(정확도)만 보면 어디가 약한지 모르지만, 오답 노트를 보면 “나는 특히 3번 유형을 자주 틀린다”가 드러납니다.

아래는 강아지/고양이/토끼 3-클래스 모델의 예시 혼동 행렬입니다.

실제＼예측강아지고양이토끼
강아지1820
고양이5141
토끼0119

이 표에서 고양이를 강아지로 5번 착각한 것이 가장 큰 오류입니다. “정확도 85%“라는 숫자보다 이 한 칸이 훨씬 많은 정보를 줍니다.

flowchart LR
  A[정확도 85%] -->|숫자만| B[어디가 약한지 모름]
  C[혼동 행렬] -->|패턴 발견| D["고양이→강아지<br/>오류 집중"]
  D --> E[개선 방향:<br/>고양이 데이터 추가]

개념 2. 발표 = 데이터를 이야기로 번역하기 [정보]

섹션 제목: “개념 2. 발표 = 데이터를 이야기로 번역하기 [정보]”

  • 정의: 좋은 프로젝트 발표는 “무엇을 만들었다”에서 멈추지 않고, 문제 → 과정 → 데이터 근거 → 배운 점의 흐름을 갖춘 하나의 논리 구조입니다.

  • 비유: 발표는 마치 요리 소개와 같습니다. 완성된 요리(웹앱)만 보여주는 것이 아니라, 왜 이 요리를 골랐고(문제), 어떤 재료로 어떻게 만들었으며(과정), 맛 평가는 어땠는지(데이터), 다음엔 뭘 바꿀지(성찰)를 함께 전합니다.

발표 슬라이드는 다음 5장 구조를 권장합니다.

슬라이드담을 내용근거 교과
1. 문제 정의왜 이 앱을 만들었나[정보]
2. 데이터·모델어떤 데이터로 몇 개 클래스를 학습했나[인공지능]
3. 성능 분석정확도 + 혼동 행렬 시각화[인공지능]
4. 시연실제 동작 데모[정보]
5. 성찰한계와 개선 방향[정보]+[인공지능]

🌉 교과 간 연결 다리

섹션 제목: “🌉 교과 간 연결 다리”

혼동 행렬은 [인공지능] 의 도구이지만, 그 자체로는 숫자 표일 뿐입니다. 이 표를 [정보] 의 발표 논리에 얹으면 “성능 분석 슬라이드”의 핵심 근거가 됩니다.

번역의 예시 [인공지능] 혼동 행렬 데이터 → “고양이→강아지 오류 5건” [정보] 발표 문장 → “우리 모델은 털 색이 비슷한 고양이를 강아지로 착각하는 경향이 있어, 다음엔 조명이 다양한 고양이 사진을 추가하려 합니다.”

즉 AI가 생성한 데이터를 정보 교과의 산출물(발표·문서)로 가공하는 지점이 두 교과가 만나는 다리입니다.

다교과 관점 비교

섹션 제목: “다교과 관점 비교”

같은 “모델이 틀렸다”는 현상을 두 교과는 다르게 봅니다.

쟁점인공지능 관점정보 관점
”틀림”의 의미오분류, 손실값 증가사용자에게 잘못된 결과 제공
관심 데이터혼동 행렬, 클래스별 정밀도발표에 쓸 근거, 사용자 영향
개선 방향데이터 추가·재학습기능 수정·안내 문구 추가
최종 목표성능 지표 향상문제를 실제로 해결하는 산출물

가로지르는 질문

섹션 제목: “가로지르는 질문”

“정확도 95%인데 사용자가 불만족하는 앱과, 정확도 80%인데 사용자가 만족하는 앱 중 어느 것이 더 좋은 프로젝트일까요?”

이 질문은 [인공지능](성능 지표)만으로도, [정보](문제 해결·사용자 가치)만으로도 답할 수 없습니다. 두 관점을 모두 동원해야 답할 수 있습니다. 여러분의 팀은 어느 쪽에 무게를 두었나요?

발표 준비 실습 (5단계)

섹션 제목: “발표 준비 실습 (5단계)”

팀별로 아래 순서를 따라 발표 자료를 완성합니다.

1단계 — 데이터 모으기 [인공지능] 탐구 활동에서 기록한 20개 테스트 결과로 혼동 행렬 표를 완성합니다.

2단계 — 시각화 [인공지능]+[정보] 혼동 행렬을 히트맵이나 막대그래프로 바꿉니다. (스프레드시트의 조건부 서식·차트 기능 활용)

3단계 — 한 문장 해석 [정보] “우리 모델은 ______를 ______로 착각하는 경향이 있다”를 데이터 근거로 채웁니다.

4단계 — 5장 슬라이드 구성 [정보] 위 표의 5장 구조에 맞춰 슬라이드를 배치합니다.

5단계 — 리허설 3분 발표 + 1분 질의응답을 팀 안에서 예행연습합니다.

📖 읽을거리

AI 대회의 진짜 승부처

세계적인 데이터 분석 대회 캐글(Kaggle)에서는 상위권 팀과 중위권 팀의 모델 정확도 차이가 1% 미만인 경우가 흔합니다. 그럼에도 순위가 갈리는 이유는 “왜 틀렸는가”를 얼마나 깊이 분석했는가에 있습니다.

우승 팀들은 오답 데이터를 하나하나 뜯어보며 “이 이미지들은 조명이 특이하다” 같은 패턴을 찾아내고, 그에 맞춰 데이터를 보강합니다. 정확도라는 숫자 뒤에 숨은 이야기를 읽어내는 힘 — 그것이 오늘 여러분이 연습한 능력입니다.

정답 확인

1. 좋다. (대각선은 실제=예측, 즉 정답을 의미합니다.)

2. 3번째 슬라이드(성능 분석).

3. 사과를 배로 5번 착각한 것이 가장 큰 오류입니다. (배를 사과로는 1번만 착각.)

4. (예시 답안) [인공지능] 혼동 행렬을 보면 A클래스만 오류가 집중되어 있어, 이는 A클래스의 학습 데이터가 부족하거나 다른 클래스와 특징이 비슷하기 때문일 수 있습니다. 개선 방향은 A클래스의 데이터를 다양한 조건(각도·조명)으로 추가 수집해 재학습하는 것입니다. [정보] 발표에서는 “전체 정확도는 높지만 A를 잘 인식하지 못해, 실제 사용자가 A를 입력하면 불편을 겪을 수 있습니다. 다음 버전에서 A 데이터를 보강하겠습니다”처럼 사용자 영향과 개선 계획을 함께 전달합니다.
