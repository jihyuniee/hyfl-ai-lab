Part 4. AI Agent: 대답하는 AI에서 행동하는 AI로

🗺️ 이 챕터의 교과 결합

섹션 제목: “🗺️ 이 챕터의 교과 결합”
mindmap
  root((Agent<br/>워크플로우<br/>설계))
    정보
      문제 정의
      알고리즘적 분해
      순서도 표기법
    인공지능
      Agent 개념
      도구 호출
      추론과 행동 루프
    연결 다리
      문제를 단계로 쪼개기
      각 단계에 도구 배치

이번 시간은 정보의 “문제 분해와 순서도 설계”라는 도구를, 인공지능의 “Agent 실행 구조”에 결합합니다. 지금까지 배운 Agent가 어떻게 움직이는지 이해했다면, 오늘은 여러분이 직접 움직이는 설계도를 그립니다.

🔍 생각 열기

섹션 제목: “🔍 생각 열기”

여러분이 “이번 주말 부산 여행 계획 짜줘”라고 AI에게 부탁했다고 합시다.

똑똑한 Agent는 이렇게 움직입니다. 먼저 날씨를 검색합니다. 비가 온다면 실내 코스를, 맑으면 해변 코스를 고릅니다. 그다음 KTX 시간표를 조회하고, 맛집을 찾고, 마지막으로 일정표를 정리해 보여줍니다.

여기서 질문 하나. Agent는 이 순서를 누가 정해줬을까요?

챗봇은 “질문 하나 → 답변 하나”로 끝납니다. 하지만 Agent는 목표를 향해 여러 단계를 스스로 밟아 나갑니다. 그 단계의 뼈대, 즉 워크플로우(workflow, 작업 흐름)를 설계하는 것이 오늘의 임무입니다.

🎯 이 단원의 학습 목표

섹션 제목: “🎯 이 단원의 학습 목표”
  • 간단한 문제를 해결하는 Agent의 워크플로우를 목표-단계-도구 구조로 설계할 수 있다.
  • 각 단계에 필요한 도구를 배치하고, 데이터 흐름을 순서도로 시각화할 수 있다.

📚 선수학습 확인

섹션 제목: “📚 선수학습 확인”
  • Agent [인공지능]: 목표를 받아 스스로 판단하고 행동(도구 사용)하는 AI입니다. 대답만 하는 챗봇과 달리 검색·계산·저장 같은 도구를 씁니다.
  • 도구 호출(Tool Calling) [인공지능]: Agent가 웹 검색, 계산기, 데이터베이스 등 외부 기능을 불러 쓰는 것입니다.
  • 문제 분해 [정보]: 큰 문제를 작은 단계로 쪼개는 것입니다. 순서도(flowchart)로 표현합니다.

🧪 탐구 활동

섹션 제목: “🧪 탐구 활동”

탐구: “AI 급식 추천 Agent”를 손으로 굴려보기

섹션 제목: “탐구: “AI 급식 추천 Agent”를 손으로 굴려보기”
  • 준비물: 포스트잇(단계 카드용), 큰 종이 또는 화이트보드, 펜
  • 과정:
    1. 교사가 제시한 목표를 읽습니다. “오늘 급식 메뉴에 어울리는 후식을 추천해줘.”
    2. 이 목표를 이루려면 Agent가 무슨 일을 해야 할까요? 포스트잇 한 장에 한 가지 행동만 적습니다. (예: “급식 메뉴 조회”, “메뉴 영양 분석”, “후식 후보 검색”)
    3. 포스트잇을 종이 위에 순서대로 배열합니다.
    4. 각 단계 옆에, 그 일을 하려면 어떤 도구가 필요한지 적습니다. (예: 급식 API, 계산기, 웹 검색)
  • 결과 예측: “포스트잇이 몇 장 나올까요? 순서를 바꾸면 결과가 달라질까요?”
  • 토의: “‘메뉴 조회’와 ‘후식 검색’의 순서를 바꾸면 왜 안 될까요? 어떤 단계는 앞 단계의 결과가 있어야만 할 수 있나요?”

이 탐구에서 확인한 것처럼, Agent 워크플로우는 ① 행동을 단계로 쪼개고 ② 순서를 정하고 ③ 각 단계에 도구를 붙이는 세 가지 작업입니다. 앞 단계의 결과가 뒤 단계의 입력이 되는 데이터 흐름이 핵심입니다.

💡 핵심 개념

섹션 제목: “💡 핵심 개념”

개념 1: Agent 워크플로우의 3요소 — 목표·단계·도구 [정보] [인공지능]

섹션 제목: “개념 1: Agent 워크플로우의 3요소 — 목표·단계·도구 [정보] [인공지능]”
  • 정의: 워크플로우는 하나의 목표(Goal)를 이루기 위해, 여러 단계(Step)를 순서대로 잇고, 각 단계에 도구(Tool)를 배치한 실행 설계도입니다.
  • 비유: 워크플로우는 마치 요리 레시피와 같습니다. 완성 요리(목표)를 위해, 재료 손질·볶기·간 맞추기(단계)를 순서대로 하고, 칼·프라이팬·저울(도구)을 각 단계에 씁니다.

목표만 있고 단계가 없으면 Agent는 헤맵니다. 단계는 있는데 도구가 없으면 실행할 수 없습니다. 세 요소가 모두 맞물려야 Agent가 스스로 굴러갑니다.

flowchart LR
  G["목표<br/>후식 추천하기"] --> S1["단계 1<br/>급식 메뉴 조회"]
  S1 --> S2["단계 2<br/>영양 분석"]
  S2 --> S3["단계 3<br/>후식 후보 검색"]
  S3 --> S4["단계 4<br/>추천 정리"]
  S1 -.도구.-> T1["급식 API"]
  S2 -.도구.-> T2["계산기"]
  S3 -.도구.-> T3["웹 검색"]

[그림 1-1] 목표에서 출발해 단계로 내려가고, 각 단계에 도구를 붙인 워크플로우.

개념 2: 판단이 들어가는 워크플로우 — 조건 분기 [정보]

섹션 제목: “개념 2: 판단이 들어가는 워크플로우 — 조건 분기 [정보]”
  • 정의: 모든 워크플로우가 일직선은 아닙니다. 상황에 따라 길이 갈리는 조건 분기(branch)가 필요합니다. 순서도에서는 마름모(◇)로 “예/아니오” 판단을 표시합니다.
  • 비유: 조건 분기는 마치 갈림길 표지판과 같습니다. “비가 오는가?”라는 표지판에서 왼쪽(실내)과 오른쪽(야외)으로 길이 나뉩니다.

Agent가 똑똑해 보이는 이유가 바로 이 분기입니다. 검색 결과를 보고 스스로 다음 행동을 선택합니다.

flowchart TD
  A["급식 메뉴 조회"] --> B{"메뉴가<br/>기름진가?"}
  B -->|예| C["가벼운 후식 검색<br/>과일·요거트"]
  B -->|아니오| D["달콤한 후식 검색<br/>케이크·쿠키"]
  C --> E["추천 정리"]
  D --> E

[그림 1-2] 마름모에서 판단하여 길이 갈리는 조건 분기 워크플로우.

섹션 제목: “🌉 교과 간 연결 다리”

정보의 순서도와 인공지능의 Agent 실행 구조는 서로 다른 곳에서 태어났지만 오늘 하나로 만납니다.

구분정보 [정보]인공지능 [인공지능]
무엇을 그리나문제 해결 절차Agent의 행동 계획
단위처리·판단 상자단계(Step)·도구 호출
판단 표현마름모 조건 분기추론 후 도구 선택
결과물순서도실행 가능한 워크플로우

정보의 순서도 문법(상자·화살표·마름모)을 그대로 빌려 오면, Agent의 추상적인 “생각의 흐름”을 눈에 보이는 그림으로 붙잡을 수 있습니다. 순서도는 Agent를 설계하는 공용 언어입니다.

🔀 가로지르는 질문

섹션 제목: “🔀 가로지르는 질문”

“Agent에게 판단을 맡기는 것과, 우리가 순서도로 미리 길을 정해주는 것 중 무엇이 더 좋을까요?”

이 질문은 정보 하나로도, 인공지능 하나로도 답할 수 없습니다. 정보의 관점(정해진 절차가 안전하다)과 인공지능의 관점(스스로 판단해야 유연하다)을 둘 다 꺼내야 답할 수 있습니다. 여러분이라면 어느 쪽 도구를 언제 쓰겠습니까?

🛠️ 따라하기: 우리 팀의 Agent 워크플로우 설계 (AI LAB)

섹션 제목: “🛠️ 따라하기: 우리 팀의 Agent 워크플로우 설계 (AI LAB)”

이제 팀별로 직접 설계합니다. 다이어그램 산출물을 만드는 것이 목표입니다.

Step 1: 문제 정하고 목표 문장 쓰기 [정보]

섹션 제목: “Step 1: 문제 정하고 목표 문장 쓰기 [정보]”

해결하고 싶은 문제를 하나 고릅니다. 목표는 한 문장으로 씁니다.

항목팀 기록
우리가 고른 문제
한 문장 목표
성공 판단 기준

좋은 목표 예시: “내일 우리 학교 근처 미세먼지 상태를 확인해서, 운동장 체육이 가능한지 알려준다.”

Step 2: 목표를 단계로 쪼개기 [정보]

📖 읽을거리

섹션 제목: “📖 읽을거리”

ReAct: 생각하고 행동하기

2022년 연구자들은 AI가 문제를 풀 때 “생각(Reason) → 행동(Act)“을 번갈아 반복하면 훨씬 똑똑해진다는 것을 발견했습니다. 이를 ReAct라고 부릅니다.

예를 들어 “에펠탑 높이의 두 배는?”이라는 질문에, AI는 이렇게 움직입니다. 생각: “높이를 검색해야겠다.” → 행동: 검색. → 생각: “324m구나. 2를 곱하자.” → 행동: 계산. 이 “생각-행동 루프”가 바로 오늘 여러분이 그린 워크플로우의 뿌리입니다. 여러분은 이미 최신 Agent의 원리를 손으로 설계한 셈입니다.
