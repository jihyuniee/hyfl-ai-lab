# HYFL 학생 작품전 운영

교과서의 `/exhibition/` 아래 전체·공공데이터·Teachable Machine 전시를 운영합니다. 별도 서버나 API 키 없이 기존 GitHub Pages에 통합됩니다. 작품이 없으면 신청 안내를 보여주며 예시를 실제 작품으로 전시하지 않습니다.

## 제출과 공개

학생은 GitHub 로그인 후 전시 신청서를 제출합니다. 팀명으로 소개하고 학생 실명·API 키·개인정보를 제외합니다. 신청 자체는 공개 GitHub 이슈이므로 승인 전에도 저장소에서 읽을 수 있다는 점을 안내합니다.

1. 저장소 Issues에서 `[작품전]` 신청을 엽니다.
2. 실행 링크를 로그아웃 상태로 확인하고, 소개·출처·대표 화면·팀원 공개 동의를 확인합니다.
3. **저장소 소유자 `jihyuniee` 계정**으로 **Close as completed**를 선택하면 승인됩니다. 학생이 직접 닫거나 `not planned`로 닫은 신청은 전시되지 않습니다.
4. Actions의 `Build and deploy to GitHub Pages`가 완료되면 전시관에 반영됩니다. 재개방하면 전시에서 내려갑니다.
5. 승인 후 신청 본문을 편집하면 자동으로 다시 열어 재검토하고 전시에서 내립니다. 확인 후 다시 `Close as completed` 하세요. 공개되지 않는 경우 필수 항목·HTTPS 실행 주소·제작 연도(네 자리)·공개 확인 체크를 점검합니다.

작품 내용은 이슈에 지속 보관됩니다. 빌드마다 API에서 확인된 작품을 읽어 `src/data/exhibition.json`을 생성합니다. 생성 파일을 수동 편집하지 않습니다. GitHub 장애 시 기존 배포는 유지되며 새 배포가 실패합니다. Actions에서 실패 원인을 확인하고 재실행할 수 있습니다.

## 관람과 피드백

관람·웹앱 체험에는 로그인하지 않습니다. 의견은 각 작품의 제출 이슈 댓글에 남기며 **GitHub 로그인**이 필요합니다. 공개 댓글이므로 개인정보를 적지 않도록 안내합니다. 저장소 운영자는 부적절한 댓글을 관리할 수 있습니다.

학생·교사·외부 관람자는 누구의 문제를 해결하는지, 직접 사용한 장점, 개선 제안을 남깁니다. 관람 의견은 공식 심사 점수와 구분합니다. 현재 버전에는 자동 점수 집계·수상 순위·로그인 없는 평가 설문이 없습니다. 참여자의 댓글이 자동으로 검증된 교사/외부 심사 의견이 되는 것은 아닙니다.

최종 평가가 필요하면 별도의 공통 심사 기준으로 운영합니다. 학생은 받은 의견을 반영한 내용과 반영하지 않은 이유를 활동지에 기록합니다.
