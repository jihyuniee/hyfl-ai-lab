목표는 멋진 웹앱을 만드는 것이 아니라 **데이터 → 학습 → 모델 → 테스트 → 실패 → 개선**의 과정을 직접 경험하는 것입니다.

## 이번 프로젝트에서 꼭 발견해야 할 것

> **AI의 판단은 마법이 아니라 데이터와 학습의 결과다.**

AI가 틀렸다면 "AI가 바보라서"라고 끝내지 않습니다. 어떤 데이터를 학습했고, 테스트 상황은 무엇이 달랐으며, 무엇을 개선하면 결과가 달라지는지 살펴봅니다.

<Steps>
	<Step title="작은 분류 문제 정하기">사진으로 구별할 수 있는 두 가지 이상의 대상을 정합니다. 거창한 사회문제일 필요는 없습니다. 이번 프로젝트의 목적은 머신러닝 원리를 경험하는 것입니다.</Step>
	<Step title="클래스 정하기">AI가 구분해야 할 범주를 정합니다. 서로 눈으로 구별할 수 있는 범주인지 확인합니다.</Step>
	<Step title="데이터 수집">각 클래스의 사진을 여러 각도, 거리, 배경, 조명에서 모읍니다.</Step>
	<Step title="첫 번째 모델 학습">수집한 데이터로 이미지 분류 모델을 학습시킵니다.</Step>
	<Step title="훈련 때와 비슷한 환경에서 테스트">먼저 익숙한 조건에서 결과를 확인합니다.</Step>
	<Step title="새로운 환경에서 테스트">다른 사람, 배경, 거리, 조명 등 학습 때와 다른 조건에서 테스트합니다.</Step>
	<Step title="오분류 찾기">틀린 결과를 실패로 숨기지 말고 모읍니다. 이번 활동에서 가장 중요한 데이터입니다.</Step>
	<Step title="왜 틀렸는지 가설 세우기">배경을 외웠는지, 데이터가 한쪽으로 치우쳤는지, 특정 각도가 부족했는지 추론합니다.</Step>
	<Step title="데이터 한 가지 개선">가설에 따라 데이터 조건 하나를 바꿉니다.</Step>
	<Step title="재학습과 비교">같은 테스트를 다시 하고 결과가 어떻게 달라졌는지 비교합니다.</Step>
	<Step title="원리 설명하기">내 모델의 경험을 이용해 'AI가 학습한다'는 말을 자신의 말로 설명합니다.</Step>
</Steps>

## 프로젝트 속 핵심 개념

<Callout kind="concept" title="데이터 · 모델 · 학습">
**데이터**는 AI가 패턴을 찾는 재료입니다.  
**학습**은 데이터 속 패턴을 이용해 판단 기준을 조정하는 과정입니다.  
**모델**은 학습을 마친 뒤 새로운 입력에 결과를 내놓는 시스템입니다.
</Callout>

<Callout kind="concept" title="훈련과 테스트">
모델이 학습할 때 사용한 자료만 잘 맞히는 것으로는 충분하지 않습니다. 학습 때 보지 못한 새로운 상황에서도 잘 작동하는지 확인해야 합니다.

새로운 상황에서도 잘 작동하는 능력을 **일반화**라고 합니다.
</Callout>

<Callout kind="caution" title="데이터 편향과 과적합">
한 사람, 한 배경, 한 각도처럼 비슷한 데이터만 반복해서 학습하면 모델이 우리가 원한 대상이 아니라 엉뚱한 특징을 학습할 수 있습니다.

훈련 데이터에서는 잘하지만 새로운 상황에서 갑자기 성능이 떨어진다면 데이터의 다양성과 과적합 가능성을 의심해봅니다.
</Callout>

## 최종 기록

완성된 웹앱 링크는 필수가 아닙니다. 다음 내용을 기록하면 충분합니다.

- 내가 정한 분류 문제와 클래스
- 어떤 데이터를 모았는지
- 처음 모델이 잘한 상황
- 처음 모델이 실패한 상황
- 실패 원인에 대한 가설
- 어떤 데이터를 바꾸었는지
- 재학습 후 무엇이 달라졌는지
- 이 경험을 통해 이해한 'AI가 학습한다'는 의미
