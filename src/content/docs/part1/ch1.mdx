## 인공 + 지능, 말뜻부터 살펴보기

**인공(人工)**은 사람이 만들었다는 뜻이고, **지능(知能)**은 정보를 받아들이고 배우며, 추론하고 판단하여 문제를 해결하는 능력을 뜻합니다.

그렇다면 사람이 지능을 사용한다는 것은 구체적으로 어떤 일을 하는 것일까요?

<FlowDiagram items={[
	{ ko: '인식', en: '무엇인지 알아보기' },
	{ ko: '추론·예측', en: '정보와 패턴으로 예상하기' },
	{ ko: '판단·결정', en: '선택하고 결정하기' },
	{ ko: '행동·문제 해결', en: '결과를 실제 작업으로 옮기기' },
]} />

여기에 **학습**도 매우 중요합니다. 사람은 경험과 정보를 통해 배우고, 그 경험을 다음 판단에 활용합니다.

> 인식 → 추론·예측 → 판단 → 행동처럼 이어지기도 하고,  
> 경험이 쌓이면서 다시 학습이 일어나기도 합니다.

이 과정이 언제나 하나의 고정된 순서로 일어나는 것은 아닙니다. 중요한 것은 인간의 지능에는 **인식, 학습, 추론, 예측, 판단, 생성, 문제 해결**처럼 여러 기능이 있다는 점입니다.

<Callout kind="concept" title="인공지능(AI)이란?">
**인공지능(AI)은 인간의 지능적 활동과 관련된 기능을 컴퓨터 시스템이 수행하도록 구현하는 기술과 연구 분야입니다.**

인식, 학습, 추론, 예측, 판단, 생성, 문제 해결 등 다양한 기능이 포함될 수 있습니다.
</Callout>

AI가 인간과 똑같이 생각한다는 뜻은 아닙니다. 실제 AI 시스템은 **데이터, 규칙, 통계·확률, 학습된 패턴, 계산과 여러 도구**를 이용하여 결과를 만듭니다.

<Callout kind="think" title="한 문장으로 바꿔 말해보기">
‘인공지능’을 아직 교과서 문장 그대로 외우지 마세요.

**“컴퓨터가 어떤 일을 할 때 우리는 그것을 지능적인 활동이라고 볼 수 있을까?”**를 생각하며 자기 말로 설명해봅시다.
</Callout>

## 자동으로 움직이면 모두 AI일까?

### 상황 A — 정해진 알람

```text
IF 현재 시간이 오전 7시라면
THEN 알람을 울린다.
```

사람이 미리 정한 조건을 그대로 실행합니다. 입력된 시간이 같으면 언제나 같은 방식으로 작동합니다.

### 상황 B — 나에게 맞춰 시간을 정하는 알람

어떤 시스템이 다음과 같은 정보를 계속 살펴본다고 생각해봅시다.

- 평소 내가 일어나는 시간
- 오늘 첫 일정의 시작 시간
- 집에서 학교까지 걸리는 예상 시간
- 최근 수면 패턴

그리고 이 정보를 바탕으로 **“오늘은 6시 42분쯤 깨우는 것이 좋겠다”**고 예상한다면 어떨까요?

<Callout kind="discuss" title="두 알람의 차이는 무엇일까?">
A와 B는 모두 자동으로 작동합니다.

그런데 두 시스템은 **어떤 정보를 사용하고, 결과를 어떻게 결정하는지**에서 어떤 차이가 있을까요?
</Callout>

단순히 자동으로 실행된다고 해서 모두 AI라고 부르지는 않습니다. 그러나 여기서 한 가지 주의할 점이 있습니다.

<Callout kind="caution" title="AI = 반드시 스스로 학습하는 프로그램?">
**그렇지는 않습니다.**

AI를 구현하는 방법에는 사람이 지식과 판단 규칙을 직접 설계하는 **규칙 기반 방식**도 있고, 데이터를 이용해 패턴을 학습하는 **학습 기반 방식**도 있습니다.

따라서 **‘데이터를 학습하는가?’는 현대 AI를 이해하는 매우 중요한 기준이지만, AI 전체를 가르는 유일한 기준은 아닙니다.**
</Callout>

## AI는 규칙을 어떻게 알게 될까?

컴퓨터가 어떤 판단을 하려면 결국 **어떤 기준으로 결과를 정할 것인지**가 필요합니다.

그 기준을 만드는 대표적인 두 가지 방식을 비교해봅시다.

### A. 사람이 규칙을 직접 만든다면

```text
IF 제목에 ‘당첨’이 있고
   본문에 ‘무료’라는 단어가 여러 번 나오면
THEN 스팸으로 분류한다.
```

사람이 문제를 분석한 뒤 판단 규칙을 직접 만들어 프로그램에 넣습니다.

### B. 여러 사례를 보여주고 패턴을 찾게 한다면

```text
스팸 메일 사례 + 정상 메일 사례
          ↓
        학습
          ↓
       분류 모델
          ↓
새로운 메일 → 스팸일 가능성 예측
```

사람이 모든 판단 규칙을 하나하나 적어주는 대신 많은 사례를 제공하고, 컴퓨터가 데이터에 나타난 패턴을 이용하도록 합니다.

| 비교 | 규칙 기반 방식 | 학습 기반 방식 |
| --- | --- | --- |
| 판단 기준 | 사람이 규칙을 직접 설계 | 데이터에서 패턴을 학습 |
| 사람이 주로 준비하는 것 | 지식과 규칙 | 데이터와 학습 방법 |
| 새로운 상황 처리 | 작성된 규칙의 범위에 크게 의존 | 학습한 패턴을 바탕으로 새로운 입력을 예측 |
| 중요한 질문 | 규칙을 빠뜨리지는 않았을까? | 어떤 데이터로 무엇을 학습했을까? |

<Callout kind="question" title="누가 규칙을 만들었을까?">
A와 B의 가장 큰 차이를 한 문장으로 말해보세요.

**사람이 직접 규칙을 적은 것과, 데이터에서 패턴을 찾도록 한 것은 어떻게 다를까요?**
</Callout>

이 차이를 이해하면 **머신러닝**이라는 말을 훨씬 쉽게 이해할 수 있습니다.

## 인공지능 → 머신러닝 → 딥러닝

인공지능을 구현하는 모든 방법이 머신러닝은 아닙니다. **머신러닝은 인공지능을 구현하는 중요한 방법 가운데 하나**입니다.

```text
┌──────────────── 인공지능 AI ────────────────┐
│                                               │
│      ┌──────── 머신러닝 ML ─────────┐         │
│      │                              │         │
│      │    ┌── 딥러닝 DL ─────┐      │         │
│      │    │                  │      │         │
│      │    └──────────────────┘      │         │
│      └──────────────────────────────┘         │
│                                               │
└───────────────────────────────────────────────┘
```

### 머신러닝 Machine Learning

머신러닝은 사람이 모든 판단 규칙을 하나하나 작성하는 대신 **데이터를 통해 패턴을 학습하도록 하는 방법**입니다.

```text
데이터 → 학습 → 모델 → 새로운 입력 → 예측·분류·추천
```

예를 들어 고양이와 강아지 이미지와 정답을 이용해 학습한 모델은 학습 과정에서 얻은 패턴을 이용하여 **처음 보는 이미지**가 어느 범주에 가까운지 예측할 수 있습니다.

### 딥러닝 Deep Learning

딥러닝은 머신러닝의 방법 가운데 하나로, **여러 층의 인공신경망을 이용해 데이터의 특징과 복잡한 패턴을 학습**하는 방법입니다.

이미지, 음성, 자연어처럼 복잡한 데이터를 처리하는 여러 AI 기술에 널리 사용됩니다.

<Callout kind="think" title="큰 지도 확인">
1. 모든 AI는 딥러닝일까요?
2. 모든 머신러닝은 딥러닝일까요?
3. 딥러닝은 인공지능이라는 큰 분야 안에 포함될까요?
</Callout>

지금은 세부 원리를 외우는 것보다 **AI가 가장 큰 개념이고, 그 안에 머신러닝과 딥러닝이 포함된다**는 관계를 먼저 기억하면 충분합니다.

## 컴퓨터가 ‘학습한다’는 말은 무슨 뜻일까?

사람은 경험의 의미를 이해하며 배웁니다. 그렇다면 컴퓨터의 ‘학습’도 사람의 학습과 똑같을까요?

머신러닝에서 학습은 보통 **주어진 데이터에서 반복적으로 나타나는 관계와 패턴을 찾아, 새로운 입력에 대한 결과를 더 잘 만들어내도록 모델의 내부 값을 조정하는 과정**을 뜻합니다.

즉, 컴퓨터가 교과서를 읽고 의미를 사람처럼 깨닫는다는 뜻으로 ‘학습’이라는 말을 사용하는 것은 아닙니다.

<Callout kind="think" title="곧 직접 확인합니다">
말로만 들으면 여전히 추상적입니다.

곧 작은 이미지 분류 모델을 직접 학습시키고, 일부러 실패하게도 만들어보면서 **‘데이터에서 패턴을 학습한다’는 말이 실제로 무엇을 뜻하는지** 확인합니다.
</Callout>

## 1950년, 앨런 튜링이 던진 질문

컴퓨터가 지능을 가졌다고 말하려면 무엇을 확인해야 할까요?

영국의 수학자 **앨런 튜링(Alan Turing)**은 1950년 논문에서 이 문제를 다루며, 훗날 **튜링 테스트**라고 불리게 된 ‘모방 게임’의 아이디어를 제안했습니다.

상상해봅시다.

```text
나  ←── 글로만 대화 ──→  벽 너머의 상대

상대는 사람일 수도 있고 컴퓨터일 수도 있다.
나는 대화만 보고 그것을 구별해야 한다.
```

대화를 충분히 나눈 뒤에도 사람이 상대가 컴퓨터인지 사람인지 잘 구분하지 못한다면, 우리는 그 컴퓨터의 지능을 어떻게 바라봐야 할까요?

<Callout kind="discuss" title="사람처럼 말한다 = 이해한다?">
**사람처럼 매우 자연스럽고 유창하게 말하는 것과, 그 말의 의미를 실제로 이해하는 것은 같은 일일까요?**

- 같다고 생각한다면, 왜 그런가요?
- 다르다고 생각한다면, 무엇이 더 필요할까요?
</Callout>

튜링 테스트는 ‘지능이 무엇인가’라는 어려운 질문을 **관찰할 수 있는 행동**을 통해 생각해보게 했다는 점에서 중요한 의미가 있습니다.

하지만 사람처럼 그럴듯한 답을 만들어내는 능력만으로 **이해, 의식, 책임까지 모두 증명되는 것은 아닙니다.**

이 질문은 오늘날 생성형 AI를 사용할 때도 계속 중요합니다.

## 지금 우리가 사용하는 AI는 어떤 AI일까?

현재 우리가 일상에서 사용하는 AI는 대부분 **특정한 목적과 범위의 작업을 수행하도록 만들어진 AI**입니다. 흔히 **좁은 AI(Narrow AI)** 또는 전통적으로 **약인공지능**이라고 부릅니다.

‘약’이라는 말은 성능이 낮다는 뜻이 아닙니다. 어떤 특정 작업에서는 사람보다 훨씬 빠르거나 높은 성능을 보일 수도 있습니다.

| 좁은 AI의 예 | 잘하도록 만들어진 작업의 예 |
| --- | --- |
| 얼굴 인식 시스템 | 이미지 속 얼굴의 특징을 비교·인식 |
| 추천 시스템 | 사용자의 이용 패턴을 바탕으로 콘텐츠 추천 |
| 번역 AI | 언어 사이의 문장 변환 |
| 바둑 AI | 바둑 상태를 분석하고 다음 수 선택 |
| 생성형 AI | 텍스트·이미지·코드 등 다양한 결과 생성 |

반면 사람처럼 여러 분야와 새로운 상황을 폭넓게 이해하고, 다양한 문제를 스스로 배우며 해결할 수 있는 범용적인 지능은 보통 **범용 인공지능(AGI)** 또는 문맥에 따라 **강인공지능**이라는 말로 이야기합니다.

<Callout kind="question" title="생성형 AI는 여러 일을 하는데?">
글도 쓰고, 번역도 하고, 코딩도 하고, 질문에도 답하는 생성형 AI는 한 가지 기능만 가진 것처럼 보이지 않습니다.

그렇다면 **‘여러 작업을 할 수 있다’는 것과 ‘사람처럼 세상을 폭넓게 이해하는 범용지능을 가졌다’는 것은 같은 말일까요?**
</Callout>

이 구분의 정확한 경계와 용어는 연구자와 문맥에 따라 다르게 사용되기도 합니다. 이 수업에서는 우선 **현재의 AI가 매우 뛰어난 능력을 보여도 인간의 지능 전체와 그대로 같다고 보아서는 안 된다**는 점을 기억합니다.

## AI가 결과를 내놓으면 그대로 믿어도 될까?

AI는 데이터에서 패턴을 찾고 빠르게 분석·예측할 수 있습니다. 그러나 결과가 나왔다는 것과 **그 결과가 좋은 판단이라는 것**은 다릅니다.

예를 들어 이미지 분류 모델이 어떤 사진을 `고양이 98%`라고 예측했다고 생각해봅시다.

그 숫자만 보고 바로 믿어도 될까요?

- 어떤 이미지로 학습했는가?
- 학습할 때 보지 못했던 새로운 사진에서도 잘 작동하는가?
- 고양이가 아니라 배경이나 촬영 환경을 잘못 학습한 것은 아닌가?
- 이 결과가 틀렸을 때 어떤 문제가 생기는가?
- 실제 상황에서 이 결과를 사용해도 되는가?

<Callout kind="concept" title="이번 학기의 중요한 관점">
**AI는 패턴을 찾고 결과를 제시할 수 있습니다. 사람은 그 결과가 무엇을 의미하는지 맥락 속에서 해석하고, 검증하며, 최종적으로 판단해야 합니다.**
</Callout>

이 관점은 앞으로 이미지 분류, 생성형 AI, AI 서비스 제작을 할 때 계속 다시 등장합니다.

---

## 서비스 이름과 기술 이름을 구분하기

ChatGPT, Gemini, Perplexity 등은 회사가 제공하는 **서비스 또는 제품의 이름**입니다.

반면 다음은 기술이나 모델을 설명하는 **개념의 이름**입니다.

- 인공지능 AI
- 머신러닝 Machine Learning
- 딥러닝 Deep Learning
- 대규모 언어 모델 LLM

서비스의 기능과 내부 구조는 시간이 지나면서 달라질 수 있습니다. 따라서 특정 서비스 하나의 특징을 **인공지능 전체의 특징**이라고 생각하지 않습니다.

---

## 오늘의 정리

<Callout kind="concept" title="오늘 기억할 네 문장">
1. **인공지능**은 인간의 지능적 활동과 관련된 기능을 컴퓨터가 수행하도록 구현하는 넓은 기술 분야이다.
2. AI를 만드는 방법에는 사람이 규칙을 직접 설계하는 방식도 있고, 데이터를 통해 패턴을 학습하는 방식도 있다.
3. **머신러닝**은 데이터에서 패턴을 학습하는 AI의 중요한 방법이고, **딥러닝**은 머신러닝의 한 방법이다.
4. AI가 만든 결과를 실제 상황에서 어떻게 해석하고 사용할지는 사람이 검증하고 판단해야 한다.
</Callout>

<Callout kind="exit" title="활동지에 자기 말로 정리하기">
### 1. 인공지능이란 ______________________________ 이다.

교과서 문장을 그대로 옮기기보다 **오늘 처음 AI를 배우는 사람에게 설명한다는 생각으로** 한 문장을 만들어보세요.

### 2. AI와 일반 프로그램을 구분하려 할 때, 무엇을 확인해보면 좋을까요?

예를 들어 다음 질문들을 떠올릴 수 있습니다.

- 어떤 정보를 입력으로 사용하는가?
- 결과는 어떤 방식으로 결정되는가?
- 사람이 모든 판단 규칙을 직접 정했는가?
- 데이터에서 패턴을 학습하는가?
- 새로운 상황에서도 예측이나 판단을 해야 하는가?

한 가지 질문만으로 모든 AI를 완벽하게 구분할 수는 없습니다. **시스템이 어떤 지능적 기능을 어떤 방식으로 구현하고 있는지** 함께 살펴보는 것이 중요합니다.
</Callout>

## 다음 시간으로 이어지는 질문

오늘 계속 나온 말이 있습니다.

> **“AI는 데이터에서 패턴을 학습한다.”**

그런데 컴퓨터가 학습한다는 것은 실제로 무슨 뜻일까요?

다음 활동에서는 작은 이미지 분류 AI를 직접 만들고,

1. 데이터를 보여주고,
2. 모델을 학습시키고,
3. 처음 보는 데이터로 확인하고,
4. 일부러 틀리게도 만들어봅니다.

그 경험 뒤에 **학습 데이터, 테스트 데이터, 일반화, 과대적합**이라는 개념에 이름을 붙입니다.
