번외 실습: 내 프로젝트에 카카오맵 넣기

이 페이지는 지도 기능이 필요한 팀을 위한 번외 실습입니다. 지금 만드는 프로젝트에 지도 기능을 추가합니다. 아직 프로젝트가 없다면 한 파일짜리 index.html로 시작할 수 있습니다.

🎯 완성할 결과

우리 팀이 선택한 공공데이터의 위치와 필요한 정보를 우리 팀 웹앱의 카카오 지도에 표시합니다. 먼저 가상 연습 위치·실제 자료 아님으로 표시한 세 위치와 클릭 설명으로 지도 연결을 점검하고, 그다음 팀의 실제 자료를 연결합니다.

진행 순서는 내 파일 준비 → 내 배포 주소 확인 → 카카오 설정 → 내 파일에 키 입력 → 지도 연결 점검 → 우리 팀 공공데이터 연결입니다. 교과서를 옆에 열어 두고, 아래 작업은 자신의 파일과 프로젝트에서 진행하세요.

1. 지도를 넣을 내 파일 준비하기

섹션 제목: “1. 지도를 넣을 내 파일 준비하기”

우리 팀 상황에 맞게 A 또는 B 중 하나로 시작합니다. 두 경우 모두 키는 아직 넣지 않고 YOUR_JAVASCRIPT_KEY로 남겨 둡니다.

A. 이미 만드는 프로젝트가 있다면

섹션 제목: “A. 이미 만드는 프로젝트가 있다면”

GitHub의 파일을 읽고 수정할 수 있는 AI 환경을 연결한 팀은 참고: GitHub의 내 코드를 GPT와 수정하기 →의 요청문을 사용합니다. 연결된 저장소의 최신 파일을 읽게 하고, 기존 기능을 유지하면서 지도 기능을 추가하세요. 아래는 파일을 직접 첨부하는 순서입니다.

  1. 현재 정상 작동하는 파일을 별도 폴더에 복사해 원본을 보관합니다.
  2. AI에게 현재 프로젝트 파일을 첨부합니다. HTML이 CSS·JavaScript 파일을 따로 불러온다면 관련 파일도 함께 제공합니다. 사본에 실제 키가 들어 있다면 자리표시자로 바꿉니다.
  3. 아래 요청의 빨간 부분을 우리 프로젝트에 맞게 고쳐 전달합니다. 기존 화면과 기능을 유지하면서 지도 영역만 추가하도록 요청합니다.
  4. 수정본을 확인하고 기존 프로젝트의 파일 구조와 이름에 맞게 적용합니다. 이전 버튼·입력·목록도 작동하는지 눌러 봅니다.
현재 프로젝트에 카카오맵 추가 요청 표시된 부분을 우리 팀의 내용으로 바꾸세요.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

# 구현 조건
1. 현재 파일 구조·디자인·정상 기능·데이터 연결을 유지하며 지도 영역을 추가해줘. 고유한 컨테이너 ID, 명시적인 높이, 지도 영역에 적용할 CSS를 사용해줘.
2. 기존 SDK 사용 여부를 확인해 https://dapi.kakao.com/v2/maps/sdk.js 를 한 번 불러오고 appkey와 autoload=false를 지정해줘. 지도 요소와 SDK가 준비된 뒤 kakao.maps.load에서 초기화해줘.
3. 프레임워크의 브라우저 실행과 컴포넌트 수명 주기에 맞춰 초기화해줘. 지도 탭 표시나 영역 크기 변경 시 relayout을 처리해줘.
4. 브라우저용 JavaScript 키 설정을 const javascriptKey = 'YOUR_JAVASCRIPT_KEY'; 한 곳에 두고 실제 키는 내가 입력하게 해줘. 키 입력 전에는 설정 안내를 표시해줘.
5. 가상 지점 A(37.5651, 126.9821), B(37.5670, 126.9850), C(37.5629, 126.9843)를 표시하고, 클릭 설명에 ‘가상 연습 위치·실제 자료 아님’을 넣어줘. 가상 지점과 실제 팀 데이터는 구분해 관리해줘.
6. 로딩·오류 상태와 지도 출처를 표시해줘. 같은 카카오 앱의 사용 설정 ON, JavaScript 키, 내 웹앱의 프로토콜·호스트·포트로 구성한 SDK 도메인을 확인하도록 안내해줘.

# 결과와 확인 방법
수정할 파일·위치, 적용할 코드와 이유를 알려줘. 추가로 필요한 프로젝트 파일이 있으면 경로와 역할을 구체적으로 요청해줘. 키 값은 마스킹하고 내가 키를 입력할 위치를 알려줘. 같은 웹앱 주소에 다시 배포한 뒤 지도와 기존 기능을 확인하는 순서, 실제 검사 결과와 추가 확인 항목을 정리해줘.

현재 프로젝트의 파일 구조와 기능을 유지하며 지도 영역, SDK 로딩 코드, 가상 마커 기능을 추가합니다. AI가 현재 코드를 확인하도록 파일을 첨부하거나 저장소를 연결합니다.

# 구현할 기능
1. HTML·CSS·JavaScript를 하나의 index.html에 작성하고 프로젝트 제목, 높이가 지정된 지도 영역, 로드 상태를 표시해줘.
2. 브라우저용 JavaScript 키 설정은 const javascriptKey = 'YOUR_JAVASCRIPT_KEY'; 한 곳에 두고, 실제 키는 내가 입력하게 해줘. 자리표시자 상태에서는 설정 안내를 표시하고, 키가 입력되면 SDK를 요청해줘.
3. https://dapi.kakao.com/v2/maps/sdk.js 에 appkey와 autoload=false를 지정해 한 번 불러오고, kakao.maps.load 콜백에서 지도를 초기화해줘.
4. 가상 지점 A(37.5651, 126.9821), B(37.5670, 126.9850), C(37.5629, 126.9843)를 위도·경도 순서로 표시해줘. 마커를 누르면 이름과 ‘가상 연습 위치·실제 자료 아님’ 설명이 열리게 하고, 같은 내용을 글 목록에도 표시해줘.
5. SDK 로딩·오류·시간 초과 상태를 구분하고 카카오 로고와 저작권 표시를 유지해줘. 가상 지점은 지도 연결 점검용으로 구분해줘.

# 결과와 확인 방법
- 저장할 index.html 전체와 키를 입력할 파일·위치를 제공해줘. 화면과 로그의 키 값은 마스킹해줘.
- 같은 카카오 앱의 지도 사용 설정 ON과 JavaScript 키의 SDK 도메인 등록 순서를 안내해줘. 등록값은 내 웹앱 주소의 프로토콜·호스트·사용 중인 포트로 구성해줘.
- 내 배포 주소에서 배경 지도·마커·클릭 설명·출처를 확인하는 순서를 알려줘. 실제 공공데이터 연결은 이 점검 다음 단계로 안내해줘.

직접 확인: 우리 팀이 수정할 파일을 찾을 수 있고, 그 안에 지도 코드와 키 자리표시자가 있습니다. 기존 프로젝트라면 원본도 보관했습니다.

2. 내 웹앱을 배포하고 실제 주소 확인하기

섹션 제목: “2. 내 웹앱을 배포하고 실제 주소 확인하기”

이미 배포한 프로젝트라면 기존 배포 방법으로 수정본을 올리고 실제 웹앱 주소를 엽니다. 새 index.html로 시작하는 팀은 다음 순서로 GitHub Pages 주소를 만듭니다.

  1. GitHub의 + → New repository에서 공개 가능한 연습용 Public 저장소와 README를 만듭니다.
  2. Add file → Upload files로 index.html을 저장소 맨 위에 올리고 Commit changes를 누릅니다.
  3. Settings → Pages → Build and deployment → Source를 Deploy from a branch로 선택합니다.
  4. Branch: main / (root)를 선택하고 Save합니다. 파일을 올린 브랜치가 다른 이름이면 그 브랜치를 선택합니다.
  5. 배포가 끝나면 Visit site로 웹앱을 엽니다. 아직 열리지 않으면 Actions의 배포 상태를 확인합니다.

자세한 절차는 교과서의 GitHub 배포 안내를 참고하세요. 첫 배포에서 키 입력 안내와 지도 영역, 웹앱 주소를 확인합니다.

브라우저 주소창에서 내 웹앱의 실제 주소를 복사합니다. GitHub 저장소의 코드 화면 주소나 AI 미리보기 주소와 구분하세요.

실제로 지도가 실행될 주소 예시카카오에 등록할 SDK 도메인
https://my-team.github.io/our-map/https://my-team.github.io
https://my-team-map.vercel.app/https://my-team-map.vercel.app
http://localhost:3000/index.htmlhttp://localhost:3000

표의 예시를 자신의 배포 주소로 바꿔 확인합니다. 등록값에는 프로토콜과 호스트를 쓰고, /our-map/ 같은 뒤의 경로는 뺍니다. localhost를 사용하면 실제 포트도 포함합니다. Vercel은 지도를 실행할 배포 주소를 기준으로 설정합니다.

직접 확인: 내 웹앱이 열리는 주소와 그 주소에서 뽑은 SDK 도메인을 구분해 적었습니다.

3. 카카오 앱을 켜고 내 도메인 등록하기

섹션 제목: “3. 카카오 앱을 켜고 내 도메인 등록하기”
  1. 카카오디벨로퍼스에 카카오 계정으로 로그인합니다. 처음이면 개발자 등록을 진행합니다.
  2. 앱에서 사용할 앱을 선택합니다. 아직 없다면 이름 등 필수 정보를 입력해 만듭니다.
  3. 그 앱의 카카오맵 → 사용 설정 → 상태를 ON으로 바꿉니다.
  4. 같은 앱에서 앱 설정 → 앱 → 플랫폼 키 → JavaScript 키를 선택합니다.
  5. 해당 키의 JavaScript SDK 도메인에 2단계에서 확인한 내 웹앱의 도메인을 추가하고 저장합니다.
  6. 방금 설정한 JavaScript 키를 복사합니다. 다음 단계에서 내 코드에 넣습니다.

⚠️ 키 복사와 도메인 등록에 더해, 사용 설정 ON을 확인하세요

카카오맵 → 사용 설정 → ON은 별도 설정입니다. disabled OPEN_MAP_AND_LOCAL service 응답이 나오면, 입력한 키가 속한 앱에서 이 설정부터 확인합니다.

선택한 JavaScript 키의 SDK 도메인에 우리 팀 지도가 실행되는 도메인을 등록합니다. 설정 위치는 공식 웹 준비 안내와 키·도메인 설정에서 확인합니다.

앱 정보의 카카오맵 무료 쿼터 표시와 통계 → 쿼터에서 이용량을 확인합니다. 새로 활성화하는 경우 개발자 계정에서 처음 카카오맵 API를 활성화한 앱에 무료 쿼터가 제공됩니다. 추가 앱과 제공량 초과 사용의 조건은 공식 이용 안내에서 확인합니다.

직접 확인: 사용할 앱은 카카오맵 ON이며, 그 앱의 JavaScript 키에 내 도메인이 등록되어 있습니다.

4. 내 파일의 키 한 줄을 바꾸고 다시 배포하기

섹션 제목: “4. 내 파일의 키 한 줄을 바꾸고 다시 배포하기”
  1. 코드 편집기에서 1단계의 내 파일을 엽니다. 찾기 기능으로 YOUR_JAVASCRIPT_KEY를 찾습니다.
  2. 시작 예제라면 파일 아래 <script> 안의 const javascriptKey 줄을 찾습니다. 기존 프로젝트라면 지도 초기화 코드가 있는 파일에서 같은 설정 줄을 찾습니다. 아래 줄의 따옴표 안 자리표시자만 복사한 JavaScript 키로 바꾸고, 따옴표와 세미콜론은 유지합니다.
  1. 파일을 저장합니다. JavaScript가 별도 파일이라면 그 코드가 들어 있는 파일을 수정합니다.
  2. 같은 프로젝트의 같은 파일 위치에 수정본을 올립니다. GitHub Pages라면 기존 index.html을 새 내용으로 교체하고 Commit changes합니다. GitHub 파일 편집기로 키 한 줄을 수정하고 커밋할 수도 있습니다.
  3. 배포가 완료되면 2단계에서 확인한 내 웹앱 주소를 다시 엽니다. 바뀐 내용이 안 보이면 배포 상태와 업로드한 파일을 확인하고 새로고침합니다.

저장소 연동으로 수정한 팀은 커밋 또는 PR의 변경 내역을 확인하고 배포 브랜치에 반영한 뒤 같은 주소에서 결과를 점검합니다.

이 실습에는 브라우저 지도용 JavaScript 키를 사용하고 SDK 도메인을 설정합니다. AI에게 제공할 사본과 활동지에는 키 값을 자리표시자로 바꿉니다.

직접 확인: 수정한 파일이 배포되었고, 자신의 웹앱 주소에서 열립니다.

주소만 있는 자료는 위도·경도를 확보한 뒤 연결합니다. 다른 좌표계의 값은 변환 방법을 확인합니다. 카카오의 new kakao.maps.LatLng(위도, 경도)는 위도, 경도 순서이며 GeoJSON은 [경도, 위도] 순서입니다.

아래는 가상 연습 위치·실제 자료 아님을 전제로 한 4행의 좌표 검사입니다. 위도·경도 열을 골라 좌표 확인하기를 누른 뒤, 거꾸로 선택하거나 빈칸이 있는 행을 비교해 보세요. 앞서 지도에 표시한 가상 위치 3개와는 별도의 자료입니다.

빈 값을 0으로 바꾸면 왜 안 될까요?

JavaScript의 Number('')는 0이 됩니다. 0은 위도·경도 범위 안에 있지만, 원자료에 없던 좌표를 새로 만들어 넣으면 실제와 다른 위치가 생깁니다. 빈 값인지 먼저 확인하고, 값이 있을 때 숫자로 바꿔 검사해야 합니다.

이 연습은 숫자와 범위만 검사합니다. WGS84 위도는 −90~90, 경도는 −180~180입니다. 검사를 통과해도 실제 위치가 맞는지는 원자료·좌표계·지도와 따로 대조해야 합니다. 선택과 결과는 저장되지 않습니다.

# 데이터 연결과 검증
1. 현재 지도·디자인·정상 기능·파일 구조·배포 방식과 데이터 연결을 유지해줘. 원자료의 실제 필드를 위 항목에 대응시켜줘.
2. CSV·JSON 파일은 현재 파일 읽기 방식을 사용하고, 파일 선택 방식에서는 브라우저에서 읽어줘. 데이터 배열과 API는 현재 읽은 결과를 사용해줘. API의 조회 조건·페이지별 응답·가져온 범위·남은 범위를 구분해줘.
3. CSV의 BOM·따옴표 안 쉼표·줄바꿈·빈 값을 처리하는 파서를 사용해줘. JSON·API는 실제 기록 목록 경로와 필드 이름을 확인해줘. 기존 API의 인증 방식과 호출 한도를 유지하고, 서버용 비밀키는 서버에서 관리해줘.
4. 위치 필드와 좌표계를 확인하고 검증된 좌표 매핑·변환을 유지해줘. 주소 자료나 미확인 좌표계는 좌표 확보에 필요한 정보와 절차를 먼저 정리해줘. 빈 값·공백·문자·범위 밖 좌표는 제외하고 이유를 표시해줘.
5. 읽은 기록 수, 현재 조건에 해당하는 기록 수, 유효 좌표 기록 수, 위치 문제로 제외한 기록 수를 구분해줘. CSV는 머리글 다음부터 기록으로 계산하고, 조회 중·실패·완료 상태를 함께 표시해줘.
6. 같은 좌표의 여러 기록은 원자료의 기록 단위대로 유지해줘. 고유 지점 수와 수치 합계는 위에서 지정한 식별·집계 기준에 따라 계산하고 기준을 표시해줘.

# 지도 표시
1. 유효한 WGS84 좌표를 new kakao.maps.LatLng(위도, 경도)에 넣어 표시해줘. 여러 위치는 LatLngBounds와 map.setBounds를 사용하고, 한 위치와 유효 좌표 0건도 처리해줘.
2. 클릭 설명에는 지정한 실제 항목을 textContent로 표시해줘. 지도와 글 목록에 같은 검색·필터 조건을 적용해줘.
3. 실제 자료를 적용할 때 가상 연습 지점을 제거해줘. 자료나 조건이 바뀌면 이전 마커를 setMap(null)로 정리하고 정보창을 닫은 뒤 결과와 건수를 갱신해줘.
4. 선택한 연결 방식에 맞춰 자료 준비·조회 중·조회 실패·빈 결과·필드 불일치·좌표 누락·지도 로드 상태를 안내해줘.
5. 지도 높이를 지정하고 카카오 SDK를 한 번 불러와줘. https://dapi.kakao.com/v2/maps/sdk.js 에 appkey와 autoload=false를 사용하고 kakao.maps.load에서 초기화해줘.
6. 브라우저용 JavaScript 키는 const javascriptKey = 'YOUR_JAVASCRIPT_KEY';로 두어 내가 입력하게 해줘. 카카오 앱의 사용 설정과 내 웹앱의 프로토콜·호스트·포트로 구성한 SDK 도메인을 확인하도록 안내해줘. 실제 키·토큰 값은 마스킹해줘.
7. 카카오 로고·저작권과 자료의 출처·기준일·조회 범위를 표시해줘. 설명과 수치는 원자료의 항목과 기준 시점에 맞춰 작성해줘.

# 결과와 확인 방법
수정할 파일·위치와 적용할 코드, 자료와 지도 항목의 대응 관계를 알려줘. 원자료 3건의 이름·위치·선택한 속성을 대조할 방법을 안내해줘. 좌표 누락과 현재 연결 방식의 파일 재선택·API 재조회·필터 변경을 검증하고, 실시한 검사와 추가 확인 항목을 정리해줘.

CSV 파일 선택 방식에서는 웹앱의 파일 선택 버튼으로 자료를 열고, 선택한 파일 전체를 읽어 계산합니다. 한글이 깨지면 인코딩을 확인합니다. JSON·API를 사용하는 팀은 해당 데이터 연결 방식을 이어 사용합니다.

원자료 3개 항목과 결과 대조하기

섹션 제목: “원자료 3개 항목과 결과 대조하기”

원자료에서 서로 다른 위치의 3행 또는 3개 항목을 골라 지도 위치·식별 이름과 우리 팀이 표시하기로 한 값을 비교합니다. 다음도 직접 확인합니다.

  • 빈 좌표는 잘못된 위치에 점을 만들지 않고 제외한 항목 수에 반영되는가?
  • 자료나 조회 조건을 바꾸면 이전 마커가 정리되는가? 분류 필터를 만들었다면 목록과 지도도 같은 조건을 보여 주는가?
  • 실제로 읽은 현재 조건의 항목 수 = 유효 좌표 항목 수 + 좌표 문제로 제외한 항목 수인가? 행·항목 수, 서로 다른 위치 수, 자료 속 수치의 합계를 구분했는가?
  • 원자료를 일부만 읽었다면 그 범위를 알리고, 출처·기준일·지도 저작권 표시를 유지했는가?

화면의 설명은 원자료의 값과 기준 시점에 근거해 작성합니다. 확인이 필요한 항목은 ‘확인 필요’로 표시합니다.
