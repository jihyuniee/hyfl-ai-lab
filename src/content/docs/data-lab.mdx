<Callout kind="mission" title="공통 미션">영화 데이터로 질문에 따라 그래프가 달라지는 것을 경험하고, 예상·관찰·해석·한계를 구분합니다. 그다음 같은 방법으로 관심 분야의 공공데이터를 탐색합니다.</Callout>

```text
질문 정하기 → 데이터 구조 확인 → 적절한 그래프 선택
→ 예상과 결과 비교 → 사실·해석·원인 가설 구분
→ 다음 질문 → 서비스 기회 발견
```

## 1. 같은 데이터, 다른 질문

하나의 영화 데이터도 무엇이 궁금한지에 따라 다른 그래프가 필요합니다. 그래프 이름을 외우는 것이 아니라 **내 질문에 어떤 표현이 적절한지 판단하는 것**이 목표입니다.

| 알고 싶은 것 | 질문의 예 | 주로 사용할 표현 |
| --- | --- | --- |
| 변화 | 관객 수는 시간에 따라 어떻게 달라졌는가? | 선그래프·영역그래프 |
| 비교 | 어떤 장르의 영화가 가장 많은가? | 막대그래프 |
| 분포 | 대부분의 영화는 어느 관객 구간에 몰려 있는가? | 히스토그램·상자그림 |
| 구성 | 전체 영화에서 장르가 차지하는 몫은 얼마인가? | 도넛·트리맵 |
| 관계 | 개봉일 스크린 수가 많으면 총 관객도 많은가? | 산점도·버블그래프 |

<Callout kind="concept" title="그래프는 장식이 아니라 질문에 대한 표현입니다">같은 데이터도 집계 기준, 기간, 비교 대상, 그래프 종류, 축의 범위에 따라 다른 부분이 강조됩니다. ‘무엇을 보여주고 싶은가’보다 ‘무엇을 확인하려는가’를 먼저 정합니다.</Callout>

## 2. 공통 실습 · 영화 데이터 그래프 도감

[영화 데이터 그래프 도감 2](https://movietest2026.streamlit.app/)에서 216편의 영화 데이터를 여러 그래프로 탐색합니다. 장르가 여러 개인 영화는 첫 번째 장르를 사용했다는 기준도 확인합니다.

### 먼저 예측하기

그래프의 결과를 자세히 보기 전에 적습니다.

1. 가장 많은 영화가 속한 장르는 무엇일 것 같은가?
2. 영화의 총 관객 수는 특정 구간에 고르게 분포할까, 일부 영화에 몰릴까?
3. 개봉일 스크린 수가 많으면 총 관객 수도 반드시 많을까?
4. 예상과 다른 결과가 나오면 무엇을 더 확인해야 할까?

### 모둠별 그래프 탐정

<Steps>
<Step title="질문 확인">담당 그래프가 답하려는 질문과 사용한 변수를 찾습니다.</Step>
<Step title="모양을 말로 옮기기">높고 낮음, 몰림, 퍼짐, 관계, 예외를 수치와 함께 설명합니다.</Step>
<Step title="예상과 비교">처음 예상과 같았던 점과 달랐던 점을 구분합니다.</Step>
<Step title="반례 찾기">전체 경향과 맞지 않는 영화나 집단을 찾아 단정할 수 없는 이유를 적습니다.</Step>
<Step title="그래프 평가">이 질문에 적절한 그래프인지 판단하고 다른 표현으로 바꿀 때 생기는 차이를 생각합니다.</Step>
<Step title="다음 질문 만들기">현재 데이터로 답할 수 없지만 추가로 확인하고 싶은 질문을 만듭니다.</Step>
</Steps>

### GRAPH THINK · 모든 그래프에서 반복하는 여섯 질문

1. 나는 무엇을 예상했는가?
2. 그래프에서 직접 확인한 것은 무엇인가?
3. 예상과 다르거나 예외적인 곳은 어디인가?
4. 이것은 사실인가, 가능한 해석인가, 아직 확인하지 못한 원인 가설인가?
5. 이 그래프만으로 단정할 수 없는 것은 무엇인가?
6. 그래서 다음으로 어떤 데이터와 질문이 필요한가?

> 나는 처음에 **[예상]**이라고 생각했다. 실제 그래프에서는 **[수치·차이·변화]**가 보였다. 특히 **[예외·예상과 다른 점]**이 눈에 띄었다. 이는 **[가능한 의미]**와 관련될 수 있지만 **[원인·한계]**까지는 이 데이터만으로 알 수 없다. 그래서 다음으로 **[새 질문·필요한 데이터]**를 확인하고 싶다.

## 3. 사실·해석·원인 가설을 구분하기

| 구분 | 의미 | 문장 시작 |
| --- | --- | --- |
| 확인한 사실 | 표와 그래프에서 직접 확인한 수치·차이·변화 | “자료에 따르면…” |
| 가능한 해석 | 그 변화가 사람과 사회에 가질 수 있는 의미 | “이는 …와 관련될 수 있다.” |
| 원인 가설 | 왜 나타났는지 추가 확인이 필요한 추측 | “가능한 원인으로 …를 생각할 수 있으나…” |
| 확인 불가 | 현재 자료에 포함되지 않아 판단할 수 없는 내용 | “이 자료만으로는 …를 알 수 없다.” |
| 다음 질문 | 해석과 가설을 더 확인하기 위해 필요한 탐구 | “이를 확인하려면 … 데이터가 더 필요하다.” |

<Callout kind="caution" title="함께 변한다고 원인은 아닙니다">스크린 수와 관객 수가 함께 증가하는 경향이 보여도 스크린 수만이 흥행의 원인이라고 결론 내릴 수 없습니다. 제작비·홍보·배우·평점·개봉 시기·경쟁작처럼 현재 데이터에 없는 변수도 있습니다.</Callout>

## 4. 나만의 8번째 질문

주어진 그래프의 설명을 반복하지 않고, 현재 데이터로 새롭게 확인할 수 있는 질문을 만듭니다.

- 질문은 변화·비교·분포·구성·관계 중 어디에 해당하는가?
- 답에 필요한 행과 열은 무엇인가?
- 어떤 집계나 계산이 필요한가?
- 어떤 그래프가 적절하며 그 이유는 무엇인가?
- 어떤 결과가 나오면 처음 예상과 다르다고 판단할 것인가?

### 이 순간의 생성형 AI 활용

```text
영화 데이터로 [나의 질문]을 확인하려고 해.
1. 이 질문이 변화·비교·분포·구성·관계 중 어디에 해당하는지 설명해줘.
2. 필요한 열과 집계 기준을 먼저 보여줘.
3. 적절한 그래프를 추천하고 다른 그래프보다 나은 이유를 알려줘.
4. 그래프를 만들어도 원자료의 수치와 계산한 수치를 구분해줘.
5. 내가 결과를 검증할 수 있도록 사용한 값과 처리 과정을 설명해줘.
6. 결과에서 말할 수 있는 것과 말할 수 없는 것을 구분해줘.
```

AI가 만든 그래프가 질문과 맞지 않으면 프롬프트를 고쳐 다시 요청합니다. 코드를 모두 외우지는 않지만 사용한 파일, 행의 단위, 열, 필터, 집계, 축, 단위를 팀의 말로 설명할 수 있어야 합니다.

## 5. 공공데이터에 같은 방법 적용하기

영화 데이터에서 연습한 과정을 관심 분야의 공공데이터에 적용합니다. 먼저 서비스 이름을 정하지 않고, 데이터로 확인할 질문과 예상부터 만듭니다.

<Steps>
<Step title="관심과 예상">교육·문화·국제사회·경제·환경·안전·진로·학교생활 중 관심 분야와 예상하는 현상을 적습니다.</Step>
<Step title="질문 분해">막연한 문제를 대상·기간·지역·지표가 있는 작은 질문 세 개로 나눕니다.</Step>
<Step title="공식 데이터 탐색">공공데이터 포털이나 교사가 안내한 MCP에서 관련 데이터와 지표 후보를 찾습니다.</Step>
<Step title="DATA CHECK">출처·수집 기준·행의 단위·변수·단위·결측·한계를 확인합니다.</Step>
<Step title="조건 비교">기간·지역·연령·집단·합계와 비율 중 하나를 바꾸어 결과를 비교합니다.</Step>
<Step title="질문에 맞는 시각화">변화·비교·분포·구성·관계 중 목적에 맞는 그래프를 선택합니다.</Step>
<Step title="GRAPH THINK">예상·사실·예외·해석·한계·다음 질문을 기록합니다.</Step>
<Step title="근거 검증">최종 주장에 사용할 핵심 수치 두 개 이상을 원 통계표에서 다시 확인합니다.</Step>
</Steps>

### MCP로 탐색하는 경우

```text
[연결한 MCP]의 도구를 사용해 다음 질문과 관련된 공식 데이터를 찾아줘.

질문: [대상·기간·지역·지표가 포함된 질문]

1. 어떤 도구와 통계표를 사용할지 먼저 알려줘.
2. 제공 기관, 수집 기준, 기준 시점, 단위, 조회 조건을 표시해줘.
3. 한 행의 단위와 주요 변수를 설명해줘.
4. 결과를 비교 가능한 표로 정리해줘.
5. 질문에 맞는 그래프를 만들고 선택 이유를 설명해줘.
6. 데이터에서 확인한 사실, 가능한 해석, 원인 가설을 구분해줘.
7. 이 데이터만으로 알 수 없는 것과 추가로 필요한 데이터를 알려줘.
8. 원 통계표에서 다시 확인할 핵심 수치를 표시해줘.
```

<Callout kind="concept" title="AI가 공식 데이터를 조회해도 사람의 판단은 남습니다">AI는 관련 통계를 찾고 정리하고 그래프를 만드는 일을 도울 수 있습니다. 그러나 질문에 맞는 지표인지, 조건과 단위가 정확한지, 해석이 과장되지 않았는지, 어떤 문제와 사용자에게 의미가 있는지는 사람이 판단합니다.</Callout>

## 데이터 인사이트 카드

- 처음 예상:
- 확인 질문:
- 데이터 출처와 수집 기준:
- 한 행의 단위와 사용한 변수:
- 선택한 그래프와 선택 이유:
- 그래프에서 직접 확인한 핵심 사실:
- 예상과 달랐던 점 또는 예외:
- 가능한 해석:
- 단정할 수 없는 원인:
- 추가로 필요한 데이터:
- 이 발견과 관련된 사용자·상황:
- 도울 수 있는 결정이나 행동:

<Callout kind="checklist" title="공통 미션 통과 기준">
- 데이터를 보기 전에 자신의 예상과 확인 질문을 작성했다.
- 한 행의 단위와 주요 변수·단위를 설명했다.
- 질문의 유형에 맞는 그래프를 선택하고 이유를 설명했다.
- 그래프에서 확인한 사실과 가능한 해석·원인 가설을 구분했다.
- 예외 사례와 현재 자료의 한계를 찾았다.
- 핵심 수치를 원자료에서 다시 확인했다.
- 분석 결과에서 다음 질문이나 서비스 기회를 한 가지 이상 도출했다.
- AI가 만든 결과에서 직접 확인·수정한 내용을 기록했다.
</Callout>
