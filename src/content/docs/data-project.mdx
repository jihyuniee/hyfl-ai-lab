### 2-2. 비교하고 의미 찾기

질문에 맞는 표·그래프를 만들고 계산 결과를 원자료와 대조합니다.

| 알고 싶은 것 | 해 볼 방법 |
| --- | --- |
| 시간에 따른 변화 | 같은 항목을 연도·월별로 비교하고 선그래프로 표현 |
| 지역·유형별 차이 | 같은 기준으로 집계하고 막대그래프로 비교 |
| 규모를 고려한 비교 | 인구·전체 건수 등 분모를 정해 비율 계산 |
| 두 값의 관계 | 같은 지역·기간으로 맞춘 뒤 산점도 등으로 살펴보기 |

**확인할 것:** 빠진 값과 0을 구분하고, 중복 행과 단위 차이를 확인합니다. 두 자료를 합치면 지역명·기간·집계 기준을 맞춥니다. 두 값이 함께 변한다는 결과만으로 원인을 단정할 수는 없습니다.

> **연습용 가상 수치:** A지역은 시설 10곳·인구 1만 명, B지역은 시설 15곳·인구 3만 명이라고 가정합니다. 시설 수는 B가 많지만 인구 1만 명당 시설 수는 A가 10곳, B가 5곳입니다. 실제 프로젝트에서는 같은 시점과 지역 범위의 자료로 계산합니다.

활동지에는 **확인한 사실 → 팀의 해석 → 앱에 넣을 기능**을 구분해 적습니다. 가설이나 예상은 확인한 사실과 따로 표시합니다.

## STEP 3. 실행하고 검증하기

배포한 웹앱 주소에서 직접 시험하고 활동지에 **입력값·기대 결과·실제 결과·수정 내용**을 기록합니다.

| 시험할 상황 | 확인할 결과 |
| --- | --- |
| 기본 입력 | 원자료에서 찾거나 계산한 결과와 앱의 결과가 일치함 |
| 다른 조건 | 지역·기간·필터를 바꾸면 해당 조건의 자료가 표시됨 |
| 결과 없음·실패 | 빈 결과나 요청 실패를 구분해 안내함 |
| 기존 기능 | 수정 전의 버튼·검색·지도 등이 계속 작동함 |
| 다른 사람의 사용 | 다른 팀원이 설명 없이 입력하고 결과를 찾을 수 있는지 관찰 |
| 휴대기기 | 글자·입력란·버튼을 읽고 사용할 수 있음 |

데이터 화면에는 출처·기준일·단위를 표시합니다. 공개할 파일과 화면에 개인정보와 서버용 비밀키가 포함되어 있지 않은지 확인합니다. 앱이 제공하는 도움과 아직 해결하지 못한 한계도 적습니다.

## STEP 4. AI 활용 기록하기

프로젝트의 방향이나 결과에 영향을 준 사례를 골라 기록합니다.

- **실제로 보낸 요청**과 AI가 도와준 내용
- 원자료·공식 문서·실행으로 **팀이 확인한 내용**
- 팀이 채택·수정·제외한 내용과 이유

같은 기능의 반복 수정은 묶어서 요약할 수 있습니다. 수행하지 않은 활동이나 확인하지 않은 결과를 기록하지 않습니다.

## STEP 5. 기여와 배운 점 정리하고 발표하기

발표는 활동지와 웹앱을 열어 다음 순서로 3분 동안 진행합니다.

1. 누구의 어떤 문제를 해결하려 했는가?
2. 어떤 데이터에서 무엇을 발견했고, 어떤 기능으로 연결했는가?
3. 앱에서 실제로 입력하면 어떤 결과가 나오는가? **직접 시연합니다.**
4. 결과를 어떻게 확인했고, 남은 한계와 개선할 점은 무엇인가?
