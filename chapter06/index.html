이 챕터는 [정보]의 데이터 다루기 기능과 [인공지능]의 지도학습 개념을 결합합니다. 정보 교과가 “데이터를 표로 정리하고 나누는 손”이라면, 인공지능 교과는 “그 데이터로 무엇을 예측할지 정하는 눈”입니다. 오늘의 산출물은 실생활 문제를 예측 유형으로 분류한 표와, 데이터셋을 학습·테스트로 나눈 결과입니다.

🌱 생각 열기

섹션 제목: “🌱 생각 열기”

여러분이 중고 거래 앱을 만든다고 상상해 봅시다. 두 가지 기능을 넣으려 합니다.

  • 기능 A: 사진을 올리면 “이 물건은 정품인가요, 가품인가요?”를 알려 줍니다.
  • 기능 B: 물건 정보를 입력하면 “이 물건은 얼마에 팔릴까요?”를 알려 줍니다.

두 기능은 모두 AI가 예측을 해 줍니다. 그런데 답의 모양이 다릅니다. 하나는 “정품/가품” 같은 꼬리표를 답하고, 하나는 “34,000원” 같은 숫자를 답합니다.

“예측이라고 다 같은 예측이 아닙니다. 답이 ‘이름표’인지 ‘숫자’인지에 따라 AI가 푸는 문제의 종류가 완전히 달라집니다.”

또 한 가지 궁금증이 있습니다. AI가 “이 문제 다 맞혔어요!”라고 자랑할 때, 그 말을 그대로 믿어도 될까요? 시험 문제를 미리 보고 답을 외운 학생과, 처음 보는 문제를 푼 학생 중 누구를 더 믿어야 할까요?

이 단원의 학습 목표

섹션 제목: “이 단원의 학습 목표”
  • 분류 문제와 회귀 문제의 차이를 예시로 설명할 수 있다.
  • 학습 데이터와 테스트 데이터를 나누는 이유를 설명하고, 간단한 데이터셋을 직접 분할할 수 있다.

선수학습 확인

섹션 제목: “선수학습 확인”
  • 지도학습 [인공지능]: 정답(레이블)이 붙은 데이터로 AI를 훈련시키는 방법입니다. 4차시에서 배웠습니다.
  • 특성과 레이블 [정보]: 입력으로 쓰는 열이 특성, 맞혀야 하는 답이 레이블입니다. 표에서 “입력 열”과 “정답 열”로 생각하면 됩니다.
  • 데이터셋 [정보]: 여러 행(데이터 하나하나)과 열(특성)로 이루어진 표입니다.

🔬 탐구 활동

섹션 제목: “🔬 탐구 활동”

탐구: 이 문제, 이름표를 답하나 숫자를 답하나?

섹션 제목: “탐구: 이 문제, 이름표를 답하나 숫자를 답하나?”
  • 준비물: 활동지, 필기구, 포스트잇(선택)
  • 소요 시간: 12분

과정

  1. 아래 6개의 실생활 예측 문제를 봅니다.
  2. 각 문제의 답이 어떤 모양인지 짝과 이야기합니다. “이름표(범주)“인지 “숫자(연속값)“인지 판단합니다.
  3. 판단 근거를 활동지에 한 줄씩 적습니다.
번호예측 문제답의 예시이름표 or 숫자?
1이메일이 스팸인가?스팸 / 정상
2내일 최고 기온은?27.5도
3이 사진 속 동물은?개 / 고양이 / 토끼
4이 집은 얼마에 팔릴까?3억 2천만 원
5이 리뷰는 긍정인가 부정인가?긍정 / 부정
6이 학생의 다음 시험 점수는?84점

결과 예측

“1, 3, 5번은 정해진 이름표 중에서 하나를 고르는 문제입니다. 2, 4, 6번은 끝없이 이어지는 숫자 중 하나를 맞히는 문제입니다. 두 무리로 자연스럽게 갈릴 것입니다.”

토의

  • “이름표를 답하는 문제와 숫자를 답하는 문제는 왜 다르게 다뤄야 할까요?”
  • “3번처럼 답이 3개인 것도 이름표 무리에 넣을 수 있을까요? 왜 그럴까요?”

탐구에서 확인한 두 무리가 바로 다음에 배울 분류와 회귀입니다.

📘 핵심 개념

섹션 제목: “📘 핵심 개념”

개념 1. 분류와 회귀 [인공지능]

섹션 제목: “개념 1. 분류와 회귀 [인공지능]”

  • 정의:

    • 분류(Classification): 답이 정해진 범주(이름표) 중 하나인 예측 문제입니다. 예) 스팸/정상, 개/고양이/토끼.
    • 회귀(Regression): 답이 연속된 숫자인 예측 문제입니다. 예) 기온, 집값, 시험 점수.

  • 비유: 분류는 마치 서랍에 물건을 넣는 일과 같습니다. 서랍의 개수는 정해져 있고, 물건을 그중 한 칸에 넣습니다. 회귀는 마치 자로 길이를 재는 일과 같습니다. 눈금은 끊김 없이 이어지고, 그 위의 한 지점을 가리킵니다.

두 문제를 가르는 기준은 딱 하나, 답의 모양입니다. 답이 셀 수 있는 이름표면 분류, 재야 하는 숫자면 회귀입니다.

flowchart TD
  A["예측 문제"] --> B{"답이 어떤 모양?"}
  B -->|"정해진 이름표 중 하나"| C["분류<br/>예: 스팸/정상"]
  B -->|"이어지는 숫자"| D["회귀<br/>예: 집값 3.2억"]

[그림 6-1] 답의 모양에 따라 분류와 회귀로 갈립니다.

주의: 숫자처럼 보여도 분류일 수 있습니다. 예를 들어 “별점 1-5점 중 하나”는 숫자지만 정해진 5칸 중 하나를 고르므로 분류에 가깝습니다. 핵심은 “숫자냐”가 아니라 “이어지는 값이냐, 정해진 칸이냐”입니다.

개념 2. 학습 데이터와 테스트 데이터 [정보] [인공지능]

섹션 제목: “개념 2. 학습 데이터와 테스트 데이터 [정보] [인공지능]”

  • 정의:

    • 학습 데이터(Training data): AI를 훈련시킬 때 쓰는 데이터입니다. AI는 이 데이터를 보며 규칙을 배웁니다.
    • 테스트 데이터(Test data): 훈련이 끝난 AI의 실력을 처음 보는 문제로 확인할 때 쓰는 데이터입니다.

  • 비유: 학습 데이터는 문제집, 테스트 데이터는 실전 시험지입니다. 문제집으로 공부한 뒤 실전 시험을 봐야 진짜 실력을 알 수 있습니다. 시험 문제를 미리 외웠다면 100점을 받아도 실력이라 할 수 없습니다.

AI도 마찬가지입니다. 훈련에 쓴 데이터로 다시 시험을 보면 답을 외운 것과 같아서 점수가 부풀려집니다. 이렇게 훈련 데이터만 잘 맞히고 새 데이터는 못 맞히는 현상을 과적합(overfitting)이라 합니다. 그래서 데이터를 미리 나눠, 테스트 데이터는 훈련에 절대 쓰지 않고 아껴 둡니다. 보통 전체의 70-80%를 학습용, 20-30%를 테스트용으로 나눕니다.

flowchart LR
  A["전체 데이터<br/>100개"] --> B["학습 데이터<br/>80개"]
  A --> C["테스트 데이터<br/>20개"]
  B --> D["AI 훈련"]
  C --> E["실력 측정"]
  D --> E

[그림 6-2] 데이터를 미리 나눠, 훈련에 쓴 적 없는 데이터로 실력을 잽니다.

🌉 교과 간 연결 다리

섹션 제목: “🌉 교과 간 연결 다리”

[정보] + [인공지능]이 만나는 지점

실생활 문제를 AI로 풀려면 두 교과의 도구가 순서대로 필요합니다.

  1. [인공지능] 먼저 문제를 분류인지 회귀인지 번역합니다. (“집값 예측”이면 회귀)
  2. [정보] 그다음 데이터를 표로 정리하고 학습/테스트로 나눕니다. (80행/20행)
  3. [인공지능] 마지막으로 나눈 데이터로 훈련하고 테스트해 성능을 정직하게 측정합니다.

인공지능이 “무엇을 예측할지” 정해도, 정보의 “데이터를 나누는 손”이 없으면 성능을 믿을 수 없습니다. 반대로 데이터를 잘 나눠도, 그 문제가 분류인지 회귀인지 모르면 어떤 AI를 골라야 할지 알 수 없습니다. 두 교과는 한 몸처럼 붙어 움직입니다.

다교과 관점 비교

섹션 제목: “다교과 관점 비교”
쟁점정보의 관점인공지능의 관점
”예측 문제란?”입력 열로 정답 열을 채우는 표 작업함수를 학습해 답을 추론하는 과정
”데이터 분할”표의 행을 두 묶음으로 나누는 조작일반화 성능을 측정하기 위한 실험 설계
”좋은 결과란?”결측 없이 깔끔히 정리된 데이터테스트 데이터에서도 잘 맞히는 모델

가로지르는 질문

섹션 제목: “가로지르는 질문”

“테스트 데이터 점수는 높은데 실제 서비스에서는 자꾸 틀립니다. 무엇이 잘못됐을까요?”

카글(Kaggle)의 리더보드 이야기

세계 최대의 데이터 분석 대회 플랫폼 카글에는 재미있는 규칙이 있습니다. 참가자는 자기 모델의 점수를 확인할 수 있지만, 최종 순위는 참가자가 한 번도 본 적 없는 비밀 테스트 데이터로 매깁니다. 대회 중간에 1등이던 팀이 마지막 순간에 순위가 뚝 떨어지는 일이 자주 벌어집니다. 공개된 데이터에만 맞춰 모델을 너무 세밀하게 다듬은 팀들, 즉 과적합된 팀들입니다. 이 규칙 덕분에 카글은 “진짜 일반화 실력”을 겨루는 무대가 되었습니다. 데이터를 아껴 두는 것이 얼마나 중요한지 보여 주는 사례입니다.
