## 오늘의 질문

<Callout kind="question">
**AI를 잘 활용한다는 것은 AI에게 일을 잘 시키는 것일까요, 아니면 AI와 함께 더 잘 생각하는 것일까요?**
</Callout>

생성형 AI는 빠르게 설명하고, 정리하고, 비교하고, 다양한 초안과 대안을 제시할 수 있습니다. 하지만 질문의 목적을 정하고, 어떤 답이 좋은지 판단하고, 결과의 의미와 영향을 해석하는 과정까지 AI에게 넘길 수는 없습니다.

이번 시간에는 프롬프트 기술 자체보다 **사고의 주도권을 유지하면서 AI와 협업하는 과정**에 집중합니다.

## 2. AI를 열기 전에 먼저 생각하기

AI에게 질문하기 전에 짧게라도 자신의 생각을 남깁니다.

| 먼저 생각할 것 | 질문 |
| --- | --- |
| 문제 | 내가 지금 해결하려는 것은 무엇인가? |
| 목적 | 왜 이것을 알아보거나 만들려는가? |
| 내 생각 | 지금 내가 알고 있거나 예상하는 것은 무엇인가? |
| 기준 | 어떤 결과가 좋은 결과라고 생각하는가? |
| 자료 | 어떤 정보와 근거가 필요한가? |
| 책임 | 마지막에 내가 판단해야 할 것은 무엇인가? |

이 단계가 없으면 AI가 제시한 방향이 곧 나의 방향이 되기 쉽습니다. AI의 답을 받기 전에 **내 질문과 기준을 먼저 세우는 것**이 중요합니다.

## 3. AI에게는 사고를 확장하는 일을 맡긴다

AI는 여러 후보를 빠르게 만들어 비교할 때 유용합니다.

- 내가 이해하지 못한 개념을 다른 방식으로 설명하게 하기
- 내 아이디어와 다른 관점 제안받기
- 가능한 해결 방법을 여러 개 탐색하기
- 내 주장에 대한 반론과 예외 찾기
- 제공한 자료를 기준에 따라 정리·비교하기
- 초안이나 프로토타입 후보 만들기
- 코드나 분석 방법의 초안을 제안받기

<Callout kind="think" title="AI에게 답이 아니라 다른 관점을 요청해보기">
"정답을 알려줘" 대신 다음과 같이 요청할 수 있습니다.

- 내가 놓친 관점 세 가지를 제안해줘.
- 내 아이디어가 실패할 수 있는 상황을 찾아줘.
- 이 주장에 반대하는 입장에서 가장 강한 근거를 제시해줘.
- 내가 제공한 자료만으로 말할 수 있는 사실과 추정을 구분해줘.
</Callout>

AI가 제안한 것이 많다고 해서 모두 좋은 것은 아닙니다. 생성 단계에서는 가능성을 넓히고, 다음 단계에서 사람이 좁혀갑니다.

## 4. 결과를 받으면 반드시 다시 사람이 개입한다

AI의 결과를 그대로 제출하지 않습니다. 다음 네 가지 질문으로 다시 살펴봅니다.

### 근거
이 결과를 뒷받침하는 자료가 실제로 있는가?

### 맥락
우리 문제의 대상, 상황, 문화, 시간과 장소에 적절한가?

### 가치와 영향
누구에게 도움이 되고, 누구에게 불리하거나 위험할 수 있는가?

### 최종 판단
여러 선택지 가운데 무엇을 채택하고 무엇을 버릴 것인가? 그 이유를 설명할 수 있는가?

<Callout kind="caution" title="기술적으로 가능하다고 반드시 해야 하는 것은 아닙니다">
AI가 할 수 있는 일과 실제로 AI에게 맡겨야 하는 일은 다를 수 있습니다. 개인정보, 공정성, 안전, 인간의 권리와 책임이 걸린 문제에서는 특히 사람이 가치 판단을 해야 합니다.
</Callout>

## 5. 프롬프트는 사고를 전달하는 작업 설계서

프롬프트는 마법의 주문이 아닙니다. 내가 정한 문제와 목적을 AI에게 전달하는 작업 설계서에 가깝습니다.

| 요소 | 설명 |
| --- | --- |
| 목표 | 무엇을 하려는가 |
| 맥락 | 어떤 상황에서 사용하는가 |
| 대상 | 누가 결과를 사용하는가 |
| 자료 | 무엇을 근거로 해야 하는가 |
| 조건 | 범위·분량·제외 사항은 무엇인가 |
| 출력 | 어떤 형태가 유용한가 |
| 판단 기준 | 좋은 결과의 조건은 무엇인가 |
| 검증 | 무엇을 불확실한 것으로 표시하고 확인해야 하는가 |

모든 요청에 모든 요소를 넣을 필요는 없습니다. 중요한 것은 프롬프트의 길이가 아니라 **내가 무엇을 원하는지 알고 있는가**입니다.

## 6. 첫 답은 완성본이 아니라 협업의 시작

좋은 AI 활용은 한 번의 질문과 답으로 끝나지 않습니다.

```text
내 질문과 초안
   ↓
AI의 설명·대안·반론
   ↓
내 검토
   ↓
추가 질문·수정 요청
   ↓
근거와 다른 자료로 검증
   ↓
내 언어로 재구성
   ↓
최종 판단
```

후속 질문은 막연한 "더 자세히"보다 어떤 부분을 어떤 기준으로 다시 살펴봐야 하는지 알려주는 것이 좋습니다.

- 이 결론의 근거와 추정을 구분해줘.
- 반대되는 근거나 예외가 있는지 찾아줘.
- 이 아이디어가 실제 사용자에게 불편을 줄 수 있는 지점을 찾아줘.
- 내 기준을 충족하지 못한 부분을 표시해줘.
- 다른 해결 방법과 비교했을 때 AI가 꼭 필요한지 비판해줘.

## 7. 검증의 강도는 위험에 따라 달라진다

| 활용 상황 | 필요한 검증 |
| --- | --- |
| 아이디어·창작 초안 | 목적과 표현이 적절한지 확인 |
| 학습 자료·과제 | 교과서, 원문, 신뢰할 수 있는 자료와 대조 |
| 통계·연구·뉴스 | 원출처, 수치, 날짜, 조사 조건 확인 |
| 코드·데이터 분석 | 직접 실행, 테스트, 계산 재현 |
| 건강·법률·금융 등 중요한 판단 | 공식 자료와 전문가를 통한 추가 확인 |
| 다른 사람에게 영향을 주는 결정 | 편향·공정성·개인정보·책임 주체 검토 |

AI가 출처를 제시하더라도 실제 원문에 그 내용이 있는지 확인해야 합니다.

## 8. 인간 중심 Learning Loop

이 수업에서는 AI 활용 활동을 다음 세 단계로 반복합니다.

### 중심 잡기
내가 먼저 질문하고 목표와 기준을 정합니다.

### 융합하기
AI와 협업하여 다양한 관점, 대안, 초안과 가능성을 탐색합니다.

### 성찰하기
결과를 검증하고 맥락과 가치까지 살펴본 뒤 자신의 언어와 판단으로 돌아옵니다.

<Callout kind="concept" title="AI와 함께 생각한다는 것">
AI에게 생각을 맡기는 것이 아니라, **AI를 이용해 내 질문을 더 깊게 만들고 내 판단을 더 단단하게 만드는 것**입니다.
</Callout>

## 실습 · 같은 AI를 다르게 사용해보기

하나의 주제를 정하고 다음 두 방식을 비교합니다.

**A. AI에게 시키기**  
주제를 바로 입력하고 완성된 답을 요청합니다.

**B. AI와 함께 생각하기**  
1. 먼저 내 생각과 질문을 짧게 적습니다.  
2. AI에게 다른 관점이나 반론을 요청합니다.  
3. AI의 답에서 확인할 내용을 표시합니다.  
4. 다른 자료와 비교해 검증합니다.  
5. 처음 생각과 무엇이 달라졌는지 적습니다.  
6. 최종 결론은 자신의 말로 작성합니다.

<Callout kind="reflect">
두 방식에서 **결과물의 차이**보다 **내가 생각한 과정의 차이**를 비교해보세요.
</Callout>
