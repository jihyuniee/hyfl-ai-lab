## 1. MCP와 Open API는 어떻게 다를까?

KOSIS MCP와 Open API는 모두 외부 데이터를 활용한다는 점에서는 비슷합니다. 하지만 사람이 만나는 방식이 다릅니다.

| 구분 | KOSIS MCP | Open API |
| --- | --- | --- |
| 쉽게 말하면 | AI가 통계 도구를 불러와 자료를 찾는 방식 | 주소에 조건을 넣어 데이터를 직접 요청하는 방식 |
| 사용자가 주로 하는 일 | 자연어로 질문하고 통계표 후보 확인 | 요청 주소와 조건값을 이해하고 응답 데이터 확인 |
| 자주 만나는 자료 | 통계표, 수치, 설명 | JSON, XML, CSV |
| 확인할 것 | 통계표 이름, 기간, 지역, 단위 | API 문서, 요청 변수, 응답 항목, 인증키 |
| 프로젝트 연결 | 국가통계 기반 분석 | 웹앱에서 실시간 또는 조건별 데이터 조회 |

Open API는 앱이나 웹사이트가 데이터를 가져올 때 자주 사용하는 방식입니다. 예를 들어 날짜를 바꾸면 다른 날의 급식이 나오고, 학교 코드를 바꾸면 다른 학교의 자료가 나옵니다.

## 3. API 요청 주소 읽기

NEIS 급식 API 요청 주소는 다음과 같은 구조로 볼 수 있습니다. 실제 수업에서는 선생님이 제공한 인증키와 학교 코드를 사용하거나, 선생님이 미리 준비한 예시 주소와 응답 데이터를 사용합니다.

~~~text
https://open.neis.go.kr/hub/mealServiceDietInfo
  ?KEY=발급받은_인증키
  &Type=json
  &pIndex=1
  &pSize=100
  &ATPT_OFCDC_SC_CODE=시도교육청코드
  &SD_SCHUL_CODE=학교코드
  &MLSV_YMD=급식일자
~~~

| 부분 | 의미 | 바꾸면 달라지는 것 |
| --- | --- | --- |
| <code>mealServiceDietInfo</code> | 급식식단정보 서비스 이름 | 요청하는 데이터 종류 |
| <code>KEY</code> | API 인증키 | 누가 요청하는지 확인 |
| <code>Type=json</code> | 응답 형식 | JSON 또는 XML 등 형식 |
| <code>pIndex</code>, <code>pSize</code> | 페이지 번호와 한 번에 받을 개수 | 조회 결과의 범위 |
| <code>ATPT_OFCDC_SC_CODE</code> | 시도교육청 코드 | 어느 교육청 자료인지 |
| <code>SD_SCHUL_CODE</code> | 학교 코드 | 어느 학교 자료인지 |
| <code>MLSV_YMD</code> | 급식일자 | 어느 날짜의 급식인지 |

<code>?</code> 뒤에는 요청 조건이 이어지고, 여러 조건은 <code>&</code>로 연결됩니다. 조건값 하나를 바꾸면 API가 보내 주는 결과도 달라집니다.

<Callout kind="caution" title="API 키는 비밀번호처럼 다룹니다">API 키는 공개 게시물, GitHub 저장소, GitHub Pages용 HTML 파일에 직접 넣지 않습니다. 수업에서 선생님이 제공한 키는 실습용으로만 사용하고, 공개 웹앱을 만들 때는 파일 다운로드 방식이나 서버에서 키를 숨기는 방식을 사용합니다.</Callout>

## 4. 브라우저로 직접 요청해 보기

처음에는 코드를 쓰기보다 브라우저 주소창에서 요청 주소를 열어 봅니다.

<Steps>
<Step title="예상하기">날짜를 바꾸면 어떤 결과가 달라질지 먼저 예상합니다. 메뉴, 식사명, 칼로리 같은 항목이 보일지 생각해 봅니다.</Step>
<Step title="요청 주소 열기">선생님이 제공한 예시 요청 주소를 브라우저 주소창에 붙여 넣고 실행합니다.</Step>
<Step title="응답 형식 확인하기">화면에 표가 아니라 중괄호와 대괄호가 많은 JSON 구조가 보일 수 있습니다. 이것은 앱이 읽기 쉬운 데이터 형식입니다.</Step>
<Step title="조건값 바꾸기">날짜나 페이지 크기처럼 수업에서 허용한 조건 하나를 바꿔 보고 결과가 어떻게 달라지는지 확인합니다.</Step>
<Step title="필요한 항목 찾기">학교명, 급식일자, 식사명, 요리명처럼 앱에서 쓸 항목을 찾습니다.</Step>
</Steps>

처음부터 모든 항목을 이해할 필요는 없습니다. 오늘은 **주소의 조건값이 데이터 요청을 바꾼다**는 것을 확인하는 것이 목표입니다.

## 5. JSON 응답에서 표 만들기

API 응답은 보통 사람이 보기 좋은 표가 아니라, 프로그램이 읽기 좋은 구조로 옵니다. 필요한 항목을 골라 표로 바꾸면 분석하기 쉬워집니다.

| 응답 항목 예 | 학생용 이름 | 확인할 내용 |
| --- | --- | --- |
| <code>SCHUL_NM</code> | 학교명 | 요청한 학교가 맞는가 |
| <code>MLSV_YMD</code> | 급식일자 | 원하는 날짜 또는 기간이 맞는가 |
| <code>MMEAL_SC_NM</code> | 식사명 | 조식, 중식, 석식 중 무엇인가 |
| <code>DDISH_NM</code> | 요리명 | 실제 메뉴와 알레르기 번호가 들어 있는가 |
| <code>CAL_INFO</code> | 칼로리정보 | 단위와 누락 여부를 확인해야 한다 |
| <code>NTR_INFO</code> | 영양정보 | 어떤 영양 항목이 포함되는지 확인해야 한다 |

<CopyPrompt title="API 응답 구조 읽기 프롬프트" content={apiReadPrompt} />

AI가 정리한 표가 맞는지 원자료와 비교합니다. 특히 날짜, 학교명, 식사명, 메뉴는 직접 찾아볼 수 있어야 합니다.

## 6. 간단한 웹앱으로 연결하기

Open API를 이해하면 다음 단계에서 웹앱으로 연결할 수 있습니다. 사용자가 날짜를 고르면 앱이 API에 요청을 보내고, 응답에서 메뉴를 뽑아 화면에 보여 주는 방식입니다.

~~~text
사용자 입력
→ API 요청 주소 만들기
→ 데이터 받기
→ 필요한 항목 추출하기
→ 표나 카드로 보여 주기
→ 출처와 기준 표시하기
~~~

| 만들 수 있는 기능 | 필요한 데이터 | 주의할 점 |
| --- | --- | --- |
| 오늘의 급식 조회 | 날짜, 학교명, 식사명, 메뉴 | API 키 공개 금지 |
| 특정 메뉴가 나온 날 찾기 | 기간별 요리명 | 기간 조회와 중복 처리 기준 |
| 월별 메뉴 빈도 보기 | 날짜, 요리명 | 메뉴 이름 정리 기준 |
| 알레르기 번호 확인 | 요리명 원문 | 번호의 의미를 원자료에서 확인 |
| 칼로리 비교 | 칼로리정보 | 단위와 누락값 확인 |

<CopyPrompt title="급식 API 웹앱 설계 프롬프트" content={apiAppPrompt} />

이번 차시에는 앱을 완성하는 것이 목표가 아닙니다. API가 어떤 방식으로 데이터를 가져오는지 알고, 다음 프로젝트에서 파일·API·MCP 중 어떤 길을 선택할지 판단할 수 있으면 충분합니다.

## 7. Streamlit로 확장할 수 있는 이유

Streamlit은 파이썬으로 간단한 데이터 웹앱을 만들 때 사용할 수 있습니다. API 키를 코드에 직접 쓰지 않고 비밀값으로 관리하면, 사용자는 화면에서 날짜와 학교를 선택하고 앱은 뒤에서 API를 호출할 수 있습니다.

| 방식 | 장점 | 조심할 점 |
| --- | --- | --- |
| 브라우저에서 API 주소 직접 열기 | 구조를 이해하기 쉽다 | 키와 조건값이 그대로 보인다 |
| CSV 파일 다운로드 후 웹앱에서 선택 | 공개 저장소에 키를 넣지 않아도 된다 | 자료가 자동으로 갱신되지는 않는다 |
| Streamlit 앱에서 API 호출 | 조건별 조회 앱을 만들기 좋다 | 키 관리, 배포 설정, 오류 처리가 필요하다 |
| 정적 HTML에서 직접 API 호출 | 단일 파일로 보여 주기 쉽다 | 공개하면 키가 노출될 수 있다 |

프로젝트에서는 처음부터 실시간 API 앱을 고집하지 않아도 됩니다. 파일을 내려받아 분석하는 방식이 더 안전하고 정확할 때도 있습니다. 중요한 것은 데이터 출처와 처리 기준을 설명할 수 있는 것입니다.

## 8. 팀 프로젝트로 이어가기

이제 프로젝트에서 사용할 데이터 길을 선택할 수 있습니다.

| 데이터 길 | 어울리는 프로젝트 |
| --- | --- |
| KOSIS MCP | 인구, 고용, 물가, 사회조사, 사교육비처럼 국가통계가 필요한 주제 |
| 파일 다운로드 | 급식, 영화, 날씨, 지역 시설처럼 표로 내려받아 분석할 수 있는 주제 |
| Open API | 날짜·지역·조건을 바꾸며 조회하는 웹앱 주제 |
| 직접 설문 | 우리 반의 생각, 선호, 사용 경험처럼 공식 데이터가 없는 주제 |

다음 차시부터는 팀별로 관심 주제와 역할을 정하고, 문제 정의와 데이터 수집 계획을 세웁니다. 생성형 AI는 주제와 코드를 대신 결정하는 존재가 아니라, 우리가 정한 질문을 더 잘 검증하고 구현하도록 돕는 도구입니다.
