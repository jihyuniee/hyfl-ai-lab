## 1. Open API는 데이터가 나오는 주소입니다

Open API는 기관이 정한 주소와 조건값을 사용해 데이터를 요청하는 방법입니다. 웹앱은 사용자가 입력한 값을 API 주소의 조건값으로 넣고, 서버가 보내 준 응답 데이터에서 필요한 항목을 골라 화면에 보여 줍니다.

| 수업에서 보는 것 | 뜻 | 급식 API 예시 |
| --- | --- | --- |
| 요청 주소 | 데이터를 달라고 보내는 주소 | 급식식단정보 API 주소 |
| 조건값 | 어떤 데이터를 받을지 정하는 값 | 학교 코드, 날짜, 식사 코드 |
| JSON 응답 | 서버가 보내 주는 데이터 | 학교명, 메뉴, 칼로리정보 |
| 웹앱 화면 | 필요한 값을 보기 좋게 보여 주는 곳 | 오늘의 급식 카드, 메뉴 검색 결과 |

JSON은 **반정형 데이터**입니다. 엑셀 표처럼 행과 열이 바로 보이는 형태와 달리, 이름표와 값이 계층적으로 묶여 있습니다. 앱은 이름표를 기준으로 필요한 값을 찾아 화면에 표시합니다.

~~~json
"SCHUL_NM": "한영외국어고등학교"
"MMEAL_SC_NM": "중식"
"CAL_INFO": "1196.2 Kcal"
~~~

## 2. 오늘 사용할 데이터: NEIS 급식식단정보

오늘 예시는 NEIS 교육정보 개방 포털의 **급식식단정보**입니다. 이 자료는 학교 급식의 요리명, 원산지정보, 칼로리정보, 영양정보 등을 일자별로 제공합니다.

- 원자료: [NEIS 급식식단정보](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17320190722180924242823&infSeq=1)

<Callout kind="teacher" title="수업용 인증키">수업용 인증키는 교사가 별도로 안내한 공간에서 확인합니다. 공개 교과서와 공개 저장소에는 실제 인증키 대신 <code>발급받은_인증키</code> 또는 <code>수업용_인증키</code> 같은 자리표시자를 사용합니다.</Callout>

급식 API 요청에 자주 쓰는 값은 다음과 같습니다.

| 값 | 의미 | 예시 |
| --- | --- | --- |
| <code>KEY</code> | API 인증키 | 수업용 인증키 |
| <code>Type</code> | 응답 형식 | <code>json</code> |
| <code>pIndex</code> | 페이지 번호 | <code>1</code> |
| <code>pSize</code> | 한 번에 받을 개수 | <code>100</code> |
| <code>ATPT_OFCDC_SC_CODE</code> | 시도교육청 코드 | <code>B10</code> |
| <code>SD_SCHUL_CODE</code> | 학교 코드 | <code>7010259</code> |
| <code>MLSV_YMD</code> | 급식일자 | <code>20210222</code> |

## 3. 요청 주소 만들기

아래 프롬프트를 복사한 뒤 빨간 부분을 수업에서 사용할 값으로 바꿉니다. 생성형 AI는 입력한 값을 바탕으로 브라우저 주소창에 붙여 넣을 수 있는 API 요청 주소를 만들어 줍니다.

<CopyPrompt title="급식 API 요청 주소 만들기 프롬프트" content={apiRequestPrompt} />

AI가 만들어 준 요청 주소는 다음과 같은 구조입니다.

~~~text
https://open.neis.go.kr/hub/mealServiceDietInfo?KEY=수업용_인증키&Type=json&pIndex=1&pSize=100&ATPT_OFCDC_SC_CODE=B10&SD_SCHUL_CODE=7010259&MLSV_YMD=20210222
~~~

주소에서 <code>?</code> 뒤에는 조건값이 이어지고, 여러 조건은 <code>&</code>로 연결됩니다. 날짜를 바꾸면 다른 날짜의 급식이 나오고, 학교 코드를 바꾸면 다른 학교의 급식이 나옵니다.

## 4. 브라우저에서 요청하고 받은 값 적기

요청 주소를 브라우저 주소창에 붙여 넣고 실행합니다. 화면에 중괄호와 대괄호가 많은 JSON 응답이 보입니다. 처음에는 전체 구조를 모두 이해하려고 하기보다, 아래 값을 찾아봅니다.

| 확인할 값 | JSON에서 찾을 이름표 | 내가 확인한 값 |
| --- | --- | --- |
| 정상 처리 여부 | <code>RESULT.MESSAGE</code> |  |
| 학교명 | <code>SCHUL_NM</code> |  |
| 급식일자 | <code>MLSV_YMD</code> |  |
| 식사명 | <code>MMEAL_SC_NM</code> |  |
| 메뉴 | <code>DDISH_NM</code> |  |
| 칼로리정보 | <code>CAL_INFO</code> |  |

예시 응답의 일부는 다음과 같습니다.

~~~json
{
  "mealServiceDietInfo": [
    {
      "head": [
        { "list_total_count": 1 },
        { "RESULT": { "CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다." } }
      ]
    },
    {
      "row": [
        {
          "SCHUL_NM": "한영외국어고등학교",
          "MMEAL_SC_NM": "중식",
          "MLSV_YMD": "20210222",
          "DDISH_NM": "$차조밥<br/>$설렁탕5.6.13.16.<br/>$오리훈제...",
          "CAL_INFO": "1196.2 Kcal"
        }
      ]
    }
  ]
}
~~~

<code>row</code> 안에 실제 급식 데이터가 들어 있습니다. <code>DDISH_NM</code> 안의 <code>&lt;br/&gt;</code>는 줄바꿈 표시입니다. 앱에서는 이 표시를 기준으로 메뉴를 줄마다 나누어 보여 줄 수 있습니다.

<CopyPrompt title="응답 JSON에서 받은 값 정리하기 프롬프트" content={apiValuePrompt} />

## 5. 조건값을 바꾸며 다시 요청하기

조건값 하나를 바꾸고 다시 요청합니다. 바꾼 값과 달라진 응답을 기록합니다.

| 바꿔 볼 값 | 예시 | 확인할 변화 |
| --- | --- | --- |
| 날짜 | <code>MLSV_YMD=20210223</code> | 다른 날짜의 메뉴가 나오는지 |
| 페이지 크기 | <code>pSize=5</code>, <code>pSize=100</code> | 한 번에 보이는 기록 수가 달라지는지 |
| 식사 코드 | <code>MMEAL_SC_CODE=2</code> | 중식 자료만 나오는지 |
| 기간 | <code>MLSV_FROM_YMD</code>, <code>MLSV_TO_YMD</code> | 여러 날짜의 자료가 나오는지 |

| 내가 바꾼 조건 | 바꾸기 전 | 바꾼 뒤 | 응답에서 확인한 변화 |

## 6. 받은 데이터를 앱 화면으로 바꾸기

API 응답에서 찾은 값은 웹앱의 화면 요소가 됩니다.

| JSON 항목 | 앱 화면에서 보이는 모습 |
| --- | --- |
| <code>MLSV_YMD</code> | 급식 날짜 |
| <code>MMEAL_SC_NM</code> | 조식, 중식, 석식 표시 |
| <code>DDISH_NM</code> | 메뉴 목록과 알레르기 번호 |
| <code>CAL_INFO</code> | 칼로리 정보 |
| <code>NTR_INFO</code> | 영양정보 |
| <code>RESULT.CODE</code> | 정상 처리, 데이터 없음, 오류 안내 |

같은 급식 API를 사용해도 만들 수 있는 앱은 달라집니다.

| 내가 만들고 싶은 기능 | 화면에서 입력할 값 | 주로 사용할 응답 항목 |
| --- | --- | --- |
| 특정 메뉴가 나온 날 찾기 | 메뉴 이름 | <code>DDISH_NM</code>, <code>MLSV_YMD</code> |
| 칼로리 높은 날 찾기 | 칼로리 기준 | <code>CAL_INFO</code>, <code>MLSV_YMD</code> |
| 알레르기 번호 찾기 | 알레르기 번호 | <code>DDISH_NM</code> |
| 날짜별 영양정보 보기 | 날짜 또는 기간 | <code>NTR_INFO</code>, <code>MLSV_YMD</code> |

## 7. 프롬프트를 바꿔서 HTML 앱 만들기

이번에는 생성형 AI와 함께 단일 HTML 파일 앱을 만듭니다. 먼저 아래 프롬프트를 복사한 뒤, 자신이 만들고 싶은 기능에 맞게 빨간 부분을 바꿉니다. 오늘은 작동 확인에 필요한 조건만 넣어 작은 웹페이지를 먼저 만듭니다. 최종 프로젝트에서는 기능, 디자인, 오류 처리, 개인정보, 출처 표시 조건을 더 자세히 적어 요청합니다.

| 바꿀 부분 | 예시 |
| --- | --- |
| 내가 만들고 싶은 기능 | 메뉴 이름 검색, 칼로리 높은 날 찾기, 알레르기 번호 찾기 |
| 사용자가 화면에서 입력할 값 | 메뉴 이름, 알레르기 번호, 칼로리 기준, 날짜 |
| 화면에 보여 줄 결과 | 날짜, 식사명, 메뉴, 칼로리정보, 영양정보 |
| 사용할 응답 항목 | <code>DDISH_NM</code>, <code>CAL_INFO</code>, <code>NTR_INFO</code> |

<CopyPrompt title="급식 API 미니 웹앱 만들기 프롬프트" content={htmlAppPrompt} />

앱을 만들 때 확인할 기능은 다음과 같습니다.

| 확인할 기능 | 테스트 방법 |
| --- | --- |
| API 요청 | 조회 버튼을 눌렀을 때 데이터가 불러와지는지 확인 |
| 입력값 반영 | 내가 입력한 메뉴, 알레르기 번호, 칼로리 기준이 결과에 반영되는지 확인 |
| 결과 표시 | 날짜, 식사명, 메뉴, 칼로리 등 필요한 값이 보이는지 확인 |
| 결과 없음 | 찾는 값이 없을 때 안내 문구가 나오는지 확인 |
| 출처 표시 | 화면 아래에 NEIS 급식식단정보 출처가 보이는지 확인 |

<Callout kind="caution" title="HTML 파일과 API 키">단일 HTML 파일 안에 실제 API 키를 넣으면 파일을 가진 사람이 키를 볼 수 있습니다. 수업 실습 파일은 교실 안에서 테스트하고, 공개 GitHub Pages나 공개 저장소에는 실제 키 대신 자리표시자를 사용합니다.</Callout>

## 8. 팀 프로젝트로 이어가기

오늘 실습은 API 데이터를 눈으로 확인하고, 그 값을 간단한 앱 화면으로 바꾸는 경험입니다. 팀 프로젝트에서는 주제에 따라 데이터 길을 선택합니다.

| 출발점 | 데이터 활용 방식 | 앱형 프로젝트 예시 |
| --- | --- | --- |
| 평소 불편함이 있다 | KOSIS나 공공데이터로 실제 현황 확인 | 청소년 여가, 진로, 사교육, 지역 격차 데이터를 바탕으로 정보 안내 앱 만들기 |
| KOSIS 탐색 중 문제를 발견했다 | 국가통계로 문제의 규모와 변화 확인 | 지역별 문화시설 차이를 보고 우리 지역 활동 추천 앱 만들기 |
| 조건별로 조회되는 생활 데이터가 필요하다 | Open API로 날짜, 지역, 학교 같은 조건별 데이터 요청 | 급식 조회, 메뉴 검색, 알레르기 확인, 날씨 기반 추천, 영화 정보 조회 앱 만들기 |
| 공식 데이터에 없는 학교 안 문제가 있다 | 직접 설문조사로 우리 학교 데이터를 수집 | 학습 습관, 급식 만족도, 진로 관심, 학교생활 불편을 반영한 맞춤 안내 앱 만들기 |

생성형 AI는 API 주소 만들기, JSON 응답 정리, HTML 앱 코드 초안 작성, 오류 점검에 활용합니다. 사람은 어떤 데이터를 쓸지 정하고, 응답 값이 맞는지 확인하고, 앱이 실제 사용자에게 도움이 되는지 판단합니다.

<Callout kind="exit" title="오늘의 정리">Open API는 조건값을 넣어 데이터를 요청하는 주소입니다. JSON 응답에서 필요한 값을 찾으면 날짜 선택, 메뉴 검색, 칼로리 표시, 알레르기 번호 확인 같은 웹앱 기능으로 연결할 수 있습니다.</Callout>
