이제 실험에서 이미 경험한 현상에 개념 이름을 붙입니다.

| 개념 | 실험에서의 의미 |
| --- | --- |
| 클래스 | 모델이 구분하도록 정한 범주 |
| 학습 데이터 | 모델이 패턴을 찾는 데 사용한 사례 |
| 모델 | 학습 데이터에서 찾은 패턴을 계산 가능한 형태로 담은 것 |
| 테스트 데이터 | 학습에 쓰지 않고 새로운 상황에서 성능을 확인하는 자료 |
| 분류 | 입력을 정해진 클래스 중 하나로 예측하는 작업 |
| 일반화 | 처음 보는 조건에서도 배운 기준을 적용하는 능력 |
| 과대적합 | 학습 사례에는 잘 맞지만 새로운 조건에서는 잘 작동하지 않는 상태 |
| 데이터 편향 | 특정 사람·환경·조건이 과도하거나 빠져 판단이 한쪽으로 치우치는 문제 |

## 좋은 데이터는 많기만 한 데이터가 아니다

- **양**: 패턴을 찾을 만큼 충분한가?
- **다양성**: 실제로 만날 사람·환경·조건을 포함하는가?
- **정확성**: 클래스와 정답이 일관되고 맞는가?
- **대표성**: 사용 대상과 상황을 고르게 반영하는가?

<Callout kind="caution" title="정확도 하나로 충분하지 않다">
테스트 자료가 학습 자료와 너무 비슷하면 높은 정확도가 나와도 실제 상황에서는 실패할 수 있습니다. 누구의 데이터에서, 어떤 조건으로 측정한 정확도인지 함께 확인해야 합니다.
</Callout>

## 개선은 비교 가능한 실험이어야 한다

```text
실패 조건 기록 → 원인 가설 → 데이터 변경 → 다시 학습
→ 같은 실패 조건으로 재시험 → 결과 비교
```

여러 조건을 한꺼번에 바꾸면 무엇이 개선에 영향을 주었는지 알기 어렵습니다. 가능한 한 한 번에 한 가지를 바꾸고 기록합니다.

<Callout kind="concept" title="오늘 기억할 내용">
**AI의 판단은 학습 데이터와 테스트 방법의 영향을 받습니다.** 결과를 이해하려면 무엇을 얼마나 맞혔는지만이 아니라 어떤 데이터로 어떻게 학습하고 시험했는지 살펴야 합니다.
</Callout>
