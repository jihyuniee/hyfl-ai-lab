## 1. Open API는 데이터가 나오는 주소입니다

Open API는 기관이 정한 주소와 조건값을 사용해 데이터를 요청하는 방법입니다. 웹앱은 사용자가 입력한 값을 API 주소의 조건값으로 넣고, 서버가 보내 준 응답 데이터에서 필요한 항목을 골라 화면에 보여 줍니다.

| 수업에서 보는 것 | 뜻 | 급식 API 예시 |
| --- | --- | --- |
| 요청 주소 | 데이터를 달라고 보내는 주소 | 급식식단정보 API 주소 |
| 조건값 | 어떤 데이터를 받을지 정하는 값 | 학교 코드, 날짜, 식사 코드 |
| JSON 응답 | 서버가 보내 주는 데이터 | 학교명, 메뉴, 칼로리정보 |
| 웹앱 화면 | 필요한 값을 보기 좋게 보여 주는 곳 | 오늘의 급식 카드, 메뉴 검색 결과 |

JSON은 **반정형 데이터**입니다. 이름표와 값이 묶여 있고, 여러 묶음이 계층적으로 들어갈 수 있습니다. 앱은 이름표를 기준으로 필요한 값을 찾아 화면에 표시합니다.

~~~json
"SCHUL_NM": "한영외국어고등학교"
"MMEAL_SC_NM": "중식"
"CAL_INFO": "1196.2 Kcal"
~~~

## 2. API 키와 요청값 확인하기

오늘 예시는 NEIS 교육정보 개방 포털의 **급식식단정보**입니다. 이 자료는 학교 급식의 요리명, 원산지정보, 칼로리정보, 영양정보 등을 일자별로 제공합니다.

- 원자료: [NEIS 급식식단정보](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17320190722180924242823&infSeq=1)

<Callout kind="teacher" title="수업용 인증키">수업용 인증키는 교사가 안내한 비공개 공간에서 확인합니다. 공개 교과서와 공개 저장소에는 실제 인증키 대신 <code>수업용_인증키</code> 같은 자리표시자를 사용합니다.</Callout>

급식 API 요청에 자주 쓰는 값은 다음과 같습니다.

| 값 | 의미 | 예시 |
| --- | --- | --- |
| <code>KEY</code> | API 인증키 | 수업용 인증키 |
| <code>Type</code> | 응답 형식 | <code>json</code> |
| <code>pIndex</code> | 페이지 번호 | <code>1</code> |
| <code>pSize</code> | 한 번에 받을 개수 | <code>100</code> |
| <code>ATPT_OFCDC_SC_CODE</code> | 시도교육청 코드 | <code>B10</code> |
| <code>SD_SCHUL_CODE</code> | 학교 코드 | <code>7010259</code> |
| <code>MLSV_YMD</code> | 급식일자 | <code>20210222</code> |

API 키는 제공 기관이 발급하는 인증값입니다. 발급받은 키를 요청 주소의 <code>KEY=</code> 뒤에 넣으면 서버가 요청자를 확인하고 데이터를 보내 줍니다. 시도교육청 코드와 학교 코드는 NEIS 포털의 학교기본정보 서비스, 제공 기관의 코드 안내, 수업용 예시 자료에서 확인할 수 있습니다.

## 3. 요청 주소 만들고 실행하기

아래 프롬프트를 복사한 뒤 빨간 부분을 수업에서 사용할 값으로 바꿉니다. 생성형 AI는 입력한 값을 바탕으로 브라우저 주소창에 붙여 넣을 수 있는 API 요청 주소를 만들어 줍니다.

<CopyPrompt title="급식 API 요청 주소 만들기 프롬프트" content={apiRequestPrompt} />

AI가 만들어 준 요청 주소는 다음과 같은 구조입니다.

~~~text
https://open.neis.go.kr/hub/mealServiceDietInfo?KEY=수업용_인증키&Type=json&pIndex=1&pSize=100&ATPT_OFCDC_SC_CODE=B10&SD_SCHUL_CODE=7010259&MLSV_YMD=20210222
~~~

주소에서 <code>?</code> 뒤에는 조건값이 이어지고, 여러 조건은 <code>&</code>로 연결됩니다. 조건은 <code>이름=값</code> 형태로 씁니다.

| 바꿔 볼 값 | 예시 | 확인할 변화 |
| --- | --- | --- |
| 날짜 | <code>MLSV_YMD=20210223</code> | 다른 날짜의 메뉴가 나오는지 확인 |
| 페이지 크기 | <code>pSize=5</code>, <code>pSize=100</code> | 한 번에 받는 기록 수 확인 |
| 식사 코드 | <code>MMEAL_SC_CODE=2</code> | 중식 자료만 나오는지 확인 |
| 학교 코드 | <code>SD_SCHUL_CODE=...</code> | 다른 학교의 급식 자료 확인 |

## 4. JSON 응답에서 받은 값 찾기

요청 주소를 브라우저 주소창에 붙여 넣고 실행하면 JSON 응답이 보입니다. 처음에는 전체 구조보다 아래 값을 먼저 찾습니다.

| 확인할 값 | JSON에서 찾을 이름표 | 내가 확인한 값 |
| --- | --- | --- |
| 정상 처리 여부 | <code>RESULT.MESSAGE</code> |  |
| 학교명 | <code>SCHUL_NM</code> |  |
| 급식일자 | <code>MLSV_YMD</code> |  |
| 식사명 | <code>MMEAL_SC_NM</code> |  |
| 메뉴 | <code>DDISH_NM</code> |  |
| 칼로리정보 | <code>CAL_INFO</code> |  |
| 영양정보 | <code>NTR_INFO</code> |  |

예시 응답의 일부는 다음과 같습니다.

~~~json
{
  "mealServiceDietInfo": [
    {
      "head": [
        { "list_total_count": 1 },
        { "RESULT": { "CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다." } }
      ]
    },
    {
      "row": [
        {
          "SCHUL_NM": "한영외국어고등학교",
          "MMEAL_SC_NM": "중식",
          "MLSV_YMD": "20210222",
          "DDISH_NM": "$차조밥<br/>$설렁탕5.6.13.16.<br/>$오리훈제...",
          "CAL_INFO": "1196.2 Kcal"
        }
      ]
    }
  ]
}
~~~

| JSON 부분 | 뜻 | 급식 응답에서 보는 방법 |
| --- | --- | --- |
| <code>head</code> | 응답 상태 정보 | 전체 개수, 정상 처리 여부 확인 |
| <code>row</code> | 실제 데이터 목록 | 학교명, 날짜, 메뉴, 칼로리 확인 |
| <code>{ }</code> | 하나의 묶음 | 한 건의 급식 기록 |
| <code>[ ]</code> | 여러 개의 묶음 | 여러 날짜 또는 여러 식사 기록 |
| <code>"이름": "값"</code> | 항목 이름과 실제 값 | <code>"SCHUL_NM": "한영외국어고등학교"</code> |

<code>row</code> 안에 실제 급식 데이터가 들어 있습니다. <code>DDISH_NM</code> 안의 <code>&lt;br/&gt;</code>는 줄바꿈 표시입니다. 앱은 이 표시를 기준으로 메뉴를 줄마다 나누어 보여 줄 수 있습니다.

## 5. 받은 값을 앱 기능으로 연결하기

API 응답에서 찾은 값은 웹앱의 화면 요소가 됩니다.

| JSON 항목 | 앱 화면에서 보이는 모습 |
| --- | --- |
| <code>MLSV_YMD</code> | 급식 날짜 |
| <code>MMEAL_SC_NM</code> | 조식, 중식, 석식 표시 |
| <code>DDISH_NM</code> | 메뉴 목록과 알레르기 번호 |
| <code>CAL_INFO</code> | 칼로리 정보 |
| <code>NTR_INFO</code> | 영양정보 |
| <code>RESULT.CODE</code> | 정상 처리, 데이터 없음, 오류 안내 |

같은 급식 API를 사용해도 만들 수 있는 앱은 달라집니다.

| 내가 만들고 싶은 기능 | 화면에서 입력할 값 | 주로 사용할 응답 항목 |
| --- | --- | --- |
| 특정 메뉴가 나온 날 찾기 | 메뉴 이름 | <code>DDISH_NM</code>, <code>MLSV_YMD</code> |
| 칼로리 높은 날 찾기 | 칼로리 기준 | <code>CAL_INFO</code>, <code>MLSV_YMD</code> |
| 알레르기 번호 찾기 | 알레르기 번호 | <code>DDISH_NM</code> |
| 날짜별 영양정보 보기 | 날짜 또는 기간 | <code>NTR_INFO</code>, <code>MLSV_YMD</code> |

## 6. 다음 시간 준비하기

다음 시간에는 오늘 확인한 API 키와 JSON 항목을 사용해 작은 HTML 웹앱을 만듭니다. 오늘 기록한 값 중 하나를 골라 앱 기능으로 바꿔 봅니다.

| 준비할 것 | 예시 |
| --- | --- |
| 만들고 싶은 기능 | 메뉴 이름 검색, 칼로리 기준 검색, 알레르기 번호 검색 |
| 사용자가 입력할 값 | 메뉴 이름, 칼로리 기준, 알레르기 번호, 날짜 |
| 화면에 보여 줄 값 | 날짜, 식사명, 메뉴, 칼로리정보, 영양정보 |
| 확인 방법 | 브라우저 JSON 원문과 앱 화면 결과 비교 |

<Callout kind="caution" title="API 키 관리">실제 API 키가 들어간 주소와 HTML 파일은 공개 게시물, 공개 GitHub 저장소, 공개 GitHub Pages에 올리지 않습니다. 수업 실습에서는 교사가 안내한 범위에서 사용하고, 공개할 때는 키를 가리거나 서버에서 숨기는 방식을 선택합니다.</Callout>

<Callout kind="exit" title="오늘의 정리">Open API는 조건값을 넣어 데이터를 요청하는 주소입니다. JSON 응답에서 필요한 값을 찾으면 날짜 선택, 메뉴 검색, 칼로리 표시, 알레르기 번호 확인 같은 웹앱 기능으로 연결할 수 있습니다.</Callout>
