## HYFL AI Lab의 중심 철학

이 수업의 목표는 학생에게 AI 도구를 많이 소개하거나, AI로 그럴듯한 결과물을 빠르게 만드는 방법만 가르치는 것이 아닙니다. 우리가 지향하는 수업은 다음과 같습니다.

> **AI의 원리를 이해하고, AI와 제대로 협업하여, 사람과 세상의 실제 문제를 해결하는 사람을 길러내는 수업**

AI 자체가 목적이 아닙니다. AI는 인간이 지금까지 해결하기 어려웠던 과학적·사회적·일상적 문제를 더 잘 이해하고 해결하기 위한 도구입니다. 학생이 AI를 답을 얻는 도구, 과제를 대신하는 도구로만 바라보지 않도록, 이 책 전체는 "AI로 무엇을 만들까?"보다 <strong>"내가 해결하고 싶은 문제는 무엇이며, AI가 그 문제 해결에 어떻게 기여할 수 있을까?"</strong>를 먼저 묻도록 설계되어 있습니다.

공식 슬로건은 다음과 같으며, 첫 화면의 Hero·이 페이지·마지막 성찰 페이지에서 일관되게 사용합니다 (매 페이지 반복하지는 않습니다).

> **Understand AI. Think with AI. Solve for Humanity.**
> AI를 이해하고, AI와 함께 생각하며, 사람과 세상을 위한 문제를 해결한다.

이 교재는 설명식 교과서가 아니라 **AI Lab Book**입니다.

```
개념을 이해한다 → 바로 해본다 → 실패한다 → 왜 그런지 생각한다 → 필요한 이론을 다시 배운다 → 개선한다
```

이론을 몇 주 동안 먼저 배우고 나중에 실습하는 구조를 의도적으로 피했습니다. 학생이 먼저 예측하고 실험한 뒤, 그 경험에 정확한 AI 개념을 붙이는 순서로 설계되어 있습니다. (예: Teachable Machine에서 자기 사진으로는 성공하지만 친구 사진에서는 실패하는 경험 → "왜 틀렸을까?" → 훈련/테스트 데이터, 일반화, 과적합, 데이터 편향)

이 철학은 다른 어떤 요구보다 우선합니다. 수업 중 콘텐츠를 줄이거나 순서를 바꿔야 할 때도 위 슬로건을 판단 기준으로 삼으세요.

## 세 프로젝트의 철학적 연결

세 프로젝트는 서로 떨어진 별개의 과제가 아니라 하나의 성장 흐름입니다.

```
AI의 판단을 이해한다 → AI와 협업해 만든다 → AI를 사람과 사회의 문제 해결에 사용한다
```

| Project | 핵심 질문 | 배우는 태도 |
| --- | --- | --- |
| 1. 나만의 이미지 분류 AI 웹앱 | AI는 무엇을 보고 판단하며, 왜 새로운 상황에서 실패하는가? | 판단은 데이터와 연결되어 있다 · 높은 숫자가 항상 좋은 모델은 아니다 · 실패는 이해해야 할 증거다 |
| 2. 생성형 AI와 웹서비스 만들기 | AI와 협업하면 아이디어를 실제 서비스로 어떻게 구현할 수 있는가? | 문제와 목적은 사람이 정한다 · 실행된다는 것과 이해했다는 것은 다르다 · AI의 첫 결과는 검토할 초안이다 |
| 3. Data to AI Solution | 데이터를 통해 문제를 더 정확히 이해하고, 어떤 AI 서비스가 정말 필요한지 어떻게 결정하는가? | 서비스를 먼저 정하지 않는다 · 사실과 해석을 구분한다 · 인사이트가 기능의 근거가 된다 |

홈페이지의 프로젝트 카드에도 이 연결이 태그로 드러나 있습니다.

## 결과물보다 사고 과정

화려한 결과물, 기능의 수, 빠른 완성을 최우선으로 두지 않습니다. 결과물과 함께 다음 과정을 평가하세요.

어떤 문제를 선택했는가 · 왜 중요한 문제라고 판단했는가 · 어떤 데이터와 근거를 사용했는가 · AI에게 어떤 역할을 맡겼는가 · AI에게 어떤 맥락과 조건을 제공했는가 · 첫 결과에서 어떤 문제를 발견했는가 · AI의 오류를 어떻게 확인했는가 · 어떤 부분을 받아들이고 어떤 부분을 버렸는가 · 무엇을 직접 수정하고 판단했는가 · 해결책이 사람과 사회에 어떤 영향을 줄 수 있는가 · 아직 해결하지 못한 한계는 무엇인가.

Project 1은 모델의 실패와 데이터 개선 과정으로, Project 2는 AI가 생성한 첫 코드·오류·디버깅·사용성 개선 과정으로, Project 3는 문제·데이터·패턴·인사이트·서비스 기능의 연결 과정으로 이를 확인합니다.

## 프로젝트 평가 관점

| 평가 요소 | 무엇을 보는가 |
| --- | --- |
| 문제 정의 | 문제와 대상 사용자가 구체적인가 |
| 데이터·근거 | 데이터(또는 근거)를 충분히, 다양하게 확보했는가 |
| 실험과 검증 | 공정하게 테스트하고, AI의 결과를 검증했는가 |
| 문제 해결 | 실패 원인을 분석하고 실제로 개선했는가 |
| AI 협업 | AI에게 던진 질문과 검토 과정이 드러나는가 |
| 성찰과 책임 | 한계를 정직하게 설명하고, AI와 인간의 역할을 구분했는가 |

## 교사의 핵심 발문

Lab 활동 중 학생이 막히거나 결과만 보고 넘어가려 할 때 아래 질문을 던지세요.

- 왜 이 문제가 중요하다고 생각했나요? 그 문제는 데이터에서도 확인되나요?
- AI는 무엇을 입력받고 무엇을 출력했나요? 어떤 데이터를 학습했을까요?
- AI가 꼭 필요한 이유는 무엇인가요? AI에게 어떤 맥락을 제공했나요?
- 성공보다 실패에서 무엇을 발견했나요? 바꾼 조건은 하나인가요? 공정하게 비교했나요?
- 그 결과가 맞다는 것을 어떻게 확인했나요? 다른 해석은 없나요?
- 누구에게 도움이 되고 누구에게 불리할 수 있나요?
- AI가 한 일과 여러분이 판단한 일은 무엇인가요? 최종적으로 여러분이 판단한 것은 무엇인가요?

## 수업이 지향하는 학생의 변화

<Callout kind="caution" title="수업 전">
AI에게 바로 답을 요청한다 · 그럴듯한 결과를 정확한 결과라고 생각한다 · 서비스를 먼저 정하고 문제와 데이터를 나중에 붙인다 · AI가 만든 결과와 자신의 판단을 구분하지 않는다 · 완성된 결과물만 중요하다고 생각한다.
</Callout>

<Callout kind="lab" title="수업 후">
먼저 문제를 정의하고 자신의 생각을 정리한다 · AI가 필요한 이유와 맡길 역할을 설명한다 · 목표·맥락·조건을 제공하며 AI와 반복적으로 협업한다 · 데이터와 외부 자료로 AI의 결과를 검증한다 · 실패와 오류를 분석해 개선한다 · 인사이트와 서비스 기능을 근거로 연결한다 · AI가 한 일과 자신의 판단을 구분한다 · 기술이 사람과 사회에 미칠 영향을 고려한다.
</Callout>

## 수업 성공의 기준

모든 학생이 높은 수준의 웹앱을 완성하는 것을 성공 기준으로 두지 않습니다. 다음과 같은 변화도 중요한 성공입니다.

AI의 답을 한 번 더 확인하기 시작함 · 실패한 모델의 원인을 데이터에서 찾음 · 자신의 질문을 더 구체적으로 바꿈 · 서비스보다 문제를 먼저 설명함 · 데이터에서 예상과 다른 결과를 발견함 · AI의 제안을 그대로 따르지 않고 수정함 · 기술의 영향과 책임을 생각함 · "AI로 무엇을 만들까?"보다 "어떤 문제를 해결할까?"를 먼저 질문함.
