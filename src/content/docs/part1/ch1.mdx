대화형 생성 AI, 번역, 추천, 얼굴 인식, 내비게이션은 겉으로 보이는 기능이 서로 다릅니다. 그런데도 모두 인공지능이라고 부르는 이유는 무엇일까요?

특정 서비스 하나를 AI의 대표로 생각하기보다, 먼저 **사람이 지능을 사용해 하는 일**을 살펴보면 AI라는 큰 개념을 이해하기 쉽습니다.

## 사람은 어떻게 지능을 사용할까?

사람은 주변의 정보를 알아보고, 경험에서 배우며, 현재의 정보를 바탕으로 예상하고 판단해 문제를 해결합니다.

예를 들어 길을 건널 때 사람은 신호등과 자동차를 **인식**하고, 이전의 경험과 교통 규칙을 바탕으로 상황을 **추론**하며, 지금 건너도 되는지 **판단**합니다. 이처럼 지능은 단순히 많이 아는 능력이 아니라 정보를 바탕으로 상황에 맞는 결과를 만들어내는 능력과 관련됩니다.

<Callout kind="concept" title="인공지능의 큰 개념">
**인공지능(AI)은 인식·학습·추론·예측·판단·생성·문제 해결처럼 인간의 지능적 활동과 관련된 기능을 컴퓨터 시스템이 수행하도록 구현하는 기술과 연구 분야입니다.**
</Callout>

이 정의가 AI가 인간과 똑같이 생각하거나 세상을 사람처럼 이해한다는 뜻은 아닙니다. 실제 AI 시스템은 사람이 설계한 규칙, 데이터에서 학습한 패턴, 통계와 확률, 계산, 검색이나 코드 실행 같은 여러 도구를 이용해 결과를 만듭니다.

## 생활 속 AI는 어떤 일을 할까?

| 생활 속 사례 | 입력되는 정보의 예 | AI가 수행하는 기능 | 만들어지는 결과의 예 |
| --- | --- | --- | --- |
| 얼굴·사물 인식 | 카메라 이미지 | 특징을 찾아 인식·분류 | 사용자 확인, 사물 이름 |
| 콘텐츠 추천 | 시청·검색·선택 기록 | 선호 가능성 예측 | 볼 만한 영상이나 음악 |
| 내비게이션 | 출발지·도착지·교통 정보 | 경로와 시간을 계산·예측 | 추천 경로, 예상 도착 시각 |
| 번역 | 문장·음성 | 언어의 패턴을 바탕으로 변환 | 다른 언어의 문장 |
| 생성형 AI | 질문·지시·이미지·파일 | 학습된 패턴을 바탕으로 생성 | 글·이미지·코드·분석 초안 |
| 이미지 분류 모델 | 새로운 이미지 | 학습한 패턴과 비교해 분류 | 클래스와 예측 점수 |

이 시스템들은 모두 같은 방식으로 작동하지 않습니다. 하지만 **주어진 정보를 바탕으로 인식·예측·분류·생성과 같은 지능적 기능을 수행한다는 공통점**이 있습니다.

<Callout kind="caution" title="입력과 출력만으로 AI를 구분할 수는 없다">
대부분의 컴퓨터 프로그램은 어떤 입력을 받아 처리한 뒤 출력을 만듭니다. 계산기도 숫자를 입력받아 답을 출력합니다.

따라서 입력과 출력이 있다는 사실만으로 AI라고 부르지는 않습니다. **그 사이에서 어떤 방법으로 어떤 기능을 수행하는지**를 함께 살펴봐야 합니다.
</Callout>

## 자동으로 작동하면 모두 AI일까?

오전 7시에 울리도록 설정한 알람은 시간이 되면 자동으로 작동합니다. 자판기 역시 돈과 버튼 입력에 따라 정해진 음료를 내보냅니다. 자동으로 작동하지만 일반적으로 이런 기능을 AI라고 부르지는 않습니다.

그렇다면 다음 두 방식은 무엇이 다를까요?

| 방식 | 규칙을 정하는 방법 | 예 |
| --- | --- | --- |
| **규칙 기반** | 사람이 조건과 처리 규칙을 직접 설계 | 특정 단어가 있으면 스팸으로 분류 |
| **학습 기반** | 여러 사례 데이터에서 판단에 유용한 패턴을 학습 | 스팸과 정상 메일 사례로 분류 모델 학습 |

초기의 여러 AI는 사람이 지식과 판단 규칙을 직접 작성하는 방식으로 구현되었습니다. 오늘날 이미지 인식, 추천, 번역, 생성형 AI에는 데이터에서 패턴을 학습하는 머신러닝과 딥러닝이 널리 활용됩니다.

<Callout kind="caution" title="한 가지 기준으로 단정하지 않기">
모든 AI가 반드시 데이터로 학습하는 것은 아니며, 학습 기반 AI에도 사람이 설계한 규칙과 프로그램이 함께 사용됩니다.

따라서 ‘규칙이 있으면 일반 프로그램, 데이터가 있으면 AI’처럼 단순하게 나누기보다 **시스템이 어떤 정보와 방법으로 어떤 지능적 기능을 수행하는지** 확인하는 것이 좋습니다.
</Callout>

## AI·머신러닝·딥러닝의 큰 지도

### 인공지능 AI

인공지능은 가장 넓은 개념입니다. 사람이 규칙을 직접 설계한 AI와 데이터에서 패턴을 학습하는 AI를 모두 포함할 수 있습니다.

인공지능이라는 말은 특정 프로그램 하나나 특정 학습 방법만을 가리키지 않습니다. **컴퓨터가 지능적 기능을 수행하도록 만드는 기술과 연구 전체**를 가리킵니다. 따라서 다음과 같이 서로 다른 접근이 모두 인공지능의 범위에 들어갈 수 있습니다.

- 사람이 지식과 규칙을 논리식으로 표현하여 문제를 해결하는 방식
- 많은 사례에서 통계적 관계와 패턴을 학습하는 방식
- 목표를 달성하기 위해 탐색하고 계획하는 방식
- 언어·이미지·음성 등을 인식하거나 새로운 결과를 생성하는 방식
- 학습 모델에 검색·데이터베이스·코드 실행 같은 도구를 결합한 시스템

예를 들어 체스 프로그램은 사람이 만든 탐색 규칙과 평가 방법을 중심으로 작동할 수도 있고, 많은 경기나 자기 대국을 통해 전략을 학습할 수도 있습니다. 두 시스템은 작동 방식이 다르지만 모두 체스 상황을 분석하고 다음 행동을 선택하는 지능적 기능을 수행하므로 넓은 의미의 AI에 포함됩니다.

<Callout kind="concept" title="AI는 하나의 모델이 아니라 넓은 분야이다">
AI 서비스의 화면 뒤에는 하나의 모델만 있는 것이 아닐 수 있습니다. 학습된 모델, 사람이 작성한 규칙, 데이터베이스, 검색, 센서, 코드 실행, 사용자 인터페이스가 함께 하나의 **AI 시스템**을 이룰 수 있습니다.
</Callout>

### 머신러닝 Machine Learning

머신러닝은 사람이 모든 판단 규칙을 하나하나 작성하는 대신 **데이터를 이용해 패턴을 학습하도록 하는 방법**입니다.

예를 들어 고양이와 강아지를 구분하는 모든 규칙을 사람이 문장으로 작성하기는 어렵습니다. 대신 정답이 표시된 여러 이미지를 보여주면 모델은 분류에 도움이 되는 패턴을 계산을 통해 찾습니다.

일반 프로그램과 머신러닝의 차이는 입력과 출력의 유무가 아니라 **문제를 해결하는 규칙을 어떻게 얻는가**에 있습니다.

| 일반적인 규칙 기반 프로그램 | 머신러닝 |
| --- | --- |
| 사람이 데이터 처리 규칙을 작성한다. | 학습 알고리즘이 데이터에서 규칙에 해당하는 패턴을 찾는다. |
| `입력 + 사람이 만든 규칙 → 출력` | `학습 데이터 + 기대하는 결과 → 학습 → 모델` |
| 규칙을 바꾸려면 사람이 프로그램을 수정한다. | 데이터·학습 방법·설정을 바꾸어 모델을 다시 학습할 수 있다. |
| 모든 상황을 명확한 조건으로 표현할 수 있는 문제에 적합하다. | 규칙을 문장으로 모두 적기 어렵지만 사례 데이터가 있는 문제에 유용하다. |

머신러닝에서 ‘학습한다’는 말은 컴퓨터가 사람처럼 경험의 의미를 깨닫는다는 뜻이 아닙니다. 모델이 예측한 값과 기대한 값의 차이를 계산하고, 그 차이가 작아지는 방향으로 모델 내부의 수치를 반복해서 조정한다는 뜻입니다.

```text
1. 학습 데이터를 모델에 입력한다.
2. 모델이 현재 상태에서 결과를 예측한다.
3. 예측과 정답의 차이인 손실을 계산한다.
4. 손실이 줄어들도록 모델의 내부 값을 조정한다.
5. 이 과정을 여러 데이터에 반복한다.
```

이때 사용하는 **학습 알고리즘**은 모델의 값을 어떤 방향으로 조정할지 정하는 절차이고, 학습이 끝난 **모델**은 새 입력에 결과를 만들 수 있도록 조정된 계산 구조입니다. 알고리즘과 모델은 같은 말이 아닙니다.

### 머신러닝이 규칙을 스스로 찾는다는 말의 의미

“AI가 스스로 규칙을 찾는다”는 표현은 사람이 아무것도 정하지 않는다는 뜻이 아닙니다. 사람은 여전히 다음을 결정합니다.

- 어떤 문제를 풀 것인지와 결과의 범주를 어떻게 정할지
- 어떤 데이터를 수집하고 어떤 정답을 붙일지
- 어떤 모델과 학습 방법을 사용할지
- 무엇을 오류로 보고 어떤 기준으로 성능을 평가할지
- 어느 정도의 오류를 허용하며 실제로 어디에 사용할지

모델이 찾는 것은 사람이 정한 문제와 데이터의 범위 안에서 예측에 도움이 되는 **수학적 패턴**입니다. 그래서 문제 정의나 데이터가 잘못되면 계산이 정확해도 가치 있는 결과가 나오지 않을 수 있습니다.

### 딥러닝 Deep Learning

딥러닝은 머신러닝의 방법 가운데 하나입니다. 여러 층의 인공신경망을 이용해 이미지·음성·텍스트처럼 복잡한 데이터의 특징과 패턴을 학습합니다.

‘딥러닝’의 ‘딥’은 사람이 더 깊게 생각한다는 뜻이 아니라, 신경망을 이루는 계산 층이 여러 단계로 연결되어 있다는 뜻에 가깝습니다.

전통적인 머신러닝에서는 사람이 문제에 중요하다고 생각하는 특징을 먼저 골라 수치로 표현하는 경우가 많았습니다. 예를 들어 꽃을 분류하려면 꽃잎의 길이·너비·색처럼 구분에 도움이 될 특징을 사람이 정리해 모델에 제공할 수 있습니다. 딥러닝은 원시 데이터에 가까운 이미지·소리·문장으로부터 필요한 특징의 조합도 학습 과정에서 함께 찾아낼 수 있다는 장점이 있습니다.

```text
전통적 머신러닝의 예
이미지 → 사람이 특징을 선택·수치화 → 머신러닝 모델 → 분류 결과

딥러닝의 예
이미지 → 여러 신경망 층이 특징의 조합을 학습 → 분류 결과
```

이미지를 처리하는 신경망에서는 앞쪽 층이 선이나 색의 변화처럼 비교적 단순한 특징에 반응하고, 뒤쪽 층으로 갈수록 모양과 부분의 조합처럼 더 복잡한 특징을 표현할 수 있습니다. 이것은 사람이 각 층에 ‘귀를 찾아라’, ‘눈을 찾아라’라고 일일이 명령한 결과가 아니라, 학습 목표에 맞게 많은 가중치가 함께 조정된 결과입니다.

딥러닝은 이미지·음성·자연어처럼 크고 복잡한 데이터를 다루는 데 강점을 보이지만 항상 가장 좋은 선택은 아닙니다. 충분한 데이터와 연산 자원이 필요할 수 있고, 내부 판단 과정을 사람이 쉽게 설명하기 어려우며, 학습 데이터의 편향이나 오류도 함께 배울 수 있습니다. 데이터가 적고 관계가 단순한 문제라면 더 간단한 머신러닝이나 명확한 규칙이 더 적절할 수 있습니다.

<Callout kind="think" title="지금은 큰 관계만 기억하기">
**딥러닝은 머신러닝에 포함되고, 머신러닝은 인공지능을 구현하는 여러 방법 중 하나**라는 관계만 먼저 기억합니다.
</Callout>

### 세 개념을 한 번에 비교하기

| 구분 | 인공지능 AI | 머신러닝 ML | 딥러닝 DL |
| --- | --- | --- | --- |
| 범위 | 가장 넓은 기술·연구 분야 | AI를 구현하는 방법 중 하나 | 머신러닝의 방법 중 하나 |
| 핵심 생각 | 컴퓨터가 지능적 기능을 수행하게 한다. | 데이터에서 예측에 유용한 패턴을 학습한다. | 여러 층의 인공신경망으로 복잡한 특징과 패턴을 학습한다. |
| 규칙·특징 | 사람이 직접 만든 규칙도 포함한다. | 사람이 특징을 정하거나 모델이 데이터 관계를 학습한다. | 여러 층에서 특징의 조합도 함께 학습할 수 있다. |
| 대표 사례 | 규칙 기반 전문가 시스템, 탐색·계획, 머신러닝 시스템 | 스팸 분류, 가격 예측, 고객 군집화 | 이미지 인식, 음성 인식, 번역, 대규모 언어 모델 |
| 반드시 필요한 것 | 모든 AI가 대량의 학습 데이터를 필요로 하지는 않는다. | 학습에 사용할 데이터와 평가 기준이 필요하다. | 보통 많은 데이터·계산·가중치를 다룬다. |

<Callout kind="caution" title="자주 생기는 오해">
- **AI와 머신러닝은 같은 말이 아닙니다.** 머신러닝을 사용하지 않는 AI도 있습니다.
- **머신러닝과 딥러닝도 같은 말이 아닙니다.** 딥러닝이 아닌 머신러닝 방법도 많습니다.
- **딥러닝이라고 항상 더 정확한 것은 아닙니다.** 문제와 데이터에 맞는 방법을 선택해야 합니다.
- **학습했다고 사람처럼 이해한 것은 아닙니다.** 데이터에서 계산 가능한 관계를 조정한 것입니다.
- **AI가 스스로 학습한다고 사람이 사라지는 것은 아닙니다.** 목적·데이터·평가·사용의 기준은 사람이 정합니다.
</Callout>

## 머신러닝은 어떤 방식으로 배울까?

머신러닝은 학습에 어떤 정보를 제공하고 어떤 목표를 주는지에 따라 크게 다음과 같이 구분할 수 있습니다.

| 학습 방법 | 학습할 때 제공하는 것 | 모델이 배우는 것 | 사례 |
| --- | --- | --- | --- |
| **지도학습** | 입력 데이터와 사람이 표시한 정답 | 입력과 정답 사이의 관계 | 이미지 분류, 스팸 분류, 가격 예측 |
| **비지도학습** | 정답이 없는 입력 데이터 | 데이터 안의 구조·유사성·집단 | 비슷한 고객이나 문서 묶기 |
| **강화학습** | 환경, 행동, 행동 결과에 대한 보상 | 더 큰 보상을 얻는 행동 전략 | 게임, 로봇 제어, 일부 의사결정 시스템 |

곧 만들 이미지 분류 모델은 사진과 클래스 이름을 함께 제공하므로 **지도학습**에 해당합니다. 다만 실제 AI 시스템은 한 가지 방식만 사용하지 않고 여러 방법과 사람이 작성한 규칙을 함께 사용할 수도 있습니다.

### 분류와 회귀

지도학습에서 자주 만나는 두 작업은 분류와 회귀입니다.

- **분류 Classification**: 입력이 어떤 범주에 속하는지 예측합니다. 예: 고양이/강아지, 정상 메일/스팸 메일
- **회귀 Regression**: 입력을 바탕으로 연속적인 수치를 예측합니다. 예: 주택 가격, 예상 소요 시간

추천·번역·생성형 AI처럼 실제 서비스의 작업은 이 두 가지로만 설명되지 않습니다. 그러나 분류와 회귀는 머신러닝의 학습 원리를 이해하는 중요한 출발점입니다.

## 인공신경망은 무엇일까?

인공신경망은 여러 입력값에 서로 다른 중요도를 주고 계산을 반복하면서 입력과 결과 사이의 복잡한 관계를 학습하는 모델 구조입니다. 사람의 뇌에서 영감을 받았지만 **사람의 뇌를 그대로 복제한 것은 아닙니다.**

```text
입력층 → 여러 은닉층의 계산 → 출력층
```

학습 과정에서는 모델의 예측과 실제 정답의 차이를 계산하고, 그 차이가 줄어들도록 내부의 많은 수치인 **가중치**를 조금씩 조정합니다. 딥러닝은 이러한 계산 층을 여러 단계로 쌓아 복잡한 특징을 학습합니다.

예를 들어 이미지 딥러닝 모델은 사람이 ‘귀 모양을 보라’고 모든 특징을 직접 지정하지 않아도, 학습 과정에서 분류에 도움이 되는 색·선·모양·질감의 조합을 계산할 수 있습니다. 다만 모델이 찾아낸 특징이 사람이 의도한 특징과 항상 같지는 않습니다.

## 컴퓨터가 데이터에서 학습한다는 것은 무엇일까?

학습 기반 이미지 분류 AI의 흐름은 다음과 같습니다.

```text
학습 데이터와 정답 → 학습 → 모델
모델 + 새로운 입력 → 분류·예측 결과
```

- **데이터**: 모델이 패턴을 찾을 수 있도록 제공하는 사례
- **학습**: 데이터의 특징과 정답 사이의 관계를 계산하며 모델을 조정하는 과정
- **모델**: 학습 과정에서 찾은 패턴이 계산 가능한 형태로 담긴 것
- **새로운 입력**: 학습에 그대로 사용하지 않은 이미지나 정보
- **결과**: 클래스, 예측값, 추천, 생성된 내용 등

모델은 모든 정답을 저장해둔 사전이 아닙니다. 학습 데이터에서 찾은 패턴을 새로운 입력에 적용해 결과를 예측합니다. 그래서 학습할 때 보지 못한 사람·배경·거리·조명에서는 결과가 달라지거나 틀릴 수 있습니다.

<Callout kind="concept" title="데이터가 중요한 이유">
**모델이 무엇을 배우는지는 어떤 데이터를 어떤 기준으로 제공했는지에 영향을 받습니다.**

데이터에 특정 배경이나 사람만 반복해서 등장하면 모델은 우리가 의도한 대상보다 그 배경이나 사람의 특징을 더 중요한 단서로 학습할 수도 있습니다.
</Callout>

## 학습과 테스트는 왜 나눌까?

모델이 학습에 사용한 문제를 잘 맞히는 것과 처음 보는 문제를 잘 해결하는 것은 다릅니다.

- **학습 데이터**: 모델이 패턴을 찾는 데 사용하는 자료
- **테스트 데이터**: 학습에 사용하지 않고 모델이 새로운 자료에서도 작동하는지 확인하는 자료
- **일반화**: 학습할 때 보지 못한 새로운 입력에도 배운 패턴을 적용하는 능력
- **과대적합**: 학습 데이터에는 지나치게 잘 맞지만 새로운 데이터에서는 성능이 떨어지는 상태

시험 문제와 답을 그대로 외운 학생이 숫자나 상황이 달라진 문제를 풀지 못한다면 원리를 충분히 이해했다고 보기 어렵습니다. 모델도 마찬가지입니다. 학습 자료와 너무 비슷한 자료로만 확인하면 실제 성능을 과대평가할 수 있습니다.

<Callout kind="caution" title="확률이 높으면 반드시 정답일까?">
분류 모델이 ‘고양이 95%’라고 표시해도 현실에서 95%의 확률로 반드시 고양이라는 뜻으로 단정할 수는 없습니다. 이 값은 현재 모델이 학습한 클래스 사이에서 해당 결과에 부여한 상대적인 점수입니다.

모델이 학습하지 않은 대상을 입력해도 기존 클래스 중 하나에 높은 점수를 줄 수 있습니다. 따라서 예측 점수와 실제 정확성은 구분해서 봐야 합니다.
</Callout>

## 기존 AI와 생성형 AI는 무엇이 다를까?

이미지 분류 AI는 입력을 미리 정한 클래스 중 하나로 구분합니다. 생성형 AI는 학습한 데이터의 패턴을 이용해 글·이미지·음성·영상·코드처럼 새로운 형태의 결과를 만듭니다.

| 구분 | 주된 결과 | 예 |
| --- | --- | --- |
| 분류·예측 AI | 정해진 범주나 수치 | 이미지 클래스, 가격, 추천 순위 |
| 생성형 AI | 새로운 내용이나 표현 | 문장, 이미지, 음악, 코드 |

두 방식 모두 데이터에서 패턴을 학습한 모델을 사용할 수 있다는 공통점이 있습니다. 생성형 AI가 사람처럼 내용을 이해하거나 사실을 확인한 뒤 말한다는 뜻은 아닙니다.

### 대규모 언어 모델 LLM

대규모 언어 모델은 많은 텍스트에서 언어의 패턴을 학습하고, 지금까지 주어진 문맥을 바탕으로 다음에 이어질 가능성이 높은 **토큰**을 예측하며 문장을 생성하는 모델입니다.

```text
인공지능 AI
└─ 머신러닝 ML
   └─ 딥러닝 DL
      └─ 대규모 언어 모델 LLM을 구현하는 주요 기반
```

LLM은 생성형 AI를 구현하는 중요한 모델이지만, 생성형 AI가 모두 LLM인 것은 아닙니다. 이미지·음악·영상 생성에는 목적에 맞는 다른 생성 모델도 사용됩니다.

## 서비스 이름과 기술 개념을 구분하기

ChatGPT, Gemini, Perplexity 등은 특정 회사가 제공하는 **서비스 또는 제품의 이름**입니다. 반면 인공지능, 머신러닝, 딥러닝, 대규모 언어 모델(LLM)은 기술이나 모델을 설명하는 **개념**입니다.

하나의 AI 서비스에는 언어 모델뿐 아니라 검색, 파일 처리, 이미지 인식, 코드 실행 같은 여러 기능이 결합될 수 있습니다. 서비스의 기능과 내부 구조는 시간이 지나며 바뀔 수 있으므로, 특정 서비스의 특징을 인공지능 전체의 특징으로 일반화하지 않습니다.

## AI가 ‘생각한다’는 것은 무슨 뜻일까?

1950년 앨런 튜링은 기계가 생각하는지를 직접 정의하는 대신, 글로 대화한 상대가 사람인지 기계인지 구별할 수 있는지를 살펴보는 방법을 제안했습니다. 이것이 오늘날 **튜링 테스트**라고 불리는 생각 실험입니다.

튜링 테스트는 기계가 사람과 비슷하게 대화할 수 있는지를 생각하게 했다는 점에서 의미가 있습니다. 그러나 말을 유창하게 만드는 것과 내용을 실제로 이해하고, 경험하고, 책임질 수 있는 것은 같은 문제가 아닙니다. 대화가 자연스럽다는 이유만으로 모델이 사람과 같은 방식으로 이해한다고 단정할 수 없습니다.

### 약인공지능과 강인공지능

| 구분 | 의미 |
| --- | --- |
| **약인공지능·좁은 인공지능** | 특정 목적이나 범위의 작업을 수행하도록 만들어진 AI |
| **강인공지능·범용 인공지능** | 사람처럼 다양한 영역을 폭넓게 이해하고 새로운 상황에 스스로 적용할 수 있다고 가정하는 AI |

현재 사용하는 이미지 인식, 추천, 번역, 생성형 AI 서비스는 대부분 특정 목적과 설계 범위 안에서 작동하는 약인공지능에 해당합니다. 여기서 ‘약하다’는 성능이 낮다는 뜻이 아닙니다. 특정 작업에서는 사람보다 빠르거나 높은 성능을 보일 수 있습니다.

강인공지능은 아직 합의된 형태로 실현되었다고 보기 어렵고, 무엇을 이해·지능·범용성으로 볼지에 대해서도 논의가 계속되고 있습니다.

## 인공지능은 어떻게 발전해왔을까?

| 시기 | 중요한 흐름 |
| --- | --- |
| 1950년대 | 튜링의 질문과 다트머스 회의를 거치며 인공지능 연구 분야가 형성됨 |
| 1960~1980년대 | 사람이 지식과 규칙을 입력하는 문제 해결 프로그램과 전문가 시스템 연구 |
| 1990~2000년대 | 데이터와 통계적 방법을 이용하는 머신러닝이 다양한 분야로 확산 |
| 2010년대 | 데이터·연산 능력·알고리즘의 발전으로 딥러닝이 이미지·음성·언어 처리에서 성장 |
| 2020년대 | 대규모 언어 모델과 생성형 AI가 확산되고 검색·파일·코드 등 여러 도구와 결합 |

AI의 발전은 알고리즘 하나만의 결과가 아닙니다. 데이터의 증가, 반도체와 컴퓨팅 성능의 발전, 네트워크와 저장 기술, 연구 성과, 사람이 정한 목적과 투자 등이 함께 영향을 주었습니다.

## AI의 결과에서 사람은 무엇을 할까?

AI는 많은 데이터를 빠르게 처리하고 패턴을 찾아 결과를 제시할 수 있습니다. 하지만 결과가 현재 상황에서 무엇을 의미하는지, 실제로 사용해도 되는지는 자동으로 결정되지 않습니다.

- 무엇을 해결하려고 만든 AI인가?
- 어떤 데이터와 기준으로 학습하거나 작동하는가?
- 처음 보는 사람과 상황에서도 잘 작동하는가?
- 의도한 대상이 아니라 배경이나 엉뚱한 특징을 본 것은 아닌가?
- 잘못된 결과가 나오면 누가 영향을 받는가?
- 이 결과를 실제 상황에 사용해도 되는가?

<Callout kind="concept" title="AI와 사람의 역할">
**AI**는 데이터와 규칙, 학습된 패턴과 계산을 이용해 결과를 만듭니다.

**사람**은 문제와 목적을 정하고, 필요한 데이터와 맥락을 선택하며, 결과를 해석·검증하고, 최종 사용 여부를 판단하고 책임집니다.
</Callout>

| 지도·비지도·강화학습 | 정답·구조·보상 중 무엇을 이용해 학습하는지에 따른 구분 |
| 분류·회귀 | 범주 또는 연속적인 수치를 예측하는 대표적인 지도학습 작업 |
| 딥러닝 | 여러 층의 인공신경망을 사용하는 머신러닝 방법 |
| 모델 | 학습 과정에서 찾은 패턴이 계산 가능한 형태로 담긴 것 |
| 일반화·과대적합 | 새로운 자료에도 적용하는 능력과 학습 자료에만 지나치게 맞는 문제 |
| 생성형 AI | 학습한 패턴을 바탕으로 새로운 내용과 표현을 만드는 AI |
| LLM | 문맥에서 다음 토큰을 예측하며 텍스트를 생성하는 대규모 언어 모델 |
| 튜링 테스트 | 대화를 통해 사람과 기계를 구별할 수 있는지 살펴보는 생각 실험 |
| 약인공지능·강인공지능 | 특정 작업 중심의 AI와 범용적 지능을 가정한 AI의 구분 |
| 사람의 역할 | 목적·질문·데이터·맥락을 정하고 결과를 검증하며 최종 판단을 책임지는 일 |

## 다음 학습으로 연결하기

설명만으로는 ‘데이터에서 패턴을 학습한다’는 말을 충분히 이해하기 어렵습니다. 다음 시간에는 직접 두 가지 이미지를 구분하는 작은 모델을 학습시키고, 익숙한 조건과 처음 보는 조건에서 결과를 비교합니다.

<Callout kind="think" title="실험에서 찾을 것">
모델을 멋지게 만드는 것보다 **언제 틀리는지, 왜 틀렸다고 생각하는지, 데이터를 어떻게 바꾸면 결과가 달라지는지** 찾는 것이 중요합니다.
</Callout>
