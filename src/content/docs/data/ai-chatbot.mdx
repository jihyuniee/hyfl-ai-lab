챗봇·요약·설명·번역 기능이 필요한 팀을 위한 **프로젝트 도움말**입니다. 교과서의 신청 양식과 시작 파일을 이용해 **자신의 웹앱 안에 AI 기능**을 연결합니다.

<Callout kind="mission" title="AI API 사용 신청">

우리 팀 앱에 **GPT나 Claude를 활용하는 기능**을 넣고 싶다면 **선생님께 API 사용을 요청하세요.** 사용할 서비스·모델, 사용 대상·기간·한도를 확인하고 프로젝트 서버의 키 설정을 지원받습니다.

**진행 순서:** 역할 정하기 → 신청문 전달 → 내 프로젝트 준비 → 서버 환경변수 설정·배포 → 질문과 답변 확인

</Callout>

## 1. 우리 앱에서 AI가 할 일 정하기

AI API는 앱에서 보낸 질문이나 자료를 모델이 처리하고 결과를 돌려주는 연결 방식입니다. 팀은 **누가 어떤 질문을 하고, 어떤 자료를 바탕으로 어떤 답변을 받을지** 정합니다.

| 기능 예시 | AI에 전달할 내용 | 확인할 결과 |
| --- | --- | --- |
| 데이터 설명 | 코드로 계산한 통계, 출처·기준일, 사용자 질문 | 수치와 의미를 설명한 답변 |
| 시설 안내 | 우리 앱이 검색한 시설 정보와 사용자 조건 | 해당 자료에 근거한 안내 |
| 외국어 안내 | 출처가 있는 안내문과 선택한 언어 | 번역문과 원문 출처 |

프로젝트의 주제와 사용할 자료는 각 팀이 정합니다. 집계·검색·필터는 코드로 처리하고 원자료와 대조한 결과를 AI에 전달합니다.

## 2. 선생님께 API 사용 신청하기

아래 양식의 표시된 부분을 채워 **수업에서 안내한 방법으로 선생님께 전달**합니다. 프로젝트 주소와 실제로 구현할 기능을 함께 준비합니다.

<CopyPrompt title="선생님께 전달할 API 사용 신청문" content={requestApiPrompt} />

신청 후에는 다음 내용을 확인합니다.

| 확인할 항목 | 기록할 내용 |
| --- | --- |
| 서비스·모델 | OpenAI 또는 Claude, 선생님이 지정한 정확한 모델 식별자 |
| 사용 대상·기간 | 앱을 사용할 사람과 사용 종료 시점 |
| 사용 한도 | 프로젝트에 적용할 제공사의 사용량·지출 한도 |
| 서버 설정 | 키를 등록할 프로젝트와 배포 서비스의 환경변수 설정 위치 |
| 앱 이용코드 | 선생님과 정한 코드의 전달 여부와 사용 대상 |

API 키의 실제 값은 **프로젝트 서버의 환경변수 설정 화면에서 등록**합니다. 신청문·활동지·AI에 제공할 코드 사본에는 변수 이름과 자리표시자를 기록합니다.

## 3. 내 프로젝트와 연결 파일 준비하기

**사용자 질문 → 내 프로젝트의 서버 API → GPT·Claude → 서버 API → 내 앱의 답변 화면** 순서로 연결합니다.

| 구성 | 역할 |
| --- | --- |
| `index.html` 등 화면 코드 | 질문·이용코드를 입력받고 답변을 표시 |
| 서버 API | 이용코드와 입력을 확인하고 설정된 모델 호출 |
| 서버 환경변수 | API 비밀키, 사용할 모델, 앱 이용코드 보관 |

GitHub Pages는 HTML·CSS·JavaScript를 제공하는 정적 호스팅입니다. AI를 호출하는 서버 코드는 **Vercel Functions 같은 서버 실행 환경**에 배포합니다. 아래 시작 파일은 화면과 서버 API를 **하나의 Vercel 프로젝트 주소**에서 실행하도록 구성되어 있습니다. [GitHub Pages 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages) · [Vercel Functions 안내](https://vercel.com/docs/functions)

### A. 현재 만드는 앱이 있는 팀

1. 현재 정상 작동하는 프로젝트를 보관합니다.
2. 아래 시작 파일을 연결 예제로 준비하고, 현재 프로젝트 파일이나 저장소를 AI에 제공합니다.
3. **5단계의 요청문**으로 현재 화면·기능을 유지하며 챗봇 화면과 서버 경로를 추가합니다. 프레임워크 프로젝트는 해당 프레임워크의 서버 경로를 사용합니다.
4. 기존 배포 환경에서 서버 실행이 지원되는지 확인합니다. HTML 프로젝트를 Vercel로 배포할 때는 4단계를 따릅니다.

### B. 작은 챗봇부터 연결할 팀

<Callout kind="lab" title="챗봇 시작 파일 받기">

**[챗봇 시작 파일 ZIP 다운로드](/hyfl-ai-lab/templates/ai-chatbot-starter.zip)**

압축을 풀어 파일을 준비합니다. 질문·답변 화면, 이용코드 확인, OpenAI·Claude 호출용 서버 코드, 설정 안내가 들어 있습니다. 서비스와 모델은 서버 환경변수로 선택합니다.

</Callout>

1. 압축을 푼 폴더에서 `index.html`, `api` 폴더, `package.json`, `vercel.json`, `README.md`와 함께 제공된 파일을 확인합니다.
2. GitHub에 프로젝트 저장소를 만들고 **폴더 안의 파일과 하위 폴더를 구조대로** 올립니다. `index.html`과 `package.json`이 저장소의 최상위에 오도록 합니다.
3. `README.md`를 열어 필요한 환경변수와 서버 구성을 확인합니다.
4. 다음 단계에서 서버 환경변수를 설정하고 배포합니다.

## 4. 서버 환경변수 설정하고 배포하기

다음은 **시작 파일을 Vercel로 배포하는 순서**입니다. 기존 프로젝트의 서버 환경을 쓰는 팀은 그 서비스의 환경변수 설정과 배포 절차를 사용합니다.

1. Vercel에 로그인하고 **New Project**를 엽니다. 처음 연결할 때는 GitHub 계정을 연결하고 사용할 저장소의 접근 권한을 설정한 뒤 우리 저장소를 선택합니다.
2. 시작 파일은 **Framework Preset: Other**, **Root Directory: 파일이 있는 저장소 루트**를 확인합니다. **Build Command**의 Override를 켜고 값을 비워 빌드 단계를 생략합니다.
3. **Environment Variables**에 아래 이름과 값을 등록합니다. 기존 프로젝트는 **Settings → Environment Variables**에서 등록합니다.
4. 사용할 배포 환경을 선택합니다. 실제 수업용 주소에는 **Production** 설정을 적용합니다.
5. **Deploy**로 배포하고 완료된 웹앱 주소를 엽니다. 환경변수를 나중에 추가하거나 변경했으면 **Redeploy**하여 새 배포에 적용합니다.

[Git 저장소에서 배포하기](https://vercel.com/docs/git) · [일반 HTML 프로젝트의 빌드 설정](https://vercel.com/docs/builds/configure-a-build) · [환경변수 등록과 적용](https://vercel.com/docs/environment-variables/managing-environment-variables)

### 시작 파일에 등록할 값

| 변수 이름 | 입력할 값 | 적용 대상 |
| --- | --- | --- |
| `AI_PROVIDER` | `openai` 또는 `anthropic` | 공통 |
| `AI_MODEL` | 선생님과 확인한 정확한 모델 식별자 | 공통 |
| `OPENAI_API_KEY` | 팀 프로젝트에 사용할 OpenAI 키 | OpenAI 선택 시 |
| `ANTHROPIC_API_KEY` | 팀 워크스페이스에 범위를 지정한 Claude 키 | Claude 선택 시 |
| `CHAT_ACCESS_CODE` | 선생님과 정한 무작위 영문·숫자·`_`·`-` 조합의 16~128자 이용코드 | 공통 |

API 비밀키는 **서버가 AI를 호출할 때 사용하는 값**입니다. 앱 이용코드는 **허용된 이용자가 챗봇 화면에서 입력하는 값**입니다. 두 값은 각각 따로 설정합니다. 이용코드는 허용된 사람에게 전달하고, 코드 파일에는 자리표시자를 사용합니다.

선택 설정인 `CHAT_SYSTEM_PROMPT`에는 챗봇의 역할을, `MAX_OUTPUT_TOKENS`에는 서버의 최대 출력 토큰 수를 지정할 수 있습니다. 시작 파일의 기본값과 설정 범위는 함께 받은 `README.md`에서 확인합니다. [OpenAI 키 보관](https://developers.openai.com/api/reference/overview) · [Claude 인증과 워크스페이스 범위](https://platform.claude.com/docs/en/manage-claude/authentication)

**첫 실행:** 배포된 주소에서 앱 이용코드를 입력하고 짧은 질문을 보냅니다. 답변, 처리 상태, 새 대화 기능을 확인합니다. 기존 앱에 지도를 사용한다면 새 배포 주소에 맞춰 지도 서비스의 도메인 설정도 갱신합니다.

## 5. 우리 앱의 기능과 자료 연결하기

현재 프로젝트와 시작 파일을 AI에 함께 제공하고 아래 요청문을 채웁니다. 저장소를 연결해 수정하는 방법은 [GitHub의 내 코드를 GPT와 수정하기](/hyfl-ai-lab/data/github-ai/)에서 확인합니다.

<CopyPrompt title="내 프로젝트에 챗봇 기능 추가하기" content={addChatbotPrompt} />

자료를 활용하는 팀은 **관련 항목·출처·기준일을 질문과 함께 전달**합니다. 시작 파일의 참고자료 입력란에는 작은 자료와 출처를 넣어 연결을 확인할 수 있습니다. 이후에는 현재 앱의 검색·조회 결과를 전달하도록 수정합니다.

질문과 대화, 참고자료에는 시작 파일이 정한 입력 제한이 적용됩니다. AI에 전달할 자료는 질문에 필요한 범위로 골라 준비합니다. 답변 화면에는 **AI가 생성한 답변**임을 표시하고 원자료를 확인할 수 있는 출처를 함께 제공합니다.

## 6. 실행 결과와 오류 확인하기

| 확인할 상황 | 직접 확인할 결과 |
| --- | --- |
| 기본 질문 | 프로젝트의 역할에 맞는 답변이 표시됨 |
| 자료를 사용한 질문 | 수치·이름·날짜가 원자료와 맞고 출처를 확인할 수 있음 |
| 근거가 부족한 질문 | 추가로 확인할 내용을 안내함 |
| 빈 질문·연속 클릭 | 입력 안내가 나오고 처리 중 중복 전송이 제한됨 |
| 이용코드 확인 | 올바른 코드로 요청할 수 있고 잘못된 코드에는 안내가 표시됨 |
| 입력 제한·서버 실패 | 실제 상태에 맞는 오류 안내가 표시됨 |
| 기존 기능 | 원래 있던 검색·지도·표·버튼이 계속 작동함 |

AI 답변의 수치·고유명사·출처는 원자료와 대조합니다. 개인을 식별하는 자료는 익명화하고, API에 보낼 내용을 확인한 뒤 테스트합니다.

시작 예제에서 오류가 생기면 브라우저 개발자도구의 **Network → `/api/chat` 요청**에서 상태 코드와 응답의 오류 코드를 확인합니다. 기존 프로젝트는 자신이 연결한 서버 API 경로를 확인합니다. 서버 설정과 제공사 사용량은 선생님과 함께 확인합니다.

<summary>교사용 · 팀 프로젝트의 API 지원 설정</summary>

1. 팀의 사용 목적·대상·기간을 확인하고 서비스와 모델을 정합니다.
2. OpenAI의 프로젝트 또는 Claude의 워크스페이스로 사용량을 구분하고, 팀 프로젝트 서버에서 사용할 권한과 키를 설정합니다. Claude 시작 예제는 해당 워크스페이스에 범위를 지정한 키를 사용합니다.
3. 서버 환경변수에 키를 등록하고, 제공사의 지출 한도와 사용량을 확인합니다. OpenAI는 월간 강제 지출 한도, Claude는 워크스페이스별 월간 지출 한도를 제공합니다. OpenAI는 한도 적용 지연으로 소폭 초과할 수 있음을 안내합니다.
4. 앱 이용코드와 입력·출력 길이 설정을 확인합니다. 시작 파일은 이용코드·입력 크기·출력 토큰을 검사하고, 월간 사용량과 지출은 제공사에서 관리합니다.
5. 사용 기간이 끝나면 제공사에서 해당 키를 회수하거나 비활성화합니다.

[OpenAI 지출 한도](https://developers.openai.com/api/docs/guides/spend-limits) · [Claude 워크스페이스와 한도](https://platform.claude.com/docs/en/manage-claude/workspaces)
