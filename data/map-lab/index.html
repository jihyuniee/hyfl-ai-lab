번외 실습: 내 프로젝트에 카카오맵 넣기

이 페이지는 지도 기능이 필요한 팀을 위한 번외 실습입니다. 지금 만드는 프로젝트에 지도 기능을 추가합니다. 아직 프로젝트가 없다면 한 파일짜리 index.html로 시작할 수 있습니다.

🎯 완성할 결과

우리 팀이 선택한 공공데이터의 위치와 필요한 정보를 우리 팀 웹앱의 카카오 지도에 표시합니다. 먼저 가상 연습 위치·실제 자료 아님으로 표시한 세 위치와 클릭 설명으로 지도 연결을 점검하고, 그다음 팀의 실제 자료를 연결합니다.

진행 순서는 내 파일 준비 → 내 배포 주소 확인 → 카카오 설정 → 내 파일에 키 입력 → 지도 연결 점검 → 우리 팀 공공데이터 연결입니다. 교과서를 옆에 열어 두고, 아래 작업은 자신의 파일과 프로젝트에서 진행하세요.

1. 지도를 넣을 내 파일 준비하기

섹션 제목: “1. 지도를 넣을 내 파일 준비하기”

우리 팀 상황에 맞게 A 또는 B 중 하나로 시작합니다. 두 경우 모두 키는 아직 넣지 않고 YOUR_JAVASCRIPT_KEY로 남겨 둡니다.

A. 이미 만드는 프로젝트가 있다면

섹션 제목: “A. 이미 만드는 프로젝트가 있다면”
  1. 현재 정상 작동하는 파일을 별도 폴더에 복사해 원본을 보관합니다.
  2. AI에게 현재 프로젝트 파일을 첨부합니다. HTML이 CSS·JavaScript 파일을 따로 불러온다면 관련 파일도 함께 제공합니다. 사본에 실제 키가 들어 있다면 자리표시자로 바꿉니다.
  3. 아래 요청의 빨간 부분을 우리 프로젝트에 맞게 고쳐 전달합니다. 기존 화면과 기능을 유지하면서 지도 영역만 추가하도록 요청합니다.
  4. 수정본을 확인하고 기존 프로젝트의 파일 구조와 이름에 맞게 적용합니다. 이전 버튼·입력·목록도 작동하는지 눌러 봅니다.
현재 프로젝트에 카카오맵 추가 요청 {{빨간 부분}}을 우리 팀의 내용으로 바꾸세요.
프롬프트 구조와 각 부분이 필요한 이유 보기

역할·프로젝트 맥락은 AI가 어떤 관점에서 어느 팀의 문제를 다루는지 정합니다.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

첨부한 우리 팀 프로젝트에 카카오 지도를 추가해줘. 최종 결과는 우리 팀의 웹앱 주소 안에서 지도가 작동하는 것이야.

# 현재 프로젝트
- 프로젝트 이름과 목적: {{이름과 해결하려는 문제}}
- 첨부한 파일과 구조: {{index.html 한 파일 / HTML·CSS·JS 여러 파일 / React 등 실제 구조}}
- 현재 실행 또는 배포 주소: {{우리 팀 주소, 아직 없으면 미배포}}
- 지도를 넣을 위치: {{예: 검색 결과 목록 오른쪽 / 지도 탭 / 본문 아래}}
- 그대로 유지할 기능: {{검색·필터·표·파일 읽기 등 실제 있는 기능}}

# 추가할 기능
1. 현재 프로젝트의 파일 구조, 디자인, 정상 작동하는 기능과 데이터 연결을 유지해줘. 기존 앱 전체를 새 지도 예제로 덮어쓰지 말고 지도 영역을 추가해줘.
2. 지도 컨테이너 ID가 기존 요소와 충돌하지 않게 하고 높이를 명시해줘. 지도 전용 CSS만 추가해 기존 body·제목·버튼 등의 스타일을 바꾸지 마.
3. 카카오 지도 SDK가 이미 있는지 확인하고 한 번만 불러와줘. SDK 주소는 https://dapi.kakao.com/v2/maps/sdk.js 이고 appkey와 autoload=false를 사용해줘. 지도 요소와 SDK가 준비된 다음 kakao.maps.load 콜백에서 초기화해줘. 프레임워크라면 실제 컴포넌트 수명 주기에 맞추고 브라우저에서만 실행해줘. 숨겨진 지도 탭이 열리거나 지도 영역 크기가 바뀌면 필요한 relayout을 처리해줘.
4. 키 설정은 const javascriptKey = 'YOUR_JAVASCRIPT_KEY';처럼 한 곳으로 모아줘. 실제 키는 내가 직접 바꿀 거야. 키가 없는 동안에는 설정 안내를 보여줘. REST API 키·어드민 키·Client Secret은 넣지 마.
5. 먼저 가상 지점 A(37.5651, 126.9821), B(37.5670, 126.9850), C(37.5629, 126.9843)를 마커로 표시해줘. 마커를 누르면 이름과 ‘가상 연습 위치·실제 자료 아님’ 설명을 보여줘. 가상 좌표를 우리 팀의 실제 데이터나 분석 결과에 섞거나 저장하지 마.
6. 우리 팀이 선택한 실제 자료는 지도 연결을 확인한 뒤 적용할 거야. 기존 데이터 연결은 유지하고 현재 위치·길찾기는 새로 추가하지 마. 지도 출처와 로딩·실패 안내를 제공하고 기존 기능도 그대로 테스트할 수 있게 해줘.
7. 내가 등록할 도메인은 우리 팀 웹앱의 실제 호스트와 사용 중인 포트야. 저장소 경로·파일명은 제외해줘. 카카오 앱의 사용 설정 ON과 해당 JavaScript 키의 SDK 도메인 설정을 안내해줘.

# 결과 형식
- 변경한 파일과 이유를 먼저 알려줘.
- 한 파일 HTML 프로젝트면 수정한 전체 HTML을, 여러 파일이나 프레임워크 프로젝트면 수정한 파일별 전체 코드와 적용 위치를 제공해줘. 현재 구조를 임의로 다른 방식으로 바꾸지 마.
- 내가 키를 교체할 정확한 파일·한 줄, 같은 주소에 다시 배포할 방법, 지도와 기존 기능을 확인할 순서를 알려줘.
- 첨부 정보가 부족해 기존 기능을 유지할 수 없다면 필요한 파일을 구체적으로 알려줘. 실행해 보지 않은 결과를 확인 완료라고 쓰지 마.

아래 B의 새 시작 HTML 전체로 현재 프로젝트를 덮어쓰지 않습니다. 지도 영역의 높이, SDK를 한 번 불러오는 코드, 가상 마커 기능을 현재 파일 안에 추가하는 작업입니다. 기존 파일을 첨부하지 않으면 AI가 원래 기능을 알 수 없습니다.

B. 아직 프로젝트가 없다면

섹션 제목: “B. 아직 프로젝트가 없다면”

아래 index.html 다운로드로 시작 파일을 받습니다. 배경 지도와 가상 연습 위치 3개를 위한 코드가 들어 있습니다. 가상 연습 위치·실제 자료 아님을 표시한 예제입니다. 이번 순서에서는 키를 바꾸지 말고 먼저 2단계에서 배포 주소를 만듭니다.

내 프로젝트로 사용할 index.html을 내려받으세요.

처음 만드는 팀을 위한 한 파일짜리 시작 예제입니다. 기존 프로젝트가 있다면 본문의 ‘기존 프로젝트에 추가하기’를 이용하세요. 세 지점은 실제 자료가 아닌 가상 연습 위치입니다. 지도 연결을 확인한 뒤 출처가 있는 우리 팀의 실제 위치 자료로 교체하세요.

카카오맵 시작 예제

카카오맵 사용 설정 ON, JavaScript 키와 웹앱 도메인 등록이 필요합니다.

index.html 다운로드

처음 배포할 때는 키 자리표시자를 그대로 둡니다. 본문 순서대로 자기 웹앱 주소와 카카오 설정을 준비한 뒤, 파일 아래 <script> 안의 const javascriptKey = 'YOUR_JAVASCRIPT_KEY';에서 따옴표 안만 본인의 JavaScript 키로 바꾸고 다시 배포하세요. REST API 키·어드민 키·Client Secret은 넣지 않습니다.

카카오디벨로퍼스에서 카카오맵 → 사용 설정 → ON을 확인하고, 앱 → 플랫폼 키 → JavaScript 키 → JavaScript SDK 도메인에 실행할 웹앱 주소를 등록하세요. localhost는 포트까지 맞춥니다.

내려받은 index.html을 코드 편집기로 열어 수정하고, 등록한 HTTPS 웹앱 주소 또는 localhost 웹 서버에서 실행하세요. 이 시작 예제는 웹 서버에서 실행하도록 만들어서, 더블클릭한 file:// 화면에서는 안내만 표시합니다. 지도에 표시되는 로고와 저작권 정보는 유지하세요.

전체 코드 보기

  1. 내려받은 파일을 코드 편집기 또는 메모장에서 엽니다. 브라우저에 열린 화면을 편집하는 것이 아니라 HTML 파일의 코드를 수정합니다.
  2. 파일 이름이 index.html인지 확인합니다. 다른 이름으로 내려받았다면 바꿉니다.
  3. 코드를 복사해서 새 파일을 만들었다면 메모장의 다른 이름으로 저장 → 파일 형식: 모든 파일 → 인코딩: UTF-8을 선택하고 index.html로 저장합니다. index.html.txt로 저장되지 않았는지 확인합니다. Mac 텍스트 편집기를 쓴다면 일반 텍스트로 저장합니다.
  4. YOUR_JAVASCRIPT_KEY가 그대로 있는 상태로 저장합니다. 지금은 지도가 안 보여도 됩니다.

# 구현 조건
1. 지도 영역에 명시적인 높이를 주고, 화면에는 프로젝트 제목과 로드 상태를 표시해줘.
2. 키 설정은 실행되는 JavaScript의 const javascriptKey = 'YOUR_JAVASCRIPT_KEY'; 한 줄로 만들어줘. 실제 키는 내가 직접 바꿀 거야. 키 자리표시자는 이 설정 한 곳에서만 사용하고, 키 값을 화면에 출력하거나 저장하지 마. REST API 키·어드민 키·Client Secret은 넣지 마.
3. SDK는 https://dapi.kakao.com/v2/maps/sdk.js 에 appkey와 autoload=false를 붙여 한 번만 불러와줘. SDK를 불러온 뒤 kakao.maps.load 콜백 안에서 지도를 초기화해줘. 키가 자리표시자일 때는 외부 요청 없이 설정 안내를 보여줘.
4. 가상 지점 A(37.5651, 126.9821), B(37.5670, 126.9850), C(37.5629, 126.9843)를 표시해줘. 좌표는 위도·경도 순서야. 마커를 누르면 이름과 ‘가상 연습 위치·실제 자료 아님’ 설명이 열리게 해줘. 같은 내용을 글 목록으로도 보여줘.
5. SDK 오류와 시간 초과를 안내하고, 배경 지도까지 확인하지 않았는데 성공했다고 단정하지 마. 카카오 로고와 저작권 표시는 유지해줘.
6. 실제 실행할 내 웹앱 도메인을 카카오에 등록해야 한다고 설명해줘. 등록값은 프로토콜·호스트·사용 중인 포트이며 뒤의 저장소·파일 경로는 제외해줘.

# 결과 형식
저장할 index.html 전체를 제공하고, 내가 키를 바꿀 위치와 배포 후 확인할 행동을 설명해줘. 코드 일부만 주거나 교과서의 공용 실습창을 최종 결과물로 제시하지 마.

직접 확인: 우리 팀이 수정할 파일을 찾을 수 있고, 그 안에 지도 코드와 키 자리표시자가 있습니다. 기존 프로젝트라면 원본도 보관했습니다.

2. 내 웹앱을 배포하고 실제 주소 확인하기

섹션 제목: “2. 내 웹앱을 배포하고 실제 주소 확인하기”

이미 배포한 프로젝트라면 기존 배포 방법으로 수정본을 올리고 실제 웹앱 주소를 엽니다. 새 index.html로 시작하는 팀은 다음 순서로 GitHub Pages 주소를 만듭니다.

  1. GitHub의 + → New repository에서 공개 가능한 연습용 Public 저장소와 README를 만듭니다.
  2. Add file → Upload files로 index.html을 저장소 맨 위에 올리고 Commit changes를 누릅니다.
  3. Settings → Pages → Build and deployment → Source를 Deploy from a branch로 선택합니다.
  4. Branch: main / (root)를 선택하고 Save합니다. 파일을 올린 브랜치가 다른 이름이면 그 브랜치를 선택합니다.
  5. 배포가 끝나면 Visit site로 웹앱을 엽니다. 아직 열리지 않으면 Actions의 배포 상태를 확인합니다.

자세한 절차는 교과서의 GitHub 배포 안내를 참고하세요. 첫 배포에서는 키 입력 안내나 지도 자리가 보이면 됩니다. 아직 키를 넣지 않았으므로 지도 연결 성공을 기다리지 않습니다.

브라우저 주소창에서 내 웹앱의 실제 주소를 복사합니다. GitHub 저장소의 코드 화면 주소나 AI 미리보기 주소와 구분하세요.

실제로 지도가 실행될 주소 예시카카오에 등록할 SDK 도메인
https://my-team.github.io/our-map/https://my-team.github.io
https://my-team-map.vercel.app/https://my-team-map.vercel.app
http://localhost:3000/index.htmlhttp://localhost:3000

표의 주소는 형식을 보여 주는 예시입니다. 그대로 등록하지 말고 자신의 주소에서 확인합니다. 등록값에는 프로토콜과 호스트를 쓰고, /our-map/ 같은 뒤의 경로는 뺍니다. localhost를 사용하면 실제 포트도 포함합니다. Vercel의 미리보기 주소와 정식 배포 주소가 다르면, 실제 확인할 주소를 기준으로 설정합니다.

직접 확인: 내 웹앱이 열리는 주소와 그 주소에서 뽑은 SDK 도메인을 구분해 적었습니다.

3. 카카오 앱을 켜고 내 도메인 등록하기

섹션 제목: “3. 카카오 앱을 켜고 내 도메인 등록하기”
  1. 카카오디벨로퍼스에 카카오 계정으로 로그인합니다. 처음이면 개발자 등록을 진행합니다.
  2. 앱에서 사용할 앱을 선택합니다. 아직 없다면 이름 등 필수 정보를 입력해 만듭니다.
  3. 그 앱의 카카오맵 → 사용 설정 → 상태를 ON으로 바꿉니다.
  4. 같은 앱에서 앱 설정 → 앱 → 플랫폼 키 → JavaScript 키를 선택합니다.
  5. 해당 키의 JavaScript SDK 도메인에 2단계에서 확인한 내 웹앱의 도메인을 추가하고 저장합니다.
  6. 방금 설정한 JavaScript 키를 복사합니다. 다음 단계에서 내 코드에 넣습니다.

⚠️ 키 복사와 도메인 등록에 더해, 사용 설정 ON을 확인하세요

카카오맵 → 사용 설정 → ON은 별도 설정입니다. disabled OPEN_MAP_AND_LOCAL service 응답이 나오면, 입력한 키가 속한 앱에서 이 설정부터 확인합니다.

등록 위치는 선택한 JavaScript 키 안의 SDK 도메인입니다. 앱의 대표 도메인이나 다른 키의 설정과 구분하세요. 등록할 값은 우리 팀 지도가 실행되는 도메인입니다. 교과서 주소를 대신 등록하지 않습니다. 메뉴가 달라졌다면 공식 웹 준비 안내와 키·도메인 설정을 확인합니다.

앱 정보의 카카오맵 무료 쿼터 표시도 확인하세요. 현재 새로 활성화하는 경우 개발자 계정에서 처음 카카오맵 API를 활성화한 앱에 무료 쿼터가 제공됩니다. 두 번째 이후의 새 활성화 앱이나 제공량 초과 사용에는 유료 API 설정이 필요합니다. 통계 → 쿼터와 현재 이용 조건을 확인하며, 유료 설정은 이 실습에 포함하지 않습니다. 같은 앱·키를 계속 사용할 수 있다면 새 키를 만들기보다 그 키에 사용할 도메인을 추가합니다.

직접 확인: 사용할 앱은 카카오맵 ON이며, 그 앱의 JavaScript 키에 내 도메인이 등록되어 있습니다.

4. 내 파일의 키 한 줄을 바꾸고 다시 배포하기

섹션 제목: “4. 내 파일의 키 한 줄을 바꾸고 다시 배포하기”
  1. 코드 편집기에서 1단계의 내 파일을 엽니다. 찾기 기능으로 YOUR_JAVASCRIPT_KEY를 찾습니다.
  2. 시작 예제라면 파일 아래 <script> 안의 const javascriptKey 줄을 찾습니다. 기존 프로젝트라면 지도 초기화 코드가 있는 파일에서 같은 설정 줄을 찾습니다. 아래 줄의 따옴표 안 자리표시자만 복사한 JavaScript 키로 바꾸고, 따옴표와 세미콜론은 유지합니다.
  1. 파일을 저장합니다. JavaScript가 별도 파일이라면 그 코드가 들어 있는 파일을 수정합니다.
  2. 같은 프로젝트의 같은 파일 위치에 수정본을 올립니다. GitHub Pages라면 기존 index.html을 새 내용으로 교체하고 Commit changes합니다. GitHub의 해당 파일 화면에서 편집 버튼으로 키 한 줄을 직접 수정하고 커밋해도 됩니다. 새 저장소를 만들지 않습니다.
  3. 배포가 완료되면 2단계에서 확인한 내 웹앱 주소를 다시 엽니다. 바뀐 내용이 안 보이면 배포 상태와 업로드한 파일을 확인하고 새로고침합니다.

JavaScript 키는 브라우저 지도용 식별자이며, 등록한 도메인에서 사용하도록 설정합니다. REST API 키·어드민 키·서버용 비밀키로 대체하지 않습니다. AI에게 수정을 부탁할 때는 사본의 키를 다시 자리표시자로 바꾸고, 활동지에도 실제 키를 적지 않습니다.

직접 확인: 컴퓨터에 저장한 파일뿐 아니라 배포된 파일도 수정했습니다. 자신의 웹앱 주소에서 결과를 확인할 준비가 되었습니다.

5. 내 프로젝트에서 지도와 기존 기능 확인하기

섹션 제목: “5. 내 프로젝트에서 지도와 기존 기능 확인하기”

이 수업의 시작 예제는 HTTP(S) 웹 서버에서 실행하도록 만들어져 파일을 더블클릭한 file:// 화면에서는 안내만 표시합니다. AI 미리보기에서도 외부 지도 실행이 제한될 수 있으므로 내 배포 주소를 새 탭으로 열고 다음을 직접 확인합니다.

직접 확인: 내 주소 안에서 배경·세 지점·클릭 설명·출처가 보이고 기존 기능도 작동하면 지도 연결 점검을 마친 것입니다. 이제 아래에서 우리 팀이 선택한 자료를 연결합니다.

6. 안 보이면 내 웹앱의 실제 오류 확인하기

섹션 제목: “6. 안 보이면 내 웹앱의 실제 오류 확인하기”

먼저 배포된 내 파일에 키를 넣었는지, 그 키의 앱이 ON인지, 현재 주소가 SDK 도메인에 등록됐는지 확인합니다. 흰 화면이나 실패 안내만으로 저작권 문제라고 단정하지 않습니다.

PC에서 오류 문구 찾기

섹션 제목: “PC에서 오류 문구 찾기”
  1. 내 웹앱 주소를 Chrome·Edge 등으로 엽니다. Windows는 F12 또는 Ctrl+Shift+I, Mac은 ⌘+⌥+I, 또는 페이지에서 우클릭 → 검사로 개발자도구를 엽니다.
  2. Network(네트워크)를 누른 상태에서 페이지를 새로고침합니다. 검색·필터 칸에 sdk.js를 입력합니다.
  3. dapi.kakao.com의 sdk.js 요청을 선택하고 Response(응답)를 봅니다. 오류 JSON이 있으면 message의 실제 문구를 확인합니다. 401·403 같은 숫자만으로 원인을 정하지 않습니다.
  4. Console(콘솔)의 실제 오류도 확인합니다. sdk.js 요청이 아예 없으면 키 자리표시자·이전 배포본·앞서 발생한 코드 오류를 점검합니다.
  5. 도움을 요청할 때는 키나 토큰을 지운 오류 문구와 내 웹앱 주소를 전달합니다. 요청 URL의 appkey= 뒤 값이나 화면에 나온 실제 키는 가립니다. 응답이 긴 프로그램 코드라면 전체를 복사하지 말고 Console의 실패 문구를 확인합니다.

iPad처럼 개발자도구를 바로 열기 어렵다면 화면에 표시된 오류 문구를 키 없이 기록하고, 선생님과 PC에서 같은 웹앱 주소를 확인하세요. 오류를 못 읽었다면 ‘확인하지 못함’이라고 적으면 됩니다.

현재 파일 사본의 실제 키를 자리표시자로 바꾼 뒤 AI에 첨부하고, 아래 요청에 직접 관찰한 내용을 채우세요.

내 카카오 지도 오류 확인 요청 {{빨간 부분}}을 우리 팀의 내용으로 바꾸세요.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

# 확인 순서
1. 지도 영역의 높이, SDK 로딩, autoload=false와 kakao.maps.load 콜백 안에서 초기화하는지 확인해줘.
2. JavaScript 키를 사용했는지, 카카오맵 사용 설정이 ON인지, 실제 웹앱 호스트·포트가 해당 키의 JavaScript SDK 도메인 설정에 포함되는지 확인해줘. 도메인 입력 형식은 실제 주소의 프로토콜·호스트·포트를 쓰고 뒤의 페이지 경로는 제외한다. 현재 카카오 설정은 http/https 중 하나를 등록하면 둘 다 지원하므로 프로토콜 차이만으로 오류라고 단정하지 마.
3. AI 미리보기의 iframe·CSP 제한인지, 실제 배포 주소에서도 생기는 오류인지 구분해줘. 등록할 주소는 지도를 실제로 실행하는 우리 팀 웹앱의 도메인이다. 교과서 주소나 GitHub 저장소 화면 주소를 등록하지 않도록 안내해줘.
4. 401·403·429 또는 차단 문구는 실패한 요청과 실제 응답을 보고 인증·도메인·사용 설정·쿼터·네트워크 문제를 구분해줘. disabled OPEN_MAP_AND_LOCAL service 응답이면 입력한 키가 속한 앱의 카카오맵 → 사용 설정 → ON을 먼저 확인해줘. ON인데 계속되면 같은 앱의 키인지와 이용 상태를 확인하고, 모든 403을 같은 원인으로 단정하지 마. 오류 문구 없이 저작권 문제라고 단정하거나, 출처 표시 한 줄만 넣으면 무조건 해결된다고 말하지 마.
5. 지도는 보이는데 마커가 없다면 우리 팀 자료를 실제로 읽었는지, 파일·API 응답의 목록 경로와 필드 이름·좌표계·위경도 순서·빈 값·조회 범위·필터를 확인해줘. 없는 좌표를 추정해서 채우지 마.

# 수정 조건
- 확인한 사실과 추정을 나누어 설명하고, 부족한 정보가 있으면 무엇을 직접 확인할지 알려줘.
- 정상 작동하는 기능과 실제 데이터 연결, 파일 구조와 배포 방식을 유지해줘. 한 파일 HTML이면 수정한 전체 HTML을, 여러 파일 프로젝트면 수정한 파일별 전체 코드와 적용 위치를 제공해줘.
- SDK 주소는 https://dapi.kakao.com/v2/maps/sdk.js?appkey=YOUR_JAVASCRIPT_KEY&autoload=false 를 사용해줘. JavaScript 키는 YOUR_JAVASCRIPT_KEY로 남겨 내가 직접 입력하게 하고, REST API 키·어드민 키·서버용 비밀키는 요청하거나 코드에 넣지 마.
- 브라우저 보안 설정을 끄거나, 인증·지도 타일 차단을 프록시 등으로 우회하게 하지 마. 출처 표시는 유지해줘.
- 수정한 파일을 실제 배포 주소에서 다시 확인할 구체적인 행동과 예상 결과를 알려줘. 아직 실행하지 않은 결과를 확인 완료라고 쓰지 마.

JavaScript의 Number('')는 0이 됩니다. 0은 위도·경도 범위 안에 있지만, 원자료에 없던 좌표를 새로 만들어 넣으면 실제와 다른 위치가 생깁니다. 빈 값인지 먼저 확인하고, 값이 있을 때 숫자로 바꿔 검사해야 합니다.

# 만들어야 할 기능
1. 기존 지도·디자인·정상 기능과 데이터 연결 방식을 유지하고, 위에서 지정한 우리 팀 자료를 지도에 연결해줘. 특정 시설 종류나 데이터 열을 임의로 정하거나 없는 이름·설명·수치를 만들어내지 마.
2. CSV·JSON 파일을 쓰는 팀이면 기존 파일 읽기를 활용해줘. 파일 선택 기능이 아직 필요하다면 추가하되 선택한 파일은 브라우저에서 읽어줘. 이미 데이터 배열이나 API 응답을 읽고 있다면 그 실제 결과를 사용하고 CSV 파일 선택을 필수로 만들지 마. 샘플 몇 건을 하드코딩해 전체 데이터로 취급하지 마.
3. CSV라면 BOM, 따옴표 안 쉼표와 줄바꿈, 빈 값을 처리하고 단순 split(',')로 파싱하지 마. JSON·API라면 실제 응답에서 기록 목록이 있는 경로와 필드 이름을 확인해줘. API의 페이지별 응답·조회 범위·아직 가져오지 않은 자료를 구분하고, 일부 응답을 전체 자료로 표시하지 마.
4. 위치 필드와 좌표계를 확인해줘. 기존에 검증한 좌표 매핑이나 변환이 있다면 유지해줘. 주소만 있거나 좌표계가 불명확하면 확인할 정보와 좌표 확보 방법을 먼저 설명하고, 좌표를 임의로 만들거나 새 변환 API를 자동으로 추가하지 마. 빈 문자열·공백·문자·범위 밖 좌표를 0으로 바꾸지 마.
5. 현재 읽은 기록 수, 그중 현재 조건에 해당하는 기록 수, 유효 좌표 기록 수와 위치 문제로 제외된 기록 수를 구분해줘. CSV 머리글은 세지 마. 조회 실패·미완료를 '0건'으로 확정하지 말고, 다른 파일·조건·API 응답으로 바뀌면 계산을 갱신해줘.
6. 유효한 WGS84 좌표를 new kakao.maps.LatLng(위도, 경도)에 넣어 마커로 표시해줘. 여러 위치는 LatLngBounds와 map.setBounds로 보여주고, 한 위치·유효 좌표 없음도 처리해줘. 마커 설명에는 위에서 지정한 실제 항목만 보여줘. 분류 필터는 자료에 있고 우리 팀에 필요한 경우에만 만들고, 지도와 목록에 같은 조건을 적용해줘. 자료의 텍스트는 textContent로 넣어 HTML이 실행되지 않게 해줘.
7. 실제 자료를 적용할 때 가상 연습 지점은 제거해줘. 자료나 조건이 바뀌면 이전 마커를 setMap(null)로 정리하고 열린 정보창을 닫은 뒤 새 결과를 보여줘. 원자료와 비교할 수 있는 글 목록도 함께 제공해줘.
8. 같은 좌표의 여러 기록을 임의로 하나로 합치지 마. 기록 수·고유 지점 수·수치의 합계는 각각의 기준을 설명할 수 있을 때만 구분해서 보여줘. 고유 지점을 판단할 기준이 없다면 그 수를 추정하지 마.
9. 자료 미선택·조회 중·조회 실패·자료 없음·필드 불일치·좌표 누락·필터 결과 없음·배경 지도 실패 중 실제 방식에 해당하는 상태를 안내해줘. 원자료가 알려 주지 않는 현재 상태나 기능을 확인한 것처럼 표현하지 마.

# 지도와 실행 조건
- 첨부한 프로젝트의 파일 구조와 배포 방식을 유지해줘. 한 파일 HTML이면 그 구조로, 프레임워크 프로젝트면 그 구조에 맞게 수정하고 지도 영역에 높이를 지정해줘. 지도 표시만을 위해 새 서버·데이터베이스나 실시간 기능을 추가하지 마.
- SDK는 https://dapi.kakao.com/v2/maps/sdk.js?appkey=YOUR_JAVASCRIPT_KEY&autoload=false 를 사용하고, SDK 로드 후 kakao.maps.load 콜백 안에서 지도 객체를 만들어줘. 카카오 지도만 사용해줘.
- JavaScript 키는 코드의 YOUR_JAVASCRIPT_KEY 자리표시자로 남겨 내가 직접 입력하게 해줘. REST API 키·어드민 키·서버용 비밀키를 넣지 마. 등록할 JavaScript SDK 도메인은 학생 웹앱의 프로토콜·호스트·사용 중인 포트이며, 뒤의 경로는 제외한다.
- 로컬 CSV·JSON 파일을 읽는 기능에는 별도 공공데이터 API 인증키를 요구하지 마. API를 사용하는 팀은 기존 서비스의 인증·호출 방식과 한도를 유지하고, 아직 해결되지 않은 인증·브라우저 호출 제한이 있으면 필요한 설정을 설명해줘. 서버용 비밀키를 공개 코드에 넣거나 보안 제한을 우회하지 마.
- 카카오 로고와 저작권 표시, 우리 팀 데이터의 출처·기준일·조회 범위를 표시해줘.

# 결과 형식
한 파일 HTML이면 수정한 index.html 전체를, 여러 파일 프로젝트면 수정한 파일별 전체 코드와 적용 위치를 알려줘. 자료와 지도 항목을 어떻게 연결했는지 설명하고, 원자료 3건의 이름·위치·선택한 속성과 대조할 방법을 알려줘. 빈 좌표 처리와 우리 팀 방식에 맞는 파일 재선택·API 재조회·필터 변경 중 해당하는 검증을 안내해줘. 직접 확인하지 않은 결과를 성공했다고 쓰지 마.

CSV 파일 선택은 구체적인 연결 방법의 한 예입니다. 이 방식을 택했다면 내 웹앱의 파일 선택 버튼으로 CSV를 열고, 일부 샘플이 아닌 선택한 파일 전체를 읽어 계산합니다. 한글이 깨지면 인코딩을 확인합니다. 브라우저에서 파일을 읽는 기능에는 공공데이터 API 키나 서버 저장이 필요하지 않으며, CSV를 공개 저장소에 올릴 필요도 없습니다. JSON·API를 사용하는 팀이 CSV로 바꿀 필요는 없습니다.

원자료 3개 항목과 결과 대조하기

섹션 제목: “원자료 3개 항목과 결과 대조하기”

원자료에서 서로 다른 위치의 3행 또는 3개 항목을 골라 지도 위치·식별 이름과 우리 팀이 표시하기로 한 값을 비교합니다. 다음도 직접 확인합니다.

  • 빈 좌표는 잘못된 위치에 점을 만들지 않고 제외한 항목 수에 반영되는가?
  • 자료나 조회 조건을 바꾸면 이전 마커가 정리되는가? 분류 필터를 만들었다면 목록과 지도도 같은 조건을 보여 주는가?
  • 실제로 읽은 현재 조건의 항목 수 = 유효 좌표 항목 수 + 좌표 문제로 제외한 항목 수인가? 행·항목 수, 서로 다른 위치 수, 자료 속 수치의 합계를 구분했는가?
  • 원자료를 일부만 읽었다면 그 범위를 알리고, 출처·기준일·지도 저작권 표시를 유지했는가?

자료에서 확인되지 않는 실시간 상태나 의미를 추정하여 표시하지 않습니다. 확인하지 못한 것은 ‘확인 필요’로 남깁니다.
