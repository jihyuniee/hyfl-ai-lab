STEP 1. 문제와 사용자 정하기

섹션 제목: “STEP 1. 문제와 사용자 정하기”

누가, 어떤 상황에서, 무엇이 어려운지 한 문장으로 적습니다. 관련 용어와 제도는 기관의 원문 자료를 찾아 확인합니다.

[사용자]는 [상황]에서 [하려는 일]을 하고 싶지만 [어려움]을 겪는다. 우리는 [데이터로 확인할 부분]을 살펴보고 [도울 방법]을 만들려고 한다.

작성 예시 · 사실 조사 전의 아이디어: “우리 지역 청소년이 이용할 문화시설을 찾을 때 위치와 운영시간을 한곳에서 비교할 수 있는 앱을 만들고 싶다.” 실제 불편과 필요한 정보는 사용자에게 묻거나 관찰하고, 데이터에 해당 항목이 있는지 확인합니다.

위 내용은 주제 작성 예시입니다. 실제 자료에 위치·주소·이용 조건이 있는지 먼저 확인한 뒤 기능을 정합니다. 목표 상태는 “사용자가 조건을 골라 필요한 정보를 찾는다”처럼 앱에서 직접 시험할 수 있는 행동으로 적어 보세요.

다음 작업: 주제 후보 하나에 대해 실제 자료를 열어 보고, 필요한 항목이 있는지 확인합니다. 자료가 없으면 대상·지역·기간·보여 줄 항목 중 조정할 부분을 팀에서 정합니다.

2-1. 실제 데이터 확보하기

섹션 제목: “2-1. 실제 데이터 확보하기”

공공데이터포털·KOSIS·관련 공공기관에서 자료를 찾습니다. 파일과 Open API 중 확보한 자료의 제공 방식을 사용합니다.

자료를 받는 방법앱에 연결할 때 준비할 것
CSV·JSON 등 파일실제 파일, 열 이름과 의미, 단위, 출처 주소
Open API공식 문서, 요청 주소와 조건, 비밀값을 가린 실제 응답 예시

한 행이 무엇을 뜻하는지 먼저 확인하세요. 시설 한 곳의 정보인지, 지역별 합계인지에 따라 계산 방법이 달라집니다. 출처·기준일·지역·단위·이용 조건도 기록합니다. API를 쓰면 응답 항목과 전체 건수, 페이지별 제공 건수를 확인합니다.

검색 결과는 있는데 쓸 수 있는 자료인지 모르겠다면

자료 소개 페이지만 읽지 말고 파일을 내려받아 열거나 API 요청을 한 번 보내 응답을 확인하세요.

  1. 실제 열 이름 또는 응답 항목을 찾습니다.
  2. 앱에서 보여 줄 정보가 있는지 확인합니다. 지역별 시설 수만 있는 자료로 개별 시설 주소를 표시할 수는 없습니다.
  3. 우리 팀이 사용할 지역·기간의 자료가 있는지 확인합니다.
  4. 한 행 또는 응답 항목 하나를 골라 뜻을 설명해 봅니다.

여기까지 준비: 출처 주소, 실제 파일 또는 응답, 사용할 항목과 의미. 요청 오류나 파일 열기 문제는 오류 문구와 함께 선생님께 보여 주세요.

파일 경로코드의 경로·파일 이름·대소문자가 올린 파일과 같은지 확인
컴퓨터 안의 주소내 PC의 파일 경로 대신 배포 환경에서 읽을 경로를 사용하는지 확인
지도·API 설정실제 배포 주소를 서비스에 등록해야 하는지 공식 문서에서 확인
변경 반영수정 파일이 저장됐는지, 배포가 완료됐는지 확인한 뒤 새로고침

원인은 실제 오류로 확인합니다. 선생님이나 AI에게 배포 주소·관련 파일·클릭 순서·오류 문구를 함께 전달하세요.

STEP 4. AI 활용 기록하기

섹션 제목: “STEP 4. AI 활용 기록하기”

프로젝트의 방향이나 결과에 영향을 준 사례를 골라 기록합니다.

  • 실제로 보낸 요청과 AI가 도와준 내용
  • 원자료·공식 문서·실행으로 팀이 확인한 내용
  • 팀이 채택·수정·제외한 내용과 이유

같은 기능의 반복 수정은 묶어서 요약할 수 있습니다. 수행하지 않은 활동이나 확인하지 않은 결과를 기록하지 않습니다.

STEP 5. 기여와 배운 점 정리하고 발표하기

섹션 제목: “STEP 5. 기여와 배운 점 정리하고 발표하기”

각자 실제로 한 일, 중요한 판단, 확인하거나 수정한 경험, 배운 점을 활동지에 작성합니다. 팀원 모두 문제·데이터·핵심 기능을 설명할 수 있도록 함께 검토합니다.

발표는 활동지와 웹앱을 열어 다음 순서로 3분 동안 진행합니다.

  1. 누구의 어떤 문제를 해결하려 했는가?
  2. 어떤 데이터에서 무엇을 발견했고, 어떤 기능으로 연결했는가?
  3. 앱에서 실제로 입력하면 어떤 결과가 나오는가? 직접 시연합니다.
  4. 결과를 어떻게 확인했고, 남은 한계와 개선할 점은 무엇인가?
AI 도움받기 · 발표 순서 정리
3분 발표 준비 표시된 부분을 우리 팀의 내용으로 바꾸세요.
프롬프트 구조와 각 부분이 필요한 이유 보기

역할·프로젝트 맥락은 AI가 어떤 관점에서 어느 팀의 문제를 다루는지 정합니다.

과업·필수 기능은 만들어야 할 결과와 빠뜨리면 안 되는 동작을 정합니다.

화면·디자인·기술 조건은 실제 사용자와 실행 환경의 제약을 전달합니다.

오류 처리·검증 기준은 실패했을 때의 안내와 완성 여부를 판단하는 기준입니다.

우리 팀의 프로젝트 발표를 준비하려고 한다.
구글 클래스룸 활동지 내용: [문제 정의, 데이터, 분석, 인사이트, 구현, 검증]
발표 시간: 3분
발표 화면: 활동지의 핵심 표·그래프와 최종 웹앱

다음 흐름으로 발표 대본과 보여 줄 화면, 시연 순서를 제안해줘.
1. 누구의 어떤 문제를 해결하려 했는가? (STEP 1-2·1-3)
2. 어떤 데이터에서 무엇을 발견했고, 왜 그 기능을 만들었는가? (STEP 2-1·2-2의 표·그래프)
3. 웹앱에 실제로 입력하거나 조건을 선택하면 어떤 결과가 나오는가? (최종 웹앱 시연)
4. 결과를 어떻게 검증했고, 남은 한계와 개선 방향은 무엇인가? (STEP 3-2·3-3)

AI 활용과 팀원별 기여는 STEP 4·5에 기록한 실제 사례를 관련 장면에서 짧게 설명하도록 구성해줘.
슬라이드는 선택 사항이며, 활동지와 웹앱만으로 발표할 수 있게 해줘.
확인하지 않은 역할이나 활동은 만들지 말아줘.

데이터로 확인한 사실, 팀의 해석, 앞으로 확인해야 할 내용을 구분해줘. 근거 없이 효과를 과장하지 말아줘.

제출 전 확인: 활동지의 주제·출처·분석 결과·앱 설명이 실제 웹앱과 일치하는지 확인합니다. 실행 주소 또는 파일은 STEP 3-1에도 적고, 활동지 최종본을 구글 클래스룸에 제출합니다.
