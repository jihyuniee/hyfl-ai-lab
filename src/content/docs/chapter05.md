지금까지 배운 지도학습·훈련/테스트·모델이라는 개념을 하나의 프로젝트로 묶습니다. 이 프로젝트는 여러 챕터로 나뉘어 있지 않습니다 — **문제 발견부터 공유까지 하나의 흐름**으로 진행하며, 중간중간 필요한 이론을 그때그때 배웁니다. (약 5~7차시)

## 미션

> **우리 생활의 작은 문제를 해결하는 이미지 분류 AI를 만들어라.**

거창할 필요 없습니다. "내 물병과 친구 물병이 자꾸 섞인다", "분리수거를 할 때 이게 플라스틱인지 헷갈린다"처럼 교실·집·학교에서 진짜로 겪는 작은 불편함에서 시작하세요.

## STEP 1. 문제 발견

모둠별로 "이미지로 구분할 수 있는 작은 문제"를 하나 찾습니다. AI에게 시킬 일은 결국 **사진을 보고 무엇인지 구분하는 것**이라는 점을 기억하세요.

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 데이터란?]
AI가 학습하는 재료를 **데이터**라고 합니다. 우리 프로젝트에서 데이터는 곧 '사진'입니다. 좋은 문제는 곧 좋은 데이터를 모을 수 있는 문제입니다. 사진으로 찍어서 눈으로 구분이 되는 문제인지 먼저 점검하세요.
:::

## STEP 2. AI가 무엇을 인식해야 하는지 결정 — 클래스 설계

문제를 정했다면, AI가 구분해야 할 **범주(클래스)**가 몇 개이고 각각 무엇인지 정합니다.

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 클래스와 레이블]
**클래스**는 AI가 구분해야 할 범주(카테고리)입니다. **레이블**은 각 데이터(사진)에 붙이는 정답 이름입니다. "이 사진은 Class 1(플라스틱)이다"라고 붙이는 이름표가 바로 레이블입니다. 4차시 Teachable Machine 실습에서 Class 1, Class 2라고 이름 붙였던 것과 같습니다.
:::

클래스는 최소 2개 이상, 서로 눈으로 확실히 구분되도록 설계하세요. 애매한 클래스는 나중에 STEP 6에서 반드시 문제를 일으킵니다.

## STEP 3. 데이터 촬영

클래스별로 최소 30~50장씩 사진을 찍습니다. 각도, 배경, 조명, 거리를 다양하게 바꿔가며 찍으세요.

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 특징(feature)]
AI는 사진 전체를 사람처럼 '이해'하는 게 아니라, 색깔·모양·질감 같은 **특징(feature)**의 패턴을 수치로 찾아냅니다. 배경이나 조명처럼 우리가 신경 쓰지 않는 요소도 AI에게는 특징으로 잡힐 수 있습니다. 그래서 사진을 다양한 조건에서 찍는 것이 중요합니다 — 배경만 다르고 실제로는 같은 물건인데, 배경 색깔을 특징으로 잘못 학습해버릴 수도 있기 때문입니다.
:::

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 훈련 데이터]
지금 찍고 있는, 모델을 **학습시키는 데 사용할 데이터**를 훈련 데이터라고 합니다. 모델의 실력은 결국 훈련 데이터의 양과 다양성에 달려 있습니다.
:::

## STEP 4. 학습

Teachable Machine에 데이터를 업로드하고 **Train Model**로 학습시킵니다.

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 모델]
학습이 끝난 결과물을 **모델**이라고 부릅니다. 모델은 "이런 특징을 가진 사진은 Class 1일 확률이 높다"는 판단 기준을 갖게 된 프로그램입니다. 아직 이 모델이 실제로 얼마나 똑똑한지는 모릅니다 — 그건 다음 단계에서 확인합니다.
:::

## STEP 5. 테스트

이제 훈련에 쓰지 않은 **새로운 사진**으로 모델을 테스트합니다. 모둠 안에서 촬영에 참여하지 않은 친구, 또는 다른 모둠 친구에게 부탁해서 테스트해보세요.

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 테스트 데이터]
모델을 학습시킬 때 쓰지 않고 **성능을 평가하기 위해 따로 남겨둔 데이터**를 테스트 데이터라고 합니다. 훈련 데이터로 다시 테스트하면 모델이 이미 '외운' 사진이라 당연히 잘 맞습니다. 진짜 실력은 **한 번도 보지 못한 데이터**로 확인해야 정확합니다.
:::

:::note[📚 잠깐, 여기서 배우는 AI 원리 — 정확도]
테스트 데이터 중 모델이 맞힌 비율을 **정확도(Accuracy)**라고 합니다. "정확도 90%"는 테스트 사진 10장 중 9장을 맞혔다는 뜻입니다. 정확도는 높을수록 좋지만, 정확도만으로 모델이 완벽하다고 판단하면 안 됩니다 — 그 이유는 바로 다음 단계에서 확인합니다.
:::

## STEP 6. 실패

친구가 테스트했을 때 갑자기 틀리는 사진이 나올 겁니다. 자연스러운 일입니다. **이 실패가 이번 프로젝트에서 가장 중요한 순간**입니다.

> "내 사진에서는 정확도 100%였는데, 왜 친구 사진에서는 틀렸을까?"

## STEP 7. 원인 분석

모둠별로 틀린 사진들을 모아놓고 공통점을 찾아보세요. 배경이 비슷했나요? 촬영 각도가 훈련 데이터에는 없던 각도였나요? 특정 클래스의 사진 수가 유독 적었나요?

:::caution[📚 잠깐, 여기서 배우는 AI 원리 — 일반화 · 데이터 편향 · 과적합]
- **일반화(Generalization)**: 훈련 때 보지 못한 새로운 데이터에서도 잘 작동하는 능력. 우리가 원하는 진짜 목표입니다.
- **데이터 편향(Bias)**: 훈련 데이터가 한쪽으로 치우쳐 있으면, 모델도 그 치우침을 그대로 배웁니다. (예: 촬영자 한 명의 손, 한 가지 배경으로만 찍었다면 다른 사람·다른 배경에서는 성능이 떨어집니다.)
- **과적합(Overfitting)**: 모델이 훈련 데이터를 너무 '외워버려서', 새로운 데이터에는 오히려 성능이 떨어지는 현상. 훈련 정확도는 100%인데 테스트 정확도는 낮다면 과적합을 의심해야 합니다.

내 모델이 친구 사진에서 틀린 이유는 이 세 가지 중 무엇에 가장 가까운가요?
:::

## STEP 8. 데이터 수정 → 재학습 → 성능 개선

원인을 찾았다면 데이터를 보완합니다. 부족한 각도의 사진을 더 찍거나, 배경을 다양하게 바꾸거나, 클래스별 사진 수를 맞춥니다. 그리고 **다시 학습 → 다시 테스트**합니다. 정확도가 올라갔다면 무엇을 바꿔서 나아졌는지 기록해두세요. 이 과정을 1~2회 반복합니다.

## STEP 9. 웹앱으로 공유

완성된 모델을 Teachable Machine의 **Export Model** 기능으로 내보내고, 생성형 AI(ChatGPT, Claude 등)의 도움을 받아 이 모델을 사용하는 간단한 웹페이지를 만들어봅니다. "웹캠으로 사진을 찍으면 AI가 어떤 클래스인지 알려주는 페이지를 만들어줘"처럼 자연어로 요청하면 됩니다. 완성한 웹앱은 GitHub Pages 등으로 배포해서 다른 모둠과 링크를 공유하고, 서로의 AI를 테스트해줍니다.

## 발표

모둠별로 다음 내용을 3분 안에 발표합니다.

1. 어떤 문제를 풀려고 했는가
2. 클래스는 어떻게 설계했는가
3. 처음 테스트에서 무엇이 실패했는가, 원인은 무엇이었는가
4. 데이터를 어떻게 바꿔서 얼마나 개선했는가 (정확도 변화)
5. 데모: 실시간으로 다른 모둠 친구를 테스트해보기

## 정리

- 이 프로젝트에서 여러분은 데이터 수집부터 클래스·레이블 설계, 훈련/테스트 데이터 분리, 모델 학습, 정확도 평가, 실패 원인 분석(편향·과적합), 재학습을 통한 개선까지 머신러닝의 전체 과정을 직접 경험했습니다.
- "훈련 데이터와 테스트 데이터를 분리해야 올바른 성능 평가와 일반화 능력을 확보할 수 있다"는 문장은 이제 외운 문장이 아니라, 여러분이 직접 겪은 경험이 되었습니다.
