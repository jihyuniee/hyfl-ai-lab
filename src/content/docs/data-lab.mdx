## 1. 만들 앱과 사용 장면 살펴보기

**만들 앱: 급식 메뉴 탐색기**

학생이 학교·월·검색어를 선택하면, 해당 메뉴가 포함된 중식 날짜와 일수를 보여 줍니다. 첫 사용 흐름을 만든 뒤 비교와 화면 기능을 발전시켜 봅니다.

**CSV 선택 → 조건 선택 → 검색 → 날짜·식단 확인 → 다른 조건으로 비교**

[기본 앱 열기](/hyfl-ai-lab/templates/meal-explorer/)에서 화면을 살펴봅니다. 처음에는 ‘가상 점검 데이터 불러오기’로 조작해 볼 수 있습니다. 이 6개 기록은 기능 확인용으로 만든 자료입니다. 실제 학교의 식단 분석에는 다음 단계에서 확보한 공공데이터를 사용합니다.

앱을 만져 보며 ‘어떤 정보가 먼저 보여야 할까?’, ‘검색한 결과를 어떻게 확인하면 좋을까?’를 생각해 봅시다.

## 2. 급식 데이터 준비하기

### 원자료에서 CSV 받기

나이스의 [급식식단정보 Sheet 화면](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17320190722180924242823&infSeq=1)을 엽니다. 이 화면에는 조회 결과를 파일로 저장하는 기능이 있습니다.

<Steps>
<Step title="학교와 기간 정하기">조회 조건에서 사용할 학교와 급식일자 범위를 정합니다. 수업에서 정한 공통 학교·기간을 기준으로 조회하고, 결과의 학교명·날짜·식사명을 확인합니다.</Step>
<Step title="자료의 범위 확인하기">검색된 건수와 실제 날짜를 살펴봅니다. 화면 일부와 전체 조회 결과 중 어느 범위를 저장하는지 확인합니다.</Step>
<Step title="CSV 저장하기">‘파일변환저장’의 CSV를 선택해 저장합니다. 화면이나 다운로드 방식이 달라졌다면 같은 출처에서 준비한 공통 파일을 사용하고 조회 조건을 확인합니다.</Step>
<Step title="원본과 사본 나누기">원본 파일은 보관하고 사본을 만들어 분석합니다. 사본을 스프레드시트로 열어 아래 네 항목을 확인합니다.</Step>
</Steps>

| 분석용 열 | 원자료에서 찾을 항목 | 앱에서 하는 일 |
| --- | --- | --- |
| 날짜 | 급식일자 또는 MLSV_YMD | 날짜·월 선택과 일수 계산 |
| 학교명 | 학교명 또는 SCHUL_NM | 학교 구분 |
| 식사명 | 식사명 또는 MMEAL_SC_NM | 중식 기록 선택 |
| 메뉴 | 요리명 또는 DDISH_NM | 검색과 식단 원문 표시 |

사본의 열 이름을 `날짜, 학교명, 식사명, 메뉴`로 맞춥니다. 날짜는 `YYYY-MM-DD` 또는 `YYYYMMDD` 형태로 준비하고, 메뉴 원문과 알레르기 표시는 함께 보존합니다. 이 기본 앱은 표에 적힌 NEIS 열 이름도 읽을 수 있습니다.

Google 스프레드시트에서는 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**, Excel에서는 **다른 이름으로 저장 → CSV UTF-8** 형식으로 저장할 수 있습니다. 원본이 XLSX일 때도 이 과정을 거쳐 CSV를 만듭니다. 화면 명칭은 사용 중인 버전에 따라 조금 다를 수 있습니다.

### 작업 폴더 만들기

```text
meal-project/
  source/          원본 자료와 출처 메모
  meals.csv        분석용 사본
  index.html       우리가 만들 앱
  versions/        정상 실행본과 수정 기록
```

파일명과 저장 위치를 알아두면 AI에게 오류를 설명하거나 다른 기기에서 다시 실행할 때 도움이 됩니다. 우선은 파일 선택 방식으로 시작하고, API를 이용한 자동 갱신은 이후 확장 단계에서 살펴볼 수 있습니다.

## 3. 데이터를 읽고 질문 다듬기

자료의 일부를 직접 읽고, 한 행이 무엇을 뜻하는지 확인합니다. 같은 학교·날짜에 조식과 중식이 함께 있거나 같은 날짜의 기록이 여러 줄인지도 살펴봅니다.

> **[학교·기간]의 중식에서 ‘카레’라는 문자열이 포함된 메뉴가 나온 날짜는 며칠일까?**

예상한 결과를 적은 뒤 짧은 기간을 골라 직접 셉니다. 전체 중식일 수, 검색어가 포함된 날짜, 중복을 처리한 기준을 기록합니다. 이 결과를 나중에 앱의 계산과 대조합니다.

<CopyPrompt title="급식 자료를 읽고 계산 기준을 정하는 프롬프트" content={mealDataPrompt} />

### 발견에서 기능으로 연결하기

같은 날짜가 여러 행에 있다면 행 수와 급식일 수가 달라질 수 있습니다. 월별 전체 급식일 수가 다르면 횟수와 비율을 함께 보아야 비교가 쉬울 수 있습니다. 우리 자료에서 실제로 확인한 점을 골라 기능으로 연결합니다.

**확인한 사실 → 사용자에게 필요한 정보 → 앱의 처리·표시 방법**

자료에 들어 있는 것은 편성된 식단 기록입니다. 학생의 선호도나 만족도까지 알아보려면 그에 맞는 추가 자료가 필요합니다. 찾은 자료가 처음 질문과 다르면 기간·대상·검색 기준을 바꾸어 봅시다.

## 4. 화면과 기능 설계하기

앱을 열었을 때 사용자가 무엇을 할지 떠올리며 화면을 다섯 영역으로 나눕니다.

| 화면 영역 | 보여 줄 내용 | 사용자가 하는 일 |
| --- | --- | --- |
| 제목과 설명 | 앱 이름, 찾아볼 수 있는 정보 | 앱의 목적 이해 |
| 데이터 준비 | 파일 선택, 출처·조회 조건·확인일 | 사용할 자료 확인 |
| 조건 선택 | 학교, 월, 검색어, 검색 버튼 | 원하는 조건 입력 |
| 결과 | 일수 요약, 날짜별 메뉴 원문 | 결과 읽고 원자료 대조 |
| 도움말과 출처 | 계산 기준, 자료 범위, 안내 | 결과의 의미 확인 |

### 첫 화면과 결과 화면 그려 보기

```text
[급식 메뉴 탐색기]
어떤 메뉴가 언제 나왔는지 찾아보세요.

[CSV 파일 선택]       자료 출처·기간
[학교 선택] [월 선택] [검색어 입력] [검색]

[전체 중식일]         [검색된 중식일]

날짜                 메뉴 원문
검색 조건에 맞는 날짜와 식단이 표시됩니다.

출처 · 확인일 · 계산 기준
```

아직 파일을 고르기 전에는 시작 방법을, 결과가 없을 때는 조건을 바꾸는 방법을 안내합니다. 파일을 읽기 어려울 때는 필요한 열 이름이나 파일 형식을 알려 줍니다. 이런 화면도 앱의 기능에 포함됩니다.

<CopyPrompt title="화면과 기능을 먼저 설계하는 프롬프트" content={mealPlanPrompt} />

<Step title="파일 이름과 인코딩 확인">Windows 메모장에서는 ‘다른 이름으로 저장’을 선택하고 파일 이름 index.html, 파일 형식 모든 파일, 인코딩 UTF-8로 저장합니다. 실제 확장자가 .html인지 확인합니다.</Step>
<Step title="브라우저로 열기">index.html을 Chrome이나 Edge로 엽니다. 앱의 파일 선택에서 meals.csv를 불러옵니다. 이 단계는 PC의 웹브라우저에서 진행합니다.</Step>
<Step title="같은 조건으로 검색">직접 센 것과 같은 학교·월·검색어를 선택합니다. 출처와 확인일을 적고, 날짜·일수가 예상한 결과와 맞는지 확인합니다.</Step>
<Step title="첫 실행본 보관">정상 실행된 index.html을 versions 폴더에 별도 이름으로 복사합니다. 이후에는 무엇을 바꾸었는지 비교하며 수정합니다.</Step>
</Steps>

코드를 읽기 어려울 때는 AI에게 **자료를 읽는 부분, 조건을 적용하는 부분, 날짜를 세는 부분, 결과를 표시하는 부분**을 짚어 설명해 달라고 요청합니다. 각각이 화면의 어느 동작과 연결되는지 살펴봅니다.

기본 흐름을 다시 확인할 때는 <a href="/hyfl-ai-lab/templates/meal-explorer/index.html" download="index.html">기본 index.html</a>과 <a href="/hyfl-ai-lab/templates/meal-explorer/check-data.csv" download="check-data.csv">가상 점검 CSV</a>를 사용할 수 있습니다. 기본 코드를 출발점으로 선택했다면 우리 팀이 바꾼 부분을 기록합니다.

## 6. 원자료와 실행 결과 대조하기

정상 검색부터 빈 결과와 파일 오류까지 조건을 바꾸어 실행합니다.

| 시험할 상황 | 확인할 결과 |
| --- | --- |
| 실제 메뉴 검색 | 직접 확인한 날짜·일수와 일치 |
| 검색어를 비운 상태 | 선택한 범위의 전체 중식일 |
| 자료에 없는 검색어 | 0일과 검색 결과 없음 안내 |
| 월을 바꾼 상태 | 해당 월의 기록과 결과 |
| 중복·누락 기록 | 날짜를 묶는 기준과 제외·확인 안내 |
| 잘못된 CSV | 필요한 항목 안내, 이전 결과 초기화 |

<details>
<summary>가상 점검 CSV로 계산 확인하기</summary>

가상학교의 6개 기록을 날짜별로 묶으면 전체 중식일은 5일입니다. ‘카레’를 검색하면 3일이 나옵니다. 2025년 9월은 전체 3일 중 2일, 10월은 전체 2일 중 1일입니다. 이 숫자는 기능 확인용이며 실제 학교의 식단 결과와 구분합니다.

## 7. 화면을 다듬고 기능 확장하기

첫 흐름이 작동하면 데이터에서 발견한 점이나 직접 사용하며 느낀 불편을 바탕으로 다음 기능을 정합니다.

### 비교 기능 발전시키기

월별 비교 표, 검색된 중식일의 비율, 날짜별 보기 등 필요한 기능을 선택합니다. 비율을 표시할 때는 **검색된 중식일 ÷ 선택한 범위의 전체 중식일 × 100**이라는 기준과 분모를 함께 확인합니다.

### 사용하기 편한 화면 만들기

화면의 글자 크기와 여백을 조정하고, 자주 사용하는 조건을 찾기 쉽게 배치합니다. 표의 날짜와 메뉴는 읽기 편하게 정렬하고, 휴대기기에서는 입력 영역이 한 열로 내려오도록 구성할 수 있습니다. 색상과 함께 문구로도 상태를 설명합니다.

AI에게 화면을 요청할 때는 ‘예쁘게’라는 말에 더해 **누가 어떤 기기에서 쓰는지, 먼저 보여 줄 정보가 무엇인지, 현재 불편한 배치가 어디인지**를 설명합니다. 기능과 계산 기준은 유지하면서 화면만 바꾸는 요청도 연습해 봅시다.

짝에게 검색 과제를 주고 앱을 사용하게 합니다. 혼자 할 수 있었던 일과 머뭇거린 장면을 살펴본 뒤 한 부분을 개선합니다. 개선 후에는 검색과 계산도 다시 실행합니다.

## 8. 공유하고 다음 프로젝트로 이어가기

### 웹 주소로 공유하기

GitHub Pages에 게시하면 다른 기기에서도 주소로 앱을 열 수 있습니다. 기존 작업을 보존하며 새 저장소를 준비합니다.

<Steps>
<Step title="새 저장소 만들기">GitHub에서 New repository를 열어 meal-data-lab 같은 이름을 정하고 저장소를 만듭니다. 계정과 공개 범위는 수업 안내를 따릅니다.</Step>
<Step title="파일 올리기">Add file → Upload files로 index.html을 저장소 최상위에 올리고 Commit changes를 누릅니다. 파일 선택 방식에서는 사용자가 CSV를 별도로 준비합니다.</Step>
<Step title="Pages 설정">Settings → Pages의 Source에서 Deploy from a branch를 선택합니다. Branch는 main, 폴더는 /(root)를 선택하고 Save를 누릅니다.</Step>
<Step title="주소로 테스트">Actions에서 게시 작업을 확인하고 Pages에 표시된 주소를 엽니다. iPad에서는 Safari로 주소에 접속하고 파일 앱에 저장한 CSV를 선택합니다.</Step>
</Steps>

공개할 파일은 데이터의 이용 조건을 확인해 정합니다. 개인정보와 인증 정보는 공개 파일과 분리합니다. 게시가 진행되는 동안에는 PC에서 파일 실행과 원자료 확인을 계속할 수 있습니다.

<details>
<summary>실행·게시가 막힐 때 확인할 곳</summary>

| 상황 | 먼저 확인할 것 |
| --- | --- |
| 코드가 글자로 보인다 | 파일 이름이 index.html인지, 브라우저로 열었는지 |
| 파일을 골라도 결과가 없다 | CSV 형식, 필수 열, 중식 기록, 실제 학교·기간 |
| 한글이 깨진다 | UTF-8로 저장한 CSV인지 |
| Pages에서 파일을 찾지 못한다 | 지정한 브랜치·폴더의 최상위에 index.html이 있는지 |
| 수정 내용이 보이지 않는다 | Commit 완료, Actions 결과, 새로 고침 |
| 학교에서 계정 접속이 어렵다 | 수업에서 안내한 접속 환경을 확인하고 PC 파일 실행으로 기록 이어가기 |

</details>

통합 학습지의 공통 실습 기록을 마무리합니다. **어떤 자료와 기준을 썼는지, 어떤 기능을 바꾸었는지, 무엇을 직접 확인했는지**를 남깁니다. 다음 프로젝트에서는 같은 제작 방법을 활용하며 우리 팀의 문제와 자료를 탐구합니다.
