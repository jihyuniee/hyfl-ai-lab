## Final Project Mission

<Callout kind="mission" title="AI for a Better World">
**사람과 사회에 도움이 되는 문제 하나를 선택하고, AI를 활용한 해결책을 기획하세요.**

완성된 앱이나 웹서비스를 개발할 필요는 없습니다. 중요한 것은 문제를 깊이 이해하고, 왜 AI가 필요한지 판단하고, AI가 맡을 역할을 구체적으로 설계하는 것입니다.
</Callout>

## 무엇을 만들까보다 무엇을 해결할까

이번 프로젝트에서는 "AI 앱 하나 만들기"부터 시작하지 않습니다.

**문제 → 사람 → 원인 → 현재 해결 방법 → 한계 → AI가 도울 수 있는 지점 → 서비스 아이디어**

순서로 생각합니다.

<Callout kind="caution" title="좋은 프로젝트의 출발점">
❌ "진로 추천 AI를 만들겠다."  
⭕ "진로를 탐색하는 학생들은 정보가 너무 많지만 자신의 관심과 연결해 비교하기 어렵다. 이 문제에서 AI는 어떤 도움을 줄 수 있을까?"
</Callout>

## 프로젝트 흐름

<Steps>
	<Step title="1. 해결할 문제 선택">DISCOVER 단계에서 찾은 문제 중 실제로 더 알아보고 싶은 문제 하나를 선택합니다.</Step>
	<Step title="2. 대상 사용자 구체화">'학생'처럼 넓게 쓰지 않습니다. 어떤 상황에 있는 어떤 사람인지 구체적으로 정합니다.</Step>
	<Step title="3. 문제를 이해할 근거 찾기">인터뷰, 간단한 설문, 관찰, 공개 자료, 통계, 신뢰할 수 있는 보고서 등 필요한 만큼만 찾아 내 생각이 실제 문제와 맞는지 확인합니다.</Step>
	<Step title="4. 기존 해결 방법 조사">사람들은 지금 이 문제를 어떻게 해결하고 있는지 살펴봅니다.</Step>
	<Step title="5. 해결되지 않는 GAP 찾기">현재 방법이 있는데도 남아 있는 어려움이 무엇인지 정리합니다.</Step>
	<Step title="6. AI가 필요한지 판단">AI를 사용하면 무엇이 실제로 더 좋아지는지 설명합니다. AI가 필요하지 않다면 다른 해결 방법을 선택해도 됩니다.</Step>
	<Step title="7. AI의 역할 설계">분류, 추천, 생성, 번역, 요약, 분석, 개인화, 대화 등 AI에게 맡길 구체적인 일을 정합니다.</Step>
	<Step title="8. 사람의 역할 설계">AI가 결정하면 안 되는 부분, 사람이 확인해야 하는 부분, 최종 책임을 져야 하는 부분을 정합니다.</Step>
	<Step title="9. 사용자 시나리오 만들기">사용자가 어떤 상황에서 서비스를 만나고, 무엇을 입력하고, AI가 무엇을 하며, 어떤 도움을 받는지 이야기처럼 설명합니다.</Step>
	<Step title="10. 위험과 한계 점검">잘못된 답, 편향, 개인정보, 저작권, 과도한 의존 등 서비스에서 발생할 수 있는 문제를 예상합니다.</Step>
	<Step title="11. 해결책 개선">친구에게 기획을 설명하고 "정말 필요한가?", "AI가 왜 필요한가?", "어디가 위험한가?" 피드백을 받아 수정합니다.</Step>
	<Step title="12. 최종 제안">문제와 해결책의 연결이 한눈에 보이도록 최종 서비스 기획안을 발표합니다.</Step>
</Steps>

## AI에게 맡길 수 있는 일

AI가 할 수 있는 일을 기능 이름이 아니라 **문제 속 역할**로 생각해봅니다.

| AI가 할 수 있는 일 | 문제 해결에서의 예 |
| --- | --- |
| 분류 | 많은 자료를 기준에 따라 구분하기 |
| 추천 | 사람의 상황에 맞는 선택지를 제안하기 |
| 생성 | 초안, 설명, 학습 자료, 아이디어 만들기 |
| 요약 | 긴 정보에서 중요한 내용 정리하기 |
| 번역 | 언어 장벽 낮추기 |
| 분석 | 데이터나 기록에서 패턴 찾기 |
| 대화 | 사용자의 질문을 받고 필요한 정보를 이어서 제공하기 |
| 개인화 | 사람마다 다른 상황과 필요에 맞게 결과 조정하기 |

하나의 서비스에 모든 기능을 넣을 필요는 없습니다. **문제 해결에 꼭 필요한 역할 한두 개를 정확하게 설계하는 것이 더 중요합니다.**

## 정말 AI가 필요한가?

<Callout kind="concept" title="AI Necessity Check">
다음 질문에 답해보세요.

1. 이 문제는 AI 없이도 간단히 해결할 수 있는가?
2. AI를 사용하면 사용자가 구체적으로 무엇을 더 얻는가?
3. AI가 틀렸을 때 피해가 큰 문제인가?
4. AI가 판단해도 되는 부분과 사람이 판단해야 하는 부분은 무엇인가?
5. 필요한 데이터나 정보는 안전하고 적절하게 사용할 수 있는가?
</Callout>

AI를 쓰지 않는 것이 더 좋은 해결책이라면 그것도 좋은 판단입니다.

## 서비스 이용 시나리오

기능 목록만 작성하지 말고 한 사람의 경험으로 설명합니다.

> **사용자 상황 → 입력 → AI가 하는 일 → 결과 → 사용자가 얻는 도움 → 사람이 확인할 부분**

예를 들어 외국어 학습 서비스라면 "단어 테스트 기능, 챗봇 기능"이라고 쓰는 것보다, 어떤 학습자가 언제 왜 사용하며 AI가 정확히 어떤 어려움을 줄여주는지 보여주는 것이 더 중요합니다.
