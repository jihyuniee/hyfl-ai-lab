내 웹앱에 AI 챗봇 넣기

챗봇·요약·설명·번역 기능이 필요한 팀을 위한 프로젝트 도움말입니다. 교과서의 신청 양식과 시작 파일을 이용해 자신의 웹앱 안에 AI 기능을 연결합니다.

🎯 AI API 사용 신청

우리 팀 앱에 GPT나 Claude를 활용하는 기능을 넣고 싶다면 선생님께 API 사용을 요청하세요. 사용할 서비스·모델, 사용 대상·기간·한도를 확인하고 프로젝트 서버의 키 설정을 지원받습니다.

진행 순서: 역할 정하기 → 신청문 전달 → 내 프로젝트 준비 → 서버 환경변수 설정·배포 → 질문과 답변 확인

1. 우리 앱에서 AI가 할 일 정하기

섹션 제목: “1. 우리 앱에서 AI가 할 일 정하기”

AI API는 앱에서 보낸 질문이나 자료를 모델이 처리하고 결과를 돌려주는 연결 방식입니다. 팀은 누가 어떤 질문을 하고, 어떤 자료를 바탕으로 어떤 답변을 받을지 정합니다.

기능 예시AI에 전달할 내용확인할 결과

시설 안내우리 앱이 검색한 시설 정보와 사용자 조건해당 자료에 근거한 안내
외국어 안내출처가 있는 안내문과 선택한 언어번역문과 원문 출처

프로젝트의 주제와 사용할 자료는 각 팀이 정합니다. 집계·검색·필터는 코드로 처리하고 원자료와 대조한 결과를 AI에 전달합니다.

A. 현재 만드는 앱이 있는 팀

섹션 제목: “A. 현재 만드는 앱이 있는 팀”
  1. 현재 정상 작동하는 프로젝트를 보관합니다.
  2. 아래 시작 파일을 연결 예제로 준비하고, 현재 프로젝트 파일이나 저장소를 AI에 제공합니다.
  3. 5단계의 요청문으로 현재 화면·기능을 유지하며 챗봇 화면과 서버 경로를 추가합니다. 프레임워크 프로젝트는 해당 프레임워크의 서버 경로를 사용합니다.
  4. 기존 배포 환경에서 서버 실행이 지원되는지 확인합니다. HTML 프로젝트를 Vercel로 배포할 때는 4단계를 따릅니다.

B. 작은 챗봇부터 연결할 팀

섹션 제목: “B. 작은 챗봇부터 연결할 팀”

🧪 챗봇 시작 파일 받기

챗봇 시작 파일 ZIP 다운로드

압축을 풀어 파일을 준비합니다. 질문·답변 화면, 이용코드 확인, OpenAI·Claude 호출용 서버 코드, 설정 안내가 들어 있습니다. 서비스와 모델은 서버 환경변수로 선택합니다.

  1. 압축을 푼 폴더에서 index.html, api 폴더, package.json, vercel.json, README.md와 함께 제공된 파일을 확인합니다.
  2. GitHub에 프로젝트 저장소를 만들고 폴더 안의 파일과 하위 폴더를 구조대로 올립니다. index.html과 package.json이 저장소의 최상위에 오도록 합니다.
  3. README.md를 열어 필요한 환경변수와 서버 구성을 확인합니다.
  4. 다음 단계에서 서버 환경변수를 설정하고 배포합니다.

4. 서버 환경변수 설정하고 배포하기

섹션 제목: “4. 서버 환경변수 설정하고 배포하기”

다음은 시작 파일을 Vercel로 배포하는 순서입니다. 기존 프로젝트의 서버 환경을 쓰는 팀은 그 서비스의 환경변수 설정과 배포 절차를 사용합니다.

  1. Vercel에 로그인하고 New Project를 엽니다. 처음 연결할 때는 GitHub 계정을 연결하고 사용할 저장소의 접근 권한을 설정한 뒤 우리 저장소를 선택합니다.
  2. 시작 파일은 Framework Preset: Other, Root Directory: 파일이 있는 저장소 루트를 확인합니다. Build Command의 Override를 켜고 값을 비워 빌드 단계를 생략합니다.
  3. Environment Variables에 아래 이름과 값을 등록합니다. 기존 프로젝트는 Settings → Environment Variables에서 등록합니다.
  4. 사용할 배포 환경을 선택합니다. 실제 수업용 주소에는 Production 설정을 적용합니다.
  5. Deploy로 배포하고 완료된 웹앱 주소를 엽니다. 환경변수를 나중에 추가하거나 변경했으면 Redeploy하여 새 배포에 적용합니다.

API 비밀키는 서버가 AI를 호출할 때 사용하는 값입니다. 앱 이용코드는 허용된 이용자가 챗봇 화면에서 입력하는 값입니다. 두 값은 각각 따로 설정합니다. 이용코드는 허용된 사람에게 전달하고, 코드 파일에는 자리표시자를 사용합니다.

선택 설정인 CHAT_SYSTEM_PROMPT에는 챗봇의 역할을, MAX_OUTPUT_TOKENS에는 서버의 최대 출력 토큰 수를 지정할 수 있습니다. 시작 파일의 기본값과 설정 범위는 함께 받은 README.md에서 확인합니다. OpenAI 키 보관 · Claude 인증과 워크스페이스 범위

첫 실행: 배포된 주소에서 앱 이용코드를 입력하고 짧은 질문을 보냅니다. 답변, 처리 상태, 새 대화 기능을 확인합니다. 기존 앱에 지도를 사용한다면 새 배포 주소에 맞춰 지도 서비스의 도메인 설정도 갱신합니다.

3. 현재 프레임워크에 맞는 서버 경로를 만들고, 브라우저가 같은 배포 주소의 서버 API를 호출하도록 연결해줘. 정적 HTML 프로젝트라면 교과서의 Vercel 시작 예제 구조를 적용해줘.
4. AI_PROVIDER·AI_MODEL과 해당 서비스의 OPENAI_API_KEY 또는 ANTHROPIC_API_KEY를 서버 환경변수에서 읽어줘. 실제 키는 내가 배포 서비스 설정 화면에 입력할 거야. 설명·예제·공개 파일에는 자리표시자를 사용해줘.
5. 시작 예제의 CHAT_ACCESS_CODE 인증, 입력·대화·출력 길이 제한, 시간 초과·실패 처리를 유지해줘. 모델과 출력 한도는 서버 설정을 적용해줘.
6. 자료를 활용하는 기능은 현재 조회한 관련 항목과 출처·기준일을 질문과 함께 전달해줘. 계산·검색·필터 결과는 기존 코드로 구하고, 자료와 AI 답변을 화면에서 구분해줘. 확인할 근거가 부족한 내용은 확인 필요로 안내해줘.
7. 키나 이용코드의 실제 값은 마스킹해줘. 추가로 필요한 프로젝트 파일이 있으면 경로와 역할을 알려줘.

# 결과
수정 파일·위치·이유, 적용할 코드, 환경변수 이름, 배포 순서, 실제 검사 결과와 추가 확인 항목을 정리해줘. 연결된 저장소를 수정했다면 실제 커밋 또는 PR 링크를 알려줘. 원자료와 대조할 질문 3개와 오류 상황을 검증할 방법을 포함해줘.

자료를 활용하는 팀은 관련 항목·출처·기준일을 질문과 함께 전달합니다. 시작 파일의 참고자료 입력란에는 작은 자료와 출처를 넣어 연결을 확인할 수 있습니다. 이후에는 현재 앱의 검색·조회 결과를 전달하도록 수정합니다.

질문과 대화, 참고자료에는 시작 파일이 정한 입력 제한이 적용됩니다. AI에 전달할 자료는 질문에 필요한 범위로 골라 준비합니다. 답변 화면에는 AI가 생성한 답변임을 표시하고 원자료를 확인할 수 있는 출처를 함께 제공합니다.
